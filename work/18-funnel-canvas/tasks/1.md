# Task 1: Backend additive persistence — canvasPosition + notes[] round-trip

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Add the single new persisted concept the canvas needs — **node coordinates** — as additive, nullable
fields on the existing funnel graph model. No migration (Decision 8): missing embedded fields read as
`null` on old documents and the frontend auto-layouts those nodes.

Three new things are stored:
- `canvasPosition {x,y}` embedded on `FunnelStep` (per-step node coordinates).
- `canvasPosition {x,y}` embedded on `Trigger` (per-trigger / start-node coordinates).
- `Funnel.notes[]` — a new top-level array of `{id, text, canvasPosition}` for free-floating canvas
  notes that the engine never executes (Decision 7: notes live outside `steps[]`).

**The load-bearing risk (Decisions 6, 7):** because every funnel DTO is
`@JsonIgnoreProperties(ignoreUnknown = true)`, a new field that is not threaded through **all five seams**
is silently dropped on the PATCH↔read round-trip and the saved value never returns to the editor. The five
seams for each field are:
1. Domain field + accessors (`FunnelStep`, `Trigger`, `Funnel`).
2. `FunnelStep.copyOf` (the deep-copy execution snapshot — its own silent-drop seam).
3. The DTO record component (`FunnelStepDto`, `TriggerDto`, `FunnelResponse`, `UpdateFunnelRequest` + new
   `NoteDto` / `CanvasPositionDto`).
4. The forward mapper (`toSteps` for steps; the trigger pass `applyTriggers` for triggers; a new
   notes-forward pass).
5. The reverse mapper (`toStepDto` for steps; `toTriggerDtos` for triggers; a new notes-reverse pass).

**Security bounds (Data Models, AC):** `notes[]` gets an array cap with a service-side re-check (mirroring
the existing `MAX_TRIGGERS` DoS guard); note `text` gets a `@Size` length cap; note `id` is **server-minted**
(`new ObjectId().toHexString()` when the incoming id is null, preserved otherwise — exactly like
`FunnelService.toSteps` mints step ids), never trusted from the body; `CanvasPositionDto` rejects
non-finite coordinates (NaN / Infinity).

Result: a PATCH carrying `canvasPosition` (step + trigger) and `notes[]` round-trips back on read; the app
starts without error on funnels that have no stored coordinates.

## What to do

- Add an immutable `CanvasPosition` value record (`Double x; Double y;`) in the `com.botfunnel.funnel`
  package — the embedded coordinate type shared by steps, triggers, and notes.
- Add a `Note` embedded POJO/record (`String id; String text; CanvasPosition canvasPosition;`) in the
  `com.botfunnel.funnel` package (mirror the existing flat-embedded `Trigger` / `FunnelStep` convention: no
  `@Document`, no `_class`).
- `FunnelStep`: add a nullable `canvasPosition` field + accessors; carry it (reference copy, immutable
  record) in `FunnelStep.copyOf`.
- `Trigger`: add a nullable `canvasPosition` field + accessors. **`canvasPosition` stays OUT of
  `Trigger.equals` and `Trigger.hashCode`** — those two methods must keep comparing **exactly the four
  existing routing fields and no others: `triggerType`, `triggerValue`, `keywords`, `entryStepId`**
  (`entryStepId` is already part of equals/hashCode today — do not add or remove any field). `canvasPosition`
  is rendering-only metadata; leaving it out keeps the trigger redirect re-scan / dedupe behaviour from
  17-funnel-multi-entry unchanged. Document the choice in a code comment next to the field.
- `Funnel`: add a nullable `List<Note> notes` field + accessors.
- DTOs (records, all already `@JsonIgnoreProperties(ignoreUnknown = true)`):
  - New `CanvasPositionDto {Double x; Double y;}` with finite-value bean validation (reject NaN/Infinity).
  - New `NoteDto {String id; @Size(max=NOTE_TEXT_MAX) String text; CanvasPositionDto canvasPosition;}`
    (`id` null on create → server-minted).
  - `FunnelStepDto` += `CanvasPositionDto canvasPosition`.
  - `TriggerDto` += `CanvasPositionDto canvasPosition`.
  - `UpdateFunnelRequest` += `@Valid @Size(max=MAX_NOTES) List<NoteDto> notes` (define a `MAX_NOTES`
    constant on the record, mirroring `MAX_TRIGGERS`).
  - `FunnelResponse` += `List<NoteDto> notes`.
- `FunnelService` mappers — thread the new fields through both directions:
  - Forward: `toSteps` maps `dto.canvasPosition()` → step; the trigger pass `applyTriggers` maps
    `dto.canvasPosition()` → each built `Trigger`; a new notes-forward pass maps `request.notes()` →
    `Funnel.notes` with the **service-side cap re-check** (mirror the `MAX_TRIGGERS` guard), **server-minted
    note id** (preserve non-null incoming id, mint `new org.bson.types.ObjectId().toHexString()` when null),
    and a note-`text` length re-check.
  - Reverse: `toStepDto` maps step → `CanvasPositionDto`; `toTriggerDtos` maps each trigger →
    `CanvasPositionDto`; `toResponse` builds `notes` for `FunnelResponse` via a new notes-reverse pass.
- Wire the new `FunnelResponse.notes` component into the `new FunnelResponse(...)` call in `toResponse`.
- Add the round-trip + bounds integration tests (see TDD Anchor) before implementing.

## TDD Anchor

Tests written BEFORE implementation, run → confirm red → implement → confirm green. The round-trip ITs live
in `FunnelControllerIT` (existing HTTP round-trip IT; the 16-persistent-keyboard round-trip block at
~L151–L185 is the precedent to copy). The `copyOf` assertion is a focused domain test (`FunnelStepTest`
exists). Assertions check **concrete field values on the right model object**, not counts or key-presence.

- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java::canvasPosition_step_and_trigger_round_trips`
  — PATCH a funnel whose step and on_start trigger carry `canvasPosition {x,y}`; GET → both
  `canvasPosition` values return with the exact x/y (forward + reverse mapper); a sibling field that must
  NOT change (e.g. `step.next`) is asserted unchanged.
- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java::notes_round_trip_with_server_minted_id`
  — PATCH a funnel with `notes:[{id:null, text:"hi", canvasPosition:{x,y}}]`; GET → the note returns with
  the same text + coordinates and a **server-minted non-null id** (ObjectId hex shape); a second PATCH that
  echoes the minted id preserves it (id not re-minted).
- `backend/src/test/java/com/botfunnel/funnel/FunnelStepTest.java::copyOf_carries_canvasPosition`
  — `FunnelStep.copyOf(source)` returns a copy whose `canvasPosition` equals the source's (reference copy
  of the immutable record); a null `canvasPosition` copies to null.
- `backend/src/test/java/com/botfunnel/funnel/dto/CanvasPositionDtoTest.java::rejects_non_finite_coordinates`
  — a unit test that constructs a `CanvasPositionDto` **directly in Java** with a non-finite `Double`
  (`Double.NaN` and `Double.POSITIVE_INFINITY` cases) and asserts the finite-value bean validation reports a
  violation, while a finite `{x,y}` passes. This is the path that actually reaches the validator. **Do NOT**
  assert non-finite via a JSON body in an IT: a bare `NaN`/`Infinity` token is invalid JSON, so Jackson
  rejects it at parse time (HTTP 400) **before** bean validation runs — such a test would pass for the wrong
  reason and never exercise `Double.isFinite`.
- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java::rejects_non_finite_coordinate_json`
  — (optional, documents the parse-layer behaviour) PATCH whose body contains a literal `NaN` coordinate token
  → 400 at JSON parse time; the funnel is not mutated. Keep this clearly labelled as a *parse-layer* check,
  distinct from the validator unit test above.
- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java::rejects_notes_over_cap_and_oversized_text`
  — PATCH with `notes` exceeding `MAX_NOTES` → 422 (service re-check fires, not only the DTO `@Size`); a
  note `text` over `NOTE_TEXT_MAX` → 400/422.
- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java::starts_on_coordinate_less_funnel`
  — a funnel saved with no `canvasPosition` / no `notes` reads back with `canvasPosition == null` and
  `notes == null`/empty without error (additive-nullable, no migration).

## Acceptance Criteria

- [ ] `canvasPosition` (step + trigger) and `notes[]` survive a PATCH↔read round-trip (forward + reverse
      mapper + `FunnelStep.copyOf`); no silent drop.
- [ ] Application reads/writes funnels with no stored coordinates without error (nullable, no migration).
- [ ] A fresh note (`id == null` in the body) receives a server-minted ObjectId-hex id; a note with an
      existing id keeps it.
- [ ] `notes[]` array cap enforced at the DTO (`@Size(max=MAX_NOTES)`) AND re-checked service-side
      (mirrors the `MAX_TRIGGERS` DoS guard); note `text` length capped (`@Size(max=NOTE_TEXT_MAX)`).
- [ ] Non-finite coordinates (NaN / Infinity) are rejected by `CanvasPositionDto` validation.
- [ ] Note `id` is never trusted from the body for shape — server controls minting.
- [ ] `Trigger.canvasPosition` is excluded from `Trigger.equals`/`hashCode`, which still compare/hash exactly
      `triggerType`, `triggerValue`, `keywords`, `entryStepId` (semantics relied on by 17-funnel-multi-entry;
      documented choice).
- [ ] No regressions in existing backend tests (`./gradlew test`).

**Edge cases:**
- Funnel saved before this feature: `canvasPosition == null` on every step/trigger, `notes == null` →
  must read back without error (additive nullable, Decision 8).
- `notes == null` vs `notes == []` in the body — both valid; decide and keep consistent (mirror how
  `triggers` null/empty is handled in `applyTriggers` L683–687).
- Note with a non-null id echoed from a prior read — preserved as-is. The tech-spec requires server-minting,
  not cross-note dedupe; if you add a uniqueness check, document it.
- Non-finite `x` OR `y` (NaN/Infinity in either) → reject.
- `canvasPosition` with one coord null (`{x:1, y:null}`) — prefer all-or-nothing finite when present;
  document the choice.

**Implementation hints:**
- Copy the 16-persistent-keyboard round-trip IT block in `FunnelControllerIT` (~L151–L185) as the structural
