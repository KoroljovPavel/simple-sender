# Task 2: Frontend foundation — Vue Flow/dagre deps + types

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Закладываем фундамент фронтенда для канвас-редактора воронок, на который опираются все последующие
фронтенд-задачи (Task 4 mapping layer, Task 5 canvas surface, Task 6 authoring, Task 7 page wiring).

Две части:

1. **Зависимости + SSR-плумбинг.** Добавить `@vue-flow/core` (графовый редактор Vue 3) и `@dagrejs/dagre`
   (авто-лейаут) в `frontend/package.json`. Vue Flow трогает `window`/DOM на этапе setup, а приложение
   работает с включённым SSR (в `nuxt.config.ts` нет `ssr: false`) → без client-only плумбинга сборка/рендер
   падает с `window is not defined` (Decision 12, Risk 1). На этом шаге нужно подготовить почву: импорт CSS
   `@vue-flow/core/dist/style.css` и, если потребуется для чистой сборки, тюнинг `vite.transpile` /
   `optimizeDeps` в `nuxt.config.ts`. Прецедент уже есть в проекте — alias-стаб `@vue/devtools-api`
   (`nuxt.config.ts` L34-42), который спец-кейсит причуды бандлера. Сам `*.client.vue`-компонент канваса
   создаётся в Task 5 — здесь только зависимости и базовая конфигурация, которые должны пройти `pnpm build`.

2. **Типы.** Расширить `frontend/types/funnel.ts` новыми полями, зеркалящими backend-DTO из Task 1:
   `canvasPosition` на шаге и триггере, `notes[]` на воронке/ответе/запросе обновления. Поля additive,
   nullable/optional — никакой ломки существующих контрактов.

Результат: типы компилируются (`pnpm typecheck`), `pnpm build` проходит чисто с установленными новыми
зависимостями (без `window is not defined`).

## What to do

1. Добавить в `frontend/package.json` (секция `dependencies`) пакеты `@vue-flow/core` и `@dagrejs/dagre`,
   затем выполнить `pnpm install`, чтобы зафиксировать версии в lock-файле и поставить пакеты.
2. Расширить `frontend/types/funnel.ts`:
   - Добавить `interface CanvasPosition { x: number; y: number }`.
   - На `FunnelStep` добавить optional `canvasPosition?: CanvasPosition | null`.
   - На `FunnelTrigger` добавить optional `canvasPosition?: CanvasPosition | null`.
   - Добавить `interface FunnelNote { id?: string | null; text: string; canvasPosition?: CanvasPosition | null }`.
   - На `FunnelResponse` добавить optional `notes?: FunnelNote[] | null`. (В файле сейчас нет отдельного
     `interface Funnel` — есть `FunnelResponse` и `FunnelSummaryResponse`; целевой носитель `notes` —
     `FunnelResponse`. Не создавай общий `Funnel`-тип в этой задаче — держи скоуп минимальным.)
   - На `UpdateFunnelRequest` (PATCH body) добавить optional `notes?: FunnelNote[] | null`.
   - Каждое новое поле снабдить кратким doc-комментарием в стиле файла (зеркало backend-DTO, семантика
     nullable, server-minted `id` для заметок — см. Decision 7).
3. Подготовить SSR-плумбинг в `nuxt.config.ts`: импорт CSS Vue Flow и (только если без этого сборка
   ругается) точечный тюнинг `vite` (`optimizeDeps.include` / транспайл). Не отключать SSR глобально и не
   создавать `*.client.vue` — это скоуп Task 5.
4. Убедиться, что `pnpm typecheck` и `pnpm build` проходят чисто.

## Details

<!-- Все детали для выполнения задачи. -->

**Files:**
- `frontend/package.json` — добавить `@vue-flow/core` и `@dagrejs/dagre` в `dependencies`. Текущее состояние:
  графовых/canvas-библиотек нет вообще (code-research §6). `packageManager` зафиксирован `pnpm@10.33.2` —
  ставить через `pnpm`, не npm/yarn. `scripts.prebuild` (`node scripts/check-locales.mjs`) выполняется
  перед `nuxt build` — на этой задаче новых i18n-ключей нет, паритет локалей трогать не нужно.
- `frontend/nuxt.config.ts` — текущее состояние: SSR включён (нет `ssr: false`), DevTools выключены,
  есть `vite.resolve.alias` стаб для `@vue/devtools-api` (L34-42) — это прямой прецедент для бандлер-причуд.
  Сюда добавить CSS-импорт Vue Flow и, при необходимости, `vite.optimizeDeps`/транспайл. Не ломать
  существующие `vite.resolve.alias`, `i18n`, `nitro.devProxy`, `routeRules`.
- `frontend/types/funnel.ts` — текущее состояние: `FunnelStep` (L125-166) уже несёт граф-поля
  (`id`/`next`/`buttons`/`timeout*`), но НЕТ `canvasPosition`; `FunnelTrigger` (L44-49) — `triggerType`/
  `triggerValue`/`keywords`/`entryStepId`, без `canvasPosition`; `FunnelResponse` (L186-201) и
  `UpdateFunnelRequest` (L213-219) — без `notes`. Нет `interface Funnel` (есть только `FunnelResponse`/
  `FunnelSummaryResponse`) и нет `FunnelNote`/`CanvasPosition`. Поля добавляются additive.

**Dependencies:**
- Зависит от: ничего (Wave 1, `depends_on: []`).
- Эту задачу потребляют: Task 4 (mapping layer читает `canvasPosition`/`notes`), Task 5 (canvas surface),
  Task 7 (page wiring/persist). Бэкенд-зеркало этих полей — Task 1 (DTO/доменные поля); типы фронта должны
  соответствовать DTO Task 1 (`CanvasPositionDto {Double x, Double y}`, `NoteDto {id, text, canvasPosition}`),
  но это разные задачи — здесь только фронтовые типы.
- Новые пакеты: `@vue-flow/core`, `@dagrejs/dagre`.

**Edge cases:**
- `notes` и `canvasPosition` должны быть optional И nullable (`?: ... | null`) — backend отдаёт `null` на
  старых воронках без координат/заметок (Decision 8, нет миграции); тип должен это допускать без приведения.
- `canvasPosition` использует `number` (не `Double`) на фронте — это норма зеркалирования; backend
  валидирует конечность значений (отдельная задача).
- `FunnelNote.id` optional/nullable: фронт шлёт `id: null` для новой заметки, сервер минтит ObjectId hex
  (Decision 7) — отрази это в doc-комментарии типа.
- Не путать `canvasPosition` (координаты канваса) с `position`/`order` (индекс в массиве `steps[]`) —
  именно поэтому имя `canvasPosition`, а не `position` (Decision 6, code-research §4 NAME-COLLISION).

**Implementation hints:**
- Стиль файла `funnel.ts`: каждое поле/интерфейс сопровождается комментарием «mirrors backend DTO …» с
  семантикой — придерживайся того же тона для новых полей.
- SSR-плумбинг: цель шага — чтобы `pnpm build` прошёл с установленными deps. Если `nuxt build` зелёный
  только с импортом CSS — лишний `vite`-тюнинг не добавляй (YAGNI). `optimizeDeps`/транспайл — только если
  сборка реально ругается; alias-стаб `@vue/devtools-api` показывает, как проект адресует подобные кейсы.
- CSS Vue Flow подключается через `css: [...]` в `nuxt.config.ts` (рядом с существующим
  `~/assets/css/tailwind.css`) либо импортом в client-компоненте Task 5 — для прохождения сборки на этой
  задаче достаточно зарегистрировать `@vue-flow/core/dist/style.css` в `nuxt.config.ts`.
- Не создавать `*.client.vue`/`<ClientOnly>` и не отключать SSR глобально — это скоуп Task 5 и явный
  анти-паттерн по Decision 12 (over-broad).
