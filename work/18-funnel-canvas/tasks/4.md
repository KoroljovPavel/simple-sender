# Task 4: Frontend model↔graph mapping layer

## Required Skills

Перед выполнением задачи загрузи:

## Description

Build the **pure model↔graph mapping layer** that sits between the funnel model
(`FunnelResponse` steps + triggers + notes) and Vue Flow. This is the deterministic, side-effect-free
core that the canvas surface component (Task 5) consumes — no DOM, no Vue Flow runtime, no rendering. It
has two directions:

- **Forward (model → graph):** turn `steps[]` + `triggers[]` + `notes[]` into Vue Flow `Node[]` + `Edge[]`.
  Each edge is derived from a specific model field (`FunnelStep.next`, each callback `Button.targetStepId`,
  `FunnelStep.timeoutTargetStepId`, `Trigger.entryStepId`). dagre auto-layouts any node whose
  `canvasPosition` is absent; stored positions are used as-is.
- **Reverse (graph → model):** apply a graph mutation (connect/disconnect an edge, move a node, delete a
  node) back onto a model object by writing the **correct** field — and only that field — so the PATCH
  payload the page sends matches the drawn graph.

The load-bearing contracts (tech-spec Data Models edge-field table, Decisions 3/7/9/11): "no edge" must
serialize to `null`, never `""` (an empty-string id 422s as `funnel_broken_edge`); edges only target
**saved** nodes (`id != null`); notes live in `Funnel.notes[]` and must **never** leak into `steps[]`;
deleting a node auto-cleans every inbound edge and reports an exact disconnect count; broken edges
(target missing/deleted, or `on_start` entry edge deleted → `entryStepId == null`) are detected and
flagged; cross-funnel `SUBSCRIBE_TO_FUNNEL` is surfaced as an exit badge, not an edge.

This task is **unit-heavy** (Testing Strategy: "Unit tests — always"). The layer is the single place the
edge-field semantics live, so it must be exhaustively tested before the canvas component is built on it.

## What to do

1. Create `frontend/composables/useFunnelCanvas.ts` — a pure module/composable exporting the mapping
   functions. No Vue Flow component imports, no DOM access; depend only on the model types from
   `frontend/types/funnel.ts` and on `@dagrejs/dagre` for layout (added in Task 2). Keep all functions
   deterministic and individually unit-testable (prefer plain exported functions over hidden internal
   state).
2. **Forward mapping (model → nodes + edges):** produce a node per saved step, a node per event-trigger,
   an optional `on_start` start node (only when the funnel has an `on_start` trigger — Decision 11), and a
   node per note. Produce edges:
   - default `next` edge from a step (source field `FunnelStep.next`),
   - one callback edge per callback `Button` (source field that button's `targetStepId`; URL buttons carry
     no edge),
   - a timeout edge (source field `FunnelStep.timeoutTargetStepId`),
   - a start/trigger entry edge (source field `Trigger.entryStepId`).
   Tag each edge with enough metadata (source handle type + which button/step it owns) that the reverse
   mapping knows exactly which model field to write.
3. **Layout:** for nodes with a stored `canvasPosition`, use it as-is; for nodes without, run `@dagrejs/dagre`
   over the **full** node/edge set (forest-aware — never assume a single root, never drop orphans). In the
   mixed case lay out only the unpositioned nodes. Wrap the dagre call so a degenerate/malformed graph
   throws are caught and fall back to a simple grid/stacked placement (never return a blank/NaN layout).
4. **Reverse mapping (graph mutation → model):**
   - **Connect** an edge → write the matching field on the source model object with the target node's id;
     touch no sibling field.
   - **Disconnect** ("no edge") → set that field to `null` (never `""`).
   - **Delete a node** → remove it from the model and auto-clean every inbound edge (`next` / button
     `targetStepId` / `timeoutTargetStepId` / `trigger.entryStepId`) that pointed at it; return an exact
     disconnect count; leave all surviving edges/fields unchanged.
   - Enforce the **saved-node-only edge** constraint: refuse to produce an edge whose target id is null
     (unsaved node).
5. **Broken-edge detection:** flag any edge whose target id does not resolve to a node in the set, and any
   `on_start` trigger whose `entryStepId == null` while the start node is present (edge deleted).
6. **Notes isolation:** notes round-trip through `Funnel.notes[]` only; the PATCH-payload builder must
   never place a note into `steps[]`.
7. **Cross-funnel SUBSCRIBE:** a `SUBSCRIBE_TO_FUNNEL` step's `targetEntryStepId` (another funnel) is
   represented as an exit-badge marker on the node, **not** as a graph edge.
8. Create `frontend/tests/composables/useFunnelCanvas.spec.ts` — write the unit tests from the TDD Anchor
   first (red), then implement until green. Assertions check **concrete field values on the right model
   object** plus a sibling field that must NOT change (Testing Strategy) — never counts or key-presence
   alone.

## TDD Anchor

Tests written BEFORE implementation, in `frontend/tests/composables/useFunnelCanvas.spec.ts`. Write → run →
confirm red → implement → confirm green. Assert **concrete field values on the right model object** and a
sibling field that must NOT change (Testing Strategy) — a mis-wired handle must fail the test. (Vitest
`environment: 'nuxt'`, `globals: true`; run with `pnpm test -- canvas`.)

- `tests/composables/useFunnelCanvas.spec.ts::maps model to nodes and edges with correct field+id` —
  steps + optional start node + event-trigger nodes + notes produce the correct node set, and each edge
  carries the correct source field and the correct target id (`next` / `Button.targetStepId` of the
  **right** button / `timeoutTargetStepId` / entry).
- `tests/composables/useFunnelCanvas.spec.ts::connecting a default edge writes next, siblings unchanged` —
  connect → `FunnelStep.next === targetId`; assert `timeoutTargetStepId` and buttons are unchanged.
- `tests/composables/useFunnelCanvas.spec.ts::connecting a button edge writes that button targetStepId only` —
  the right button gets `targetStepId`, other buttons and `next` unchanged.
- `tests/composables/useFunnelCanvas.spec.ts::connecting a timeout edge writes timeoutTargetStepId only` —
  `timeoutTargetStepId === targetId`; `next` and buttons unchanged.
- `tests/composables/useFunnelCanvas.spec.ts::connecting a trigger/start entry edge writes entryStepId` —
  `Trigger.entryStepId === targetId`.
- `tests/composables/useFunnelCanvas.spec.ts::no edge serializes to null not empty string` —
  disconnecting each edge type sets the field to `null` (strict `=== null`, never `''`); siblings unchanged.
- `tests/composables/useFunnelCanvas.spec.ts::dagre lays out nodes when canvasPosition absent` —
  unpositioned nodes receive finite numeric `{x,y}`.
- `tests/composables/useFunnelCanvas.spec.ts::stored canvasPosition used as-is` —
  a node with a stored position keeps exactly those coords (no dagre override).
- `tests/composables/useFunnelCanvas.spec.ts::mixed layout lays out only unpositioned nodes` —
  positioned nodes keep their coords; only the null-position nodes get dagre coords.
- `tests/composables/useFunnelCanvas.spec.ts::degenerate graph falls back to grid placement` —
  a graph that makes dagre throw still yields finite coords for every node (no blank/NaN).
- `tests/composables/useFunnelCanvas.spec.ts::cycle maps and serializes without infinite recursion` —
  a return-to-menu cycle (A.next→B, B.button→A) maps to nodes+edges and the PATCH-payload build terminates.
- `tests/composables/useFunnelCanvas.spec.ts::delete node auto-cleans all inbound edges with exact count` —
  deleting a target nulls every inbound `next`/button/timeout/`trigger.entryStepId` that pointed at it; the
  returned disconnect count is exact; surviving edges/fields unchanged.
- `tests/composables/useFunnelCanvas.spec.ts::broken edge detection flags missing target` —
  an edge to a missing/deleted step id is flagged broken.
- `tests/composables/useFunnelCanvas.spec.ts::broken edge detection flags on_start entry null` —
  an `on_start` trigger with `entryStepId == null` while the start node is present is flagged broken.
- `tests/composables/useFunnelCanvas.spec.ts::notes isolated from steps` —
  a note never appears as a step in the PATCH payload; notes round-trip only through `notes[]`.
- `tests/composables/useFunnelCanvas.spec.ts::add node/edge produces correct PATCH payload` —
  the payload reflects the new node/edge and respects the saved-node-only edge constraint (no edge to an
  unsaved `id == null` node).
- `tests/composables/useFunnelCanvas.spec.ts::cross-funnel SUBSCRIBE renders as exit badge not edge` —
  a `SUBSCRIBE_TO_FUNNEL` step's `targetEntryStepId` produces an exit-badge marker, not a graph edge.

**Edge-field semantics (tech-spec Data Models table — the contract this layer encodes):**
| Edge (handle) | Model field written | "no edge" |
|---|---|---|
| default | `FunnelStep.next` | `null` |
| callback button | that `Button.targetStepId` | `null` (= End) |
| timeout | `FunnelStep.timeoutTargetStepId` | `null` (= End) |
| start / trigger entry | `Trigger.entryStepId` | `null` (broken → 422 on activate) |
| cross-funnel SUBSCRIBE | `targetEntryStepId` (other funnel) | rendered as **exit badge**, not an edge |

**Model field reference (from `frontend/types/funnel.ts`):**
- `FunnelStep`: `id?: string|null` (server-minted, null until first save), `next?: string|null`,
  `buttons?: Button[]|null`, `timeoutTargetStepId?: string|null`, `targetFunnelId?`/`targetEntryStepId?`
  (SUBSCRIBE_TO_FUNNEL). No `order` field — array index is the order.
- `Button`: `type: 'callback'|'url'`, `targetStepId?: string|null` (callback only — URL buttons carry no edge).
- `FunnelTrigger`: `triggerType: string`, `entryStepId?: string|null`.
- Task 2 adds: `canvasPosition?: CanvasPosition|null` on `FunnelStep` + `FunnelTrigger`,
  `FunnelNote { id?, text, canvasPosition? }`, `notes?: FunnelNote[]|null` on `Funnel`/`FunnelResponse`/
  `UpdateFunnelRequest`. If Task 2's types are not yet merged when this task starts, coordinate — they are
  the depends_on:[2] base.

**Dependencies:**
- depends_on Task 2 — needs `@dagrejs/dagre` installed and the `canvasPosition`/`notes[]` type fields in
  `frontend/types/funnel.ts`.
- New packages used (added by Task 2): `@dagrejs/dagre` (layout). `@vue-flow/core` types optional/type-only.

**Edge cases:**
- "No edge" must be `null`, never `""` — an empty-string id 422s as `funnel_broken_edge` (code-research §2).
- Edges only to **saved** nodes (`id != null`); a freshly added node has no id until first PATCH — refuse to
  wire it (code-research §2 "Load-bearing").
- Disconnected subflows / orphans: dagre must lay out the **full** forest, never assume a single root, and
  the layer must preserve orphans on save (code-research §8.2). Multiple trigger `entryStepId`s = multiple
  roots.
- Cycle (return-to-menu): the PATCH-payload build and any graph traversal must be iterative or
  visited-guarded — no infinite recursion.
- dagre throws on degenerate/malformed graphs: wrap the call and fall back to grid/stacked placement so the
  canvas never gets a blank/NaN layout (Risks table).
- Mixed positions (new step added to a laid-out funnel): lay out only the unpositioned nodes; do not move
  nodes that already have a stored `canvasPosition`.
- `on_start` start node is **optional** (Decision 11) — render it only when an `on_start` trigger exists;
  cross-funnel SUBSCRIBE is an exit badge, not an edge (Decision 11).

**Implementation hints:**
- Tag each produced edge with a discriminator (e.g. source handle kind = `next | button | timeout | entry`
  plus the owning step id and, for buttons, the button index/identity) so the reverse mapper writes exactly
  one field deterministically. The assertions check the **right button** got `targetStepId`, so button
  identity must be unambiguous (a callback button has no stable id field — key on its index among callback
  buttons or its label, consistent forward+reverse).
- Keep forward and reverse symmetric: a model → graph → model round-trip with no mutation must be identity.
- dagre usage pattern (code-research §8.3): `new dagre.graphlib.Graph()`, `setNode`/`setEdge`, `dagre.layout`,
  read back `{x,y}` per node. Confirm the exact `@dagrejs/dagre` API/import via Context7 (`/dagrejs/dagre` or
  `@dagrejs/dagre`) before coding — package import shape may differ from the legacy `dagre`.
- Notes never enter `steps[]` — the PATCH-payload builder writes notes into `notes[]` only (Decision 7).
- Server-minted note id: a fresh note sends `id: null`; do not invent client ids (Decision 7).
