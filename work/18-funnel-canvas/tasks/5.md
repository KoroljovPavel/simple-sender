# Task 5: Canvas surface component (client-only)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Build the client-only Vue Flow canvas surface that renders the funnel graph produced by the Task 4 mapping
layer (`useFunnelCanvas`) and lets the author draw edges by dragging from typed output handles.

This is the visible editing surface for funnel structure. It consumes (does NOT re-implement) the mapping
layer: nodes/edges come from `useFunnelCanvas`, and a drawn connection is delegated back to the mapping
layer's edge→model-field writer. The component owns the single `useVueFlow()` instance for the editor page
(shared resource per the tech-spec Shared resources table — exactly 1 per editor page mount). Palette,
side panel, delete-with-cleanup and page wiring are NOT in this task (Tasks 6–7); this task delivers a
renderable, connectable canvas of an *existing* funnel.

Two new components:
- **`FunnelCanvas.client.vue`** — the `<VueFlow>` host. Client-only filename (Decision 12) so Vue Flow's
  `window`/DOM access at setup never runs under Nuxt SSR (`window is not defined`). Owns `useVueFlow()`,
  registers the custom node type, runs initial dagre layout + `fitView` once nodes are initialized (via the
  `onNodesInitialized` callback from `useVueFlow`, or the equivalent `@nodes-initialized` VueFlow event), handles
  `@connect` (draw-to-connect → mapping layer field write), renders broken-edge highlight and the
  cross-funnel SUBSCRIBE exit badge, enables zoom/pan and `only-render-visible-elements` viewport culling.
- **`FunnelCanvasNode.vue`** — the custom node renderer registered as a Vue Flow node type. Exposes the
  typed output handles (one default `next`, one per callback button, one timeout, start/trigger entry) and a
  **lightweight** node body (type + short label/title — NOT the full `FunnelMessagePreview`, which is
  expensive and reserved for focus per Risk: performance / §8.4). Input (target) handle for incoming edges.

Key constraints:
- Decision 12 — component file is `*.client.vue`; import `@vue-flow/core/dist/style.css`.
- Shared resources — `FunnelCanvas.client.vue` owns the one `useVueFlow()` instance; consumers (Tasks 6–7)
  reuse it, they must not create a second.
- Decisions 9/11 — typed output handles per node; cross-funnel `SUBSCRIBE_TO_FUNNEL` renders as an exit
  badge, NOT an edge (target node is not on this canvas); start node only when `on_start` entry exists.
- Edges only to **saved** nodes (`id != null`) and "no edge" serializes to `null`, never `""` (the mapping
  layer enforces the field write; the canvas must not let a connection target an unsaved node).
- Lightweight node body; full `FunnelMessagePreview` only on focus (perf — viewport-culling risk).

## What to do

- Create `FunnelCanvas.client.vue` hosting `<VueFlow>`:
  - Take the funnel model (steps + triggers + notes) as input and feed it through the Task 4
    `useFunnelCanvas` mapping layer to obtain `nodes` + `edges`; bind them to `<VueFlow>`.
  - Own the single `useVueFlow()` instance; register `FunnelCanvasNode` under the custom node type used by
    the mapping layer's node objects (`type` field).
  - Run dagre auto-layout for nodes without stored `canvasPosition` (delegate to the mapping layer's
    layout); call `fitView()` once nodes are initialized — register the `onNodesInitialized` callback from
    `useVueFlow` (equivalently the `@nodes-initialized` event on `<VueFlow>`), not on plain `onMounted`,
    so layout has real node dimensions. Render nodes with a stored `canvasPosition` at those coords.
  - Handle the draw-to-connect event (`@connect`): translate the source handle + target node into the
    correct model-field write via the mapping layer; reject/ignore a connection whose target node is unsaved
    (`id == null`). Emit the updated model upward (e.g. `update:steps` / `update:triggers`) — persistence is
    Task 7, this task only surfaces the change.
  - Render broken-edge highlight: edges the mapping layer flags as broken (dangling target, or `on_start`
    start node with `entryStepId == null`) get a distinct highlighted style.
  - Render the cross-funnel SUBSCRIBE exit badge on the source node instead of an outgoing edge.
  - Enable zoom/pan and `only-render-visible-elements` (viewport culling).
- Create `FunnelCanvasNode.vue` as the custom node renderer:
  - Render typed output `<Handle>`s: one default `next`, one per callback button (id-addressable so the
    mapping layer can resolve which `Button.targetStepId` a drawn edge writes), one timeout (when the step
    carries a timeout target capability), and a start/trigger entry handle for the start/trigger node.
  - Render an input handle for incoming edges.
  - Render a lightweight body: localized step/trigger type + a short title/label. Do NOT mount
    `FunnelMessagePreview` in the default body; reserve the full preview for the focused state only.
  - Mark broken/exit visual states driven by props from the canvas.
- Wire `data-test` attributes on the canvas root, node, handles and broken-edge/exit-badge elements so the
  `mountSuspended` component tests can target them deterministically.

`update:triggers`) — never via store mocking. (No `mockNuxtImport('useFunnelsStore')` here; that store-mock
pattern belongs to the page test, Task 7.)

- `frontend/tests/components/funnels/FunnelCanvas.spec.ts::renders a highlighted broken edge for a dangling
  edge` — mount with a funnel whose `next` (or button/timeout) points at a deleted/missing target → that
  edge renders with the broken-edge highlight class (not a normal edge).
- `frontend/tests/components/funnels/FunnelCanvas.spec.ts::renders cross-funnel SUBSCRIBE as an exit badge,
  not an edge` — mount with a `SUBSCRIBE_TO_FUNNEL` step → an exit badge renders on its node and NO outgoing
  edge to another funnel is rendered.
- `frontend/tests/components/funnels/FunnelCanvas.spec.ts::renders typed output handles per node type` —
  mount with a MESSAGE step that has N callback buttons + a timeout → the node renders the default `next`
  handle + N button handles + 1 timeout handle; a start/trigger node renders the entry handle; assert the
  rendered handle set matches the node type (a mis-typed handle set must fail).
- `frontend/tests/components/funnels/FunnelCanvas.spec.ts::a drawn connection emits the updated model` —
  simulate a `@connect` from a typed handle to a **saved** target node → the component emits
  `update:steps` / `update:triggers` carrying the model with the correct field written; a connection to an
  unsaved (`id == null`) target emits nothing.

  for nodes/edges + edge writes + broken-edge flags + layout. Handles `@connect` and calls `fitView` from
  the `onNodesInitialized` callback (or the `@nodes-initialized` VueFlow event). Enables
  `only-render-visible-elements`.
- `frontend/components/funnels/FunnelCanvasNode.vue` (new) — custom node renderer. Typed output `<Handle>`s
  (default `next`, per-button, timeout, start/trigger entry) + input handle. Lightweight body (type +
  short label). Exit-badge + broken visual states by prop.
- `frontend/tests/components/funnels/FunnelCanvas.spec.ts` (new) — `mountSuspended` component tests per the
  TDD Anchor. Props-in / emits-out: mount with the funnel model as props, assert rendered DOM + emitted
  events. No `mockNuxtImport('useFunnelsStore')` — the component does not read the store.

**Dependencies:**
- Task 4 (`useFunnelCanvas` mapping layer) — this task CONSUMES it; do not re-implement edge→field mapping,
  broken-edge detection, or dagre layout here. Depends_on: [4].
- Task 2 already added `@vue-flow/core` + `@dagrejs/dagre` deps, the CSS import plumbing, and the
  `canvasPosition` / `notes[]` types — assume they are present.

**Edge cases:**
- Unsaved target node (`id == null`): a drawn connection to it must be rejected (cannot mint an edge to an
  unsaved node — node creation/persistence is Task 6/7). "No edge" must serialize as `null`, never `""`.
- `on_start` start node with `entryStepId == null` (edge deleted) → broken edge highlight, not a hard error.
- Cross-funnel SUBSCRIBE → exit badge on the source node, no outgoing edge.
- Disconnected subflows / orphan nodes / forest (multiple trigger entry points) → layout must run over the
  full node/edge set; never assume a single root; never hide orphans (code-research §8.2).
- dagre on a malformed/degenerate graph → guard the layout call (mapping layer owns the fallback; the canvas
  must still render rather than blank).
- A node-type's handle set must match the type (MESSAGE: `next` + per-button + timeout; start/trigger:
  entry) — a mis-wired handle is a test failure.

**Implementation hints:**
- Vue Flow integration: `useVueFlow()` exposes the `onConnect`, `onNodesInitialized` **callbacks** and the
  `fitView` action. Two distinct things — do not conflate them: `onNodesInitialized` is the composable
  callback (`onNodesInitialized(() => fitView())`), and `@nodes-initialized` is the equivalent **template
  event** on the `<VueFlow>` component (`@nodes-initialized="fitView()"`). Pick ONE and use it consistently:
  call `fitView()` from whichever you choose so it fires only after nodes have real measured dimensions
  (not from `onMounted`). Likewise draw-to-connect: `onConnect` callback or the `@connect` template event —
  one, consistently. Custom node type is registered via the `<VueFlow>` `:node-types` map / a `#node-<type>`
  slot. `only-render-visible-elements` is a `<VueFlow>` prop. (Confirm exact API names against current
  `@vue-flow/core` docs via Context7 — `/websites/vueflow_dev` — before coding; the version is whatever
  Task 2 installed.)
- Each callback-button output handle needs a stable id (e.g. button index/id) so the mapping layer can
  resolve which `Button.targetStepId` a drawn edge writes — the edge-field table is in code-research §2 and
  tech-spec Data Models.
- Lightweight node body: render localized type via the existing `funnels.steps.type.*` keys + a short
  title; do NOT mount `FunnelMessagePreview` in the default body (it debounce-calls the backend `preview`
  action and is expensive — §8.4). Reserve the full preview for the focused state.
- Component tests: this is a props-in / emits-out component — do NOT mock `useFunnelsStore` (the canvas does
  not read the store; that store-mock pattern is for the page test in Task 7). Use `mountSuspended` from
  `@nuxt/test-utils/runtime`, pass the funnel model via props, and assert on rendered DOM (`data-test`
  selectors) and on emitted events (`wrapper.emitted('update:steps')` / `'update:triggers'`); `await
  settle()` for async layout. Vue Flow internals may need light stubbing — prefer asserting the canvas/node
  DOM (handles, highlight class, exit badge) and emits over driving real drag (live drag/zoom is
  user-verified, not in component tests — Testing Strategy / no E2E).
- No `v-html` anywhere (note text / labels render via `{{ }}`), matching the strict guard in
  `FunnelMessagePreview` / `FunnelStepForm`.
