# Task 6: Authoring interactions — palette, start node, delete, side panel

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Make the canvas (built in Task 5) fully authorable. This is the layer that turns a renderable/connectable
canvas into a real editor: a node palette, an optional `on_start` start node, node deletion with edge
auto-cleanup, and a side panel that reuses the existing field editors.

Four interactions, all on top of the mapping layer (`useFunnelCanvas`, Task 4) and the canvas surface
(`FunnelCanvas.client.vue`, Task 5):

1. **Palette** — add a node of any of the **9 existing step types** (MESSAGE, DELAY, ADD_TAG, REMOVE_TAG,
   SET_CUSTOM_FIELD, EMIT_EVENT, SUBSCRIBE_TO_FUNNEL, SET_KEYBOARD, CLEAR_KEYBOARD) plus **trigger** and
   **note**. A brand-new node has no `id` until first save, and edges can only target **saved** nodes
   (`id != null`), so adding a node persists it (mints its `id` via the existing PATCH round-trip) before it
   can be wired. The palette offers exactly these 11 entries — no new executable step types (Decision 10).

2. **Optional `on_start` start node** (Decision 11) — add/remove maps to the funnel's `on_start` entry.
   Adding the start node creates/enables the `on_start` trigger; the start node's outgoing edge writes
   `on_start.entryStepId` (handled by the mapping layer). Removing the start node removes the `on_start`
   entry. Removing **only its edge** (not the node) leaves a broken-edge state (`entryStepId == null`),
   highlighted like any other broken edge — not a hard error. Re-adding `on_start` from the palette is
   **disabled** while an `on_start` entry already exists (a funnel has at most one start node).

3. **Node delete with edge auto-cleanup** (Decision 9) — deleting a node removes it and the mapping layer
   auto-cleans every inbound edge pointing at it (`next` / `Button.targetStepId` / `timeoutTargetStepId` /
   `trigger.entryStepId`). Before deleting, the UI warns "N connections will be disconnected" using the exact
   disconnect count the mapping layer computes.

4. **Side panel reusing existing field editors** (Decision 10) — clicking a node opens a side panel that
   mounts the **unchanged** `FunnelStepForm` (for step nodes) or `FunnelTriggerSettings` (for trigger/start
   nodes). On the canvas the target pickers are gone — edges own them — so `FunnelStepForm` is mounted with a
   **new opt-in `hideTargetPickers` prop**. The ONLY edit to `FunnelStepForm` is this prop (default `false`);
   the form's field-editing logic and the emitted `FunnelStep` are otherwise untouched, so the existing
   list/dialog callers (AddStepDialog/EditStepDialog) stay byte-for-byte identical.

Result: a fully authorable canvas — add nodes, manage the start node, delete with safe edge cleanup, and edit
node content in a side panel without target dropdowns.

## What to do

- **Create `FunnelCanvasPalette.vue`** — a palette listing the 9 step types + trigger + note. Each entry, on
  activation, requests creation of a new node of that kind. The "add start node" / `on_start` palette entry
  is **disabled** when the funnel already has an `on_start` entry. New step/trigger nodes are persisted
  (PATCH) to mint an `id` before they become wirable. i18n via `funnels.canvas.*` keys (the keys themselves
  are added in Task 7; reference them here).
- **Create `FunnelCanvasSidePanel.vue`** — a panel that, given the selected node, mounts the right editor:
  `FunnelStepForm` with `:hide-target-pickers="true"` for step nodes, `FunnelTriggerSettings` for
  trigger/start nodes. Relay the form's `submit` / model updates back so the selected node's model object is
  updated and persisted via the page's existing `persist()` flow (wired in Task 7). Panel closes/clears on
  deselect.
- **Edit `FunnelCanvas.client.vue`** — integrate the palette and side panel: mount both, wire node selection
  → side panel, palette add → mapping-layer node creation + persist, and node delete → disconnect-count
  warning → mapping-layer delete (auto-cleans inbound edges). Render the start node's add/remove against the
  `on_start` lifecycle.
- **Edit `FunnelStepForm.vue` (surgical)** — add exactly one opt-in boolean prop `hideTargetPickers`
  (default `false`). When `true`, conditionally hide the three target `SearchableSelect`s: the callback
  button `targetStepId` picker, the timeout target picker, and the SUBSCRIBE entry picker. Do NOT change any
  field-editing logic, the emitted `FunnelStep`, validation, or the existing default behaviour. When hidden,
  the underlying values are still carried through unchanged on submit (edges own them on canvas, the form
  must not drop or zero them).

  edge auto-clean, broken-edge detection, and the disconnect count — do NOT reimplement that logic here.
- `frontend/components/funnels/FunnelStepForm.vue` (existing, ~1757 lines — edit must be SURGICAL) — add ONE
  opt-in boolean prop. The current props block is `defineProps<{ initial?: FunnelStep | null; submitLabel:
  string; siblingSteps?: FunnelStep[] }>()` (L25-29). Add `hideTargetPickers?: boolean` and default it to
  `false`. The component currently uses plain `defineProps`, not `withDefaults` — convert to `withDefaults`
  like `SearchableSelect.vue` does, OR guard with `props.hideTargetPickers === true`. Do NOT let Vue's
  Boolean-coercion silently flip the default (see the explicit warning in `SearchableSelect.vue` L8-11).
  The three target `SearchableSelect`s to hide (wrap each in `v-if="!hideTargetPickers"` or equivalent):
  - callback button target picker — in the buttons block (template around L1281-1282, the
    `<template v-if="row.type === 'callback'">` SearchableSelect over `menuTargetOptions`).
  - timeout target picker — bound to `menuTimeoutTarget` (logic around L252, L933).
  - SUBSCRIBE entry picker — bound to `subscribeEntryStepId` (logic around L501, L963).
  Critically: the on-submit mapping (L922-966) that converts sentinels → `null`/id must keep working
  unchanged. When the picker is hidden, the value is sourced from `props.initial` and carried through on
  submit — the canvas edge owns the target, so the form must NOT drop or zero `targetStepId` /
  `timeoutTargetStepId` / SUBSCRIBE entry. Verify the emitted step preserves them.

**Edge cases:**
- New node has no `id` until first save → must persist before any edge can target it (code-research §2:
  "you cannot draw an edge to an unsaved node, so node creation must persist (mint id) before it can be wired").
- "No edge" must serialize as `null`, never `""` (an empty-string id 422s as `funnel_broken_edge`). The
  hidden pickers must not introduce `""` — values come from `props.initial` or stay `null`.
- A funnel has at most one `on_start` start node — the palette entry disables when one exists.
- Deleting only the start node's edge (not the node) → `entryStepId == null` is a broken edge (highlight),
  NOT a validation failure here (422 only happens on activate, backend).
- `SearchableSelect.selectedLabel` already falls back to the raw id for a missing target (code-research §2) —
  relevant when an edge dangles after a delete, but on canvas the picker is hidden, so this is the canvas
  broken-edge highlight's job, not the select's.
- SUBSCRIBE_TO_FUNNEL cross-funnel target is rendered as an exit badge (Task 5 / Decision 11), not an edge —
  the SUBSCRIBE entry picker being hidden is consistent with that.
