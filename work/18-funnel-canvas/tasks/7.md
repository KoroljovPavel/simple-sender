# Task 7: Editor page wiring + read-only list + i18n + component tests

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Wire the canvas into the funnel editor page as the **single live editing surface** and finish the
frontend feature: mount `FunnelCanvas` client-only in `funnels/[funnelId].vue`, persist node moves and
notes through the page's existing debounced full-replace `persist()`, make the vertical
`FunnelStepsList` **read-only** (view-only — Decision 2), and add the `funnels.canvas.*` i18n keys to
**both** `uk.json` and `en.json` with parity + non-empty values. Everything is covered by
`mountSuspended` + `mockNuxtImport('useFunnelsStore')` component tests, plus the i18n parity gate.

This is the last frontend task (Wave 5). It depends on Task 6 (authoring interactions — palette,
start node, delete, side panel) because the page mounts the fully-authorable canvas component the
previous waves produced, and on Task 3 (backend execution semantics: `next == null` = end of branch,
`on_start` explicit entry via `entryStepId`) because the end-to-end user-verify (run `/start` in the
bot and confirm the flow matches the drawn graph) needs the backend to execute the drawn graph rather
than array order.

The page already owns `steps`/`triggers`/`funnel` refs and a debounced full-replace `persist()` that
PATCHes the entire steps array (see `frontend/pages/.../funnels/[funnelId].vue` L192-212). Node drags
(`@node-drag-stop`) write the final `{x,y}` into the matching `FunnelStep.canvasPosition` /
`Trigger.canvasPosition` / `notes[]` entry on the local model and then call the same `persist()`.
Notes ride in a new `funnel.notes[]` and must be included in the PATCH body. Note text is rendered
**escaped via `{{ }}`, never `v-html`** (Decision 7 — stored-XSS guard); a component test asserts an
injection payload renders escaped.

**Files:**
- `frontend/pages/projects/[projectId]/funnels/[funnelId].vue` — mount `FunnelCanvas` client-only;
  add `notes` to the page model and to the `persist()` PATCH body + `applyResponse()`; wire
  `@node-drag-stop` → write `canvasPosition`/`notes[]` → `persist()`; switch `FunnelStepsList` to

  `funnel` refs (L32-37), a re-entrancy-guarded `applyResponse()` (L143-150) and a full-replace
  `persist()` (L192-212) that PATCHes the entire steps array — reuse them, do NOT add a second save
  path. The existing `onMounted` client gate (L169-175) is the convention for client-only init.
- `frontend/components/funnels/FunnelStepsList.vue` — make read-only: remove/disable move/edit/delete/
  add controls (or add a read-only mode prop) so the list is view-only. Today it emits
  `move/edit/delete/add/select` by array index (L11-17); after this task it must not drive structural
  changes on the canvas-driven page.
- `frontend/i18n/locales/uk.json`, `frontend/i18n/locales/en.json` — add the `funnels.canvas.*`
  namespace (same keys in both, non-empty). Existing `funnels.*` keys live under `editor/steps/
  trigger/triggersPanel` — follow that nesting style.
- `frontend/tests/i18n/required-keys.spec.ts` — add the visible-text `funnels.canvas.*` keys to
  `REQUIRED_KEYS` (L34-89) and extend `NON_EMPTY_REQUIRED_KEYS` (L94-96) so the filter also matches
  `funnels.canvas.` (currently only `funnels.triggersPanel.`).
- `frontend/tests/pages/funnel-editor.spec.ts` — extend the existing 1162-line spec; reuse its
  `vi.hoisted()` `storeMock` + `mockNuxtImport('useFunnelsStore', ...)` + `mockNuxtImport('navigateTo')`
  + `vi.mock('vue-sonner')` setup (code-research §5). Stub the Vue Flow canvas as needed (it is
  client-only / browser-API heavy) and assert on `storeMock.update` calls and rendered DOM.

**Dependencies:**
- Task 6 (authoring interactions: palette, start node, delete, side panel) — provides the
  fully-authorable `FunnelCanvas` this page mounts.
- Task 3 (backend execution semantics) — required for the end-to-end user-verify (`/start` flow
  matches the drawn graph); not needed for the automated/smoke checks.
- Task 2 supplied `frontend/types/funnel.ts` with `canvasPosition` + `notes[]`; Task 4 supplied the
  mapping layer; Task 5 supplied `FunnelCanvas.client.vue`.

**Edge cases:**
- A funnel with no stored coordinates / no notes (old data) must still mount and render (auto-layout
  handles null coords; `notes` may be null → treat as empty array in the PATCH body).
- "No edge" / absent coordinate must serialize as `null`, never `""` (carried from earlier waves).
- The re-entrancy guard (`applyingResponse`) must still suppress the watch cycle when `persist()`
  re-applies the server response — do not regress the infinite-loop fix.
- Note `id` is server-minted: a fresh note sends `id: null`; the response echoes the minted id.
- Read-only list must not break the existing message-preview `select`/`selectedIndex` behavior if that
  is kept as a view affordance — only structural mutators (move/edit/delete/add) are removed.

**Implementation hints:**
- The page MUST receive drag end as an **event emitted from `FunnelCanvas.client.vue`** (e.g.
  `@node-drag-stop` / a custom emit carrying `{ nodeId, position }`). Do NOT call `useVueFlow()` on the
  page (`funnels/[funnelId].vue`): the canvas surface component is the sole owner of the `useVueFlow()`
  instance — calling it on the page would spin up a SECOND Vue Flow instance and violate the
  Architecture "1 `useVueFlow` instance per editor page mount" rule. Inside the canvas component,
  `useVueFlow()`'s `onNodeDragStop` (code-research §8.3) reads the dragged node id + final position and
  re-emits it upward; the page handler then finds the matching step/trigger/note by id, sets its
  `canvasPosition`/`notes[]` coord, then `void persist()`.
- Note text rendering: bind with `{{ note.text }}` only. NEVER `v-html`. This mirrors the existing
  strict no-`v-html` guard in `FunnelMessagePreview`/`FunnelStepForm` (Decision 7, code-research §2).
- i18n parity: `node scripts/check-locales.mjs` (`collectKeySet`) only checks key-SET equality (empty
  `""` counts as present); the non-empty guarantee comes from `required-keys.spec.ts` value assertions —
  add `funnels.canvas.*` to BOTH layers (code-research §5).
- Concrete `NON_EMPTY_REQUIRED_KEYS` change: the current predicate filters
  `REQUIRED_KEYS.filter(k => k.startsWith('funnels.triggersPanel.'))`. Change it to an OR that ALSO
  matches the canvas namespace, e.g.
  `k.startsWith('funnels.triggersPanel.') || k.startsWith('funnels.canvas.')`, so canvas keys get the
  non-empty assertion WITHOUT dropping the existing `triggersPanel` coverage.
- The canvas is client-only; in the page test you will likely stub/mock the heavy Vue Flow render and
  assert on the wiring (drag-stop → `storeMock.update`) and on the read-only list + escaped-note DOM,
  rather than driving real drag interactions (E2E drag is intentionally manual — Testing Strategy).
