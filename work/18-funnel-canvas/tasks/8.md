# Task 8: Code Audit

## Description

Полный аудит качества кода фичи **18-funnel-canvas** после завершения всех задач реализации (Wave 1–5,
задачи 1–7). Это **не** задача написания кода — код не пишется, правки не вносятся. Результат задачи —
**отчёт об аудите**.

Аудит холистический: предыдущие per-task ревью (code-reviewer на задачах 1–7) смотрели каждую задачу
изолированно. Эта задача смотрит фичу **как единое целое** и ловит то, что не видно в рамках одной задачи:
кросс-компонентные проблемы на стыках слоёв (бэкенд-маппинг ↔ типы фронтенда ↔ mapping-композабл ↔ canvas-
компонент ↔ обвязка страницы), дублирование инициализации ресурсов, несоблюдение договорённостей о
разделяемых ресурсах из раздела Architecture техспека, архитектурную консистентность между тремя тонкими
слоями фичи.

Фокус аудита на трёх стыках, специфичных для этой фичи:
1. **Canvas mapping (Task 4) ↔ canvas component (Task 5) ↔ page wiring (Task 7)** — единая ли модель данных
   проходит сквозь слои, нет ли расхождения семантики рёбер (`next` / `Button.targetStepId` /
   `timeoutTargetStepId` / `entryStepId` / cross-funnel exit badge) между маппером, компонентом и обвязкой.
2. **Разделяемые ресурсы (раздел Architecture → Shared resources):** `useVueFlow` — **ровно 1 инстанс на
   маунт страницы редактора** (владелец — canvas-surface компонент; авторинг и обвязка страницы — потребители,
   не создают свой инстанс); dagre-граф — **транзиентный, 1 на прогон лейаута** (владелец — mapping-слой
   `useLayout`, потребитель — canvas только для начального лейаута). Аудит проверяет, что нет дублирующей
   инициализации `useVueFlow` и что dagre не висит долгоживущим синглтоном.
3. **Бэкенд-консистентность (Tasks 1, 3):** одно ли понимание `canvasPosition` / `notes[]` / `entryStepId`
   проходит сквозь пять seam'ов round-trip'а (домен + `copyOf` + DTO + forward-маппер + reverse-маппер),
   согласована ли семантика `next == null` = конец ветки между движком и тем, что рисует canvas.

## Details

<!-- All details for task execution — technical, organizational, any other. -->

**Files:** код **не** меняется. Единственный записываемый артефакт —
`work/18-funnel-canvas/logs/working/task-8/code-audit.md` (отчёт), плюс короткая запись в `decisions.md`.

**Dependencies:** задачи 1–7 (вся реализация фичи). Аудит запускается после того, как все они завершены и
прошли per-task ревью.

**Что именно ищем (кросс-компонентно, чего не видит per-task ревью):**
- Дублирование инициализации `useVueFlow`: владелец — `FunnelCanvas.client.vue`; `FunnelCanvasPalette.vue`,
  `FunnelCanvasSidePanel.vue` и обвязка `[funnelId].vue` должны **потреблять** существующий инстанс (доступ к
  тому же контексту через `useVueFlow()`/provide), а не создавать второй. Второй инстанс = рассинхрон
  состояния графа.
- dagre: используется в mapping-слое (`useFunnelCanvas.ts` / `useLayout`) **транзиентно** на прогон лейаута,
  не висит модульным синглтоном между прогонами.
- Семантика рёбер согласована между маппером (`useFunnelCanvas.ts`), узловым компонентом
  (`FunnelCanvasNode.vue` typed handles) и записью в модель: default→`next`, button→`Button.targetStepId`,
  timeout→`timeoutTargetStepId`, start/trigger→`Trigger.entryStepId`, cross-funnel SUBSCRIBE→exit badge (не
  ребро). «No edge» сериализуется как `null`, не `""`.
- Бэкенд round-trip: `canvasPosition` / `notes[]` присутствуют во всех пяти seam'ах (домен+accessors,
  `FunnelStep.copyOf`, DTO-record, forward-маппер `toSteps`/`applyTriggers`, reverse-маппер
  `toStepDto`/`toTriggerDtos`) — иначе тихий drop на `@JsonIgnoreProperties(ignoreUnknown)`.
- Бэкенд-семантика: `advanceToNext` трактует `next == null` как конец ветки (нет fall-through к следующему
  элементу массива); `on_start` валидирует `entryStepId` через funnel-scoped проверку, не `requireNoEntryStep`;
  `fire()` и `testRun` стартуют с `entryStepId` через `insertExecutionAt`, не с шага 0.
- Безопасность note text — на уровне холистики только сверка: рендер через `{{ }}`, не `v-html` (глубокий
  security-аудит — отдельная Task 9, здесь не дублировать, лишь зафиксировать если бросается в глаза).

**Edge cases отчёта:**
- Если `decisions.md` пуст к моменту аудита → источник списка файлов = tech-spec «Files to modify».
- Если фактически созданы файлы, которых нет в техспеке (отклонения реализации) → включить их в аудит и
  отметить как отклонение.
- Нет находок по дименшену → явно «чисто», а не пропуск.

**Implementation hints:**
- Severity находок согласовать со шкалой из skill code-reviewing.
- Отчёт — структурированный markdown: сводка → находки по дименшенам (severity, файл:строка, проблема,
  предлагаемый фикс) → итог по разделяемым ресурсам → вердикт (готово к мержу / нужны фиксы).
- Это аудит, не правки: не редактировать исходники, только отчёт + запись в decisions.md.
