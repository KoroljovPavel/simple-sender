# Task 1: Monorepo root scaffold

## Required Skills

Before starting, load: `/skill:infrastructure-setup` — [SKILL.md](~/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Create the top-level directory structure for the Bot Funnel Service monorepo: `backend/`, `frontend/`, `infra/`, `docs/`, and `scripts/`. This is the first task of Epic 01 — Foundation Infrastructure — and produces the skeleton that all subsequent tasks build on.

In addition to the directories, this task extends the existing `.gitignore` with patterns specific to Java/Gradle, Node.js/Nuxt, secrets, and IDE tooling. It also creates two new root-level files: `.env.example` with the two environment variables needed in Epic 01 (MongoDB URI and Redis URL, each with an explanatory inline comment), and `.nvmrc` pinning the project to Node 24 LTS.

The directories are empty placeholders at this stage — actual code and config land in Tasks 2–7. The `scripts/` directory is created here because Task 6 (Gitleaks hook installer) will drop `install-hooks.sh` into it.

## What to do

1. Create the five top-level directories. Each must exist as a real directory (not just a path reference). Add a `.gitkeep` file inside each empty directory so git tracks them: `backend/`, `frontend/`, `infra/`, `docs/`, `scripts/`.

2. Extend `.gitignore` (file already exists — do not replace it). Append a clearly labelled section that covers:
   - Java/Gradle: `backend/build/`, `backend/.gradle/`, `*.class`, `*.jar` (except wrapper jar), `*.war`
   - Node/Nuxt: `frontend/node_modules/`, `frontend/.nuxt/`, `frontend/.output/`, `frontend/dist/`
   - Secrets and credentials: `.env`, `*.key`, `secrets/`, `*.pem`, `*.p12`, `*.jks`
   - IDE: `.idea/` (already partially covered — confirm it is present; if not, add it)

3. Create `.env.example` at the repo root with exactly two variables and inline comments explaining each one.

4. Create `.nvmrc` at the repo root containing `24` (Node 24 LTS).

**Files:**

Append the following groups in a new `# Project: Java/Gradle` and `# Project: Node/Nuxt` and `# Project: Secrets` block to keep it organized. Do not remove existing entries.

  ```

  ```

- `backend/.gitkeep`, `frontend/.gitkeep`, `infra/.gitkeep`, `docs/.gitkeep`, `scripts/.gitkeep` (new) — empty files to make git track the directories. These will be removed or replaced in subsequent tasks when real files land.

**Dependencies:** None — Wave 1 task, no prerequisites.

**Edge cases:**
- `.gitignore` already has `.idea/` in it (confirmed from reading the file). Do not duplicate the entry — just add the Java/Gradle/Node/Nuxt/secrets patterns.
- The existing `.gitignore` content is clearly for the Claude Code tooling workspace (`.claude`, `workflow/`, etc.). The new section must be clearly separated with a comment header so the two concerns do not merge.
- Node 24 LTS: do NOT write `v24` or `v24.0.0` — write only `24`. The `.nvmrc` spec for nvm accepts bare major version numbers. Node 20 is EOL April 2026, so 22 or earlier is wrong.

**Implementation hints:**
- Use `touch backend/.gitkeep` (or equivalent Write) for each empty directory — git will not track empty directories.
- For `.env.example`: the comment must be on the line immediately above the variable it describes (not grouped at the top). This is the "inline comment" pattern described in the acceptance criteria and user-spec.
- For `.gitignore`: check the current file content first (already read above). Current entries are all Claude-workspace-specific. The Java/Gradle/Node patterns have no overlap with existing entries, so a clean append is safe.
