# Task 2: Backend Gradle skeleton

## Required Skills

Before starting, load: `/skill:infrastructure-setup` — [SKILL.md](../../../.claude/skills/infrastructure-setup/SKILL.md)

## Description

Initialize the Gradle project in `backend/` for the Bot Funnel Service reactive backend. This task creates the full build configuration and the minimal Java source tree needed for `./gradlew compileJava` to succeed and for subsequent tasks (Task 5: /health endpoint + tests) to build on top of.

The Spring Security configuration is the most critical deliverable: without an explicit `SecurityWebFilterChain` bean, Spring Boot auto-configuration blocks all endpoints with HTTP 401. We define the security baseline here in Epic 01 — CSRF disabled, `/health` open, everything else authenticated — so that all future epics start from a known, working security posture.

This is a Wave 1 task with no dependencies. It runs in parallel with Tasks 1, 3, and 4.

## What to do

1. Generate the Gradle wrapper in `backend/` using Gradle 8.x. Produce `backend/gradle/wrapper/gradle-wrapper.properties` that points to Gradle 8.x distribution URL.

2. Create `backend/settings.gradle` (Groovy DSL) that:
   - Applies the Foojay resolver plugin for automatic JDK provisioning
   - Sets `rootProject.name = 'bot-funnel-backend'`

3. Create `backend/build.gradle` (Groovy DSL) that:
   - Applies `org.springframework.boot` plugin (version 3.5.x) and `io.spring.dependency-management`
   - Applies `java` plugin
   - Pins Java 21 toolchain via `java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }`
   - Declares `developmentOnly` configuration for devtools
   - Adds all required dependencies (see Details)

4. Create the main application class `backend/src/main/java/com/botfunnel/BotFunnelApplication.java` annotated with `@SpringBootApplication`.

5. Create `backend/src/main/java/com/botfunnel/security/SecurityConfig.java` with a `SecurityWebFilterChain` bean. See Details for the exact annotation requirements and rule ordering — this is non-obvious and easy to get wrong.

6. Create the placeholder `backend/src/main/java/com/botfunnel/common/package-info.java`.

7. Create `backend/src/main/resources/application.properties` with the Spring application name and any minimal config needed to start the context (suppress DB auto-connect warnings for now; actual connection config is not needed until Docker Compose is running).

## Details

### Files and what to create

**`backend/settings.gradle`** — Groovy DSL. Must apply the Foojay resolver plugin so Gradle can auto-provision Java 21 if not locally installed:
```
plugins {
    id 'org.gradle.toolchains.foojay-resolver-convention' version '0.8.0'
}
rootProject.name = 'bot-funnel-backend'
```

**`backend/build.gradle`** — Groovy DSL. Key structure:
- plugins block: `org.springframework.boot` (3.5.x), `io.spring.dependency-management`, `java`
- `java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }` — toolchain, not `sourceCompatibility`
- `developmentOnly` configuration is auto-registered by the Spring Boot Gradle plugin — just use it in the dependencies block (no `configurations {}` block needed)
- dependencies block with all 8 dependencies listed below

**Dependencies to declare:**
- `implementation 'org.springframework.boot:spring-boot-starter-webflux'`
- `implementation 'org.springframework.boot:spring-boot-starter-security'`
- `implementation 'org.springframework.boot:spring-boot-starter-data-mongodb-reactive'`
- `implementation 'org.springframework.boot:spring-boot-starter-data-redis-reactive'`
- `developmentOnly 'org.springframework.boot:spring-boot-devtools'`
- `testImplementation 'org.springframework.boot:spring-boot-starter-test'`
- `testImplementation 'io.projectreactor:reactor-test'`
- `testImplementation 'org.springframework.security:spring-security-test'`

Versions are managed by `io.spring.dependency-management` via the Spring Boot BOM — do not specify version numbers explicitly for Spring dependencies.

**`backend/gradle/wrapper/gradle-wrapper.properties`** — must specify a Gradle 8.x distribution URL, e.g.:
```
distributionUrl=https\://services.gradle.org/distributions/gradle-8.13-bin.zip
```
Also include `distributionBase`, `distributionPath`, `zipStoreBase`, `zipStorePath` as standard wrapper properties.

**`backend/src/main/java/com/botfunnel/BotFunnelApplication.java`** — standard Spring Boot entry point:
```java
package com.botfunnel;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class BotFunnelApplication {
    public static void main(String[] args) {
        SpringApplication.run(BotFunnelApplication.class, args);
    }
}
```

**`backend/src/main/java/com/botfunnel/security/SecurityConfig.java`** — CRITICAL. The implementation must follow Decision 5 exactly:

```java
package com.botfunnel.security;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.reactive.EnableWebFluxSecurity;
import org.springframework.security.config.web.server.ServerHttpSecurity;
import org.springframework.security.web.server.SecurityWebFilterChain;

@Configuration
@EnableWebFluxSecurity
public class SecurityConfig {

    @Bean
    public SecurityWebFilterChain springSecurityFilterChain(ServerHttpSecurity http) {
        return http
            .csrf(csrf -> csrf.disable())
            .authorizeExchange(exchanges -> exchanges
                .pathMatchers("/health").permitAll()
                .anyExchange().authenticated()
            )
            .build();
    }
}
```

Key correctness requirements:
- Both `@Configuration` AND `@EnableWebFluxSecurity` are required — `@EnableWebFluxSecurity` does NOT include `@Configuration` in Spring Security 6.
- Use `ServerHttpSecurity` (reactive), NOT `HttpSecurity` (servlet).
- Return type is `SecurityWebFilterChain`, NOT `SecurityFilterChain`.
- `.csrf(csrf -> csrf.disable())` must be present — otherwise all non-GET requests return 403.
- `pathMatchers("/health").permitAll()` MUST come before `anyExchange().authenticated()` — the chain is first-match, and swapping the order causes `/health` to require auth.

**`backend/src/main/java/com/botfunnel/common/package-info.java`** — minimal placeholder:
```java
/**
 * Common shared utilities and configuration for Bot Funnel Service.
 */
package com.botfunnel.common;
```

**`backend/src/main/resources/application.properties`** — minimal config:
```
spring.application.name=bot-funnel-backend
# Disables automatic index creation on startup (index management handled explicitly in later epics)
spring.data.mongodb.auto-index-creation=false
```

### Edge cases

- **Gradle wrapper binaries:** `gradlew` and `gradlew.bat` scripts and `gradle/wrapper/gradle-wrapper.jar` must be present for `./gradlew compileJava` to work. Generate them via `gradle wrapper` command inside `backend/`, or create them manually. If Gradle 8.x is not installed locally, bootstrap with any available Gradle version first, then let the wrapper self-upgrade.
- **MongoDB/Redis auto-config at compile time:** `compileJava` does not start the Spring context, so no DB connection is required at this stage. Connection failures only occur at runtime (`bootRun` or integration tests).
- **`developmentOnly` configuration:** The Spring Boot Gradle plugin (Boot 3.x) registers the `developmentOnly` configuration automatically — do NOT declare a `configurations { developmentOnly { ... } }` block, as this causes a Gradle build failure ("Configuration with name 'developmentOnly' already exists"). Simply use `developmentOnly 'org.springframework.boot:spring-boot-devtools'` in the dependencies block.
