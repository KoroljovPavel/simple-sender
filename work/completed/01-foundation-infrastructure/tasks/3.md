# Task 3: Frontend Nuxt 4 skeleton

## Required Skills

Before starting, load: `/skill:infrastructure-setup` — [SKILL.md](/Users/pavlokorolov/IdeaProjects/simple-sender/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Initialize a minimal Nuxt 4 (4.4.x) project in the `frontend/` directory using pnpm as the package manager. The project uses Vue 3 and TypeScript. The output is a buildable, SSR-enabled Nuxt 4 app with a single Hello World page — enough to confirm that the frontend stack compiles and is ready for future development in subsequent epics.

This is a Wave 1 task with no dependencies. The Node version to use is defined in `.nvmrc` at the project root (Node 24). SSR must stay enabled (the default) — there is a known Nuxt 4.4.x bug with `ssr: false` (SPA mode); do NOT add `ssr: false` to `nuxt.config.ts`.

## What to do

1. Create `frontend/package.json` — define the project as a Nuxt 4.4.x app managed by pnpm. Include `nuxt` at `^4.4.0` as the sole dependency. Add `dev`, `build`, and `generate` scripts.
2. Create `frontend/nuxt.config.ts` — set `compatibilityDate` to a recent stable date string (YYYY-MM-DD format, e.g. `"2025-07-01"`). Enable TypeScript strict mode via `typescript: { strict: true }`. Do NOT set `ssr: false`.
3. Create `frontend/app.vue` — a minimal single-file component that renders a Hello World heading. No router, no complex layout — just enough to make `pnpm build` succeed.
4. Verify the skeleton: from `frontend/`, run `pnpm install` then `pnpm build` — both must exit with code 0.

## Details

**Files:**

- `frontend/package.json` — new file. Must declare `nuxt` at `^4.4.0`. Scripts: `"dev": "nuxt dev"`, `"build": "nuxt build"`, `"generate": "nuxt generate"`. Package manager field: `"packageManager": "pnpm@latest"` is optional but helpful.
- `frontend/nuxt.config.ts` — new file. Key fields:
  - `compatibilityDate`: YYYY-MM-DD string. This field is strongly recommended for Nuxt 4 (generated by `nuxi init` by default); it controls Nitro preset behavior. Use a date from 2025, e.g. `"2025-07-01"`.
  - `typescript: { strict: true }` — enables strict TypeScript checking.
  - Do NOT include `ssr: false` — there is a known Nuxt 4.4.x bug in SPA mode. SSR is enabled by default and must stay that way.
- `frontend/app.vue` — new file. Minimal single-file Vue component. A `<template>` with a single heading is sufficient. Example structure: `<template><div><h1>Hello World</h1></div></template>`.

**Dependencies:**

- `nuxt` 4.4.x — Vue 3 meta-framework, provides SSR, dev server, and TypeScript integration out of the box. No additional packages are needed for this skeleton task.
- Node 24 (from `.nvmrc`) — ensure the correct Node version is active before running `pnpm install`.

**Implementation hints:**

- `nuxi init` can be used to scaffold the initial project structure, but its output includes many files not listed in Files to modify (e.g. `public/`, `server/`, `.nuxtignore`, etc.). Trim the result down to exactly the three required files: `package.json`, `nuxt.config.ts`, and `app.vue`. Do not commit any generated files outside of these three.
- `compatibilityDate` format is a plain string in YYYY-MM-DD format (e.g. `"2025-07-01"`). Nuxt uses this to apply the correct Nitro defaults without breaking changes.
- pnpm must be used (not npm or yarn) — the project uses pnpm as the package manager per architecture decision.
- After `pnpm install`, a `node_modules/` and a `pnpm-lock.yaml` will be created. The `node_modules/` directory is already in `.gitignore` (covered by Task 1). The `pnpm-lock.yaml` should be committed (it is not in `.gitignore`).
- Both `.nuxt/` (intermediate build cache) and `.output/` (SSR build output) are covered by `.gitignore` from Task 1.

**Edge cases:**

- If Node version does not match `.nvmrc`, `pnpm install` may fail or warn. Use `nvm use` before running pnpm commands.
- Do not add `ssr: false` even as a comment to avoid accidentally enabling SPA mode.
