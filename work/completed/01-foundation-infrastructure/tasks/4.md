# Task 4: Docker Compose (MongoDB + Redis)

## Required Skills

Before starting, load: `/skill:infrastructure-setup` — [SKILL.md](~/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Create `infra/docker-compose.yml` that brings up MongoDB 8.0 and Redis 7.4 for local development. This is the sole infrastructure file for Epic 01 — no application containers are included. The file uses named volumes (`mongodb_data`, `redis_data`) to persist data across `docker compose down` / `up` cycles, and binds both ports to `127.0.0.1` only to prevent unauthenticated access from other machines on the local network.

Port defaults match `.env.example`: MongoDB on :27017, Redis on :6379. No auth is configured — localhost binding is the security compensating control for local dev convenience.

This task is Wave 1 (independent) — it has no prerequisites and can run in parallel with Tasks 1, 2, and 3.

## What to do

1. Create the `infra/` directory if it does not exist.
2. Create `infra/docker-compose.yml` with:
   - `services.mongodb` using image `mongo:8.0`, port mapping `127.0.0.1:27017:27017`, named volume mount at `/data/db`
   - `services.redis` using image `redis:7.4`, port mapping `127.0.0.1:6379:6379`, named volume mount at `/data`
   - Top-level `volumes` block declaring `mongodb_data` and `redis_data` (no driver options needed — Docker default local driver)
3. Validate the file: `docker compose -f infra/docker-compose.yml config --quiet` must exit 0.

## Details

**Files:**
- `infra/docker-compose.yml` (new) — full file to create from scratch. No existing state.

**Port binding format — critical security detail:**
Use the long form with explicit host IP:
```yaml
ports:
  - "127.0.0.1:27017:27017"
```
Do NOT use `27017:27017` (binds to `0.0.0.0` by default — exposes unauthenticated MongoDB to the local network) or `"0.0.0.0:27017:27017"` (same problem, explicit). The `127.0.0.1` binding is the security compensating control for running without auth in local dev (Decision 9).

**Volume mount paths:**
- MongoDB: `/data/db` — this is where `mongo:8.0` stores its data files by default
- Redis: `/data` — this is where `redis:7.4` stores RDB/AOF persistence files by default

Using the wrong mount path silently results in data not being persisted (container uses an anonymous volume or tmpfs instead of the named volume).

**Named volumes block:**
Declare both volumes at the top level with no extra options — the Docker default local driver is sufficient:
```yaml
volumes:
  mongodb_data:
  redis_data:
```
Empty value (not `{}` or `null`) is valid YAML and Docker Compose accepts it.

**No application containers:**
This Compose file is intentionally limited to infrastructure only. Backend (`bootRun`) and frontend (`pnpm dev`) run outside Docker in local development (Decision 10). Do not add `backend` or `frontend` services.

**Dependencies:** None — this task is fully independent (Wave 1).

**Edge cases:**
- Port conflict: if :27017 or :6379 is already occupied, `docker compose up -d` will fail with "address already in use". This is documented in `docs/local-setup.md` (Task 7) — not something to handle in the compose file itself.
- Windows developer: Docker Desktop on Windows handles `127.0.0.1` binding correctly. No special handling needed in the compose file.
