# Task 5: Backend /health endpoint + integration tests

## Required Skills

Before starting, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Implement `HealthController` — a plain `@RestController` that exposes `GET /health` returning `{"status":"ok"}`. Then write three `@SpringBootTest` WebTestClient integration tests that exercise HTTP routing and Spring Security filters without requiring `docker compose` to be running.

This task depends on Task 2 (Gradle skeleton + `SecurityConfig`) being complete. The `SecurityWebFilterChain` from Task 2 permits `/health` without auth and blocks all other paths with 401 — this task verifies that contract holds via integration tests.

The integration test strategy intentionally deviates from `patterns.md` ("no mocking DB in integration tests"). Decision 6 documents why: Epic 01 tests exercise HTTP routing and Spring Security filters only — MongoDB is never queried. Using `@MockBean` for both DB connection factories is the simplest approach that lets `./gradlew build` run without a live Docker environment.

## What to do

1. Write the three failing integration tests first (TDD — they must fail before `HealthController` exists):
   - `HealthEndpointTest` — `GET /health` returns HTTP 200 and body `{"status":"ok"}`
   - `HealthSecurityTest` — `GET /health` without an `Authorization` header returns HTTP 200 (verifies `SecurityWebFilterChain` permits `/health`)
   - `SecurityBlockTest` — `GET /api/nonexistent` without an `Authorization` header returns HTTP 401 (verifies `anyExchange().authenticated()` blocks undefined paths)

2. Run `./gradlew build` and confirm all three tests fail (or that `HealthEndpointTest` and `HealthSecurityTest` fail with 404/error while `SecurityBlockTest` may already pass depending on `SecurityConfig` state from Task 2).

3. Implement `HealthController` in `backend/src/main/java/com/botfunnel/HealthController.java`:
   - `@RestController` annotation (plain, not an Actuator endpoint — no `spring-boot-starter-actuator` on classpath)
   - `@GetMapping("/health")` method returning `Mono<Map<String, String>>` with a hardcoded `{"status":"ok"}` map
   - No DB calls, no connectivity checks

4. Run `./gradlew build` and confirm all three tests pass with `BUILD SUCCESSFUL`.

## Details

**Files and what to implement:**

- `backend/src/main/java/com/botfunnel/HealthController.java` (new) — plain `@RestController` with one `@GetMapping("/health")` method. Return type: `Mono<Map<String, String>>`. Body: `Mono.just(Map.of("status", "ok"))`. No constructor injection needed. No Actuator — `spring-boot-starter-actuator` is NOT on the classpath in Epic 01.

- `backend/src/test/java/com/botfunnel/HealthEndpointTest.java` (new) — `@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)`. Fields: `@Autowired WebTestClient webTestClient` and two `@MockBean` fields (see below). Test method: `webTestClient.get().uri("/health").exchange().expectStatus().isOk().expectBody().jsonPath("$.status").isEqualTo("ok")`.

- `backend/src/test/java/com/botfunnel/HealthSecurityTest.java` (new) — identical setup. Test method: call `GET /health` with no auth header (just `.get().uri("/health").exchange()`). Assert `.expectStatus().isOk()` and `.expectBody().jsonPath("$.status").isEqualTo("ok")`. This verifies `SecurityWebFilterChain.pathMatchers("/health").permitAll()` works correctly.

- `backend/src/test/java/com/botfunnel/SecurityBlockTest.java` (new) — identical setup. Test method: `webTestClient.get().uri("/api/nonexistent").exchange().expectStatus().isUnauthorized()`. This verifies `anyExchange().authenticated()` returns 401 for undefined paths.

**CRITICAL — @MockBean class names:**

Each test class must declare two `@MockBean` fields:
```
@MockBean
com.mongodb.reactivestreams.client.MongoClient mongoClient;

@MockBean
org.springframework.data.redis.connection.ReactiveRedisConnectionFactory redisConnectionFactory;
```

Use `com.mongodb.reactivestreams.client.MongoClient` — this is the correct interface from the reactive MongoDB driver. Do NOT use `ReactiveMongoClient` — that class does NOT exist. Using the wrong class name causes a `NoSuchBeanDefinitionException` or `ClassNotFoundException` at test startup.

**JSON assertion pattern:**
```
.expectBody()
.jsonPath("$.status").isEqualTo("ok")
```

**HTTP 401 assertion pattern:**
```
.expectStatus().isUnauthorized()
```

**Dependencies:** Task 2 must be complete — `build.gradle`, `SecurityConfig.java`, `BotFunnelApplication.java`, and `application.properties` must all exist. `WebTestClient` is available via `spring-boot-starter-webflux` (already declared in `build.gradle` from Task 2). `@MockBean` is provided by `spring-boot-starter-test`.

**Decision 6 deviation from patterns.md:** `patterns.md` states "No mocking of the database in integration tests — use real embedded MongoDB." This task intentionally deviates: Epic 01 tests exercise HTTP routing and Spring Security filters only — MongoDB is never queried. The `@MockBean` approach avoids a heavyweight embedded-DB dependency for tests that don't touch the DB. This deviation is scoped to Epic 01 skeleton only.

**Edge cases:**
- If `SecurityConfig` rule ordering is wrong (i.e., `anyExchange()` before `pathMatchers("/health")`), `HealthSecurityTest` will fail with 401 instead of 200 — fix is in `SecurityConfig`, not here.
- Spring Boot auto-configuration tries to connect to MongoDB and Redis on startup. Without `@MockBean`, the test context will fail to start with a connection refused error. Both beans must be mocked.
- `WebTestClient` in `@SpringBootTest(RANDOM_PORT)` mode auto-binds to the random port via `@Autowired` if `spring-boot-starter-webflux` is on the classpath.
