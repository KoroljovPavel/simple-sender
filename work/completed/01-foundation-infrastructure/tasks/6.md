# Task 6: Gitleaks pre-commit hook

## Required Skills

Before starting, load:
- `/skill:infrastructure-setup` — [SKILL.md](~/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Create `scripts/install-hooks.sh` — a shell script that installs a gitleaks pre-commit hook into `.git/hooks/pre-commit`. The hook scans staged files for secrets before each commit using `gitleaks detect --staged --verbose --no-banner`.

This is the security gate for the monorepo: any developer who runs `bash scripts/install-hooks.sh` after cloning will have gitleaks scanning run automatically before every commit. The `.git/hooks/` directory is not tracked by git, so the hook must be distributed via an install script (Decision 7). No Husky or pre-commit frameworks are used — keeping dependencies minimal in Epic 01.

If gitleaks CLI is not installed on the developer's machine, the hook exits 0 with a warning instead of blocking the commit (soft failure). This is an accepted risk in Epic 01 — the install instructions are provided in `docs/local-setup.md` (Task 7). The script must be idempotent: running it multiple times produces the same result.

## What to do

1. Create `scripts/install-hooks.sh` with the following behavior:
   - Write the pre-commit hook content to `.git/hooks/pre-commit` (overwrite if already exists)
   - Set the hook file executable with `chmod +x .git/hooks/pre-commit`
   - Print a success message confirming the hook was installed

2. The pre-commit hook written by the script must:
   - Check if gitleaks is installed; if not — print a WARNING and exit 0 (soft failure, do not block commit)
   - If gitleaks is installed — run `gitleaks detect --staged --verbose --no-banner`
   - If gitleaks finds secrets — exit 1 (blocks commit)
   - If no secrets found — exit 0 (commit proceeds)

3. Make `scripts/install-hooks.sh` itself executable: `chmod +x scripts/install-hooks.sh`

4. Verify idempotency: running the script a second time overwrites the hook without error

## Details

**Files:**
- `scripts/install-hooks.sh` (new) — the install script. The `scripts/` directory was created in Task 1. This file must be committed with executable permissions; set them with `chmod +x scripts/install-hooks.sh` before committing.

**Implementation hints:**

Soft-failure pattern inside the hook (when gitleaks not installed):
```sh
if ! command -v gitleaks &>/dev/null; then
  echo "WARNING: gitleaks not installed. Skipping secret scan."
  echo "Install: brew install gitleaks (macOS) or see docs/local-setup.md"
  exit 0
fi
```

Gitleaks scan command inside the hook:
```sh
gitleaks detect --staged --verbose --no-banner
```

The install script writes hook content using a heredoc to `.git/hooks/pre-commit`, then sets it executable:
```sh
cat > .git/hooks/pre-commit << 'EOF'
#!/bin/sh
# ... hook content ...
EOF
chmod +x .git/hooks/pre-commit
```

The install script itself must be made executable before committing:
```sh
chmod +x scripts/install-hooks.sh
```

Idempotency is achieved by using `cat >` (overwrite, not append) — running the script N times always writes the same hook content.

**Edge cases:**
- `.git/hooks/` directory is present in any git repo by default — no need to create it
- Script should be run from the monorepo root (where `.git/` lives); add a guard or note if needed
- Use `#!/bin/sh` (POSIX sh) in the hook, not `#!/bin/bash`, for broader compatibility (including Alpine-based environments)
- Use `#!/usr/bin/env bash` in `install-hooks.sh` for portability on macOS and Linux

**Dependencies:**
- Task 1 must be complete (`scripts/` directory exists)
- gitleaks CLI is a developer prerequisite (documented in Task 7's `docs/local-setup.md`)
