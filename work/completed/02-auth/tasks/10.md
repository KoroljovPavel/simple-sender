# Task 10: Auth pages

## Required Skills

Before starting, load:

## Description

Create all five authentication Nuxt pages using vee-validate/zod forms and the `auth` layout: login, register, forgot-password, reset-password, and verify-email. Each page handles inline validation errors, API calls, and appropriate redirects.

The verify-email page is the most complex: it auto-calls the backend on mount, handles loading/success/error states, and shows a resend button when the backend returns `TOKEN_EXPIRED`.

## What to do

1. **`/auth/login.vue`** — login form:
   - Fields: email (type=email), password (type=password), remember-me checkbox
   - zod schema: `z.object({ email: z.string().email(), password: z.string().min(1), rememberMe: z.boolean() })`
   - On submit: call `POST /api/auth/login`; on success: `authStore.fetchUser()` then `navigateTo('/dashboard')`; on 429: show "Забагато спроб. Спробуйте через 15 хв"
   - Show inline errors under each field from vee-validate
   - Links: "Зареєструватись" → `/auth/register`, "Забули пароль?" → `/auth/forgot-password`
   - Loading state: disable submit button while request is in progress
   - `definePageMeta({ layout: 'auth' })`

2. **`/auth/register.vue`** — registration form:
   - Fields: email, name, password, confirm-password
   - zod schema: email format, name non-blank, password min 8 chars + 1 letter + 1 digit, confirmPassword must match password
   - On submit: call `POST /api/auth/register`; on success: navigate to `/auth/login` with success message
   - 409 error: show "Користувач з таким email вже існує" or support contact message
   - `definePageMeta({ layout: 'auth' })`

3. **`/auth/forgot-password.vue`** — forgot password form:
   - Field: email only
   - On submit (any email, valid format): call `POST /api/auth/forgot-password`; ALWAYS show success message "Якщо акаунт існує, ви отримаєте лист" (do not reveal existence)
   - Show success state regardless of backend response status (always 200)
   - `definePageMeta({ layout: 'auth' })`

4. **`/auth/reset-password.vue`** — reset password form:
   - Read `token` from `useRoute().query.token`; redirect to `/auth/forgot-password` if token missing
   - Fields: newPassword, confirmPassword
   - On submit: call `POST /api/auth/reset-password` with `{token, newPassword}`
   - On success: navigate to `/auth/login` with "Пароль змінено" message
   - On 400: show "Посилання недійсне або прострочено" + link to `/auth/forgot-password`
   - `definePageMeta({ layout: 'auth' })`

5. **`/auth/verify-email.vue`** — email verification result page:
   - Read `token` from `useRoute().query.token`
   - On mount (or `useFetch` with immediate): call `GET /api/auth/verify-email?token=...`
   - Loading state: spinner
   - Success: show "Email підтверджено! [Увійти →]"
   - Error 400 generic: show "Посилання недійсне"
   - Error 400 with `code: TOKEN_EXPIRED`: show "Посилання прострочено" + "Надіслати новий лист" button
   - Resend button calls `POST /api/auth/resend-verification` with the user's email; show a small email input field for the user to enter their email when requesting a resend; on 429 disable for 60s
   - `definePageMeta({ layout: 'auth' })`

**vee-validate + zod pattern:**
Use the vee-validate/zod pattern from `frontend/tests/` examples set up in Task 8. Pattern: `useForm({ validationSchema: toTypedSchema(schema) })`, `useField('fieldName')`.

**Edge cases:**
- verify-email resend button: the email verification token is a raw 32-byte base64url random value — it contains no claims or email. Show a small email input field for the user to enter their email when requesting a resend.
- reset-password page without `?token=`: show "посилання недійсне" immediately or redirect to forgot-password
- 429 on login: show cooldown message; no timer UI needed (just text)

**Dependencies:**
Task 8 (layouts/auth.vue, stores/auth.ts, test infrastructure, vitest setup).

**Implementation hints:**
- Use `shadcn-vue` components: `Button`, `Input`, `Card`, `CardHeader`, `CardContent`, `Form`, `FormField`, `FormItem`, `FormLabel`, `FormMessage`
- Submit button: `<Button type="submit" :disabled="isSubmitting">` — `isSubmitting` from `useForm()`
- For async submit: `isSubmitting` is automatically managed by vee-validate when using `handleSubmit`
