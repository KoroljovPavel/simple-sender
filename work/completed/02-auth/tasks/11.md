# Task 11: Profile page + dashboard

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Create the `/dashboard` page with a pending-user email verification banner, and the `/profile` page with five sections: profile view/edit, resend verification, change password, terminate all sessions, and delete account with confirmation modal. Both pages use the `default` layout.

The delete-account flow (Decision 5) requires only an active session — no password re-entry. A modal with consequences list must be shown first.

## What to do

1. **`/dashboard.vue`** (layout: default):
   - Show pending banner if `authStore.isPending`: "Підтвердіть email для повного доступу. [Перейти до профілю →]"
   - Banner links to `/profile`
   - Otherwise, show a basic "Ласкаво просимо, {user.name}" message (content placeholder for future epics)
   - `definePageMeta({ layout: 'default' })`

2. **`/profile.vue`** (layout: default) — five sections:

   **Section 1: Profile info** — view/edit name:
   - Show current `name` and `email` (email is read-only, not editable)
   - "Edit" button toggles inline edit mode for name
   - On save: call `PATCH /api/profile` with `{name}`; show success toast; update auth store user

   **Section 2: Email verification** (visible only if `authStore.isPending`):
   - Text: "Ваш email не підтверджено"
   - "Надіслати лист повторно" button → calls `POST /api/auth/resend-verification`; on 429 show "Почекайте 60 секунд"

   **Section 3: Change password**:
   - Fields: current password, new password, confirm new password
   - zod schema: currentPassword non-blank, newPassword min 8 + 1 letter + 1 digit, confirmPassword match
   - On submit: call `POST /api/profile/change-password`; on success show "Пароль змінено"; on 400 show "Невірний поточний пароль"

   **Section 4: Session management**:
   - "Завершити всі сесії" button → calls `POST /api/profile/terminate-all-sessions`; on success: clear `authStore.user` to null, then navigate to `/auth/login`. This prevents the auth middleware from triggering an extra GET /api/auth/me call (which would return 401 and redirect again).

   **Section 5: Delete account**:
   - "Видалити акаунт" button → opens confirmation modal
   - Modal content: "Це видалить: всі ваші проекти, ботів, підписників" (list)
   - Modal footer: Cancel + "Видалити акаунт" (danger variant)
   - On confirm: call `DELETE /api/profile`; on success: clear authStore.user, navigate to `/auth/login`

3. **`definePageMeta({ layout: 'default' })`** on both pages.

- Delete account modal: `Dialog`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogFooter`

**Edge cases:**
- Profile name edit: show character limit if needed (e.g., max 100 chars)
- Delete account modal: disable confirm button while request is in progress
- Terminate sessions: after success, the current session is gone; any subsequent API call returns 401 → navigate to `/auth/login` immediately

**Implementation hints:**
- `authStore.user?.status === 'pending'` for conditional rendering
- For section visibility with pending check: `v-if="authStore.isPending"`
- Change password form: use the same `@ValidPassword` logic as in register — port to zod: `.refine(val => /[a-zA-Z]/.test(val) && /[0-9]/.test(val), { message: '...' })`
