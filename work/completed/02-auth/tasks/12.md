# Task 12: Code Audit

## Required Skills

Before starting, load:
- `/skill:code-reviewing` — [SKILL.md](~/.claude/skills/code-reviewing/SKILL.md)

## Description

Holistic code quality review of all feature code written in Tasks 1–11. Focus: Spring WebFlux reactive chain correctness (no blocking calls, correct error propagation), session management patterns, naming conventions, error handling consistency. Also review all Nuxt frontend files for Vue 3/Nuxt 4 best practices and reactivity correctness.

This is an Audit Wave task — the auditor IS the review. No reviewers. Output: findings report written to decisions.md and a JSON report at the specified path.

## What to do

1. **Read all backend packages** created/modified in this feature:
   - `com.botfunnel.auth` (AuthController, AuthService, TokenService, DTOs, validation)
   - `com.botfunnel.user` (User, UserRepository, UserService, UserStatus)
   - `com.botfunnel.profile` (ProfileController, ProfileService, DTOs)
   - `com.botfunnel.email` (EmailService + templates)
   - `com.botfunnel.events` (Event, EventRepository, EventService)
   - `com.botfunnel.admin` (SuperAdminSeeder)
   - `com.botfunnel.jobs` (HardDeleteJob)
   - `com.botfunnel.common` (AppException, ErrorResponse, GlobalErrorHandler)
   - `com.botfunnel.security.SecurityConfig`
   - All test files

2. **Read all frontend files** created in Tasks 8, 10, 11:
   - `stores/auth.ts`, `middleware/auth.ts`, `composables/useApi.ts`
   - `layouts/default.vue`, `layouts/auth.vue`
   - `pages/auth/*.vue` (5 pages)
   - `pages/dashboard.vue`, `pages/profile.vue`

3. **Apply code-reviewing skill** — check all review dimensions:
   - Architecture: reactive chains correct (no `.block()` in reactive context), proper use of `flatMap` vs `map`
   - Error handling: AppException thrown correctly, fire-and-forget errors logged (not swallowed silently), GlobalErrorHandler covers all exception types
   - Security hygiene: no secrets in logs, BCrypt cost, DUMMY_HASH usage
   - Naming: consistent with Spring/Vue conventions
   - Code duplication: terminate-all-sessions logic reused between AuthService and ProfileService
   - Frontend reactivity: no direct mutation of reactive state, correct use of `computed`, `watch`

4. **Write findings** to `work/02-auth/logs/working/task-12/code-reviewer-1.json` as a JSON array of `{severity, file, issue, recommendation}` objects.

5. **Write summary** to `work/02-auth/decisions.md`.

## Details

**Known risk areas to focus on (from tech-spec):**
- `AuthService.login()`: session fixation sequence must be exactly: invalidate old session → get new session → store SecurityContext → set TTL
- `AuthService.terminateAllSessions()`: `ReactiveMongoTemplate` query uses verified field path (documented in Task 6); if copied to `ProfileService`, same field path used
- `EmailService`: fire-and-forget pattern — errors must go to log, not propagate to subscriber
- `SuperAdminSeeder`: ApplicationRunner must not throw; must use BCrypt for password hashing
- `HardDeleteJob`: cron expression `"0 3 * * *"` — verify this is minute=0, hour=3 (daily 03:00), not some other format
- Frontend `useApi.ts`: `credentials: 'include'` must be set; missing it breaks session cookie transmission
