# Task 2: User domain

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Create the `User` domain (document, repository, service, status enum) and the `common` error-handling infrastructure (AppException, ErrorResponse, GlobalErrorHandler). Extend `SecurityConfig` to remove the stateless/JWT setup and wire session-based auth correctly: open `/api/auth/**`, wire `WebSessionServerSecurityContextRepository`, configure CSRF per Decision 12, configure CORS per Decision 8, disable httpBasic/formLogin.

This task runs in Wave 1 parallel with Task 1. Wave 2 tasks depend on `User`, `UserRepository`, `SecurityConfig`, and `AppException` being ready.

## What to do

1. **Create `UserStatus` enum** at `backend/src/main/java/com/botfunnel/user/UserStatus.java`: values `pending`, `active`, `blocked`, `deleted`.

2. **Create `User` @Document** at `backend/src/main/java/com/botfunnel/user/User.java`:
   - `@Document(collection = "users")`, `@Id String id`
   - Fields: `String email`, `String passwordHash`, `String name`, `UserStatus status`, `boolean isSuperAdmin`
   - Token fields: `String emailVerificationTokenHash`, `Instant emailVerificationExpiresAt`, `String passwordResetTokenHash`, `Instant passwordResetExpiresAt`, `Instant passwordResetUsedAt`
   - Timestamps: `Instant createdAt`, `Instant updatedAt`, `Instant deletedAt`
   - Add `@Indexed(unique=true)` on email; `@Indexed` on status (for hard-delete query)
   - Add `@CreatedDate` / `@LastModifiedDate` or set manually in service

3. **Create `UserRepository`** at `backend/src/main/java/com/botfunnel/user/UserRepository.java`:
   - Extends `ReactiveMongoRepository<User, String>`
   - Custom finders: `findByEmail(String email)`, `findByEmailVerificationTokenHash(String hash)`, `findByPasswordResetTokenHash(String hash)`, `findByStatusAndDeletedAtBefore(UserStatus status, Instant cutoff)`

4. **Create `UserService`** at `backend/src/main/java/com/botfunnel/user/UserService.java`:
   - `findByEmail(String email)` → `Mono<User>`
   - `save(User user)` → `Mono<User>`
   - `softDelete(String userId)` → sets status=deleted, deletedAt=now, saves
   - Status transition guard: `canActivate(User user)` — blocked users cannot be activated

5. **Create `AppException`** at `backend/src/main/java/com/botfunnel/common/AppException.java`:
   - Extends `RuntimeException`; fields: `HttpStatus status`, `String code` (optional), `String message`
   - Static factory methods: `badRequest(String msg)`, `unauthorized(String msg)`, `forbidden(String msg)`, `conflict(String msg)`, `tooManyRequests(String msg)`

6. **Create `ErrorResponse`** at `backend/src/main/java/com/botfunnel/common/ErrorResponse.java`:
   - Record or class: `String message`, `String code` (nullable)

7. **Create `GlobalErrorHandler`** at `backend/src/main/java/com/botfunnel/common/GlobalErrorHandler.java`:
   - `@ControllerAdvice` annotated class
   - Handle `AppException` → return `ResponseEntity<ErrorResponse>` with correct status
   - Handle `WebExchangeBindException` (Bean Validation failure) → 400 with field errors
   - Handle generic `Throwable` → 500 without exposing internals

8. **Extend `SecurityConfig`** at `backend/src/main/java/com/botfunnel/security/SecurityConfig.java`:
   - Remove `.csrf(csrf -> csrf.disable())` and the misleading "stateless API" comment
   - Add `WebSessionServerSecurityContextRepository` as security context repository
   - Configure CSRF with `CookieCsrfTokenRepository.withHttpOnlyFalse()` for dev (SameSite=Lax) and SameSite=Strict in prod (Decision 12)
   - Configure CORS: inject the allowed origin via `@Value("${app.url:http://localhost:3000}") String appUrl` at class level, then pass `allowedOrigins(appUrl)` — Spring does NOT resolve property placeholders inside Java string literals passed to method calls. Also set `allowCredentials(true)`, explicit methods (GET, POST, PATCH, DELETE, OPTIONS), explicit headers (Content-Type, X-Requested-With) — Decision 8
   - Permit `/api/auth/**` without auth; permit `/health`; require auth for all other `/api/**`
   - Disable `httpBasic()` and `formLogin()`

**SecurityConfig current state:** The existing `SecurityConfig` has `.csrf(csrf -> csrf.disable())` with a comment "stateless API", permits `/health`, and is otherwise a minimal configuration. It does NOT have CORS config, session wiring, or WebSessionServerSecurityContextRepository.

**Note on patterns.md:** `patterns.md` currently contains incorrect guidance stating "CSRF must be explicitly disabled for stateless REST APIs" — the opposite of what Task 2 implements. Task 9 (documentation update) will fix this. Ignore any `patterns.md` guidance about disabling CSRF — this task implements session-based CSRF (not stateless).

**Edge cases:**
- CORS: wildcard `*` origin with `allowCredentials(true)` is BLOCKED by browsers — must use explicit origin
- `WebSessionServerSecurityContextRepository.getInstance()` returns a shared singleton; use this static factory method
- Do NOT call `http.securityContextRepository(new WebSessionServerSecurityContextRepository())` with new — use `getInstance()`
- Index creation: `@Indexed(unique=true)` on email requires `spring.data.mongodb.auto-index-creation=true` in prod, OR manual index. Since auto-creation is false globally, document that manual index creation is needed in production MongoDB setup.

**Dependencies:**
- Task 1 must be complete (Gradle deps must be added before SecurityConfig changes compile)

**Implementation hints:**
- `BCryptPasswordEncoder` bean should be declared in `SecurityConfig` as `@Bean` so it can be injected elsewhere
- `WebExchangeBindException` carries field-level errors; extract via `ex.getFieldErrors()` for a useful error response
- **CORS `@Value` injection (critical):** Spring does NOT resolve `${...}` placeholders in Java string literals passed as method arguments. Do NOT write `allowedOrigins("${app.url:http://localhost:3000}")` — the literal string will be used verbatim and CORS will never match. Instead, inject at class level: `@Value("${app.url:http://localhost:3000}") private String appUrl;`, then use `allowedOrigins(appUrl)` inside the CORS configuration.
