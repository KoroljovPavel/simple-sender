# Task 6: Logout + password reset

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement logout, forgot-password, and reset-password endpoints. The reset-password flow has a critical complexity: invalidating ALL sessions for the user requires querying the `sessions` MongoDB collection via `ReactiveMongoTemplate`. The exact field path for principal name in spring-session-data-mongodb documents must be verified at runtime before building the query — this is the Task 6 risk area documented in the tech-spec.

Logout only invalidates the current session (other device sessions remain). Reset-password invalidates ALL sessions across all devices (user must re-login everywhere).

## What to do

1. **Extend `AuthController`** with:
   - `POST /api/auth/logout` → call `authService.logout(exchange)` → 200
   - `POST /api/auth/forgot-password` → body `{email}` → call `authService.forgotPassword(email)` → always 200
   - `POST /api/auth/reset-password` → body `{token, newPassword}` → `@Valid` → call `authService.resetPassword(...)` → 200

2. **Create `ForgotPasswordRequest` DTO** (`@Email @NotBlank String email`).

3. **Create `ResetPasswordRequest` DTO** (`@NotBlank String token`, `@NotBlank @ValidPassword String newPassword`).

4. **Extend `AuthService`** with:
   - `logout(ServerWebExchange exchange)`:
     - `exchange.getSession().flatMap(WebSession::invalidate)` → removes session from MongoDB `sessions` collection
     - Return `Mono<Void>`
   - `forgotPassword(String email)`:
     - Always return `Mono<Void>` → 200 (never reveal email existence)
     - If user exists and `status != deleted`: generate rawToken, store SHA-256 hash in `passwordResetTokenHash`, set `passwordResetExpiresAt = now + 1h`, save, send reset email fire-and-forget
     - Log `password_reset_requested` event (with userId=null if email not found, to prevent enumeration via event log)
   - `resetPassword(String rawToken, String newPassword, ServerWebExchange exchange)`:
     1. Hash rawToken
     2. Find user by `passwordResetTokenHash` where `passwordResetExpiresAt > now`
     3. If not found or expired: throw `AppException.badRequest("Посилання недійсне або прострочено")`
     4. If `passwordResetUsedAt != null`: throw `AppException.badRequest(...)` (already used)
     5. Bean Validation on `newPassword` via `@ValidPassword` on DTO
     6. BCrypt-hash new password, update user: new hash, `passwordResetUsedAt=now`, clear token fields, `updatedAt=now`
     7. **Verify sessions collection field path** (see Details): log all fields of one session document on first run
     8. Invalidate ALL user sessions via `ReactiveMongoTemplate` query on `sessions` collection
     9. Log `password_changed` event
     10. Return 200

5. **Implement terminate-all-sessions utility** in `AuthService`:
   - `terminateAllSessions(String userId)`: query `sessions` collection with `ReactiveMongoTemplate`
   - spring-session-data-mongodb stores principal name in the session document. **Verify the exact field path** by logging or querying a session document from the Testcontainer after a test login.
   - Expected field path (verify, do not assume): `principal` at document top level, or nested under `attrs` — check actual schema
   - Use `Query(Criteria.where("principal").is(userId))` or the verified path
   - `reactiveMongoTemplate.remove(query, "sessions")` → `Mono<DeleteResult>`

**Sessions collection field path verification (Risk area):**
The `sessions` collection document schema from spring-session-data-mongodb looks like:
```json
{ "_id": "sessionId", "principal": "userId", "lastAccessedTime": ..., "maxInactiveInterval": ..., "attrs": {...}, "expireAt": ... }
```
Verify this by adding a test that logs a session document: `reactiveMongoTemplate.findAll(Document.class, "sessions").blockFirst()` and log the keys. The terminate-all query should use `Criteria.where("principal").is(userId)` if the principal is at the top level.

**Edge cases:**
- `forgotPassword`: email service unavailable — fire-and-forget means the endpoint returns 200 regardless. The email failure is logged.
- `resetPassword`: if `passwordResetExpiresAt` is null (user never requested reset) → the lookup by hash will not find them; 400 returned correctly.
- Token reuse: `passwordResetUsedAt != null` check must happen AFTER the expiry check to give the most relevant error message.

**Implementation hints:**
- `ReactiveMongoTemplate` must be injected as a constructor argument in `AuthService`
- `Criteria.where("principal").is(userId)` — userId is a String (MongoDB ObjectId string); ensure type matches
- `reactiveMongoTemplate.remove(query, "sessions")` returns `Mono<DeleteResult>`, not `Mono<Long>`. If the deleted count is needed, extract it with `.map(DeleteResult::getDeletedCount)`. Chain with `flatMap` in the reactive chain.
