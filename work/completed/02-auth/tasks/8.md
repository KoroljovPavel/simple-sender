# Task 8: Frontend bootstrap

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Bootstrap the entire Nuxt frontend for the feature: install all required npm packages (Pinia, Vue Query, shadcn-vue, vee-validate/zod), configure `nuxt.config.ts`, create auth store with SSR-safe hydration, create layouts, and implement the global auth middleware. This is the foundation layer — Tasks 10 and 11 (auth pages and profile/dashboard) depend on everything here being in place.

Key complexity: Nuxt SSR auth hydration. `GET /api/auth/me` must be called server-side to avoid a flash of unauthenticated state. Use `useState` composable for SSR-safe initialization.

## What to do

1. **Install npm packages** in `frontend/`:
   - `@pinia/nuxt`, `pinia`
   - `@tanstack/vue-query`
   - `shadcn-vue` (and `radix-vue`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-vue-next`)
   - `vee-validate`, `@vee-validate/zod`, `zod`
   - `@nuxtjs/tailwindcss` (if not already installed from Epic 01)
   - Add to `devDependencies` in `package.json` as appropriate

2. **Bootstrap frontend test infrastructure** in `frontend/`:
   - Install `vitest`, `@vue/test-utils`, `@nuxt/test-utils` as devDependencies
   - Create `frontend/vitest.config.ts` with Nuxt environment preset
   - Add `"test": "vitest"` script to `frontend/package.json`
   - Create `frontend/tests/` directory as the root for all frontend unit tests

3. **Update `nuxt.config.ts`**:
   - Add modules: `@pinia/nuxt`, `@nuxtjs/tailwindcss`
   - Configure `$fetch` base URL: `runtimeConfig.public.apiBase = process.env.NUXT_PUBLIC_API_BASE || 'http://localhost:8080'`

4. **Create `frontend/composables/useApi.ts`**:
   - `$fetch` wrapper that sets `baseURL` from `useRuntimeConfig().public.apiBase` and `credentials: 'include'`

5. **Create `frontend/stores/auth.ts`** (Pinia store):
   - State: `user: User | null` (User type: `{id, email, name, status}`)
   - `fetchUser()` action: calls `GET /api/auth/me` via `useApi()`, sets `user`; on 401, sets `user = null`
   - `logout()` action: calls `POST /api/auth/logout`, sets `user = null`
   - SSR-safe initialization: use `useState('auth-user', () => null)` as the backing state to avoid SSR/client hydration mismatch
   - `isAuthenticated` getter: `user !== null`
   - `isPending` getter: `user?.status === 'pending'`

6. **Create `frontend/middleware/auth.global.ts`** (global route middleware):
   - On every navigation: if `authStore.user === null`, call `fetchUser()` once
   - If route requires auth (layout is `default` or route meta `requiresAuth: true`) and user is still null after fetch → redirect to `/auth/login`
   - If route is public auth route (`/auth/**`) and user is NOT null → redirect to `/dashboard`

7. **Create `frontend/layouts/default.vue`** (authenticated shell):
   - Topbar: logo left, user avatar + name right, logout button
   - Sidebar: navigation links (Dashboard, Profile)
   - `<slot />` for page content
   - On logout button click: call `authStore.logout()` then navigate to `/auth/login`

8. **Create `frontend/layouts/auth.vue`** (public shell):
   - Centered card layout for login/register/forgot-password pages
   - `<slot />` inside the card

## Details

**Files:**
- `frontend/nuxt.config.ts` — extend with modules and runtimeConfig
- `frontend/package.json` — add new dependencies
- `frontend/stores/auth.ts` — new Pinia store
- `frontend/middleware/auth.global.ts` — new global middleware
- `frontend/layouts/default.vue` — new authenticated layout
- `frontend/layouts/auth.vue` — new public layout
- `frontend/composables/useApi.ts` — new $fetch wrapper
- `frontend/plugins/vue-query.ts` — Nuxt plugin that installs VueQueryPlugin
- `frontend/vitest.config.ts` — vitest configuration with Nuxt environment preset
- `frontend/tests/` — root directory for all frontend unit tests

**Dependencies:**
- None from backend — this task bootstraps the frontend independently. Requires Node/pnpm environment.

**Edge cases:**
- SSR double-fetch: use `useState('auth-user')` as backing state — Nuxt serializes `useState` to the page payload and reuses it on client, preventing a second fetch
- CORS + credentials: `useApi.ts` must pass `credentials: 'include'` for session cookies to be sent
- Nuxt 4 middleware: only files named `*.global.ts` inside `middleware/` are auto-applied to every route — the file must be `auth.global.ts`, not `auth.ts`. A plain `auth.ts` requires explicit `definePageMeta({ middleware: 'auth' })` on every page and will not protect routes globally.

**Implementation hints:**
- shadcn-vue setup: run `npx shadcn-vue@latest init` for initial config, then add components: `npx shadcn-vue@latest add button input card form dialog badge`
- Vue Query setup: create `frontend/plugins/vue-query.ts` that installs `VueQueryPlugin`
- For the logout button: use `navigateTo('/auth/login')` after `authStore.logout()` completes
