# Task 9: Documentation update

## Required Skills

Before starting, load:
- `/skill:documentation-writing` — [SKILL.md](~/.claude/skills/documentation-writing/SKILL.md)

## Description

Update four project-knowledge documents to reflect the architectural decisions made in Epic 02. These updates are required to keep project documentation accurate and avoid misleading future AI agents working on subsequent epics.

Four documents need changes:
- `architecture.md` — remove jjwt reference (never actually added), add session + mail + validation + jobrunr deps, update Redis scope, add frontend deps
- `deployment.md` — remove JWT env vars, add SESSION_*, SUPER_ADMIN_*, MAIL_*, SUPPORT_EMAIL, add Mailpit section
- `patterns.md` — update CSRF guidance: session-based SPAs use CookieCsrfTokenRepository; CSRF disable is only for truly stateless endpoints
- `ux-guidelines.md` — update account deletion from "requires password re-entry" to "modal with consequences, no password required" (Decision 5)

## What to do

1. **Update `architecture.md`**:
   - Remove `jjwt` entry from backend dependencies section (it was listed as planned but never added to build.gradle; the project uses spring-session-data-mongodb instead)
   - Add new backend deps that are missing: `spring-session-data-mongodb`, `spring-boot-starter-validation`
   - Update Redis description: from general cache to "brute-force counters (auth) + analytics cache"
   - Note: `spring-session-data-mongodb` stores sessions in **MongoDB**, not Redis — do not add it to the Redis row. It belongs in the backend dependencies section (already covered above). The Redis row should only reflect Redis-backed features: brute-force counters and analytics cache.
   - Note: `jobrunr-spring-boot-3-starter`, `spring-boot-starter-mail`, and all frontend packages (`@pinia/nuxt`, `@tanstack/vue-query`, `shadcn-vue`, `vee-validate`, `zod`) are already present in architecture.md — do not add duplicates

2. **Update `deployment.md`**:
   - Remove: `JWT_SECRET`, `JWT_ACCESS_TTL_MINUTES`, `JWT_REFRESH_TTL_DAYS`
   - Add the following variables that are currently missing: `MAIL_FROM`, `SESSION_TTL_DEFAULT_HOURS`, `SESSION_TTL_REMEMBER_ME_DAYS`, `SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_PASSWORD`, `SUPPORT_EMAIL`
   - Note: `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, and `APP_URL` already exist in deployment.md — do not add duplicates
   - Add Mailpit section under "Local Development": how to access UI (`http://localhost:8025`), SMTP port (1025), purpose (local email testing)

3. **Update `patterns.md`**:
   - Find the guidance about CSRF (likely in a Security or API patterns section). It currently states something like "CSRF must be explicitly disabled for stateless REST APIs."
   - This task implements session-based CSRF (not stateless), so that rule is no longer universally correct.
   - Change or remove the old rule and replace with: "For session-based SPAs: use `CookieCsrfTokenRepository` with SameSite cookie policy (defense in depth). CSRF disable is only for truly stateless endpoints (webhooks, public APIs)."

4. **Update `ux-guidelines.md`**:
   - Account deletion section: change from "requires current password confirmation" to "confirmation modal listing consequences (projects, bots, subscribers to be deleted) — no password required. Active session is sufficient proof of identity."
   - Add note: this overrides the earlier guideline; rationale is Decision 5 in tech-spec.
