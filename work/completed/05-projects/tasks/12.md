## Description

Full-feature security audit of epic `05-projects`. The auditor reads every source file created or modified across Tasks 1–10 and analyzes the feature holistically against the OWASP Top 10 (2021+), with particular attention to the cross-component auth and data-flow invariants the tech-spec relies on:

- **Single ownership entry point.** Every project-scoped handler (`GET/PATCH/DELETE /api/v1/projects/{id}` and `/restore`) routes through `ProjectService.requireOwned(ownerId, projectId, includeSoftDeleted)`. No other path may read/write a `Project` document by id without going through this guard. (Decision 1.)
- **No `ownerId` from the request body.** `CreateProjectRequest` and `UpdateProjectRequest` must not expose `ownerId`; the controller must derive `ownerId` from the authenticated session via the existing `currentUserId()` pattern. Mass-assignment attempts (extra JSON fields) are silently dropped by `@JsonIgnoreProperties(ignoreUnknown = true)` on both DTO records. (Data Models section, Decision 1.)
- **Anti-enumeration via uniform 404.** `requireOwned` returns the same `404 Project not found` body for: foreign project, soft-deleted project on default GET, malformed `projectId`, and `restore` on an already-active project. The response body, status code, and timing must be indistinguishable across these cases — there must be no `403`, no `409 "exists but not yours"`, no early-return short-circuit that skips the Mongo read. (Decisions 2, 14.)
- **CSRF and session inheritance.** The new endpoints inherit the existing CSRF + session-cookie filter chain from `com/botfunnel/security/SecurityConfig.java` without modification. The auditor must verify `SecurityConfig` is on the AC-T7 zero-touch list and that no new `permitAll`, no new `csrf().disable()`, and no new public path is introduced under `/api/v1/projects/**`. (Decision 8, AC-T7.)
- **No new secrets.** No bot tokens, API keys, encryption keys, or PII are persisted, logged, or shipped to the frontend. The only non-PII identifier persisted in the browser is the opaque `currentProjectId` (ObjectId hex) under `localStorage` key `bot-funnel.currentProjectId`, gated by `import.meta.client`. (Decision 10, AC-T12.)
- **Rate-limit acceptance.** The tech-spec explicitly accepts the absence of brute-force / rate-limit on `/api/v1/projects/*` (Decision 8). The auditor confirms the documented mitigations (5-active quota, uniform 404, audit-log volume monitoring) are actually present in the implementation, not just the design.

The auditor produces a written report covering all OWASP categories with concrete file/line citations, severity grading, and a fix recommendation per finding. The report is the deliverable; reviewers are empty because the auditor IS the review for this task. The audit is a hard gate before Final Wave (Task 14 Pre-deploy QA).

## Verification Steps

### Automated

- `find backend/src/main/java/com/botfunnel/project -name '*.java' | xargs grep -l 'requireOwned'` — every project-scoped handler invokes the guard.
- `grep -nE 'ownerId' backend/src/main/java/com/botfunnel/project/dto/*.java` — must return zero hits in `CreateProjectRequest` and `UpdateProjectRequest`.
- `grep -n '@JsonIgnoreProperties' backend/src/main/java/com/botfunnel/project/dto/*.java` — must show `ignoreUnknown = true` on both request DTOs.
- **AC-T7 zero-touch verification (content-read, not diff).** The feature is being developed on `main` itself (no `dev` branch despite tech-spec frontmatter `branch: dev`), so `git diff main -- <file>` is a no-op and `git log -- <path>` without a commit range shows full repo history. Instead, read each zero-touch file in full and verify its content matches the documented pre-feature state. The zero-touch files per AC-T7 are:
  - `backend/src/main/java/com/botfunnel/security/SecurityConfig.java`
  - `backend/src/main/java/com/botfunnel/jobs/JobRunrMongoConfig.java`
  - `frontend/middleware/auth.global.ts`
  For each: open the file, scan for any reference to `projects` / `project` / `/api/v1/projects/**` (there must be none specific to this feature — the existing `pathMatchers("/api/**").authenticated()` already covers it per tech-spec line 50). If the report needs a stronger anchor, compare the file content against the pre-feature snapshot recorded in `code-research.md` (which captured the security baseline before Wave 1) and note any drift as a finding. Do not rely on `git diff main` or unbounded `git log` for this check.
- `cd frontend && pnpm audit --prod` — record the summary (advisory output, not a hard gate unless Critical).

The audit is a read-only review pass; there is no test suite to run for this task itself. Test coverage of the security invariants is part of Task 13 (Test Audit) and Task 14 (Pre-deploy QA).

**OWASP focus areas for this feature (the auditor still covers all 10):**
- **A01 Broken Access Control** — primary concern. Every `Project` document mutation/read must pass through `requireOwned`. Verify `ProjectController` does not call `projectRepository.findById(...)` directly. Verify `ProjectHardDeleteJob` only operates on its own derived `findByDeletedAtBefore(...)` query and does not accept caller-supplied IDs.
- **A03 Injection** — Mongo NoSQL injection. Spring Data reactive repositories with method-name derived queries are parameterized; verify no raw `Query`/`Criteria` with string concatenation, no `where().is(userInput)` with un-validated user input. Verify `name` regex/equality lookups in `findByOwnerIdAndNameAndDeletedAtIsNull` use the value verbatim (Mongo driver escapes BSON; no `$where` or JS evaluation).
- **A04 Insecure Design** — anti-enumeration. The four 404 cases (foreign / soft-deleted / malformed / already-active restore) must return identical bodies. Spot-check `ProjectControllerIT` to confirm assertions exist on the body shape, not just the status code.
- **A05 Security Misconfiguration** — `SecurityConfig` AC-T7 zero-touch. New `application.properties` keys (`app.projects.max-per-user`) must not weaken existing config. `.env.example` must not contain real secrets.
- **A07 Identification and Authentication Failures** — `currentUserId()` is the only auth source. Verify no `@AuthenticationPrincipal` reactive principal binding (per Decision 1 alternatives — out of scope for this codebase). Verify no controller method derives identity from a header, query param, or body field.
- **A08 Software and Data Integrity** — mass-assignment defense. `@JsonIgnoreProperties(ignoreUnknown = true)` on both request DTOs; no `Project` entity bound directly as `@RequestBody` (only DTOs).
- **A09 Security Logging and Monitoring** — every mutation emits an audit event via `EventService` (`project_created`, `project_updated`, `project_renamed`, `project_soft_deleted`, `project_restored`, `project_hard_deleted`). Verify the cron job's structured INFO log per AC-17c is present.
- **A02, A06, A10** — light-touch. No new crypto, no new HTTP egress, dependencies unchanged. Confirm and move on; do not invent findings.

**Edge cases the audit must explicitly check:**
- The `restore` flow uses `requireOwned(includeSoftDeleted = true)` and then checks `deletedAt != null` AS THE FIRST ACTION (Decision 14). Confirm the order: a regression that flipped this to last-action would silently rename live projects.
- The 404 interceptor in `frontend/composables/useApi.ts` only fires for the path regex `^/api/v1/projects/[^/]+$` (Decision 11). A wildcard would clear the project on unrelated 404s and constitute a UX denial-of-service vector.
- `localStorage` writes in `stores/projects.ts` must be gated by `import.meta.client` (Decision 10). An ungated write throws `ReferenceError` under SSR — not a security vulnerability per se, but a robustness finding under A04 Insecure Design.
- `errors.projects.*` i18n keys must not echo back raw input (e.g. attempted project name) into the toast — would create a stored-XSS sink if Vue's auto-escaping is ever bypassed by `v-html`. Spot-check toast rendering for `v-html`.
- `events` collection writes for project mutations must NOT serialize the entire DTO into `metadata` — only the documented metadata keys (`projectId`, `name`, `previousName`, `renamedDueToConflict`). Bulk-DTO logging would expose `description` content in the audit log unintentionally.

**Implementation hints for the audit pass:**
- Read entry points (controllers) first, then services, then repositories. Trace each path top-down.
- Every `Mono<...>` chain in `ProjectService` should start with a `requireOwned` call, except `list` (which uses `ownerId` directly, never an external `projectId`) and `create` (which has no `projectId` yet).
- AC-T7 zero-touch verification is content-read, not git-diff (see Verification Steps → Automated). The feature lives on `main`, so `git diff main -- ...` is a no-op and `git log --oneline -- backend/.../security/` without a commit range would show full repo history rather than feature-scoped changes. Read the three zero-touch files in full and confirm their content matches the pre-feature baseline captured in `code-research.md`; treat any drift as a finding.
- For the i18n files, search for `<%`, `${`, `{{` inside string values — no template interpolation should leak server-side data.
- The audit report writer is YOU — produce findings with concrete file:line citations the implementing agents (or Pre-deploy QA) can act on directly.

**Out of scope (do not audit; document as such in the report):**
- The wider `auth/`, `profile/`, `email/`, `events/`, `user/` packages. They are existing baseline; Task 12 is feature-scoped.
- Future epics (`bot/`, `subscriber/`, etc.). They will register their own `requireOwned` callers when implemented.
