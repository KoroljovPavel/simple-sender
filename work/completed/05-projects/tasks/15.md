## What to do

### 1. Видимий tooltip про ліміт 5 проектів (закриває реальне виконання AC-30)

**Зараз** (`components/ProjectSelector.vue:136`, `pages/projects/index.vue:123`):
disabled-кнопки "+ Create new project" мають native `:title="t('projects.create.limitReachedTooltip')"`.
На disabled-кнопці Chrome не показує native title, на mobile його взагалі немає,
і навіть на desktop затримка ~1-2с робить його непомітним.

**Що зробити:**
- Замінити `:title="..."` на **завжди видимий** inline-текст біля disabled-кнопки
  (або під нею) — наприклад `<span class="text-xs text-muted-foreground mt-1">{{ t(...) }}</span>`.
  В дропдауні селектора — той самий текст блочно під disabled-пунктом.
- Гарантувати, що i18n-ключ `projects.create.limitReachedTooltip` рендериться в DOM,
  не через атрибут.
- Залишити `aria-disabled="true"` + `disabled` на самій кнопці.

**Tests:**
- `tests/components/ProjectSelector.spec.ts` — додати assertion, що при `length >= 5`
  у DOM присутній **текст** `projects.create.limitReachedTooltip` (поряд із disabled-кнопкою),
  а не як атрибут `title`. Існуючий тест на `:title=` оновити чи замінити.
- `tests/pages/projects/index.spec.ts` — те саме для top-of-page кнопки.

### 3. Stale-state redirect на /projects/{deletedId}/settings (закриває AC-24 + AC-22d + Сценарій 6)

**Зараз** (`pages/projects/[projectId]/settings.vue:165-173`): коли `project === null`
рендериться тихий amber-banner із посиланням на `/projects`. Юзер часто не бачить його:
- **Same-tab back-after-delete:** store вже без видаленого, `project` null → banner, юзер
  розгублений ("я ж тільки видалив, чому я тут?").
- **Cross-tab (test 2.6):** store stale → форма показує застарілі дані → 404 не тригериться
  на mount → ніякого toasta.
- **Після reload у cross-tab:** 404 нарешті ловиться через якийсь API-виклик, interceptor
  смикає `selectProject(null)` + auto-select іншого, у topbar selector стрибає, юзер не
  розуміє звідки змінився проект.

**Що зробити:**

(a) `pages/projects/[projectId]/settings.vue` — **on mount робити явну валідацію через API**:
```ts
onMounted(async () => {
  if (!import.meta.client) return
  try {
    await useApi()<Project>(`/api/v1/projects/${projectId.value}`)
  } catch (e) {
    // 404 — interceptor у useApi вже зчистив store; нам лишається явний редірект.
    // інші помилки — лишити banner-fallback як було.
    if ((e as { statusCode?: number })?.statusCode === 404) {
      await navigateTo(localePath('/projects'))
      return
    }
  }
})
```
Це гарантує, що навіть у cross-tab сценарії юзер не побачить стейл-форму — або форма свіжа,
або редірект.

(b) Замість passive banner (`v-if="!project"`) — якщо `isLoaded && !project` після mount-перевірки,
теж зробити `navigateTo(localePath('/projects'))` (не показувати порожню сторінку взагалі).

(c) Зробити toast про unavailable project **persistent** (sticky, без auto-dismiss за 3с) —
зараз `pendingBannerKey` у store ставиться, але якщо UI його показує через швидкий toast,
юзер пропускає. Рекомендований варіант: у `pages/projects/index.vue` рендерити banner у
верхній частині сторінки (поряд із існуючим `restore-toast`) із кнопкою dismiss, читаючи
`projectsStore.pendingBannerKey` і скидаючи її при dismiss.

**Tests:**
- `tests/pages/projects/settings.spec.ts` — додати кейс: mock `useApi` повертає 404 на
  `GET /api/v1/projects/{id}`, assert `navigateTo` викликаний з `'/projects'`, форма не
  рендериться.
- `tests/pages/projects/index.spec.ts` — assert, що при `pendingBannerKey !== null` banner
  присутній; click на dismiss скидає у store до null.
- E2E `e2e/projects.spec.ts` (опційно): додати крок із soft-delete + browser-back на settings →
  assert URL = `/projects` (редірект відбувся).

### 4. TimezonePicker з пошуком (з `workflow/improvements.md` — Projects/UX)

**Зараз** (`pages/projects/new.vue`, `pages/projects/[projectId]/settings.vue`):
timezone — native `<select>` з ~400+ IANA зон з `Intl.supportedValuesOf('timeZone')`.
Юзер скролить довго; на мобільному поганий UX.

**Що зробити:**
- Створити `frontend/components/TimezonePicker.vue` — combobox з пошуком:
  - Текстовий інпут із typeahead-фільтром (`tz.toLowerCase().includes(query.toLowerCase())`).
  - Dropdown із opcij. Біля кожної опції — поточний UTC-offset через
    `new Intl.DateTimeFormat('en', {timeZone: tz, timeZoneName: 'shortOffset'})
     .formatToParts().find(p => p.type === 'timeZoneName').value` (формат `GMT+2`, `UTC+05:30`).
  - Default-обрана опція — TZ браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`).
  - Емітить `update:modelValue` (для v-model), приймає `modelValue: string | undefined`.
  - Keyboard: стрілки (active descendant), Enter (select), Escape (close).
  - ARIA: `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-activedescendant`.
  - Empty-state у dropdown коли немає матчів — `{{ t('timezone.noMatches') }}`.
- Реюз: підставити `<TimezonePicker v-model="..." />` замість native select у `pages/projects/new.vue`
  і `pages/projects/[projectId]/settings.vue`.
- Зберегти всю поточну валідацію (zod refine з timezones списком) — компонент не приймає
  довільний рядок, тільки те, що є у списку. Якщо юзер очистив поле — emit empty string.
- i18n: `timezone.searchPlaceholder`, `timezone.noMatches` — обидві локалі.
- **Бекенд не чіпати** — валідація `@ValidTimezone` уже строга, не вимагає змін.

**Tests:**
- `tests/components/TimezonePicker.spec.ts` (новий):
  - Default-value = TZ браузера при `modelValue === undefined`.
  - Typeahead фільтрує (input "kyiv" → опція `Europe/Kyiv` присутня).
  - Keyboard nav: ArrowDown→Enter обирає опцію, emits `update:modelValue`.
  - Escape закриває dropdown.
  - UTC-offset рендериться у dropdown поряд із кожною опцією.
- `tests/pages/projects/new.spec.ts` і `tests/pages/projects/settings.spec.ts` — оновити,
  щоб працювали через новий компонент (data-test-стик).
