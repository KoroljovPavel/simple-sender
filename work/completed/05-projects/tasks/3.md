## Description

Wave 2, ядро бекенду фічі `05-projects`. Реалізуємо service-layer + REST controller, які перетворюють примітиви Wave 1 (`Project` entity, `ProjectRepository`, DTOs, `@ValidTimezone`, `AppException` factories, `app.projects.max-per-user` config) у працюючий API під `/api/v1/projects` із повним CRUD + soft-delete + restore.

`ProjectService.requireOwned(ownerId, projectId, includeSoftDeleted)` — це **isolation primitive** усієї платформи: кожен майбутній модуль (`04-bots`, `05-subscribers`, `06-funnels`, `07-broadcasts`, `08-api`, `09-analytics`) монтуватиметься під `/api/v1/projects/{projectId}/...` і проходитиме через цей access-guard перед будь-якою бізнес-логікою. Тому чистота 404-уніфікації (foreign / soft-deleted-by-default-GET / malformed `projectId` → ідентичний 404) — критичний security-гейт (Decision 2, AC-8/9/10, Risk R1).

Сервіс enforce-ить два бізнес-правила, які не виражаються індексами: квоту 5 активних проектів на user (Decision 6 → 422 `project_limit_reached` через `AppException.unprocessableEntity("project_limit_reached", "...")`) та унікальність `(ownerId, name)` серед активних (Decision 4 → 409 `project_name_taken` через `AppException.conflict("project_name_taken", "...")` — нова дво-аргументна factory, додана в Task 1; race-window 10–60ms свідомо допустимий, бо обмежений тією ж квотою). Restore має дві особливості: спочатку перевіряємо `deletedAt != null` (Decision 14 — інакше 404), потім квоту, потім name-conflict із автосуфіксом `" (restored)"` і `metadata.renamedDueToConflict=true` в audit-event. Кожна мутація (`create/update/rename/softDelete/restore`) пише подію через `EventService.logEvent` (fire-and-forget, не падає при збої запису).

Controller — тонкий: `currentUserId()` витягує `AppUserDetails.id()` з `ReactiveSecurityContextHolder` (приватний static helper, точна копія з `ProfileController.currentUserId`); `extractIp` + `capUserAgent` — теж з `ProfileController`. Обробка PATCH-семантики (нормалізація `null`/blank для name/description/timezone — див. tech-spec "PATCH semantics") робиться у controller перед передачею в service.

Тести: `ProjectServiceTest` (юнит — Mockito, без Spring) покриває логіку квоти, name-collision, requireOwned всі 5 кейсів, restore-suffix, deletedAt-FIRST guard. `ProjectControllerSliceTest` (`@WebFluxTest`) — тільки те, що не вкладається в IT (response-shape happy-path). `ProjectControllerIT` (extends `AbstractIntegrationTest`, `@WithMockAppUser`) — повне покриття всіх AC-1..15 + AC-T1 + anti-enumeration parity для всіх дієслів (PATCH/DELETE/RESTORE на foreign/malformed/soft-deleted) + bare-client unauthenticated → 401 + audit-event presence з `metadata.projectId`/`metadata.name`/`metadata.previousName` де треба. Жодних змін у `SecurityConfig.java`, `auth.global.ts`, `EventService.java` (zero-touch contract per AC-T7).

   - `Mono<Project> create(String ownerId, CreateProjectRequest dto, String ip, String userAgent)` — порядок: count active → `AppException.unprocessableEntity("project_limit_reached", "Project limit reached")` якщо `>= max`; name-collision check (`findByOwnerIdAndNameAndDeletedAtIsNull`) → `AppException.conflict("project_name_taken", "Project name already taken")`; save новий `Project` з `ownerId`, `name`, `description` (blank → null), `timezone`, `createdAt=now`, `updatedAt=now`, `deletedAt=null`; emit `project_created` з metadata `{projectId, name}`.

   - `Mono<Project> restore(String ownerId, String projectId, String ip, String userAgent)` — `requireOwned(includeSoftDeleted=true)`; **FIRST** check `project.deletedAt == null` → `AppException.notFound("Project not found")` (Decision 14, defense-in-depth — БЕЗ цієї перевірки активний проект міг би мовчки потрапити в rename-логіку); count active → `AppException.unprocessableEntity("project_limit_reached", "Project limit reached")` якщо `>= max`; name-collision check серед активних → якщо collision: `name = original + " (restored)"` і запам'ятати `renamedDueToConflict=true` (НЕ кидаємо 409 у restore — auto-suffix замість conflict-у); `deletedAt=null`; save; emit `project_restored` з `{projectId, name, [renamedDueToConflict: true]}`.

## Acceptance Criteria

User-spec carry-forward:
- [ ] **AC-1:** POST `/api/v1/projects` valid body → 201 + Project body + `project_created` audit event.
- [ ] **AC-2:** POST invalid `name` (missing / blank / `<3` / `>50`) → 400 with `name` in message.
- [ ] **AC-3:** POST invalid `timezone` (missing / blank / not in `ZoneId.getAvailableZoneIds()`, e.g. `GMT+5`, `+02:00`, `NotAZone`) → 400 with `timezone` in message.
- [ ] **AC-3b:** POST `description.length > 200` → 400 with `description` in message.
- [ ] **AC-4:** POST when user already has 5 active → 422 + `code: "project_limit_reached"`.
- [ ] **AC-5:** POST `name` collides with active own project → 409 with response body `{message: <non-empty>, code: "project_name_taken"}` (constructed via `AppException.conflict("project_name_taken", "...")`).
- [ ] **AC-6:** GET `/api/v1/projects` → only own active, sorted `createdAt desc`.
- [ ] **AC-7:** GET `/api/v1/projects?include_deleted=true` → active + soft-deleted, each carries `deletedAt`.
- [ ] **AC-8:** GET `/api/v1/projects/{foreign-id}` → 404.
- [ ] **AC-9:** GET `/api/v1/projects/{malformed-id}` → 404 (uniform).
- [ ] **AC-10:** GET `/api/v1/projects/{soft-deleted-own-id}` (default) → 404.
- [ ] **AC-11:** Any `/api/v1/projects/*` without session → 401.
- [ ] **AC-12:** PATCH valid body → 200 + updated; emit `project_renamed` if name changed (with `previousName`), else `project_updated` (no `name`/`previousName` in metadata).
- [ ] **AC-12b:** PATCH `name` collides with another active own project → 409 with response body `{message: <non-empty>, code: "project_name_taken"}` (constructed via `AppException.conflict("project_name_taken", "...")`). No-op rename (same name) NOT considered conflict.
- [ ] **AC-13:** DELETE → 200 + `deletedAt = now()` + `project_soft_deleted` event. Project disappears from default list, appears in `?include_deleted=true`.
- [ ] **AC-14:** POST `/{id}/restore` on soft-deleted own project when `active < limit` → 200 + `deletedAt = null` + `project_restored`. If name conflicts with active → server appends `" (restored)"` + `metadata.renamedDueToConflict = true`.
- [ ] **AC-15:** POST `/{id}/restore` when `active == limit` → 422 + `code: "project_limit_reached"`.

Anti-enumeration parity (Decision 2 across verbs):
- [ ] PATCH/DELETE/restore on foreign-id → 404.
- [ ] PATCH/DELETE/restore on malformed-id → 404.
- [ ] PATCH/DELETE on soft-deleted-own-id → 404.
- [ ] POST `/{id}/restore` on already-active own project → 404 (Decision 14), with NO `project_renamed` and NO `project_restored` event written.

Tech-spec criteria:
- [ ] **AC-T1:** All endpoints return JSON with `Content-Type: application/json`. Error bodies conform to `{message: string, code: string | null}`.
- [ ] Mass-assignment defense: hostile POST body `{name, ownerId: "<other>"}` → DB record's `ownerId` equals authenticated user; response body does NOT contain `ownerId` field (verified for GET/POST/PATCH/RESTORE responses — response-shape lock).
- [ ] **AC-T9:** No `@CompoundIndex(unique=true, partialFilterExpression=...)` anywhere in `com.botfunnel.project.*` (uniqueness is service-layer only).
- [ ] **AC-T11:** All Mongo queries use `ReactiveMongoRepository` derived finders or `Query.query(Criteria.where(field).is/in(typedValue))` with typed values. No string concatenation into `Criteria`.
- [ ] **AC-T7 (zero-touch):** No edits to `SecurityConfig.java`, `auth.global.ts`, `JobRunrMongoConfig.java`, `EventService.java`, `AbstractIntegrationTest`.
- [ ] `Verify-smoke` passes: `cd backend && ./gradlew test --tests 'com.botfunnel.project.*'` → green; `curl -i -X POST localhost:8080/api/v1/projects` (no session) → 401.

**Edge cases:**
- Malformed `projectId` (non-ObjectId hex): Spring Data Mongo throws `IllegalArgumentException` from `findById`. Catch via `.onErrorMap(IllegalArgumentException.class, e -> AppException.notFound("Project not found"))` inside `requireOwned` so all three "not yours" cases (foreign / soft-deleted / malformed) collapse to identical 404 — anti-enumeration (Decision 2, AC-9).
- PATCH `name` to own current name (`name == project.getName()`): MUST NOT trigger 409 (AC-12b). Use `findByOwnerIdAndNameAndIdNotAndDeletedAtIsNull` (excludes the project being renamed). For audit event in this case: technically it IS a rename request that ended in no DB-level name change — emit `project_updated` (no `previousName`/`name` metadata fields). Guard via `if (newName != null && !newName.equals(currentName)) { /* rename path */ } else { /* update path */ }`.
- `description` semantics on PATCH: `null` → no change; blank string (`""` or whitespace) → set to `null` in DB (AC-22b). Since record fields are always present after deserialization, distinguish via Jackson default: missing JSON field deserializes to `null`; empty-string JSON field deserializes to `""`. Service receives normalized intent: `null` = no change, `""` = clear, non-blank = set.
- `timezone` on PATCH: `null` OR blank → no change (NEVER overwrite with empty string, AC-22c). Bean-validation `@ValidTimezone` allows null/blank (delegated to `@NotBlank` which is absent on update DTO).
- Restore on hard-deleted (record gone) → falls through `requireOwned(includeSoftDeleted=true)` → `findById` returns empty → 404. No special handling needed.
- Concurrent name-collision race (Risk R3): service-layer pre-check has 10–60ms window. Accepted per Decision 4 — quota of 5 active caps abuse. Do NOT add programmatic `IndexOps.ensureIndex` here (deferred fallback).
- 401 path: `pathMatchers("/api/**").authenticated()` in `SecurityConfig.java:71` fires BEFORE the controller — unauthenticated requests never reach `currentUserId()`. The IT bare-client test verifies this: 401 comes from Spring Security filter, body shape is whatever the security filter chain returns. The `currentUserId()` `Mono.error(AppException.unauthorized(...))` fallback is defense-in-depth for the case where security config drifts.
- `events.metadata` typed values only (AC-T11): `Map.of("projectId", project.getId(), "name", project.getName())` for create/soft-delete/restore; `Map.of("projectId", id, "previousName", oldName, "name", newName)` for rename; `Map.of("projectId", id)` for plain update; `Map.of("projectId", id, "name", newName, "renamedDueToConflict", true)` for restore-with-rename. No string concatenation into `Criteria`.

**Implementation hints:**
- `requireOwned` signature: `Mono<Project> requireOwned(String ownerId, String projectId, boolean includeSoftDeleted)`. Returns the `Project` so callers can chain `.flatMap(project -> doMutation(project))` without re-fetching.
- **AppException factory selection (critical for AC-5 and AC-12b):** for 409 name-collision use the **two-argument** `AppException.conflict("project_name_taken", "Project name already taken")` (this factory was added in Task 1 specifically to set `code = "project_name_taken"` on the response body). The single-argument `AppException.conflict(String message)` overload hardcodes `code = null` and MUST NOT be used in `ProjectService` — calling it would silently fail the AC-5 / AC-12b assertion `code == "project_name_taken"`. For 422 quota use `AppException.unprocessableEntity("project_limit_reached", "Project limit reached")` (also two-argument, same pattern). For 404 use `AppException.notFound("Project not found")` (single-argument is fine here — `code = null` is acceptable for 404 per AC-T1).
- For `update`, the rename-vs-update branch decides which event type fires. Compute `boolean nameChanging = req.name() != null && !req.name().equals(project.getName())`. If nameChanging — collision-check + emit `project_renamed` with `previousName`. Else — emit `project_updated` with only `projectId`.
- For `restore` ordering (Decision 14): (1) `requireOwned(includeSoftDeleted=true)` returns project; (2) **FIRST** check `if (project.getDeletedAt() == null) throw AppException.notFound(...)`; (3) quota check; (4) name-collision + suffix; (5) `setDeletedAt(null)`; (6) save; (7) emit event. Mockito test asserts that on a project with `deletedAt==null`, neither `project_renamed` nor `project_restored` events fire (verifies the deletedAt-FIRST guard).
- Event metadata for `project_renamed` MUST include `previousName` (AC-12 IT explicitly asserts `metadata.previousName == oldName`). Capture `oldName = project.getName()` BEFORE assigning new name.
- Use `Mono.just(...)` / `Mono.error(...)` / `.flatMap(...)` chain style — match `ProfileService.updateProfile` shape. No `block()` calls in production code.
- For `list` ordering — use the derived finder names from Task 1's `ProjectRepository`: `findByOwnerIdAndDeletedAtIsNullOrderByCreatedAtDesc` (active) and `findByOwnerIdOrderByCreatedAtDesc` (all).
- For controller PATCH normalization: do it in controller method body BEFORE calling service. Service should receive a "normalized" intent — non-null `name` means rename, non-null `description` means set (where empty-string already mapped to null), non-null/non-blank `timezone` means change. Avoid passing the raw DTO to service.
- Tests: assertions on JSON path use `webTestClient.expectBody().jsonPath("$.code").isEqualTo("project_limit_reached")` style. For audit-event polling: `await().atMost(Duration.ofSeconds(2)).untilAsserted(() -> { Event e = eventRepository.findAll().filter(ev -> ev.getEventType().equals("project_created")).blockFirst(); assertThat(e.getMetadata().get("projectId")).isEqualTo(...); });`
- IT seed `User` record with `USER_ID = "test-user-fixed-id"` to match `@WithMockAppUser(userId=USER_ID)` — exactly as `ProfileControllerIT` does. The user is needed because event-log writes carry `userId` and the security context resolves through user lookup.
- **Slice-test connection-factory mocks — verify empirically, do not preemptively add:** patterns.md mentions three connection-factory mocks (`ReactiveMongoTemplate`, `MongoConverter`, `ReactiveMongoDatabaseFactory`) for slice tests, but `AuthControllerSliceTest` (`@WebFluxTest`) in this codebase passes without those mocks. First write the slice test with only `@MockitoBean ProjectService` and run it. Only if bootstrap fails with `NoSuchBeanDefinitionException` (or similar) for a connection-factory bean — add `@MockitoBean` for that specific bean. Avoid blanket-mocking all three when the actual context only needs zero or one. Document the empirical result (mocks needed: 0 / 1 / 3) in the post-completion report.
