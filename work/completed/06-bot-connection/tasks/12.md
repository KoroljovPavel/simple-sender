## Description

Full-feature test quality audit for the 06-bot-connection epic. Read every test file created in this feature (`TokenEncryptorTest`, `TelegramApiClientTest`, `BotServiceTest`, `BotControllerIT`, `BotTokenLeakTest`, frontend `frontend/tests/pages/projects/[projectId]/settings/bot.spec.ts`) and assess:

- **AC coverage.** Map every user-spec AC1–AC23 (and the tech-spec supplementary criteria) to a concrete test method. Flag any AC without a corresponding test or with only an incidental assertion.
- **Meaningful assertions.** Tests must assert observable outcomes (HTTP status, DB row, audit-event metadata, order of side effects, MockWebServer request log), not just "no exception thrown". Flag tautological assertions, missing negative assertions, and assertions on irrelevant fields.
- **Test pyramid balance.** TokenEncryptor / TelegramApiClient / token-mask helper → unit; BotService orchestration → unit with mocked deps; BotController + persistence + audit-event + Telegram integration → integration via `AbstractIntegrationTest` + `MockWebServer`. Flag inversions (integration test doing a unit's job, or a unit test depending on Mongo/Redis/MockWebServer).
- **MockWebServer usage correctness.** Each test that mocks Telegram must `enqueue` the right responses for the expected number of calls, assert the recorded request count, and assert URL/method/body of each `takeRequest()` where the AC requires it (e.g. AC8 ordering, AC9 compensating `deleteWebhook`, AC10 webhook URL shape, AC12 race-condition request log, AC11 "zero further requests on the 11th call"). Flag missing `takeRequest` assertions, leaked `MockWebServer` instances (not shut down), and shared/parallel-unsafe instances across tests.
- **Concurrency anti-patterns.** No `Thread.sleep`, no `Awaitility` without an explicit small ceiling, no `Mono.block()` outside of `StepVerifier` blocks, no shared mutable counters across reactive tests. The AC11/AC12 race tests must use `Flux.range(...).parallel(N).runOn(Schedulers.parallel()).flatMap(...)` or equivalent — flag any `Thread.sleep` polling.
- **Audit-event negative assertion actually runs.** AC17/AC23 require an assertion that no value in any emitted event's `metadata` map matches the token regex (`\d{1,20}:[A-Za-z0-9_-]{30,50}`). Verify the assertion is wired to a real event collector (in-memory `EventService` spy, captured via `ArgumentCaptor` or a `TestEventListener`), is invoked after Connect+Disconnect, and would actually fail if the token slipped in (sanity check by reasoning about the path).
- **`BotTokenLeakTest` reflective assertion.** Verify the test reflects over production code paths (not test classes), targets the encrypted-token field of the `Bot` entity, and the masking helper positive test asserts the literal AC18 form (`{telegramBotId}:•••...{tokenSuffix}`).
- **Frontend `bot.spec.ts` (bot connection scope).** Verify every error branch from tech-spec Testing → Frontend component tests is covered (400/409/422/429/500/502 connect; 404 disconnect; 422/502 test-message); verify Connected view asserts the literal AC18 mask string; verify Disconnect modal copy assertion matches AC19 verbatim; verify no leak of the raw token into rendered DOM or store state snapshot.

Output is a markdown audit report at `work/06-bot-connection/logs/working/task-12/test-audit-report.md`.

## What to do

1. Read every test file listed in the Details section.
2. Build the AC ↔ test-method mapping table covering AC1–AC23 plus the tech-spec supplementary criteria (tech-spec.md lines 475–484). One row per AC; column `test method` lists every test that covers it; column `status` is one of `covered` / `partial` / `missing`.
3. Walk each test file once and flag findings under: assertion quality, pyramid placement, MockWebServer usage, concurrency anti-patterns, leak-negative-assertion, frontend coverage gaps.
4. Grade each finding `blocker` / `major` / `minor` per the test-master rubric. A blocker is anything that (a) leaves an AC effectively untested or (b) introduces flakiness.
5. Produce the audit report with sections: Summary, AC Coverage Matrix, Pyramid Assessment, MockWebServer Usage, Concurrency Anti-patterns, Token-leak Negative Assertion, Frontend Coverage, Recommendations.
6. The report ends with a verdict: `pass` (no blockers, ≤2 majors) / `pass-with-followup` (no blockers, >2 majors) / `fail` (any blocker).

- `BotTokenLeakTest` reflecting over test classes or wired to non-production paths.
- Frontend test asserting "modal opens" without asserting AC19 copy verbatim.
- Frontend test that allows the raw token to reach any other observable surface (store state, devtools snapshot, rendered DOM, error toast text).
