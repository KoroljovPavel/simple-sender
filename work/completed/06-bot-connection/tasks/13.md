# Task 13: Pre-deploy QA

## Required Skills

Перед выполнением задачи загрузи:

## Description

Final-wave acceptance testing for feature `06-bot-connection` before deploy. Executes every automated check called out in user-spec "Как проверить → Агент проверяет" and tech-spec "Acceptance Criteria", maps each user-spec AC1–AC23 to concrete test evidence (test method name, integration class, locale-parity log line, mongo index output, curl response), confirms tech-spec Acceptance Criteria items (HTTP status codes, both partial unique indexes with the exact `{ status: 'CONNECTED' }` filter, locale parity gate, `BOT_TOKEN_ENCRYPTION_KEY` doc + fail-fast, `MockWebServer` in `testImplementation` only, reflective token-leak test, compensating-`deleteWebhook` integration test, untouched `SecurityConfig`), and produces a single sign-off report consumable by the deploy step.

This task does NOT write or modify production/test code. If any check fails, the QA agent stops, reports the failure with file/test names, and the gap is fixed in a follow-up task (a re-run of the appropriate Wave 1–3 task) before re-running QA — pre-deploy QA only signs off; it does not patch code itself.

No code review on this task (Final Wave — QA is its own verification, no production deliverables produced). No post-deploy task in this feature: deployment platform is TBD per `deployment.md`, and the real-Telegram smoke requires a human + BotFather and runs manually after deploy. As part of this task, the QA agent ALSO creates the staging-smoke checklist file `docs/staging-smoke/06-bot-connection.md` (10-step manual real-Telegram procedure mirroring user-spec "Пользователь проверяет") so the user has a written runbook for the post-deploy manual smoke.

### Automated

- `cd backend && ./gradlew test` → exit 0; capture `backend/build/reports/tests/test/index.html` and `backend/build/test-results/test/*.xml`

### Smoke

These are pre-deploy smoke checks the QA agent runs locally (no deployment needed):

- Env/config wiring (read-only file inspections, no edits):
  - `grep -n '^BOT_TOKEN_ENCRYPTION_KEY' .env.example` → exactly one line, value is a placeholder/empty (NOT a real key)
  - `grep -nE '^(app\.bot\.token-encryption-key|app\.telegram\.base-url|spring\.data\.mongodb\.auto-index-creation)' backend/src/main/resources/application.properties` → all three properties present; `app.telegram.base-url=https://api.telegram.org`; `spring.data.mongodb.auto-index-creation=true`
  - `grep -nE 'mockwebserver' backend/build.gradle` → match is inside a `testImplementation` block, not `implementation`
  - SecurityConfig wiring: open `backend/src/main/java/com/botfunnel/security/SecurityConfig.java` and confirm `/api/v1/projects/{id}/bot/**` (or the matching ant pattern) inherits the standard authenticated + CSRF-enforced rule — i.e. it is NOT listed under any `permitAll()` matcher and is NOT in any `csrf().ignoringRequestMatchers(...)` clause
- Boot: `cd backend && ./gradlew bootRun` (with `BOT_TOKEN_ENCRYPTION_KEY` exported in the shell from your local `.env` — never paste real keys in chat) → backend reaches "Started" log line; mongo auto-index-creation completes without error
- Bean-validation 400: `curl -i -X POST http://localhost:8080/api/v1/projects/{id}/bot/connect -d '{"token":"bad"}' -H 'Content-Type: application/json' -H 'Cookie: <session>'` → `HTTP/1.1 400` with field-validation body (AC2)
- Mongo indexes: `mongosh "${MONGODB_URI:-mongodb://localhost:27017/botfunnel}" --eval 'db.bots.getIndexes()'` → three indexes with the exact names and partial filters listed under Acceptance Criteria
- Fail-fast key check: stop the backend, unset `BOT_TOKEN_ENCRYPTION_KEY`, rerun `cd backend && ./gradlew bootRun` → non-zero exit with a clear "key missing / invalid length" log message (tech-spec AC line: "backend fails to boot with a clear error message when the key is missing or wrong length")
- Staging-smoke runbook: `mkdir -p docs/staging-smoke && test -f docs/staging-smoke/06-bot-connection.md` → directory created (idempotent — safe if it already exists) and file exists; it contains the 10-step manual real-Telegram checklist created in step 12 of What-to-do
