# Task 5: Frontend Settings route restructure (folder split + sub-nav scaffolding)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Конвертировать существующую single-page Settings (`frontend/pages/projects/[projectId]/settings.vue`) в Nuxt-folder route, чтобы освободить место под будущую Bot-страницу (Task 9), сохранив поведение General + Danger Zone без изменений. После задачи маршрут `/projects/{id}/settings` остаётся 1-в-1 (тот же UI, те же `data-test` атрибуты, тот же `onMounted` redirect-guard), но рендерится из `settings/index.vue`. Сверху index-страницы появляется горизонтальный sub-nav (`SettingsSubnav.vue`) с двумя вкладками: «General» (`/projects/{id}/settings`) и «Bot» (`/projects/{id}/settings/bot`). Вкладка Bot ведёт на минимальный плейсхолдер `settings/bot.vue` — финальная страница приедет в Task 9. Цель — атомарная скелет-задача без логики: убираем риск регрессии существующего settings UI и снимаем блокировку с Task 9 (там уже можно работать в готовом каталоге).

Ссылки на спеку: AC21 (user-spec), D10 (tech-spec — Settings folder split). Сейчас в `layouts/default.vue` боковая ссылка указывает на `/projects/{id}/settings`; после преобразования в folder-route Nuxt автоматически сматчит её на `settings/index.vue`, никаких правок в layout по идее не требуется — но нужно явно проверить, что ссылка ещё резолвится и активный state не ломается.

## What to do

1. Создать каталог `frontend/pages/projects/[projectId]/settings/` (рядом с текущим `settings.vue`).
2. Переместить содержимое `settings.vue` в `settings/index.vue` целиком, без правок логики, шаблона, импортов и `data-test` атрибутов. Только одна правка шаблона:
   - подключить новый компонент `SettingsSubnav` (через auto-import Nuxt) в `<template>` выше существующего `<h1>` заголовка.
   - Относительные пути импортов (`~/types/project`, и т.п.) остаются валидными — `~` это alias на `frontend/`.
3. Удалить исходный `frontend/pages/projects/[projectId]/settings.vue` (одним коммитом с созданием index.vue, чтобы избежать двойной регистрации маршрута).
4. Создать `frontend/components/SettingsSubnav.vue`:
   - принимает `projectId: string` через `defineProps`;
   - рендерит горизонтальный tab strip с двумя `<NuxtLinkLocale>`: General → `/projects/{projectId}/settings`, Bot → `/projects/{projectId}/settings/bot`;
   - подсветка активной вкладки через `exact-active-class` (для General критично — иначе её активный класс залипает на `/settings/bot`, см. Edge cases);
   - все видимые строки через `t('bot.subnav.general')` и `t('bot.subnav.bot')` (ключи добавляются в Task 4 — той же волны; если на момент исполнения ключей ещё нет — допустим временный literal с `// TODO: bot.subnav.* from Task 4`, который чистится в Task 9 или хот-фиксом после Task 4);
   - `data-test="settings-subnav"` на root-элементе и `data-test="settings-subnav-general"` / `data-test="settings-subnav-bot"` на ссылках — для будущих e2e / component тестов.
5. Создать `frontend/pages/projects/[projectId]/settings/bot.vue` — минимальный плейсхолдер:
   - `definePageMeta({ layout: 'default' })`;
   - корневой контейнер с `SettingsSubnav` сверху и одним абзацем `<p data-test="bot-placeholder">` ниже (текст — `t('bot.placeholder')`, ключ уже добавлен в Task 4);
   - никаких store-вызовов, никакой логики — Task 9 полностью перепишет файл.
6. Обновить импорт в существующем `frontend/tests/pages/projects/settings.spec.ts`: строка 32 импортирует `../../../pages/projects/[projectId]/settings.vue`, который удаляется в шаге 3. Заменить путь на `../../../pages/projects/[projectId]/settings/index.vue`. Это **обязательный** шаг, иначе весь существующий settings-spec упадёт на этапе module resolution. Ассерты и тело тестов не трогать.
7. Проверить `frontend/layouts/default.vue` (sidebar link `Settings`): убедиться, что после удаления `settings.vue` и появления `settings/index.vue` маршрут `/projects/{id}/settings` всё ещё резолвится и ссылка кликабельна. Никаких правок в layout не делать, если не сломалось.
8. Прогнать `cd frontend && pnpm test` (vitest подхватит все спеки автоматически; для точечного фильтра можно `pnpm test -- settings` — vitest filter — это substring по имени файла, а не по пути). Существующие settings-тесты + новые тесты на `SettingsSubnav` и `bot.vue` должны быть зелёными.
9. Прогнать `cd frontend && pnpm prebuild` — locale parity gate должен оставаться зелёным (новые `bot.subnav.*` и `bot.placeholder` ключи приходят из Task 4 в той же волне).

## Details

**Files:**
- `frontend/pages/projects/[projectId]/settings.vue` — **удалить** одним коммитом вместе с созданием `settings/index.vue`. Текущее содержимое (текущее состояние, прочитано): vee-validate + Zod форма (name/description/timezone), Danger Zone с typed-confirm-модалкой, `onMounted` hydration + 404-redirect guard через `useApi`. Не трогать ни одну строку логики — только перенести.
- `frontend/pages/projects/[projectId]/settings/index.vue` — **создать**. Дословная копия `settings.vue` с одной правкой `<template>`: добавить `<SettingsSubnav :project-id="projectId" />` сразу после открывающего `<div class="max-w-2xl space-y-8">` и перед `<h1>`. Переменная `projectId` уже доступна в `<script setup>` как `computed`.
- `frontend/pages/projects/[projectId]/settings/bot.vue` — **создать**. Минимум: `<script setup lang="ts">` с `definePageMeta({ layout: 'default' })` + `const route = useRoute(); const projectId = computed(() => String(route.params.projectId ?? ''))`; `<template>` с `<SettingsSubnav :project-id="projectId" />` и одним абзацем-плейсхолдером. Никаких store/API вызовов. Task 9 этот файл перепишет полностью.
- `frontend/components/SettingsSubnav.vue` — **создать**. `<script setup lang="ts">`: `defineProps<{ projectId: string }>()`, `const { t } = useI18n()`, `const localePath = useLocalePath()`. `<template>`: горизонтальный `<nav>` (Tailwind: `flex gap-4 border-b mb-4`), две `<NuxtLinkLocale>` с `:to="localePath(\`/projects/${projectId}/settings\`)"` и `:to="localePath(\`/projects/${projectId}/settings/bot\`)"` соответственно — точно как в `frontend/components/ProjectSelector.vue` (строки 119–128, 150–159). На General — `exact-active-class`; на Bot — `active-class`. `data-test` атрибуты см. What to do п.4.
- `frontend/layouts/default.vue` — **только проверить**, не править. Sidebar `<NuxtLinkLocale :to="\`/projects/${projectsStore.currentProject.id}/settings\`">` должен продолжать работать (Nuxt resolve folder-route с `index.vue` прозрачно).

**Dependencies:**
- Task 4 (i18n keys) — той же волны. По итогам пересмотра скоупа Task 4 владеет ключами `bot.subnav.general`, `bot.subnav.bot`, `bot.placeholder` (и `bot.title`). В Task 5 используем их напрямую: `t('bot.subnav.general')`, `t('bot.subnav.bot')`, `t('bot.placeholder')` — без временных literals и TODO-комментариев. Если Task 4 ещё не закоммичен на момент старта — синхронизироваться с агентом Task 4 перед началом (внутри одной волны это решается без блокировки).
- Никаких backend / store зависимостей нет — это чистая front-end рестуктуризация маршрутов.

**Edge cases:**
- **Двойная регистрация маршрута.** Если оставить и `settings.vue`, и `settings/index.vue`, Nuxt бросит коллизию или выберет один из них непредсказуемо. Удалять старый файл и создавать новый каталог нужно в одном коммите / одном PR / одном изменении на диск перед сборкой.
- **Существующие тесты со старым путём.** В `frontend/tests/pages/projects/settings.spec.ts` строка 32 уже импортирует `../../../pages/projects/[projectId]/settings.vue` — после удаления старого файла vitest упадёт на module resolution. **Обязательная правка**: заменить путь на `../../../pages/projects/[projectId]/settings/index.vue`. Имя файла теста менять не нужно. Ассерты (23 проверки) остаются неизменными.
- **Активный класс General-вкладки.** На маршруте `/projects/{id}/settings/bot` General-вкладка не должна светиться как активная. Использовать `exact-active-class` (а не дефолтный `active-class`) для General — Vue Router без `exact` считает `/projects/{id}/settings` префиксом `/projects/{id}/settings/bot` и подсвечивает обе.
- **i18n локали-плейсхолдеры.** Ключи `bot.subnav.general`, `bot.subnav.bot`, `bot.placeholder` владеет Task 4 (та же волна). Если они ещё не доехали на момент рендеринга — Vue I18n в production silently вернёт лукап-ключ как строку (UI покажет `bot.subnav.general` буквально), но `pnpm prebuild` (locale parity gate) при этом упадёт. Не использовать временные literals — синхронизироваться с агентом Task 4 в рамках волны.
- **Локальные импорты `~/...`.** Не менять — alias на `frontend/` остаётся валидным после переезда settings.vue → settings/index.vue.
- **Sidebar link и `currentProject`.** `layouts/default.vue` рендерит ссылку условно (`v-if="projectsStore.currentProject"`); ручная проверка должна делаться при выбранном проекте.

**Implementation hints:**
- Для горизонтального sub-nav самый компактный Tailwind-стиль: `<nav class="flex gap-4 border-b mb-4">`, ссылки `class="px-3 py-2 text-sm hover:underline" exact-active-class="border-b-2 border-blue-600 text-blue-600"`. Точные значения цветов — не критично для AC; UX-полировка приедет позже.
- `NuxtLinkLocale` в этом репозитории всегда оборачивает target через `localePath()` — это явная конвенция, подтверждённая в `frontend/components/ProjectSelector.vue` (строки 119–128: `:to="localePath('/projects/new')"`; 150–159: `:to="localePath(\`/projects/${projectsStore.currentProject.id}/settings\`)"`). Сделать так же: `const localePath = useLocalePath()` в `<script setup>`, затем `:to="localePath(\`/projects/${projectId}/settings\`)"`. Не передавать в `:to` сырую строку — это отойдёт от паттерна проекта и не выдержит code review.
- При переносе `settings.vue` в `index.vue` НЕ заворачивать содержимое в дополнительный wrapper. Существующий root `<div class="max-w-2xl space-y-8">` сохраняем.
- В `bot.vue` placeholder можно опционально дать заголовок-стаб `<h1>{{ t('bot.title') }}</h1>` (ключ владеет Task 4), но это не обязательно для AC.
- Vitest filter — substring по имени файла, а не по пути. `pnpm test -- tests/pages/projects` обычно работает (vitest рассматривает аргумент как regex по полному пути), но кроссплатформенно безопаснее короткое substring: `pnpm test -- settings` или `pnpm test -- SettingsSubnav`. Если сомневаешься — просто `pnpm test` без фильтра.
