## Description

Replace the placeholder `frontend/pages/projects/[projectId]/settings/bot.vue` from Task 5 with the real page that drives the entire bot-connection UX surface for Epic 06. The placeholder file (and the `settings/` folder structure plus `<SettingsSubnav />`) is delivered by Task 5 in this feature's Wave 1; Task 9 overwrites the placeholder content here in Wave 3. The page has two distinct states driven by the Pinia `bot` store (Task 7):

- **Connect form** (when `bot.current == null` / GET returned 404): token input, BotFather inline hint, Connect button that stays disabled while the input is empty or while the request is in flight.
- **Connected view** (when `bot.current.status == "connected"`): `@username` rendered prominently, `first_name` shown as a subtle secondary line, masked token in the AC18 literal form `{telegramBotId}:•••...{tokenSuffix}`, primary "Send Test Message" button with the "send /start first" inline hint, destructive Disconnect button.

Disconnect opens a shadcn-vue `Dialog` confirmation modal with the **exact** AC19 copy: *"Disconnect bot @{username}? Incoming messages will stop and the webhook will be removed. You can reconnect anytime."* — Cancel button closes without an API call, Disconnect button issues the POST. The shadcn-vue Dialog primitive is **not yet scaffolded** in this repo (current `frontend/components/` holds `LangSwitcher.vue`, `ProjectSelector.vue`, `TimezonePicker.vue` only); the implementing agent must run `pnpm dlx shadcn-vue@latest add dialog` (or whatever the local CLI command resolves to — `shadcn-vue@^1.0.3` is already listed in `frontend/package.json`) BEFORE the first `import { Dialog } from '@/components/ui/dialog'`. Commit every file the CLI generates under `frontend/components/ui/dialog/` plus any peer-dep entry the CLI adds to `package.json`.

All visible strings must resolve through `t('bot.*')` (keys delivered in Task 4 — `uk.json` / `en.json`); the masked-token literal `:•••...` is the only hard-coded glyph. Error handling follows the `useApiError()` factory pattern from `frontend/composables/useApiError.ts`: call `const handle = useApiError()` ONCE at the top of `<script setup>` (correct lifecycle for `useI18n()`) and call `handle(err, 'bot.connect')` / `handle(err, 'bot.disconnect')` / `handle(err, 'bot.testMessage')` inside each catch — the composable resolves the status-keyed `errors.bot.{action}.{status}` entries that Task 4 delivers. Backend never returns 401 from these endpoints (CSRF / session auth lives in the global error handler), so `errors.bot.connect.401` does not exist.

A complete Vitest component spec at `frontend/tests/pages/projects/[projectId]/settings/bot.spec.ts` covers every branch listed in tech-spec Testing → Frontend component tests: initial GET + 404 fallback, paste-token-enables-button, loading state disables input + button, 200 swap-to-Connected, masked-token literal, every error status from the connect endpoint (400/409/422/429/500/502) routed through `errors.bot.connect.{status}`, the AC19 modal copy, Cancel vs Disconnect inside the modal, test-message 422 toast.

5. **Connect handler.** Read the token from the input ref, call `botStore.connect(projectId, token)`, clear the input on success (the store flips `current` to the new bot, which re-renders to the Connected view automatically). Cancel button closes the dialog and does NOT call the API. The modal's Disconnect button calls `botStore.disconnect(projectId)`; on success the store clears `current` and the page swaps back to the Connect form automatically. On error → `handle(err, 'bot.disconnect')` (only 404 is exposed via i18n — AC22).
7. **Test Message handler.** Click on "Send Test Message" calls `botStore.sendTestMessage(projectId)`. In Epic 06 the backend always returns 422 with `errors.bot.testMessage.422` per AC15; the page surfaces it via `handle(err, 'bot.testMessage')`. Forward-compat: 502 already has an i18n key (AC22) — the handler does not need branching, just resolve via status.
