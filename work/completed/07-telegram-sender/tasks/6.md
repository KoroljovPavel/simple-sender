## Required Skills

Перед виконанням задачі завантаж:

## Description

Create `docs/staging-smoke/07-telegram-sender.md` — the opt-in manual procedure for exercising the `TelegramSender` success branch on staging. Mirrors the structure and tone of the existing `docs/staging-smoke/06-bot-connection.md` runbook.

This runbook exists because the sender's happy path is unobservable in production until Epic 04b (webhook ingestion) lands — that's what will populate `Bot.ownerChatId` automatically. Until 04b, the only way to exercise the success branch end-to-end against real Telegram is: seed `Bot.ownerChatId` directly in Mongo via `mongosh`, then click "Send test message" in the UI. This is explicitly developer-/staging-only, never CI, never production.

The runbook documents:
- prerequisites (a throwaway test bot from `@BotFather`, a real Telegram account, `mongosh` access to staging Mongo, a connected bot in a staging project),
- the exact `mongosh` command shape for seeding `ownerChatId`,
- the UI click + expected 200 OK + expected Telegram message arrival ("Hello from Bot Funnel Service! Bot connected ✅"),
- the audit-event presence checks against the `events` collection (`telegram_message_sent` and `bot_test_message_sent`),
- the explicit dependency note: this runbook is the **only** way to exercise the happy path until Epic 04b ships.

Out of scope: regression smoke for the null-branch (`owner_chat_id_unknown` 422) — that is already covered by `06-bot-connection.md` Step 5 and by automated integration tests; do not duplicate.

## What to do

- Create new file `docs/staging-smoke/07-telegram-sender.md`.
- Mirror the header/intro shape of `06-bot-connection.md`: short title line, a paragraph describing what the runbook is, a paragraph flagging that this is opt-in / developer-only because real-Telegram cannot be exercised in CI.
- Write a "Prerequisites" section listing: a staging backend URL with at least one project + connected bot, a throwaway test bot from `@BotFather` (or reuse the one created during 06's smoke), a personal Telegram account to receive the message, `mongosh` access to the staging Mongo cluster, the staging admin/test owner credentials.
- Write a "Steps" section as a numbered `- [ ]` checklist, each step short and concrete:
  1. Identify the target bot doc — `mongosh` query against `db.bots` to locate the `_id` of the connected bot for your test project (filter by `projectId` and `status: "CONNECTED"`).
  2. Obtain your personal Telegram numeric chat id — via `@userinfobot` in Telegram (the runbook should name the bot exactly and explain the response shape).
  3. Seed `ownerChatId` — give the exact `mongosh` `updateOne` command shape with placeholders for `_id` and the numeric chat id. Note: numeric, NOT quoted as string.
  4. Verify the seed — `mongosh` `findOne` showing `ownerChatId` is now present as a `Long`.
  5. In the staging frontend, log in as the test owner, open `Settings → Bot`, click "Send test message".
  6. Expected UI response — success toast / no error banner, HTTP 200 OK (link to dev tools network tab guidance, mirroring 06's tone).
  7. Expected Telegram delivery — within ~5s the message "Hello from Bot Funnel Service! Bot connected ✅" arrives in your personal Telegram chat with the test bot.
  8. Verify audit events — `mongosh` query against `db.events` filtered by `eventType IN ["telegram_message_sent", "bot_test_message_sent"]` and `createdAt` near now; expect exactly two new event documents with the correct metadata shape (per tech-spec Data Models § Event types).
  9. Cleanup — optional `mongosh` `updateOne` to unset `ownerChatId` again so the staging bot returns to the null-branch state matching production.
- Write a "Sign-off" section identical in shape to 06's: each box must be checked before the feature is "07 OK" on staging; failures get filed as bugs citing the AC number from user-spec (AC17, AC21, AC23).
- Write a "Notes" section explicitly stating:
  - the runbook is manual-only because the agent cannot exercise real Telegram on a human BotFather account;
  - this procedure is the only way to exercise the success branch until Epic 04b webhook ingestion lands and populates `Bot.ownerChatId` automatically;
  - never paste the bot token or the production `BOT_TOKEN_ENCRYPTION_KEY` in chat / commits / screenshots;
  - the `mongosh` connection string for staging is read from the staging secret store, not pasted in the runbook.

- Cleanup (unsetting `ownerChatId`) is optional but recommended on shared staging so subsequent 07 smokes start from a clean null state, not from leftover seed data.
