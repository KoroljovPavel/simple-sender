# Task 1: Add `micrometer-core` dependency + explicit `@Bean SimpleMeterRegistry`

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

This feature introduces the first Micrometer dependency in the project. Without `spring-boot-starter-actuator` on the classpath, Spring Boot does NOT autoconfigure a `MeterRegistry` bean (the `MetricsAutoConfiguration` classes ship in `spring-boot-actuator-autoconfigure`). All five 04b counters (`telegram_webhook_received_total`, `telegram_webhook_duration_seconds`, `telegram_webhook_rejected_total` with reasons `invalid_secret|project_not_found|duplicate|payload_too_large`, `telegram_worker_outcome_total`) depend on a `MeterRegistry` being available for injection into `TelegramWebhookController`, `WebhookPayloadSizeFilter`, and `ProcessTelegramUpdateJob`.

Per Decision 10 the project explicitly registers a `SimpleMeterRegistry` bean (minimal-surface approach — does NOT pull in actuator endpoints). Per Risk R11 the bean must be marked `@ConditionalOnMissingBean` so that a future Spring Boot upgrade that does autoconfigure a registry (e.g. if actuator is later added) will not produce a duplicate-bean conflict.

This task is foundational for the Wave 3 controller (T10), the Wave 4 filter (T11), and the Wave 2 worker (T9). It is in Wave 1 with no dependencies.

## What to do

1. Add `implementation 'io.micrometer:micrometer-core'` to `backend/build.gradle` in the existing `dependencies { ... }` block. Version inherits from the Spring Boot BOM (do NOT pin a version explicitly).
2. Create `backend/src/main/java/com/botfunnel/common/metrics/MeterRegistryConfig.java` — a `@Configuration` class providing one `@Bean` method `meterRegistry()` annotated `@ConditionalOnMissingBean` that returns `new SimpleMeterRegistry()`.
3. Create `backend/src/test/java/com/botfunnel/common/metrics/MeterRegistryConfigTest.java` — Spring Boot test that boots the full application context and asserts:
   - `ApplicationContext.getBean(MeterRegistry.class) != null`.
   - The bean is an instance of `SimpleMeterRegistry`.
   - Probing a not-yet-created counter via `meterRegistry.find("any.metric").counter()` returns `null` (NOT NPE) — guards against the `Counter c = registry.find(...).counter(); c.count();` pattern AC16 tests will use.
4. Verify `./gradlew test --tests *MeterRegistryConfigTest` is green; full build remains compileable.

## Details

**Files:**

- `backend/build.gradle` — add one line inside the existing `dependencies { ... }` block: `implementation 'io.micrometer:micrometer-core'`. Group it next to other `io.micrometer` / observability-adjacent entries if any; otherwise place it alphabetically near other `implementation` lines.
- `backend/src/main/java/com/botfunnel/common/metrics/MeterRegistryConfig.java` — new file. Annotations: `@Configuration` on the class, `@Bean` + `@ConditionalOnMissingBean` on the `meterRegistry()` method. Method return type is `MeterRegistry`. Body returns `new SimpleMeterRegistry()`.
- `backend/src/test/java/com/botfunnel/common/metrics/MeterRegistryConfigTest.java` — new file. Use `@SpringBootTest` (full context) — bean wiring is the assertion target, slice tests will not include the config. `@Autowired ApplicationContext` + `@Autowired MeterRegistry` for assertions.

**Dependencies:**
- New: `io.micrometer:micrometer-core` (version from Spring Boot BOM).
- Task dependencies: none. This is a Wave 1 leaf task. Tasks 9, 10, 11 read `MeterRegistry` from the context — they will all break at runtime if this task is incomplete.

**Edge cases:**
- Future addition of `spring-boot-starter-actuator` would autoconfigure a registry — `@ConditionalOnMissingBean` ensures our bean steps aside without producing `BeanDefinitionOverrideException` or duplicate `Counter` instances.
- Do NOT add `spring-boot-starter-actuator` in this task even though it would also produce a `MeterRegistry`. Decision 10 rejects that option (broader autoconfig surface).
- Do NOT call `Metrics.globalRegistry` from any code in this feature — all consumers receive the bean via constructor injection.

**Implementation hints:**
- The Spring Boot BOM that this project inherits pins Micrometer. Verify no version conflict by running `./gradlew :backend:dependencies --configuration runtimeClasspath | grep micrometer-core` after the change; you should see exactly one version, not two.
- Method signature precedent: similar single-bean `@Configuration` classes in this project (e.g. `JobRunrMongoConfig`) declare the interface as the return type and instantiate the impl in the body. Follow that style.
