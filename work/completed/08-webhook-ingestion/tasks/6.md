# Task 6: `SubscriberService` stub interface + `NoOpSubscriberService`

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

The worker (T9) calls two methods on a `SubscriberService` collaborator at three branch points in its dispatch matrix:
- `/start` private + `bot.ownerChatId==null` → `upsertFromTelegramUpdate(...)` (user-spec AC7).
- `/stop` private → `markUnsubscribed(...)` (user-spec AC8).
- plain text private → `upsertFromTelegramUpdate(...)` (user-spec AC10).

Real subscriber persistence is owned by Epic 05 and is out of scope for 04b. To keep the worker compileable and testable without leaving the call site dangling, this task introduces the interface + a no-op `@Service` implementation that returns `Mono.empty()` from every method.

Per Decision 14 the interface + impl live in the FINAL package `com.botfunnel.subscriber`, NOT a `_stubs/` subpackage. Decision rationale: Epic 05 will replace the impl by adding a real `@Service` and removing `@Primary` (or by deleting the no-op class entirely) — no package renames, no consumer-side import changes. This matches the precedent set by Epic 04c.

The interface signatures are pinned by tech-spec Data Models. The implementation is a thin shim — the test is correspondingly minimal: both methods return a non-null `Mono<Void>` that completes empty.

## What to do

1. Create `backend/src/main/java/com/botfunnel/subscriber/SubscriberService.java` — `public interface SubscriberService` with exactly these two methods (signatures from tech-spec Data Models):
   - `Mono<Void> upsertFromTelegramUpdate(String projectId, Long telegramBotId, Long chatId, String chatType, Long telegramUserId, String firstName, String lastName, String username, String languageCode);`
   - `Mono<Void> markUnsubscribed(String projectId, Long telegramBotId, Long chatId);`
   Add a class-level javadoc noting that this is the contract consumed by the webhook worker (`ProcessTelegramUpdateJob`) and that the real implementation is deferred to Epic 05.
2. Create `backend/src/main/java/com/botfunnel/subscriber/NoOpSubscriberService.java` — `@Service` `public class NoOpSubscriberService implements SubscriberService`. Both methods return `Mono.empty()`. Add a class-level javadoc noting this is a placeholder until Epic 05 ships the real persistence; the class is NOT marked `@Primary` (Epic 05 will introduce its own `@Service` and rely on either bean-removal of this one or `@ConditionalOnMissingBean` to take over).
3. Create `backend/src/test/java/com/botfunnel/subscriber/NoOpSubscriberServiceTest.java`. Plain JUnit 5, no Spring context (the class under test has no injected collaborators). Cases:
   - `upsertFromTelegramUpdate(...)` with representative arg shape returns a non-null `Mono` that completes empty (StepVerifier `.expectComplete().verify()`).
   - `markUnsubscribed(...)` with representative arg shape returns a non-null `Mono` that completes empty.
   - Both methods accept `null` for the optional fields (`firstName`, `lastName`, `username`, `languageCode`) without throwing.
4. Verify `./gradlew test --tests *NoOpSubscriberServiceTest` green.

## Details

**Files:**

- `backend/src/main/java/com/botfunnel/subscriber/SubscriberService.java` — new. Public interface, two methods, javadoc.
- `backend/src/main/java/com/botfunnel/subscriber/NoOpSubscriberService.java` — new. `@Service` class implementing the interface.
- `backend/src/test/java/com/botfunnel/subscriber/NoOpSubscriberServiceTest.java` — new. JUnit 5 + Reactor `StepVerifier`.

**Dependencies:**
- No new packages.
- Task dependencies: none. Wave 1 leaf. T9 worker consumes this service via constructor injection.

**Edge cases:**
- Parameter names MUST match tech-spec Data Models — Spring's bean validation does not enforce parameter names but Java reflection and test fixture generators may. Match exactly: `projectId`, `telegramBotId`, `chatId`, `chatType`, `telegramUserId`, `firstName`, `lastName`, `username`, `languageCode` for `upsertFromTelegramUpdate`; `projectId`, `telegramBotId`, `chatId` for `markUnsubscribed`.
- Do NOT add `@Primary` to the no-op impl — Decision 14 explicitly leaves that decision to Epic 05.
- Do NOT add any logging in the no-op methods — the worker logs at its own layer; double-logging from a stub adds noise.
- Reactor: prefer `Mono.empty()` over `Mono.<Void>empty()` — Java type inference handles the generic.

**Implementation hints:**
- Interface and impl can be in the same commit; tests in a separate commit if desired (PR-level decision).
- A `@MockitoSpyBean SubscriberService` in `ProcessTelegramUpdateJobTest` (T9) will replace the no-op for invocation assertions; the no-op is only the runtime default.
- `StepVerifier.create(noOp.upsertFromTelegramUpdate(args...)).expectComplete().verify(Duration.ofMillis(100))` — keep the timeout tight; the call is in-memory.
