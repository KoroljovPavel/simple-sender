# Task 7: `FunnelTriggerService` stub interface + `NoOpFunnelTriggerService`

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

The worker (T9) calls two methods on a `FunnelTriggerService` collaborator at two branch points:
- `/start` private + `bot.ownerChatId==null` → `fire(projectId, chatId, "on_start", startPayload)` (user-spec AC7).
- `/stop` private → `cancelActiveFor(projectId, chatId)` (user-spec AC8).

Real funnel firing is owned by Epic 06 and is out of scope for 04b. This task introduces the interface + a no-op `@Service` implementation returning `Mono.empty()` so T9's call sites compile and behave correctly under integration test (no real funnel side effects, no per-test stub-only Spring config).

Per Decision 14 the interface + impl live in the FINAL package `com.botfunnel.funnel`, NOT a `_stubs/` subpackage. Epic 06 will replace the impl without forcing consumer-side import changes.

## What to do

1. Create `backend/src/main/java/com/botfunnel/funnel/FunnelTriggerService.java` — `public interface FunnelTriggerService` with exactly these two methods (signatures from tech-spec Data Models):
   - `Mono<Void> fire(String projectId, Long chatId, String triggerType, String payload);`
   - `Mono<Void> cancelActiveFor(String projectId, Long chatId);`
   Add a class-level javadoc noting the contract is consumed by the webhook worker and the real implementation is deferred to Epic 06.
2. Create `backend/src/main/java/com/botfunnel/funnel/NoOpFunnelTriggerService.java` — `@Service` implementing the interface, both methods return `Mono.empty()`. NOT `@Primary` — Epic 06 will switch impls cleanly.
3. Create `backend/src/test/java/com/botfunnel/funnel/NoOpFunnelTriggerServiceTest.java`. Plain JUnit 5 + Reactor `StepVerifier`, no Spring context. Cases:
   - `fire(...)` with representative arg shape returns a non-null `Mono` that completes empty.
   - `cancelActiveFor(...)` returns a non-null `Mono` that completes empty.
   - `fire(...)` accepts `null` for the `payload` arg without throwing (user-spec AC7 guarantees non-null `""` but the contract permits null for caller robustness).
   - `fire(...)` accepts `""` (empty string) for `payload` (real Epic 06 impl will treat this distinctly; the stub does not care).
4. Verify `./gradlew test --tests *NoOpFunnelTriggerServiceTest` green.
