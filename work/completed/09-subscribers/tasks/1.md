## Description

Lay down the persistence + crypto foundations every other Epic 05 task depends on. Concretely:

- Create five new Mongo entities (`Subscriber`, `Tag`, `SubscriberEvent`, `SubscriberExport`, plus the `CustomFieldDefinition` record embedded in `Project`) together with their Spring Data repositories, full index annotations, and the supporting enums (`SubscriberStatus`, `CustomFieldType`, `ExportStatus`).
- Apply the full index set per Data Models section of the tech-spec: unique compound `(projectId, telegramUserId)` on `subscribers`, text-index on identity fields, `(projectId, slug)` unique on `tags`, TTL 365d on `subscriber_events.createdAt`, partial-unique `(projectId)` with `partialFilter {status: {$in: ['PENDING', 'RUNNING']}}` on `subscriber_exports` (Decision 2). Auto-creation is already enabled (`spring.data.mongodb.auto-index-creation=true`).
- Extend `Project` with an embedded `customFieldDefinitions: List<CustomFieldDefinition>` field (no migration — Mongo schemaless). Add `CustomFieldDefinition` (record) and `CustomFieldType` (enum: STRING | NUMBER | BOOLEAN | DATE) under `com.botfunnel.project`.
- Implement `com.botfunnel.common.crypto.SignedDownloadToken` as an HMAC-SHA256 mint/verify primitive: constructor reads `app.subscriber.export.token-key` via `@Value`, fail-fast on missing/short/non-hex key (mirror `TokenEncryptor` shape, including the deliberate JDK message scrub for hex-parse failures); `mint(projectId, exportId, expiresAt)` produces a token whose payload binds projectId + exportId + expiresAt; `verify(token)` returns a typed result and rejects tampered/expired/cross-project tokens via constant-time compare (`MessageDigest.isEqual`).
- Wire `SUBSCRIBER_EXPORT_TOKEN_KEY` into `application.properties` as `app.subscriber.export.token-key` (env-var indirection, same shape as the existing `BOT_TOKEN_ENCRYPTION_KEY` → `app.bot.token-encryption-key`).
- Ship unit tests for `SignedDownloadToken`: mint round-trip, verify success, payload tamper rejection, signature tamper rejection, expired-token rejection, cross-project substitution rejection (payload `projectId` mismatch).

This task is consumed by every Wave 2+ task: T3 (`SubscriberServiceImpl`) needs `Subscriber` + `SubscriberEvent` + repos, T4 needs `Tag` + repo, T5 needs the embedded `CustomFieldDefinition` array, T9 needs `SubscriberExport` + repo + `SignedDownloadToken`.

NEVER commit a real value.` (mirror `BOT_TOKEN_ENCRYPTION_KEY` precedent).

**Dependencies:** none new. JDK `javax.crypto.Mac` (HmacSHA256) ships standard. `java.util.HexFormat` for the key parse. Jackson is already on the classpath for payload JSON. Spring Data Mongo annotations (`@Document`, `@CompoundIndex`, `@CompoundIndexes`, `@Indexed`, `@TextIndexed`, `@TextScore`) already in use.

**Edge cases:**
- Empty `customFieldDefinitions` list on existing `Project` documents — Mongo deserialisation should yield `null`; getter contract is "may return null" (consistent with how `Project.description` etc. are nullable today). Task 5 will normalise.
- `Subscriber.score` (`@TextScore Float`) is populated only on text-search queries; null on direct `findByProjectIdAndTelegramUserId` lookups — acceptable, mirrors Spring Data's text-search contract.
- `SignedDownloadToken` HMAC must be applied to the EXACT base64url-encoded payload bytes, not to the decoded JSON — otherwise a JSON-whitespace re-emission attack could forge tokens. Verify path must base64url-decode the payload to read fields, but HMAC-compare against the raw base64url segment.
- `ExportStatus` literals inside `partialFilter` must be UPPERCASE — Spring Data persists via `enum.name()` (mirror `RawUpdate.java:54-57`). The class-load static block is the safety net.
- `Subscriber.@Document(language="none")` — note this is on the document, not just the index. Decision 6 explicitly chose `language="none"` for UA+EN+emoji parity; do NOT change to `russian` or omit (would silently change query semantics).
- Partial-filter compound on `subscriber_exports` uses `'projectId': 1` only (no second sort key) — uniqueness is enforced across the filtered subset (any row whose status is PENDING or RUNNING), so a project can have at most one in-flight export. The `DuplicateKeyException` is mapped to 409 by Task 9; this task just installs the index.

**Implementation hints:**
- Match the exact field order in `Subscriber.java` to the tech-spec Data Models snippet — reviewers grep for it.
- For `SignedDownloadToken.verify`, use `Base64.getUrlDecoder()` and `Base64.getUrlEncoder().withoutPadding()` for the mint side — no `=` padding inside the URL.
- Payload JSON should be deterministic — use a small `record TokenPayload(String projectId, String exportId, long expiresAtEpochMilli)` with `ObjectMapper.writeValueAsBytes` and a stable Jackson configuration (default ordering is fine; do NOT pretty-print).
- Constant-time compare: `MessageDigest.isEqual(expectedHmac, actualHmac)`. Never use `Arrays.equals` for HMAC compare (timing leak).
- `Mac` instances are NOT thread-safe — instantiate one per `verify` call (cheap) or use a `ThreadLocal`. Given virtual-thread fan-out, per-call instantiation is the safer default.
