# Task 10: Subscribers list + profile pages

## Required Skills

Перед выполнением задачи загрузи:

## Description

Build the two end-user pages of the subscribers feature on top of the HTTP layer shipped by Task 8 (`SubscriberController` + `SegmentFilterBuilder`) and the export endpoints from Task 9. This task wires the actual UX: `/projects/{projectId}/subscribers` (list with filters + cursor-paginated "Load more") and `/projects/{projectId}/subscribers/{subscriberId}` (identity card + tabs Tags / CustomFields / History + action buttons).

The page shells, sub-nav, the full `subscribers.*` / `tags.*` / `customFields.*` / `exports.*` i18n key sets, and the 11 shadcn-vue UI primitives (`table`, `select`, `badge`, `input`, `sonner`, `combobox`, `tabs`, `card`, `sheet`, `tooltip`, `checkbox`) were already produced by Task 2 — replace the shell content in `subscribers/index.vue` + `subscribers/[subscriberId].vue` and add the new components / store described in Files. This task MUST NOT modify `frontend/i18n/locales/*` (Task 2 owns those — adding keys here re-opens the merge-conflict window the wave plan closed).

The store follows Decision 12 exactly: a Pinia setup-store mirroring `stores/projects.ts` shape with `items[] / nextCursor / loading / filter` state and `loadFirstPage(filter) / loadMore()` actions, NO localStorage persistence (the opaque-ID-only rule from patterns.md:165 forbids list caching). The list page does `loadFirstPage(default)` on mount, re-runs `loadFirstPage` on filter change, and calls `loadMore()` from a button that appears only while `nextCursor != null`. Row click navigates to the profile page. An "Export CSV" button opens `ExportCsvDialog` — the dialog itself is owned by Task 11 (`RecentExportsDialog`); this task ships only the trigger button + the simple "send-current-filter" dialog body (`POST /api/v1/projects/{projectId}/subscribers/export {filter}`, toast on 202 / 409 `export_in_flight` / 422 `export_filter_too_large`).

The profile page assembles a `SubscriberProfileCard` (firstName/lastName/username/languageCode/status badge using shadcn `badge` colored per status, lifecycle dates), action buttons (`Manual unsubscribe` → `POST /subscribers/{id}/unsubscribe`, `Send personal message` → opens `SendPersonalMessageDialog`), and three Tabs:
- **Tags tab** — combobox adds existing-or-new tag via `POST /subscribers/{id}/tags`, chips have `×` removing via `DELETE /subscribers/{id}/tags/{slug}`.
- **Custom fields tab** — for each project-level `CustomFieldDefinition` (fetched from `GET /api/v1/projects/{projectId}/custom-fields`) render inline editor per type (string → input, number → numeric input, boolean → checkbox, date → date input, enum → select); save via `PATCH /subscribers/{id}/custom-fields {values: {fieldName: value}}` with mass-assignment safety (only the edited field key is sent).
- **History tab** — read-only last 50 events from `GET /subscribers/{id}/events?limit=50`, sorted desc by `createdAt`, render eventType + relative timestamp.

`SendPersonalMessageDialog` is the security-sensitive piece: vee-validate + zod schema `z.object({ text: z.string().min(1).max(4096) })` wrapped in `computed()` per patterns.md:145 so live locale switch re-runs validation. Submit posts to `POST /subscribers/{id}/messages`; the response `{status, message}` maps to toast variants: `status=sent` → success toast; `blocked` / `deleted` → warning toast + auto-refresh profile (badge flips to BLOCKED/DELETED); 429 `personal_message_rate_limited` → error toast asking to retry; 503 `telegram_rate_limited` → error toast asking to retry later. Mass-assignment defense: send only `{text}` — never echo any owner-bound field.
