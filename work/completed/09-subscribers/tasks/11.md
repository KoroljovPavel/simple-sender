## Description

Closing-wave frontend task for the 09-subscribers epic. Builds the two remaining project-scoped management pages (`/tags`, `/custom-fields`), the Recent-exports dialog inside `/subscribers`, the single Playwright golden-path E2E spec that covers the whole epic end-to-end, the Vitest specs for the two NEW dialogs authored in this task (`AddTagDialog`, `AddCustomFieldDialog`), and the `docs/staging-smoke/09-subscribers.md` runbook that Task 17 executes against live staging. Vitest specs for `SendPersonalMessageDialog` and `SubscribersFilterBar` belong to Task 10 (where the components are authored) — they are explicitly OUT OF SCOPE for this task.

The `/tags` page is a thin CRUD UI on top of `TagController` (built in Task 8): list with usage counter, Create dialog (slug+label with vee-validate+zod validation), Rename dialog (label-only — slug immutable per Decision 11), Delete dialog (cascade confirmation showing affected-subscriber count from `GET /tags/{slug}` response). The `/custom-fields` page is the CRUD UI for `CustomFieldsController` (Task 9): list, Add dialog (name+label+type+defaultValue with per-type input renderer — string/number/boolean/date), Edit dialog (label + defaultValue only — name/type immutable, warning shown), Delete dialog with affected-subscriber count.

The Recent-exports dialog lives inside `/subscribers` (next to the Export button added in Task 10's `ExportCsvDialog.vue`). It lists the last N `SubscriberExport` rows for the project with status badge, filename, size, and a two-state button per Decision 15: `expiresAt > now` → "Download" (links to existing token URL); else → "Refresh URL" (POST `/api/v1/projects/{projectId}/subscribers/exports/{exportId}/refresh-url` → re-mints token via `SignedDownloadToken`). PENDING/RUNNING rows show a progress indicator instead of the button. The refresh-URL endpoint accepted-status matrix (DONE→200, PENDING/RUNNING→409 `export_in_flight`, PURGED→410 `export_purged`, FAILED→410 `export_failed`, Redis-down→503 `service_unavailable` per Decision 15 fail-CLOSED) must be surfaced via `useApiError()` toast messages.

The Playwright spec is one file (`frontend/e2e/subscribers.spec.ts`) that walks the 8-step golden path from tech-spec Testing Strategy → E2E tests section: login → empty `/subscribers` → fixture-seed two subscribers via fake webhook → search → click profile → add tag via combobox → check `/tags` counter → add custom field → set per-subscriber value → trigger export → poll Recent-exports until DONE → download CSV → parse + assert UTF-8 BOM + Cyrillic "Київ" → manual unsubscribe → status flip within 1s. Target runtime ~10 min.

Vitest specs cover vee-validate + zod schemas with the `computed-ref` reactive-schema pattern from `patterns.md:145` (single `computed()` wrapping `toTypedSchema(z.object({...}))`, passed AS-IS to `useForm`).

The `docs/staging-smoke/09-subscribers.md` runbook is authored here but executed by Task 17. It describes throwaway BotFather bot + ngrok setup, the full lifecycle scenario (start → tag → custom-field → personal message → stop → reactivate → export CSV → signed-URL refresh → cleanup), and a key-rotation runbook entry per Decision 15 ("If key rotation required, plan downtime window where pending email links break; communicate to affected owners; UI 'Refresh URL' will re-mint with new key.").

No `i18n/locales/*` changes — Task 2 has already seeded `subscribers.*`, `tags.*`, `customFields.*`, `exports.*`, validation keys, and error codes for both `uk` and `en`. If a key is missing during implementation, STOP and reopen Task 2 instead of editing locales here (the locale parity gate `pnpm prebuild` will catch any divergence).
