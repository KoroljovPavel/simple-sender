## Description

Full-feature test quality audit for Epic 09 (Subscribers). Read every test file created or modified across Tasks 1-11 (backend unit + integration, frontend Vitest, Playwright E2E) and produce a holistic audit report that answers a single question: **do the tests we shipped actually prove the feature works and stay green under realistic load and adversarial input?**

This is the third audit in the Audit Wave (parallel with Task 12 Code Audit + Task 13 Security Audit). The audit is read-only — it does not modify production or test code. It writes a single report under `work/09-subscribers/logs/audit/test-audit-report.md` that Wave 6 (Pre-deploy QA → Deploy) consumes as a gate signal: green findings allow Pre-deploy QA to start, P0 findings block until backfilled.

Focus areas — the feature's risk surface where weak tests would be most costly:
- **AC coverage matrix.** Every AC1-AC24 in user-spec must map to at least one passing automated test (unit, integration, or E2E). Missing or weakly-asserted ACs are P0 findings.
- **Assertion quality.** Tests must assert observable outcomes, not just "no exception thrown". An IT that only checks `200 OK` without asserting the persisted Mongo document, the Redis counter shape, the GridFS file presence, the event row, or the sender mock invocation is weak and gets flagged.
- **Test pyramid balance.** Unit-heavy on pure logic (state machine, validators, CSV writer, signed-token primitive, segment-filter builder); integration for cross-module flows (controller + service + Mongo + Redis + Mailpit); exactly one E2E golden path. Inverted pyramids (integration tests doing pure-logic work, E2Es replacing missing ITs) are flagged.
- **`@Tag("slow")` correctness.** Latency probes (`SubscriberControllerLatencyIT`, `SubscriberExportEstimateLatencyIT`), the heap probe (`SubscriberExportHeapIT`), and the unit-level estimate latency test (`SubscriberExportFilterEstimateTest`, per tech-spec line 379) must carry `@Tag("slow")` so the default `./gradlew test` stays fast and CI runs them only under `-PrunSlow=true`. Missing tag → default CI gets slow; unwarranted tag → real coverage hidden.
- **Concurrency test idiom.** Race tests (rate-limit, 20-cap CustomField, tag counter, export-in-flight, download rate-limit) must use `ConcurrencyTestUtils.parallelInvoke` per `patterns.md:181` (virtual threads + `CountDownLatch` barrier, not naive `Thread.start` loops). Naive concurrency does not actually race and gives false confidence.
- **IT environment fidelity.** All `*IT` tests must extend `AbstractIntegrationTest` (real Mongo + Redis + Mailpit per `patterns.md`). No `@MockBean` for Mongo/Redis/Mailpit beans inside IT classes — that would degrade an IT to a unit test and miss index/TTL/partial-unique behavior.
- **Security regression coverage.** Each security finding closed by Tasks 1-11 must have an explicit IT case proving the regression cannot return: mass-assignment drop (AC11, `TagControllerIT.create_hostileBodyWithOwnerId_ignoresMassAssignment` + `CustomFieldValueValidationIT.patch_unknownKeys_silentlyDropped_noError_noPersist`), NoSQL-injection cursor (`SubscriberControllerIT.cursor_invalidShape_returns400`), formula-injection cells (`SubscriberCsvWriterTest` formula-injection cases), signed-URL audit invariants (`SubscriberExportSignedUrlIT` Decision 16 invariants — `invalid_token`, `expired`, `project_unavailable`, `purged`, cross-project token substitution, rate-limited), rate-limit cross-project isolation (`SubscriberRateLimitIT.rateLimit_isolatedPerProject`).

The audit's deliverable is a markdown report categorizing findings as P0 (blocks deploy — missing AC coverage, weak assertions on critical paths, missing concurrency idiom on race-defended invariants), P1 (improve before next wave — missing `@Tag("slow")`, assertion strength below threshold), P2 (nice-to-have). Each finding cites the file + test method + the specific gap.

**Dependencies:** Tasks 1-11 must be merged (test files exist on the branch). Runs in parallel with Tasks 12 (Code Audit) + 13 (Security Audit) inside the Audit Wave (wave 5).

**Edge cases:**
- A test file exists but is `@Disabled` / `@Ignore`'d — count as missing for AC coverage purposes; flag as P0.
- A test asserts `assertDoesNotThrow(...)` only — count as weak assertion; flag as P0 if on a critical-path AC, P1 otherwise.
- A latency/heap probe lives outside the three expected files — flag and check whether it should carry `@Tag("slow")`.
- Frontend Vitest spec exists but only mounts the component without firing form events — count as weak; flag as P1.
- Playwright spec has `test.skip(...)` for any of the 8 documented steps — flag as P0 (golden path must be unbroken end-to-end).
- A test was added that does NOT correspond to any AC or tech-AC — note in Findings P2 (over-coverage is not a defect, but worth surfacing).

**Implementation hints (audit-time only, not code):**
- Use the test-master skill's `test-quality-review` reference as the checklist backbone.
- Generate the AC coverage matrix by searching test files for AC keyword stems first (`Reactivation`, `Rate-limit`, `Cross-project`, `mass-assignment`, `formula`, `partial-unique`, `requireOwned`), then map by reading the test body. Do NOT rely on test names alone — names lie, bodies don't.
- For `@Tag("slow")` audit: `grep -rln '@Tag("slow")' backend/src/test` gives the actual set; compare against the expected four (`SubscriberControllerLatencyIT`, `SubscriberExportEstimateLatencyIT`, `SubscriberExportHeapIT`, `SubscriberExportFilterEstimateTest`).
- For `parallelInvoke` audit: `grep -rln 'parallelInvoke' backend/src/test` gives actual usage; compare against the six expected race surfaces.
- For AbstractIntegrationTest audit: `grep -L 'extends AbstractIntegrationTest' backend/src/test/**/*IT.java` lists ITs that DON'T extend it (anomalies).
- For `@MockBean` audit inside ITs: `grep -rn '@MockBean.*\(MongoTemplate\|ReactiveMongoTemplate\|StringRedisTemplate\|RedisTemplate\|JavaMailSender\)' backend/src/test` should return zero hits inside `*IT.java`.
