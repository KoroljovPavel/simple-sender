## Description

Lay the Wave 1 frontend foundation for Epic 05 (Subscribers CRM) so Wave 4 page tasks (Task 10, Task 11) can compose UI without serializing on infrastructure work. Three concerns are bundled in this single task on purpose:

1. **shadcn-vue scaffolding** — generate all 11 components from Decision 14 (`table`, `select`, `badge`, `input`, `sonner`, `combobox`, `tabs`, `card`, `sheet`, `tooltip`, `checkbox`) into `frontend/components/ui/<name>/`. Currently only `dialog/` exists; without these, Task 10/11 reviewers would re-validate the same generated boilerplate across multiple PRs.
2. **i18n key seeding (single owner)** — write the COMPLETE `subscribers.*` / `tags.*` / `customFields.*` / `exports.*` namespaces into both `uk.json` and `en.json`. Decision 14 + Task 10/11 descriptions explicitly forbid those tasks from touching locale files — this task is the sole writer for Epic 05 keys, closing the Wave 4 merge-conflict risk flagged in the template review. The `prebuild` parity gate (`scripts/check-locales.mjs`) must pass on completion.
3. **Sidebar sub-nav + empty page shells** — add a "Subscribers" parent group to `layouts/default.vue` with three sub-nav children (Subscribers / Tags / Custom Fields), mirroring the existing `SettingsSubnav.vue` precedent from `patterns.md` line 183. Create four empty Vue page shells at the new route paths so navigation clicks resolve without 404 and the routes are wired before Wave 4 fills them.

The task is foundation-only: no business logic, no API calls, no Pinia stores, no forms. Page shells render a heading from the seeded i18n keys and nothing else. Subsequent tasks (Task 10, Task 11) layer real UI on top.

## What to do

   - `customFields.*` — list page (`title`, `empty.title`, `empty.body`, `columns.label`, `columns.name`, `columns.type`, `columns.defaultValue`, `actions.add`, `actions.edit`, `actions.delete`); type labels (`type.string`, `type.number`, `type.boolean`, `type.date`); dialogs (`addDialog.title`, `addDialog.nameLabel`, `addDialog.labelLabel`, `addDialog.typeLabel`, `addDialog.defaultValueLabel`, `addDialog.submit`, `editDialog.title`, `editDialog.labelLabel`, `editDialog.defaultValueLabel`, `editDialog.submit`, `deleteDialog.title`, `deleteDialog.confirmBody`, `deleteDialog.submit`); subnav label (`subnav.customFields`).

   Both `uk.json` (Ukrainian translations) and `en.json` (English translations) must carry the IDENTICAL key set. Place values inline; do not stub with empty strings. Run `pnpm prebuild` and confirm the parity gate exits 0.

3. **Add Subscribers sub-nav to `layouts/default.vue`.** Insert a new sidebar entry under "All projects" (after the existing `projects` link and before `Settings`) that renders ONLY when `projectsStore.currentProject` is truthy. The entry is the parent label "Subscribers" linking to `/projects/{currentProjectId}/subscribers`, followed by three indented children: "Subscribers" → `/subscribers`, "Tags" → `/tags`, "Custom Fields" → `/custom-fields` (all under the same `[projectId]` parent). Use `<NuxtLinkLocale>` wrappers (see existing pattern lines 43-58 of `default.vue`). Read `frontend/components/SettingsSubnav.vue` first — replicate its active-state computation pattern (locale-prefix strip using `NON_DEFAULT_LOCALES` from `frontend/shared/i18n-locales.ts`, exact-match for parent, prefix-match for children) but inline it in the sidebar (no separate component needed for v1 — the Settings split that warranted `SettingsSubnav.vue` doesn't apply to the sidebar). All labels via `t('layout.sidebar.subscribers')`, `t('subscribers.subnav.subscribers')`, `t('tags.subnav.tags')`, `t('customFields.subnav.customFields')`.

4. **Create four empty page shells.** Each file is a minimal `<script setup lang="ts">` + `<template>` Vue SFC. The script reads `t` from `useI18n()`. The template renders a single `<h1>` with the appropriate i18n key and nothing else — no data fetching, no components, no UI primitives. Path-to-key map:
   - `frontend/pages/projects/[projectId]/subscribers/index.vue` → `t('subscribers.title')`
   - `frontend/pages/projects/[projectId]/subscribers/[subscriberId].vue` → `t('subscribers.profile.identityCard.title')`
   - `frontend/pages/projects/[projectId]/tags/index.vue` → `t('tags.title')`
   - `frontend/pages/projects/[projectId]/custom-fields/index.vue` → `t('customFields.title')`

5. **Verify locally before declaring done.** Run `cd frontend && pnpm install && pnpm prebuild && pnpm dev`. Open `http://localhost:3000`, log in, select a project, click the new sub-nav entries — all 4 routes must render their headings without console errors and without missing-i18n-key warnings.

**Dependencies:**

- `reka-ui@^2.9.7`, `class-variance-authority`, `tailwind-merge`, `tailwindcss-animate`, `@vueuse/core`, `lucide-vue-next` — all already present per `package.json`. **Edge cases:**

- Locale parity gate is **case-sensitive on key paths**: `subscribers.empty.body` in `uk.json` must match `subscribers.empty.body` in `en.json` exactly. A typo in either file fails CI.
- `__proto__`, `constructor`, `prototype` are forbidden as keys (filtered by `collectKeySet`). Avoid using these as namespace names or sub-keys.
- shadcn-vue CLI may prompt for confirmation if a component already exists; it will NOT overwrite `dialog/` because that name isn't in the new list. If the CLI asks "overwrite?" for anything, decline.
- The `sonner` component pulls in `vue-sonner` (toast library). Decision 14 lists it as required; do not substitute.
- `pnpm dlx` uses the latest minor matching `shadcn-vue@^1`; should the CLI emit syntax incompatible with the project's TypeScript strict mode, pin to a known-good version with `pnpm dlx shadcn-vue@1.0.3 add ...`.
- Sub-nav active-state regex MUST source `NON_DEFAULT_LOCALES` from `frontend/shared/i18n-locales.ts` (not hardcoded `['en']`) — adding a third locale later only requires updating that single file (see `patterns.md` line 147).
- Empty page shells render under `layouts/default.vue` automatically (Nuxt convention) — do not add `<NuxtLayout>` wrappers; do not call `definePageMeta({ layout: 'default' })` either (default is implicit).
- The `[subscriberId].vue` shell does NOT validate the param. Task 10 owns the load-by-id flow (including 404 → redirect — see `patterns.md` line 169).
- The auth middleware (`frontend/middleware/auth.global.ts`) matches route base name against a public whitelist; the 4 new routes are NOT public, so unauthenticated users are redirected to login (no extra wiring needed).

**Implementation hints:**

- Run the shadcn-vue CLI from the `frontend/` directory (not from repo root). It locates `components.json` relative to CWD.
- After scaffolding, do a `git diff --stat frontend/components/ui/` to confirm only new files were added (no modifications to existing `dialog/`).
- When seeding i18n keys, write them in `uk.json` first (Ukrainian is the source of truth per CLAUDE.md user-facing-docs rule), then translate to `en.json`. Run `pnpm prebuild` after each file write to catch drift early.
- For the sub-nav active-state: a unit test for the sidebar doesn't yet exist; if you add inline logic, manual smoke (User verification above) is sufficient for this task. Wave 4 page tests will exercise navigation more thoroughly.
- Keep the page-shell SFCs to ~5 lines. Reviewers should not need to think about anything in this task — it is pure plumbing.
