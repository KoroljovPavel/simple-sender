# Task 9: Export pipeline — controller + job + cleanup + download + refresh-url + email

## Required Skills

Before starting, load:

## Description

Ship the full async subscriber-CSV export pipeline end-to-end per Decisions 7, 8, 9, 15, 16 of the tech-spec. This task delivers the entire export surface for the 09-subscribers feature: the HTTP controller (`SubscriberExportController` with POST / list / download / refresh-url endpoints), the streaming CSV writer (`SubscriberCsvWriter` with mandatory formula-injection neutralization), the JobRunr worker (`ExportSubscribersJob`) that runs the export, the daily cleanup job (`ExportCleanupJob`), the email-service extension with two new Ukrainian-language templates, and the seven new integration / unit test classes that cover happy path, FAILED branch, empty filter, concurrency race, signed-URL audit invariants, refresh-URL state matrix, GridFS purge, heap budget, and estimate latency.

The pipeline closes user-spec AC16, AC17, AC18, AC19, AC20, AC22 (GridFS-files-first cascade ordering already wired by Task 7 — this task only adds the entities the cascade sweeps) and security findings F1 (CSV injection), F2 (24h URL TTL), F3 (key rotation runbook), F4 (download-denied audit), F8 (errorMessage scrub+truncate), F10 (GridFS metadata rowCount/projectId integrity probe). It also delivers Decision 15's two-state refresh-URL endpoint with fail-CLOSED Redis semantics — the single fail-closed bucket in the feature, deliberately asymmetric with the fail-open download bucket because re-minting tokens during a Redis outage would defeat the 24h TTL hardening.

Foundation depends on Task 1 (`SubscriberExport` entity + repo, `ExportStatus` enum, `SignedDownloadToken @Component`, partial-unique compound index, `SUBSCRIBER_EXPORT_TOKEN_KEY` env wiring) and Task 3 (`SubscriberServiceImpl` is the sole `@Service` so cross-component beans resolve correctly inside `@SpringBootTest`).

## What to do

   - `POST /export {filter}` → compute estimated count (drop text-search criterion if present so the count-only path uses indexed-only filter per AC18 P95<200ms guarantee); >200000 → 422 `export_filter_too_large`; insert `SubscriberExport{status=PENDING, projectId, ownerId, filter=serializedSegmentFilter, createdAt=now}` (partial-unique compound index on `(projectId)` with `partialFilter={status:{$in:[PENDING,RUNNING]}}` → on `DuplicateKeyException` map to 409 `export_in_flight`); enqueue via `jobScheduler.<ExportSubscribersJob>enqueue(UUID.nameUUIDFromBytes(exportId.getBytes(UTF_8)), j -> j.handle(exportId))` (deterministic UUID mirrors `TelegramWebhookController.java:85-87` so JobRunr retries are idempotent); return 202 with `ExportResponse{exportId, status:"PENDING", ...}`.
   - `GET /exports` → list recent exports for the project (DONE rows in `createdAt desc` order, includes signed `downloadUrl` for rows where `expiresAt > now`, `null` otherwise — UI uses null to flip the button to "Refresh URL").
   - `GET /exports/{exportId}/download?token=<HMAC>` → no session auth; verify HMAC via `SignedDownloadToken` (constant-time compare; payload carries `projectId` so cross-project substitution rejects at verify-level before any DB hit); then Redis rate-limit bucket `bf:download:export:{projectId}` 30/min (INCR + EXPIRE on count==1; **fail-OPEN** on Redis transport exception → WARN with greppable constant `EXPORT_DOWNLOAD_RATE_REDIS_FAIL_OPEN`, mirrors Decision 9 / `BotService.incrementBruteForceCounter` shape); then `requireOwned` (soft-deleted project → 410 `export_project_unavailable`, foreign owner → 404); then lookup export → DONE → stream `GridFsResource` with `Content-Type: text/csv; charset=utf-8` + `Content-Disposition: attachment; filename="subscribers-export-{exportId}.csv"` + write event `subscribers_export_downloaded`; PURGED → 410 `export_purged`; FAILED → 410 `export_failed`; expired (`expiresAt < now`) → 410 `export_expired`. **Every non-200 outcome** writes audit event `subscribers_export_download_denied` to the platform `events` collection (NOT `subscriber_events`) with `metadata={reason, projectId, exportId?, tokenSegmentPrefix?}` BEFORE the HTTP response is returned — Decision 16 / F4. `reason` enum: `invalid_token` (401) / `expired` (410) / `rate_limited` (429) / `project_unavailable` (410) / `purged` (410) / `failed` (410) / `foreign_owner` (404). `tokenSegmentPrefix` = first 8 chars of the payload segment (NOT signature) for recon-attack cross-reference without leaking the full token.
   - `POST /exports/{exportId}/refresh-url` → Decision 15 state matrix: `requireOwned` first, then Redis bucket `bf:refresh:export:{projectId}` 5/hour with **fail-CLOSED on Redis transport exception** (re-minting tokens during an outage would defeat the 24h TTL hardening from F2) → 503 `service_unavailable` + WARN log with greppable constant `EXPORT_REFRESH_REDIS_FAIL_CLOSED`; lookup export → DONE → mint a fresh token (`SignedDownloadToken.mint(...)` with `now + URL_TTL_HOURS`), update `expiresAt`, return 200 `{downloadUrl, expiresAt}`; PENDING / RUNNING → 409 `export_in_flight`; PURGED → 410 `export_purged`; FAILED → 410 `export_failed`.

2. Implement `SubscriberCsvWriter` per Decision 7. Stream rows from `mongoTemplate.stream(query, Subscriber.class)` (returns `CloseableIterator<Subscriber>`) through a `PipedOutputStream` connected to a `PipedInputStream` passed to `gridFsOperations.store(in, fileName, "text/csv", new Document(Map.of("exportId", exportId, "projectId", projectId)))`. **`rowCount` is NOT in the initial GridFS metadata** — it is unknown at `store()` time because the writer counts rows as it emits them, and the `store()` call blocks on the pipe until the writer thread closes the stream. The writer returns the final `rowCount` after the stream closes (e.g. `WriterResult{rowCount, lastRowAt}` returned from the writer or captured via an `AtomicLong` shared with the job). The JobRunr job, AFTER the writer thread finishes successfully, BACK-FILLS the metadata: `mongoTemplate.update(Query.query(Criteria.where("_id").is(gridFsFileId)), new Update().set("metadata.rowCount", rowCount), "fs.files")` AND updates `SubscriberExport.rowCount` in the same transactional flow. Writer thread is the JobRunr worker (virtual thread — blocking on the pipe is cheap; no Reactor scheduler required). Emit UTF-8 BOM (`0xEF 0xBB 0xBF`) once at the head of the stream. Fixed column order: `id, telegram_user_id, telegram_chat_id, telegram_bot_id, first_name, last_name, username, language_code, status, tags, custom_fields, subscribed_at, unsubscribed_at, blocked_at, deleted_at, last_seen_at`. Tags joined with `;` between slugs. Custom fields serialized as a single JSON-string cell via the already-injected `ObjectMapper`. Dates as ISO-8601 UTC with trailing `Z`. Apply RFC 4180 escaping (`"` → `""`, wrap cell in quotes if it contains `,` `"` `\n` `\r`). **Formula-injection neutralization (mandatory — Decision 7 / F1):** BEFORE RFC 4180 escaping, any cell whose first character is one of `= + - @ \t \r` is prefixed with a single apostrophe (`'`). Applied to ALL string cells AND stringified numeric/date cells (since `Double.isFinite` accepts `=1+1` as a String upstream via custom-field NUMBER type). Apply to the `customFields` whole-string JSON cell after Jackson serialization — defuses spreadsheet formula execution in Excel / Sheets / LibreOffice / Numbers.

3. Implement `ExportSubscribersJob` as a `@Component` with `void handle(String exportId)`. Worker re-entry guard FIRST: if the export's current `status == DONE | FAILED | PURGED` return immediately (mirrors `ProcessTelegramUpdateJob` terminal-status short-circuit per `patterns.md:213`). Flip PENDING → RUNNING via `mongoTemplate.findAndModify` predicate-protected (`status=PENDING`) — `null` return = predicate-fail, already-claimed, return. Build `Query` from stored `SegmentFilter`. Stream via `mongoTemplate.stream(...)` through `SubscriberCsvWriter` → `gridFsOperations.store(in, fileName, "text/csv", new Document(Map.of("exportId", exportId, "projectId", projectId)))` (note: `rowCount` is NOT in initial metadata — see step 2). After the writer thread closes and the final `rowCount` is known: **back-fill GridFS metadata** via `mongoTemplate.update(Query.query(Criteria.where("_id").is(gridFsFileId)), new Update().set("metadata.rowCount", rowCount), "fs.files")` so the F10 integrity probe can join `subscriber_exports.rowCount == fs.files.metadata.rowCount`. On success: update DONE + `completedAt = now` + `expiresAt = completedAt + URL_TTL_HOURS` + `fileId` + `rowCount` (on the `SubscriberExport` doc) + `emailService.sendExportReadyEmail(ownerEmail, ownerName, signedUrl, expiresAt)` + `eventService.logEvent(ownerId, "subscribers_export_completed", ..., Map.of("projectId", projectId, "exportId", exportId, "rowCount", rowCount))`. On exception: `mongoTemplate.findAndModify` atomic update `status=FAILED + completedAt=now + errorMessage=TelegramApiClient.scrubTokens(ex.getMessage()).substring(0, Math.min(len, 1024))` (closes F8 — mirrors `ProcessTelegramUpdateJob` FAILED branch per `patterns.md:216`); IF a partial GridFS file was created (writer reached `store()` before the throw), delete it via `gridFsTemplate.delete(Query.query(Criteria.where("_id").is(gridFsFileId)))`; `emailService.sendExportFailedEmail(ownerEmail, ownerName)`, event `subscribers_export_failed`, then rethrow a NEW `RuntimeException(scrubbedMessage)` with stack-trace copied via `setStackTrace` and NO cause chain (bypasses JobRunr's raw-exception log path that would otherwise leak the unscrubbed message — `patterns.md:216` rule).

4. Implement `ExportCleanupJob` as a `@Component` with `@Recurring(id="cleanup-subscriber-exports", cron="0 3 * * *")` (mirrors `ProjectHardDeleteJob` cron slot). Algorithm: query `subscriber_exports` for `status=DONE AND createdAt < now - RETENTION_DAYS`; per export: delete GridFS file via `gridFsTemplate.delete(Query.query(Criteria.where("_id").is(fileId)))`, then atomic `findAndModify` set `status=PURGED`, then `eventService.logEvent(ownerId, "subscribers_export_purged", ...)`. Idempotent: subsequent run on already-PURGED → no-op (the find query filters by `status=DONE`). Per-export step may fail safely: next 24h run picks up the same row again because status is still DONE. Single structured INFO log at end of run reports total purged count + run duration (mirrors `ProjectHardDeleteJob:60,95-96`).

**Edge cases:**
- Zero subscribers in filter → DONE with valid header-only CSV + `rowCount=0` + email sent (operator gets to know their filter is empty).
- `PipedOutputStream` `write` failure during streaming → caught by job's outer `try/catch` → FAILED branch; the `PipedInputStream` reader (GridFsOperations.store) sees EOF and the file may be partial — make sure FAILED branch also deletes any partial GridFS file (`gridFsTemplate.delete` on the candidate `fileId` if `gridFsOperations.store` returned one).
- `OutOfMemoryError` thrown by Jackson on a single huge `customFields` map → caught by the outer FAILED branch; scrubbed-message + truncate guards prevent the OOM message from leaking heap-sized strings.
- Cross-project token substitution → `SignedDownloadToken.verify` returns payload with `projectId="A"`; controller compares against path `projectId` → 401 BEFORE any DB hit (defense-in-depth; the audit event still writes).
- Redis bucket key encoding — use `:` separator only; do NOT URL-encode `projectId` (Mongo ObjectId hex is `[0-9a-f]{24}`, no special chars).
- `expiresAt` IS computed at completion time, not creation time — initial-design 7d / Decision 15 24h: a long-running job mustn't pre-burn the TTL window.
- Refresh-URL rate-limit bucket TTL: `Duration.ofHours(1)` (not minutes), per Decision 15 "5/hour".
- `EmailService.sendExportReadyEmail` silent-failure contract — if the SMTP send fails, the export STILL transitions to DONE and the event STILL writes. UI's "Recent exports" + refresh-URL endpoint is the fallback recovery path (operator sees DONE in UI, clicks refresh, gets a fresh link).

**Implementation hints:**
- `SubscriberExportController` constructor accepts: `ProjectService projectService`, `SubscriberExportRepository exportRepository`, `MongoTemplate mongoTemplate`, `JobScheduler jobScheduler`, `SignedDownloadToken signedDownloadToken`, `StringRedisTemplate redisTemplate`, `EventService eventService`, `GridFsOperations gridFsOperations`, `@Value("${app.subscriber.export.download-rate-per-min}") int downloadRatePerMin`, `@Value("${app.subscriber.export.url-ttl-hours}") int urlTtlHours`, `@Value("${app.url}") String appUrl`. Build the enqueuer lambda in the constructor (mirror webhook controller pattern at lines 85-87).
- **Download endpoint order — MATCH description / tech-spec EXACTLY.** Order is `token verify → Redis bucket → requireOwned → load export → branch on status`. The order matters: token verify BEFORE any DB hit (defense-in-depth — prevents leaking project existence via timing diff), THEN rate-limit (cheap Redis check before Mongo), THEN `requireOwned` (Mongo hit), THEN load `SubscriberExport` + branch on status. Step-by-step contract for the controller:
  1. **Token verify FIRST** — `SignedDownloadToken.verify(token)` with constant-time HMAC compare; payload contains `projectId` (compared against path `projectId` — cross-project substitution caught here); expiry check (`payload.expiresAt < now` → expired). On verify failure: `eventService.logEvent(null, "subscribers_export_download_denied", ip, ua, Map.of("reason", "invalid_token" | "expired", "projectId", pathProjectId, "tokenSegmentPrefix", first8charsOfPayloadSegment))` THEN return 401 (`invalid_token`) or 410 (`expired`). NO DB hit yet.
  2. **Redis rate-limit bucket** — `bf:download:export:{projectId}` 30/min, INCR + EXPIRE-on-first; fail-OPEN on transport exception (WARN constant `EXPORT_DOWNLOAD_RATE_REDIS_FAIL_OPEN`). If rate-limited: audit `{reason:"rate_limited"}` + return 429. Still no Mongo hit beyond the audit write.
  3. **`requireOwned`** — `Project project = projectService.requireOwned(currentUserId(), projectId, false)`. Foreign owner → AppException `notFound` (404) — caught upstream and mapped to `{reason:"foreign_owner"}` audit + 404. Soft-deleted (`deletedAt != null`) → audit `{reason:"project_unavailable"}` + 410 (`export_project_unavailable`).
  4. **Load `SubscriberExport`** — by `exportId` from token payload. Branch on `status`: `DONE` → stream `GridFsResource` + emit `subscribers_export_downloaded` event on the 2xx path; `PURGED` → audit `{reason:"purged"}` + 410 (`export_purged`); `FAILED` → audit `{reason:"failed"}` + 410 (`export_failed`). Server-side double-check of `expiresAt < now` on DONE rows → audit `{reason:"expired"}` + 410 (defends against payload-expiry-stripping if token verify ever drifts).
- For the audit event in the download path: each non-200 branch is a separate `if/else if` early-return with the `audit + return responseEntity` pair encapsulated in a helper like `private ResponseEntity<?> deny(int status, String code, String reason, String projectId, String exportId, String tokenSegmentPrefix)` to keep the controller readable.
- `ExportSubscribersJob` is invoked via `jobScheduler.<ExportSubscribersJob>enqueue(...)` — keep the public entry method named `handle(String exportId)` to match the lambda. Annotate with `@Job(name="Export subscribers CSV")` for the JobRunr dashboard label.
- `MongoTemplate.stream` returns a `CloseableIterator<Subscriber>` — wrap in try-with-resources so the cursor closes even on writer-thread exception. Same for the `PipedOutputStream` / `PipedInputStream` pair.
- For the heap test: the documented flake mitigation is `System.gc() + Thread.sleep(200)` + min-of-3-runs reporting. Do NOT swap in `MemoryPoolMXBean.getPeakUsage()` — the tech-spec explicitly defers that to keep the test surface small for MVP.
- For the estimate-latency test: warm up the JVM with 5 throwaway estimator calls before timing the 50 measurement calls. Indexed-only filter means: pick a filter that hits `(projectId, status)` or `(projectId, lastSeenAt)` or `(projectId, tags)` indexes — no `$text` criterion, no full-collection scan.
- For Redis fail-CLOSED on refresh-URL: catch `org.springframework.data.redis.RedisConnectionFailureException` + `RedisSystemException` (broad enough to cover Lettuce transport errors) → log WARN with greppable constant → return 503. Test with Testcontainers `redis.stop()` mid-test.
