# Task 4: Валідація графа + DTO

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Друга фаза воронок переводить модель з плаского «список + числовий індекс» на граф (стабільні `id` + ребра). Task 1 уже додав граф-поля у `FunnelStep` (`id`, `next`, `List<Button> buttons`, `timeoutValue`/`timeoutUnit`/`timeoutTargetStepId`), immutable record `Button(type, label, targetStepId, url)` та `StepType.MENU`. Ця задача замикає **серверний шар валідації й DTO-маппінгу** поверх цієї моделі.

Мета — щоб активація воронки валідувала весь граф (а не лише per-step поля Фази 1), а PATCH/PUT round-trip-ив новий тип `MENU` з кнопками й цілями без втрати даних. Конкретно:

1. **`validateSteps`** у `FunnelService` розширюється арматурою для `MENU` та граф-цілей: кожен `MENU` має ≥1 callback-кнопку (Decision 10); усі цілі (`next`, `targetStepId` кожної кнопки, `timeoutTargetStepId`) вказують або на наявний крок-`id` у межах цієї воронки, або на «End» (`null`); URL-кнопки парсяться строго через `URI` зі схемою рівно `http`|`https` + непорожній host (Decision 10, SSRF/scheme-injection захист); лейбли (≤64 символи) і кількість кнопок (≤8) у лімітах. Будь-яка ціль на неіснуючий `id` → нове 422 з кодом `funnel_broken_edge`.
2. **DTO**: новий record `ButtonDto(type, label, targetStepId, url)` з `@JsonIgnoreProperties(ignoreUnknown=true)`; `FunnelStepDto` отримує `List<ButtonDto> buttons` + timeout-поля + поле `id` (round-trip стабільного id з/на клієнт).
3. **`toSteps`**: мінтить новий стабільний `id` крокам без нього і **зберігає** вхідний `id` (з перевіркою унікальності в межах воронки — дубль → 422); мапить `ButtonDto → Button`. **`toStepDto`**: зворотний round-trip (кнопки, цілі, timeout, id).

Результат: `POST /activate` валідує граф і повертає 422 `funnel_broken_edge` на бите ребро та 422 на `MENU` без callback; PATCH зберігає й повертає кроки `MENU` з кнопками/цілями без втрати; реордер кроків у редакторі безпечний (цілі — стабільні `id`, не індекси — Decision 2).

## What to do

0. **Звірити фактичну модель Task 1 ПЕРШ НІЖ кодити.** Поля/конструктори `Button`, `FunnelStep` граф-поля (`id`/`next`/`buttons`/`timeout*`) і `StepType.MENU` ще не існують на момент написання цієї задачі — їх додає Task 1 (gate `depends_on: [1]`). Перед стартом відкрити фактичні файли (`FunnelStep.java`, `Button.java`, `StepType.java`) і звірити **реальні** сигнатури (імена полів, порядок аргументів record-конструктора `Button`, геттери `FunnelStep`). Усі назви нижче — з опису специфікації, не з реалізації; джерело істини — код Task 1, а НЕ проза цього файлу.
1. **`ButtonDto` (новий record)** у `funnel/dto/`: поля `type` (callback|url), `label`, `targetStepId`, `url`; `@JsonIgnoreProperties(ignoreUnknown=true)` (mass-assignment defense, як інші DTO).
2. **`FunnelStepDto`**: додати `String id`, `List<ButtonDto> buttons`, `Integer timeoutValue`, `String timeoutUnit`, `String timeoutTargetStepId`. Зберегти `@JsonIgnoreProperties(ignoreUnknown=true)` та `@NotNull stepType`.
3. **`toSteps`** у `FunnelService`: для кожного DTO — перенести нові поля у `FunnelStep`; мапнути `buttons` (`ButtonDto → Button`); якщо `dto.id()` непорожній — зберегти його (і перевірити унікальність у межах масиву — дубль `id` → 422 `funnel_step_invalid` або новий код), інакше — змінтити новий стабільний id (ObjectId hex / UUID, узгоджено з тим, як це робить Task 1 backfill).
4. **`toStepDto`** у `FunnelService`: додати у конструктор `FunnelStepDto` зворотний маппінг `id`, `buttons` (`Button → ButtonDto`), timeout-поля.
5. **`validateSteps`** у `FunnelService`: додати гілку `case MENU` + загальну валідацію граф-цілей:
   - зібрати множину наявних крок-`id`;
   - `MENU` → ≥1 callback-кнопка, інакше 422 (код — наявний `funnel_step_invalid` або окремий; узгодь з тим, що очікує фронт/тест);
   - кожна кнопка: лейбл непорожній і ≤64; callback-кнопка → `targetStepId` або `null`(End), при непорожньому — мусить бути у множині id; url-кнопка → строгий `URI`-парс, схема ∈ {http, https}, host непорожній;
   - кількість кнопок ≤8;
   - `next` будь-якого кроку (якщо непорожній) і `timeoutTargetStepId` (якщо непорожній) — мусять бути у множині id;
   - будь-яка ціль на відсутній id → 422 **`funnel_broken_edge`**.
6. **Новий код помилки** `CODE_BROKEN_EDGE = "funnel_broken_edge"` у `FunnelService`.
7. **Тести** у `FunnelControllerIT` (за наявним стилем seed-funnel + activate + jsonPath `$.code`): activate з ціллю на видалений крок → 422 `funnel_broken_edge`; `MENU` без callback → 422; URL-scheme reject (`javascript:`/`data:`/`tg://`/leading-whitespace/empty-host) → 422; кнопок >8 → 422; happy-path round-trip PATCH→GET зберігає кнопки/цілі/id; реордер не ламає цілі (id стабільні).

## TDD Anchor

Тести пишемо ДО реалізації, проганяємо (падають), реалізуємо, проганяємо (зелені). Бекенд — JUnit5 + MockMvc, за зразком наявних activate-тестів у `FunnelControllerIT`.

- `funnel/FunnelControllerIT::activateBrokenEdgeReturns422` — activate воронки з callback-кнопкою на видалений крок-`id` → 422, `$.code == funnel_broken_edge`.
- `funnel/FunnelControllerIT::activateMenuWithoutCallbackReturns422` — `MENU` лише з URL-кнопкою (0 callback) → 422.
- `funnel/FunnelControllerIT::activateMenuUrlButtonRejectsNonHttpScheme` — URL-кнопка з `javascript:`/`data:`/`tg://`/leading-whitespace/empty-host → 422 (по одному негативному кейсу).
- `funnel/FunnelControllerIT::activateMenuRejectsTooManyButtons` — `MENU` з >8 кнопками → 422.
- `funnel/FunnelControllerIT::menuButtonsRoundTripThroughPatchAndGet` — PATCH воронки з `MENU`+2 callback-кнопки+ціль → GET повертає ті ж кнопки/цілі; кожен крок має server-`id`.
- `funnel/FunnelControllerIT::reorderPreservesButtonTargetsById` — після reorder (новий порядок масиву) цілі кнопок (стабільні `id`) лишаються валідними; activate зелений.
- `funnel/FunnelControllerIT::menuFanInAndLoopTargetsValidate` — кілька кнопок на один `id` (fan-in) + кнопка назад на `MENU` (петля) → activate проходить (валідні цілі).

## Acceptance Criteria

- [ ] `activate` з ціллю (`next`/кнопка/таймаут) на видалений/неіснуючий крок-`id` → 422 `funnel_broken_edge`.
- [ ] `MENU` без жодної callback-кнопки → 422 на активацію.
- [ ] URL-кнопка приймається лише при строгій схемі `http`|`https` + непорожній host; `javascript:`/`data:`/`tg://`/whitespace-обфусковані/empty-host → 422.
- [ ] Лейбл кнопки ≤64 символи; кількість кнопок ≤8 — поза лімітом → 422.
- [ ] `FunnelStepDto` + `ButtonDto` round-trip-лять `MENU` (кнопки, цілі, timeout-поля, стабільний `id`) через PATCH→GET без втрати.
- [ ] `toSteps` мінтить `id` крокам без нього і зберігає вхідний `id`; дубль `id` у межах воронки → 422.
- [ ] Реордер кроків (новий порядок масиву) не ламає цілі — вони по стабільному `id`, не по індексу (Decision 2).
- [ ] `@JsonIgnoreProperties(ignoreUnknown=true)` лишається на `FunnelStepDto` і додано на `ButtonDto` (mass-assignment defense).
- [ ] fan-in (кілька кнопок → один крок) і петля (кнопка → `MENU`) валідуються як коректний граф.
- [ ] Усі наявні тести Фази 1 у `FunnelControllerIT` лишаються зеленими (немає регресій).

## Details

**Files:**
- `funnel/dto/ButtonDto.java` (new) — record `ButtonDto(String type, String label, String targetStepId, String url)` + `@JsonIgnoreProperties(ignoreUnknown = true)`. Без bean-validation на полях (валідація умовна за типом кнопки → у `FunnelService`, 422 з бізнес-кодом — той самий патерн, що у `FunnelStepDto`).
- `funnel/dto/FunnelStepDto.java` — **record**: додати `String id`, `List<ButtonDto> buttons`, `Integer timeoutValue`, `String timeoutUnit`, `String timeoutTargetStepId`. Зберегти `@NotNull stepType` і `@JsonIgnoreProperties`. ⚠️ **`timeoutUnit` — формат рядка беруть з decisions.md (Task 3), НЕ з tech-spec Data Models.** Tech-spec Data Models показує `"minutes"|"hours"|"days"`, але наявний `delayUnit`-код використовує `"MIN"|"HOUR"|"DAY"`; Task 3 розв'язує цей конфлікт і фіксує обрану конвенцію у decisions.md (ймовірно `MIN|HOUR|DAY` для узгодженості з `delayUnit`). При додаванні валідації/маппінгу `timeoutUnit` звірятися з decisions.md і вирівнювати під обрану конвенцію — НЕ хардкодити tech-spec-літерали (`"minutes"` тощо) без підтвердження. ⚠️ Додавання полів у record змінює **канонічний конструктор** — кожен `new FunnelStepDto(...)` зламається на компіляції. Відомий call-site: `FunnelService.toStepDto` (`static`, ~рядок 381). Перед/після зміни — `grep -rn "new FunnelStepDto(" backend/src` і оновити ВСІ сайти (передати нові аргументи: `id`, `buttons`, timeout-поля). Та сама засторога діє для `ButtonDto` — після створення record-а грепни `new ButtonDto(` (хоча на момент створення сайтів ще нема — слідкуй за маппінгом у `toStepDto`).
- `funnel/FunnelService.java`:
  - `toSteps`: перенести нові поля, мапнути `buttons` (`ButtonDto → Button` через `Button`-конструктор Task 1), id-мінтинг + перевірка унікальності в межах масиву.
  - `toStepDto`: зворотний маппінг `id` + `buttons` (`Button → ButtonDto`) + timeout-поля у конструктор `FunnelStepDto`.
  - `validateSteps`: `case MENU` + граф-цілі (множина id, callback/url-перевірки, ліміти, `funnel_broken_edge`).
  - Додати `static final String CODE_BROKEN_EDGE = "funnel_broken_edge";` + хелпер `brokenEdge(msg)` за зразком `invalidStep`.
- `funnel/FunnelControllerIT.java` — нові тести (див. TDD Anchor) + хелпер-білдер для `MENU`-кроку з кнопками (за зразком наявних `sendMessage(...)`/`delayStep(...)`).

**Dependencies:**
- Залежить від **Task 1** (Wave 1): мусять існувати `FunnelStep.{id,next,buttons,timeout*}`, record `Button`, `StepType.MENU`. **Перед стартом звірити фактичні сигнатури `Button` і геттери/сеттери `FunnelStep`** — назви полів/конструктора беруться з реалізації Task 1, не з цього опису.
- Жодних нових пакетів. `URI` — `java.net.URI` (JDK). id-мінтинг — `org.bson.types.ObjectId().toHexString()` (наявна Mongo-залежність) або `UUID`, узгоджено з Task 1 backfill.

**Edge cases:**
- URL-схема: `URI.create`/`new URI` може кинути `URISyntaxException`/`IllegalArgumentException` — ловити й мапити у 422 (не 500). Перевіряти `scheme.equalsIgnoreCase("http"|"https")` (НЕ `startsWith` — Decision 10), host `!= null && !isBlank`. Leading-whitespace (`" http://..."`) і `data:`/`javascript:`/`tg://` → reject.
- `targetStepId == null` для callback-кнопки = «End» (валідно, НЕ broken_edge).
- `next == null` = дефолт (наступний у списку) — валідно.
- Дубль `id` у вхідному масиві (клієнт надіслав два кроки з однаковим id) → 422.
- `MENU` з 0 кнопок або 0 callback-кнопок → 422.
- Лейбл рівно 64 vs 65 символів — гранична перевірка (≤64).
- Порожній/`null` список `buttons` для не-`MENU` кроку — ок (ігнорується).
- **`timeoutUnit` формат:** якщо додаєш будь-яку валідацію припустимих значень `timeoutUnit` — бери дозволений набір з decisions.md (рішення Task 3), а не з tech-spec Data Models. Не хардкодь `"minutes"/"hours"/"days"`; узгодь з наявним `delayUnit`-конвеншеном (`MIN|HOUR|DAY`), якщо саме його зафіксував Task 3. Якщо Task 3 ще не записав рішення на момент старту — звірити перед коммітом і не вводити розбіжність із `delayUnit`.
- `validateSteps` викликається і з `update` (на PATCH), і з `activate` — broken_edge мусить спрацьовувати в обох (defense-in-depth, як у Фази 1). Зверни увагу: user-spec каже «чернетку зберегти можна, активувати — ні» — звір з наявною поведінкою `update`→`validateSteps` (Фаза 1 валідує per-step і на update). Якщо broken_edge має блокувати лише `activate` (а draft з битим ребром зберігатись), рознеси граф-валідацію в окрему гілку, що викликається лише з `activate`. **Рішення зафіксувати у decisions.md.**

**Implementation hints:**
- `toStepDto` зараз `static` і не має доступу до інстансних полів — id-мінтинг робиться у `toSteps` (інстансний), не у `toStepDto`. Звір модифікатори.
- Множину наявних id будуй ОДИН раз на виклик `validateSteps`, до циклу перевірки ребер.
- Не дублюй per-type Фази-1 валідацію — додавай `case MENU` у наявний `switch`, граф-цілі — окремим проходом після/у тому ж циклі.
- Тримай нові 422-коди як `static final` константи поряд з наявними `CODE_*`.
- **Record-конструктори (must do):** `FunnelStepDto` і `ButtonDto` — Java records. Розширення полів record-а змінює канонічний конструктор і ламає всі `new ...(...)`. Перед коммітом прогнати `grep -rn "new FunnelStepDto(" backend/src` (відомий: `FunnelService.toStepDto`, `static`, ~рядок 381) і `grep -rn "new ButtonDto(" backend/src`; оновити кожен сайт під новий перелік аргументів. `compileJava`/`compileTestJava` мусять бути зелені — компілятор виловить пропущені сайти.
