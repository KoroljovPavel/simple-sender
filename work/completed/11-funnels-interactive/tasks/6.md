# Task 6: Фронтенд — редактор MENU + кнопки + ціль

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Фронтенд-частина Фази 2: дати автору воронки можливість будувати **інтерактивний крок `MENU`** у наявному вертикальному списку-редакторі (без канвасу). `MENU` — це повідомлення + inline-клавіатура: до 8 кнопок (по 1 в ряд), кожна — або **callback** (лейбл + ціль: інший крок чи «End»), або **URL** (лейбл + `http(s)`-лінк). Ціль callback-кнопки обирається через наявний `SearchableSelect` зі списку інших кроків воронки + опція «End». Опційний таймаут не входить у happy-path цієї задачі форми, але форма має зберігати/round-trip-ити кнопки і `next`-граф-поля (backend Task 1 + Task 4 уже приймають їх).

Це фронтенд-дзеркало серверної валідації (Task 4 `validateSteps`, Decision 10): лейбл непорожній, `callback_data` ≤ 64 байти, кожен `MENU` має ≥1 callback-кнопку, URL — строго `http(s)`. Якщо сервер повертає `422 funnel_broken_edge` (ціль на видалений крок), редактор підсвічує це **інлайн** біля проблеми (а не глобальним тостом), за зразком наявного маппінгу `errors.funnels.<code>` у `[funnelId].vue`.

**Безпека (критично):** лейбли кнопок і ціль рендеряться **текстовою інтерполяцією** Vue (`{{ }}`), НІКОЛИ через `v-html` — це XSS-захист (лейбл вводить автор, але інтерполяція має бути дефолтом без винятків).

Результат: автор у редакторі тисне «+ Add step» → обирає `MENU` → заповнює текст + додає кнопки з цілями → зберігає (PATCH усього масиву кроків) → активує; битий edge підсвічений інлайн.

## What to do

1. **`types/funnel.ts`** — переконатися, що типи `MENU`/`Button`/граф-поля доступні (їх створює/розширює Task 1). Якщо Task 1 ще не змержений на момент старту — додати/синхронізувати: `'MENU'` у `StepType`, інтерфейс `Button` (`type: 'callback' | 'url'`, `label`, `targetStepId?`, `url?`), і граф-поля у `FunnelStep` (`id?`, `next?`, `buttons?`, `timeoutValue?`, `timeoutUnit?`, `timeoutTargetStepId?`). Узгодити з backend DTO (`FunnelStepDto`/`ButtonDto` з Task 4) byte-for-byte.

2. **`FunnelStepForm.vue`** — додати `'MENU'` у масив `STEP_TYPES`. Розширити `schemaFor(type)` гілкою для `MENU`: валідація масиву кнопок — кожна кнопка має непорожній лейбл; callback-кнопка має ціль (id кроку або «End», де «End» емітиться як `targetStepId: null`, НЕ `""`); url-кнопка має `http(s)` URL (той самий `IMAGE_URL_RE`-ідіом або строгий парс); ≥1 callback-кнопка на меню; `callback_data` довжина ≤ 64 (на практиці лейбл-незалежна — це серверна довжина `"{execId}:{idx}"`, але лейбл ≤ 64 символи). Додати sub-редактор кнопок у `<template>`: список рядків з add/remove, перемикач типу (callback|url), поле лейбла, і для callback — пікер цілі через `SearchableSelect` (опції = інші кроки воронки + «End»), для url — текстове поле URL. Розширити `onSubmit` так, щоб для `MENU` емітити крок з полем `buttons` (+ зберігати наявні `id`/`next` зі `props.initial`). ⚠️ Наявний `onSubmit`-switch не має `default`-гілки: якщо `MENU`-case не додати, `emit('step', …)` віддасть `undefined` для `MENU`. Гілка `case 'MENU'` обовʼязкова.

3. **`AddStepDialog.vue` + `EditStepDialog.vue`** — прокинути новий проп `siblingSteps` (контекст інших кроків воронки) зі сторінки `[funnelId].vue` крізь обидва діалоги вниз у `FunnelStepForm`, щоб callback-target `SearchableSelect` міг перелічити інші кроки. Наразі діалоги контекст кроків не передають — додати проп і прокидання (`:sibling-steps` на `FunnelStepForm`).

4. **`FunnelStepsList.vue`** — розширити `summary(step)` гілкою `case 'MENU'`: короткий опис меню (напр. кількість кнопок або фрагмент тексту) через новий i18n-ключ. ⚠️ Як тільки `MENU` входить у `StepType`, наявний switch у `summary()` стає **non-exhaustive** → TypeScript-помилка; гілка `MENU` обовʼязкова.

5. **`[funnelId].vue`** — переконатися, що `funnel_broken_edge` маппиться інлайн через наявний `resolveFunnelError` / `errors.funnels.<code>`-механізм (додати i18n-ключ `errors.funnels.funnel_broken_edge`). За потреби — інлайн-підсвітка біля конкретного кроку (а не лише банер активації).

6. **`i18n/locales/uk.json` + `en.json`** — додати ключі: `funnels.steps.type.MENU`, форма меню (заголовок секції кнопок, кнопки add/remove, лейбли типів callback/url, поле лейбла, поле URL, ціль, «End»-опція), валідаційні повідомлення (лейбл обовʼязковий, ≥1 callback, URL-схема, callback_data-ліміт), `funnels.steps.summary.menu`, `errors.funnels.funnel_broken_edge`. Обидві локалі мають однаковий набір ключів.

7. **`tests/pages/funnel-editor.spec.ts`** — vitest на: рендер `MENU`-форми, sub-редактор кнопок (add/remove рядок), пікер цілі (опції = кроки + «End»), валідація (порожній лейбл блокує, меню без callback-кнопки блокує, не-`http(s)` URL блокує), інлайн `funnel_broken_edge` після 422.

**Edge cases:**
- Реордер кроків (splice) НЕ має ламати цілі кнопок — цілі = стабільні `id`, не індекси (Decision 2). Форма зберігає `props.initial?.id`.
- Ціль callback-кнопки на видалений крок → сервер 422 `funnel_broken_edge`; клієнт показує інлайн.
- `SearchableSelect` показує label навіть для value без опції (видалений крок) — fallback вже є в компоненті (рядок ~34-38), використати для «битої» цілі.
- «End»-сентинел у **емітованому** `buttons`-масиві = `targetStepId: null` (бекенд: `ButtonDto.targetStepId == null` ⇒ End / завершити воронку). **КРИТИЧНО — НЕ `""`:** порожній рядок як `targetStepId` — це non-null значення, яке не відповідає жодному id кроку → `validateSteps` поверне `422 funnel_broken_edge`. Якщо `SearchableSelect` усередині форми використовує окремий sentinel (напр. `'__END__'` чи `''`) для «End»-опції, форма мусить замапити його в `targetStepId: null` перед емітом/PATCH. Звірити з фактичним `ButtonDto` Task 4; кодувати «End» строго як `null`.
- Меню без жодної callback-кнопки (лише URL) → блокувати submit клієнтом (≥1 callback, Decision 10).
- На EDIT наявного `MENU`-кроку форма має пре-заповнити кнопки з `props.initial.buttons`.

**Implementation hints:**
- НЕ використовувати `v-html` ніде для лейблів/URL/тексту кнопок — лише `{{ }}`. Це явна XSS-вимога (Decision: text interpolation).
- Список кроків-цілей для пікера = `props` зі сторінки/діалогу: інші кроки воронки (за `id` + людський лейбл = тип + summary) + опція «End». Форма зараз не знає про сусідні кроки — потрібно прокинути їх пропом через `AddStepDialog`/`EditStepDialog` → `FunnelStepForm` (новий проп, напр. `siblingSteps` / `stepOptions`), або обчислити на сторінці й передати. Це нова проп-стежка через діалоги — оновити `AddStepDialog.vue`/`EditStepDialog.vue` теж (вони наразі не передають контекст кроків).
- `IMAGE_URL_RE = /^https?:\/\//i` вже є у формі — переюзати для URL-кнопок (строгий парс схеми робить backend Task 4; клієнт — UX-mirror).
- `callback_data`-довжина клієнту невідома точно (`"{execId}:{idx}"` мінтиться сервером), тож на клієнті валідуй **лейбл ≤ 64 символи** як UX-проксі ліміту; реальний 64-байт ліміт — серверний.
- **`timeoutUnit` — формат (якщо додаєш timeout-UI):** НЕ надсилай літерали з тех-спеку (`"minutes"`/`"hours"`/`"days"`). Task 3 фіналізує конвенцію `timeoutUnit` у decisions.md, узгоджену з наявним фронтенд-`DelayUnit` (`'MIN'|'HOUR'|'DAY'`). Перевыкористовуй ту саму конвенцію `DelayUnit`; перед емітом звір значення з decisions.md (Task 3-рішення), щоб формат не розійшовся з рештою фронтенду й бекендом. (Цей happy-path форми не вимагає timeout-UI; нота — на випадок, якщо торкаєшся timeout-полів.)
- `SearchableSelect` приймає `options: {value,label,hint?}[]` — будуй опції цілей як `[{value:'__END__', label:t('...End')}, ...siblingSteps.map(s => ({value: s.id, label: ...}))]`. ⚠️ **«End» → `targetStepId: null`, НЕ `""`:** не використовуй порожній рядок `''` як value «End»-опції напряму в емітований `buttons`. Бекенд трактує `ButtonDto.targetStepId == null` як «End / завершити воронку». Порожній рядок `""` — це non-null `targetStepId`, який не є id наявного кроку → `validateSteps` поверне `422 funnel_broken_edge`. Тому, якщо `SearchableSelect` усередині тримає окремий sentinel для «End», форма ОБОВʼЯЗКОВО маппить його в `targetStepId: null` перед емітом/PATCH. Звірити з фактичним `ButtonDto` Task 4.
