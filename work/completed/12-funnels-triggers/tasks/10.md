# Task 10: API-key card in project settings

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Project settings now needs a surface for the on-demand public API key introduced in Task 8.
The backend (Task 8 — `ApiKeyController` under `/api/v1/projects/{projectId}/api-key`) exposes:
GET → current key mask (`prefix•••` or "none"); POST → generate/regenerate, returning the
**plaintext once** (hash-only at rest, so the plaintext is unrecoverable afterwards — Decision 8).

This task adds an **API-key card** to the project's *general* settings page
(`frontend/pages/projects/[projectId]/settings/index.vue`) that drives those two endpoints:

- **No key yet** → card shows a short explanation + a **"Generate"** button.
- **After Generate (or Regenerate)** → a **"save this key" modal** shows the plaintext **once**
  with a copy button and a warning that it cannot be shown again. Closing the modal returns to the
  masked state.
- **Key present** → card shows the masked `prefix•••` value + a **"Regenerate"** button (regenerate
  invalidates the old key and surfaces a new plaintext in the same show-once modal).

The card fits between the existing General section and the Danger zone, styled as a sibling
`<section class="rounded-md border p-4 space-y-3">` card, consistent with the page's existing
sections.

This task is **sequenced after Task 9** (wave 5) only because both tasks append to the shared i18n
locale files (`uk.json` / `en.json`) — single-owner-per-file avoids a merge collision. There is no
runtime dependency on Task 9.

## What to do

- Add an **API-key card** section to `frontend/pages/projects/[projectId]/settings/index.vue`
  (general settings page), rendered inside the existing `<template v-if="project">` block, placed
  between the General `<section>` and the Danger-zone `<section>`.
- On mount (or when the project resolves), fetch the current key mask via `useApi()` GET
  `/api/v1/projects/{projectId}/api-key` and store it in component state. Handle the "none" /
  no-key response by showing the **Generate** affordance; handle a present mask by showing the
  masked value + **Regenerate**.
- Wire a **Generate / Regenerate** action that POSTs to the same endpoint via `useApi()`, receives
  the plaintext once, and opens a **show-once modal** displaying it. Use a copy-to-clipboard button
  (same `navigator.clipboard.writeText` + transient "copied" feedback pattern as
  `FunnelTriggerSettings.vue`). Include explicit warning text that the key will not be shown again.
- After the modal is dismissed, refresh local state to the **masked** representation (use the prefix
  from the POST response, or re-fetch the mask) so a page reload shows masked + Regenerate.
- Disable the action button while a request is in flight; surface request failures via the existing
  `useApiError()` helper into an inline error line (mirror the `saveError` pattern on the page).
- Add `data-test` hooks so the card and its states are addressable by tests and the user-verify
  walkthrough (e.g. `api-key-card`, `api-key-generate`, `api-key-regenerate`, `api-key-mask`,
  `api-key-modal`, `api-key-plaintext`, `api-key-copy`).
- Add all new i18n keys under a new `projects.settings.apiKey.*` namespace in **both**
  `frontend/i18n/locales/uk.json` and `frontend/i18n/locales/en.json` (title, description,
  generate, regenerate, none/empty label, modal title, modal warning ("save this key — it won't be
  shown again"), copy, copied, close). Keep both locale files structurally identical.

## Details

**Files:**
- `frontend/pages/projects/[projectId]/settings/index.vue` — add the API-key card section + script
  state (mask ref, plaintext ref, modal open flag, in-flight flag, error ref) and the GET/POST
  handlers. The page already wires `useApi()`, `useApiError()`, `useI18n()`, `useRoute()`, and a
  `project` computed; reuse them. Card lives inside `<template v-if="project">`, between
  `data-test="settings-general"` and `data-test="settings-danger-zone"`. Modal can mirror the
  existing delete-confirmation modal markup (fixed overlay, `role="dialog"`, `aria-modal`).
- `frontend/i18n/locales/uk.json` + `frontend/i18n/locales/en.json` — append a
  `projects.settings.apiKey` object (the `projects.settings` block is at uk.json line ~200). Keep
  both files structurally identical; you are the single owner of these files in wave 6.

**Endpoints (from Task 8 — confirm exact response shape against the delivered `ApiKeyController`
before coding):**
- `GET /api/v1/projects/{projectId}/api-key` → masked state (`prefix•••` or a "none" indicator).
- `POST /api/v1/projects/{projectId}/api-key` → generate/regenerate, returns plaintext once
  (plus the prefix for masking). `useApi()` already attaches the session cookie + `X-XSRF-TOKEN`
  for non-safe methods, so POST works without extra header wiring.

**Dependencies:** Task 8 (endpoints) and Task 9 (co-owns locale files — serialized, no runtime dep).

**Edge cases:**
- Project still loading / not yet resolved — card should not POST against a missing projectId; gate
  on the `project` computed like the rest of the page.
- GET mask fails — degrade gracefully (do not block the rest of the settings page); show the
  Generate affordance or an inline error rather than a broken card.
- Regenerate while a key exists — the old key is invalidated server-side; the UI just shows the new
  plaintext once and updates the mask. No client-side confirmation step is required by the spec.
- Do not log or persist the plaintext anywhere (no console.log, no store) — it lives only in
  component state for the lifetime of the modal.

**Implementation hints:**
- Copy-to-clipboard: follow `FunnelTriggerSettings.vue` — `navigator.clipboard.writeText(...)`,
  a `copied` ref, and a transient timeout that clears it; the `bot.connected.copied` locale key is
  an existing precedent for a "Copied" string (add an apiKey-scoped equivalent for namespace
  cleanliness).
- Keep the show-once contract literal: clear the plaintext ref on modal close so it cannot be
  re-read from component state.
- Match the page's existing inline-error and disabled-button patterns (`saveError`, `isSubmitting`).
