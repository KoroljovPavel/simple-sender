# Task 3: ApiKey domain + generation/hash service

## Required Skills

Before starting, load:
- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Greenfield the `com.botfunnel.api` package and lay the first credential rail of the public API: a
per-project, **hash-only** API key plus the service that mints, stores, and looks it up. This is the
credential the public-API security chain (Task 7) authenticates against, and the entity the settings
generate/regenerate endpoint (Task 8) drives. It is foundation work — independent of the funnel
dispatcher waves, so it ships in Wave 1.

Three deliverables, all new:
- **`ApiKey`** — a `@Document("api_keys")` domain object. One **primary** key per project. Stores the
  SHA-256 **hash** of the plaintext (never the plaintext itself), a short `keyPrefix` for the UI mask
  (`prefix•••`), and `createdAt` / `lastUsedAt` timestamps.
- **`ApiKeyRepository`** — Spring Data Mongo repository with hash and project lookups.
- **`ApiKeyService`** — generates a ≥256-bit (32-byte) `SecureRandom` plaintext, stores
  `Sha256Hex.hex(plaintext)` + a derived `keyPrefix`, returns the plaintext **once** at generation,
  and exposes lookup-by-hash for the filter. Regenerate overwrites the project's existing key.

The security spine here (Decision 8): **hash-only at rest** — the full plaintext is never persisted
and is shown exactly once at (re)generation; the random source is `SecureRandom` with **≥256 bits** of
entropy (a 256-bit random secret is what makes unsalted SHA-256 safe — no brute-forceable low-entropy
preimage); lookup is by hash (no plaintext compare anywhere). Generation is **on-demand only** — this
task does **NOT** hook into `ProjectService.create`, ships **no backfill** runner, and deliberately
ignores the code-research §5/§7 generate-on-create / backfill suggestion.

## What to do

1. Create the `com.botfunnel.api` package (greenfield — does not exist yet).
2. **`ApiKey`** domain (`@Document("api_keys")`): `id`, `projectId` (unique index — one primary key per
   project), `keyHash` (unique index — SHA-256 hex), `keyPrefix` (short plaintext head for the UI mask,
   never the full key), `createdAt`, `lastUsedAt`. Standard getters/setters matching the project's POJO
   style (see `Project.java`). Declare the two unique indexes via annotations (auto-index-creation is on
   in dev — consistent with how `Bot`/`Project` declare indexes).
3. **`ApiKeyRepository extends MongoRepository<ApiKey, String>`**: `Optional<ApiKey> findByKeyHash(String keyHash)`
   (the filter's authentication lookup) and `Optional<ApiKey> findByProjectId(String projectId)` (the
   settings read / regenerate path).
4. **`ApiKeyService`** (`@Service`):
   - **generate / regenerate**: produce a **≥32-byte (256-bit)** `SecureRandom` value — the API key MUST
     be at least 32 bytes; do **NOT** copy `BotService`'s `WEBHOOK_SECRET_BYTES = 16` (that's only 128
     bits and is too short for an unsalted-SHA-256 secret). Mirror `BotService.connectAfterPreChecks`
     **only for the mechanics** (`SecureRandom.nextBytes(byte[])` → `HexFormat.of().formatHex(...)` →
     `Sha256Hex.hex(...)`), not for its byte-count constant. Hex-encode the ≥32 random bytes to the
     plaintext key, compute `Sha256Hex.hex(plaintext)`, derive a short `keyPrefix` from the plaintext
     head, upsert the
     project's `ApiKey` row (regenerate overwrites — the old hash is gone, invalidating the old key),
     stamp `createdAt`. Return a small result carrying the **plaintext once** (e.g. a record holding
     plaintext + prefix) — the caller surfaces it to the user a single time.
   - **lookup-by-hash**: hash the presented plaintext with `Sha256Hex.hex(...)` and `findByKeyHash(...)`;
     return the `ApiKey` (or empty). No plaintext comparison anywhere.
   - Optionally expose a `markUsed` / `lastUsedAt`-stamping helper for the Task-7 filter to call, OR
     leave the stamping to Task 7 — keep this task's surface minimal but make `lastUsedAt` settable.
5. Do **NOT** call this service from `ProjectService.create`. Do **NOT** add any `ApplicationRunner` /
   backfill. Generation is invoked only by the (later) settings endpoint.

## TDD Anchor

Tests written BEFORE implementation (run → fail → implement → pass):

- `api/ApiKeyServiceTest::generate_producesAtLeast256BitPlaintext` — generated plaintext decodes to
  **≥32 bytes (≥256 bits)** of entropy. This is a hard floor: the test must assert the decoded random
  source is ≥32 bytes, catching any accidental reuse of `BotService`'s 16-byte (`WEBHOOK_SECRET_BYTES`)
  constant.
- `api/ApiKeyServiceTest::generate_storesHashNotPlaintext` — persisted `keyHash` equals
  `Sha256Hex.hex(plaintext)` and the stored record contains the full plaintext **nowhere**
  (hash ≠ plaintext; no field holds the raw key).
- `api/ApiKeyServiceTest::generate_returnsPlaintextOnce` — generate returns the plaintext; a subsequent
  read of the stored record exposes only hash + prefix, never the plaintext.
- `api/ApiKeyServiceTest::lookupByHash_roundTrips` — `lookup(plaintext)` resolves to the project whose
  key was generated; a wrong plaintext resolves to empty.
- `api/ApiKeyServiceTest::keyPrefix_maskShape` — `keyPrefix` is a short head of the plaintext (mask
  `prefix•••`), not the full key.
- `api/ApiKeyServiceTest::regenerate_overwritesAndInvalidatesOld` — regenerating overwrites the
  project's key; the previous plaintext no longer resolves via lookup; still exactly one key per project.
- `api/ApiKeyServiceTest::lookup_nullOrBlankKey_returnsEmpty` — a null/blank presented key returns empty,
  never an NPE (do not pass null into `Sha256Hex.hex`).
- `api/ApiKeyRepositoryIT::keyHashUnique_enforced` — the `keyHash` unique index is enforced at the Mongo
  layer; `findByKeyHash` / `findByProjectId` resolve.

(IT uses real embedded Mongo per `patterns.md` → Testing Requirements; the service unit test may use a
mocked repository where it does not touch Mongo.)

## Details

**Files:**
- `backend/src/main/java/com/botfunnel/api/ApiKey.java` (new) — `@Document("api_keys")` POJO; fields
  `id`, `projectId` (unique), `keyHash` (unique), `keyPrefix`, `createdAt`, `lastUsedAt`. Declare unique
  indexes via `@Indexed(unique = true)` on `projectId` and `keyHash` (matches the dev auto-index-creation
  convention used by `Bot`/`Project`). Getters/setters in the project's plain-POJO style.
- `backend/src/main/java/com/botfunnel/api/ApiKeyRepository.java` (new) —
  `interface ApiKeyRepository extends MongoRepository<ApiKey, String>` with
  `Optional<ApiKey> findByKeyHash(String keyHash)` and `Optional<ApiKey> findByProjectId(String projectId)`.
- `backend/src/main/java/com/botfunnel/api/ApiKeyService.java` (new) — `@Service`; constructor-injects
  `ApiKeyRepository`; private `SecureRandom` field (mirror `TokenEncryptor` / `BotService`). Public:
  `generate(projectId)` → mints plaintext, stores hash + prefix (upsert/overwrite per project), returns
  a result carrying the plaintext once; `lookup(plaintext)` → `findByKeyHash(Sha256Hex.hex(plaintext))`.
  Keep `lastUsedAt` settable for Task 7's filter.

**Reuse (do not reinvent):**
- `Sha256Hex.hex(String)` for hashing — the single hashing source of truth. Note its contract: **null
  input throws NPE** — never hash a null presented key; guard at the boundary (lookup of a null/blank
  key returns empty, not an exception).
- `SecureRandom.nextBytes(byte[])` + `HexFormat.of().formatHex(...)` to mint the plaintext — reuse the
  **mechanics** of the webhook-secret idiom in `BotService.connectAfterPreChecks`, but **not its byte
  count**. `BotService` uses `WEBHOOK_SECRET_BYTES = 16` (128 bits) — for the API key the random source
  MUST be **≥32 bytes (256 bits)**. Define your own constant (e.g. `API_KEY_BYTES = 32`); do not import
  or copy `WEBHOOK_SECRET_BYTES`.

**Dependencies:** None new — Spring Data Mongo, `common.crypto.Sha256Hex`, `java.security.SecureRandom`,
`java.util.HexFormat` all already on the classpath. No dependency on other tasks (Wave 1, `depends_on: []`).

**Scope guardrails (Decision 8):**
- On-demand only — **no** call from `ProjectService.create`, **no** auto-gen on project create.
- **No** backfill runner / `ApplicationRunner` in this task (the only startup runner in this feature is
  the index-reconciliation one in Task 2). Ignore the code-research §5/§7 backfill suggestion.
- Hash-only at rest — the plaintext is never a stored field and is returned exactly once.
- No expiry/rotation logic here (accepted limitation, deferred to Epic 08); "regenerate = overwrite" is
  the only invalidation mechanism.

**Edge cases:**
- Regenerate when a key already exists → overwrite the same project row (still one key per project); the
  old hash must be gone so the old plaintext stops resolving.
- Lookup with a null / blank / unknown plaintext → empty result, no exception (do not pass null into
  `Sha256Hex.hex`).
- `keyHash` collision is astronomically improbable with 256-bit entropy, but the unique index makes a
  collision a hard failure rather than a silent overwrite — acceptable.

**Implementation hints:**
- Derive `keyPrefix` from the plaintext head (a short fixed-length slice) for the UI mask `prefix•••`;
  keep it short enough to be non-sensitive.
- Consider a small record for the generation result (plaintext + prefix) so the plaintext is a method
  return value that lives only in memory, never a stored field — reinforces "shown once".
- Match the existing index-declaration style (annotations + dev auto-index-creation), not a manual
  `MongoTemplate.ensureIndex`.
