# Task 9: Funnel-editor Phase-3 UI (trigger selector + EMIT_EVENT form)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Two coupled funnel-editor changes, kept in **one** task because they share `frontend/types/funnel.ts`
and the `funnels.*` i18n locale keys (so they cannot run in parallel without a file-merge collision):

1. **Trigger selector + per-type value editor.** Replace the static `on_start` badge in
   `FunnelTriggerSettings.vue` (currently a hard-coded `<span>` showing `/start`) with a trigger-**type**
   selector offering all five types — `on_start`, `keyword`, `tag_added`, `custom_field_set`,
   `api-event` (UI label for backend `triggerType=event`, Decision 4). Each selected type renders the
   value editor it needs:
   - `on_start` → the existing `triggerValue` text input + deep-link preview/copy (keep verbatim).
   - `keyword` → a multi-word keyword list editor (add/remove chips), feeds `Funnel.keywords`.
   - `tag_added` → a tag `SearchableSelect` (the project-tags picker, reused from the step form).
   - `custom_field_set` → a custom-field `SearchableSelect` (the project custom-fields picker).
   - `api-event` → an event-name slug input (`^[A-Za-z0-9_-]{1,64}$`).
   Built as a **portable form component** (Decision 11): the selector + per-type editor is a
   self-contained component so it migrates unchanged into a future canvas node; only the list-page
   wrapper is throwaway.

2. **`EMIT_EVENT` step.** Add `EMIT_EVENT` to `STEP_TYPES` in `FunnelStepForm.vue` with an event-name
   field block (same slug shape) + a `buildStep`/`onSubmit` branch that emits `{ stepType: 'EMIT_EVENT',
   eventName }`. It appears in the add/edit step dialogs ("Emit event") with its event-name field.

Plus the supporting type + i18n changes: extend `frontend/types/funnel.ts` (trigger-type model,
`StepType` union gains `EMIT_EVENT`, `FunnelStep.eventName`, funnel `keywords`) and add the new
`funnels.*` locale keys to **both** `uk.json` and `en.json` (the build-time parity gate fails CI if the
two key sets diverge).

WHY: authors need to configure the four new trigger paths and the in-funnel emit step in the existing
vertical-list editor now — the new triggers are useless without UI to set them.

## What to do

- **`frontend/types/funnel.ts`:**
  - Add `EMIT_EVENT` to the `StepType` union.
  - Add `eventName?: string | null` to `FunnelStep`.
  - Add a trigger-type model: a `FunnelTriggerType` union (`'on_start' | 'keyword' | 'tag_added' |
    'custom_field_set' | 'event'`) — backend value is `event`; the UI label is "api-event".
  - Add `keywords?: string[] | null` to the funnel request/response shapes (`UpdateFunnelRequest`,
    `FunnelResponse`, `FunnelSummaryResponse`) so the editor can round-trip the keyword list.

- **`FunnelTriggerSettings.vue`** (the portable component, Decision 11):
  - Replace the fixed `on_start` `<span>` with a `<select>` over the five trigger types.
  - Add a `triggerType` `defineModel`, a `keywords` `defineModel<string[]>`, and keep/extend the
    `triggerValue` model as the per-type match key for `tag_added`/`custom_field_set`/`api-event`
    (or introduce dedicated models if cleaner — see Details).
  - Render the matching value editor per selected type (see Description). Reuse `SearchableSelect.vue`
    for tag + field pickers (lazy-fetch `/tags` and `/custom-fields` the same way `FunnelStepForm`
    does). Build the keyword editor as an inline add/remove chip list. Keep the `on_start` deep-link
    preview/copy block, shown only when `triggerType === 'on_start'`.
  - Mirror the backend value validation client-side (event-name + tag/field slug shapes) the same way
    the existing component validates `triggerValue` — this is a UX mirror, not the contract.

- **`FunnelStepForm.vue`:**
  - Add `'EMIT_EVENT'` to the `STEP_TYPES` array.
  - Add a per-type template block (`v-else-if selectedType === 'EMIT_EVENT'`) with an event-name input
    + inline validation (slug regex) + error `<p>` (follow the existing field blocks' markup +
    `data-test` convention).
  - Extend the `schemaFor()` computed to validate `eventName` when the type is `EMIT_EVENT`.
  - Add the `EMIT_EVENT` case to the `onSubmit` switch building `{ stepType, eventName }`.
  - Seed `eventName` into `useForm` `initialValues` from `props.initial`.

- **`frontend/pages/projects/[projectId]/funnels/[funnelId].vue` editor page** (a **required** file to
  modify — without it the new trigger types never persist). Today it has only a `triggerValue` local
  `ref('')` (~line 24), seeds it on load (~line 73), and in `persist()` (~line 96) sends the trigger
  **hard-coded** as `triggerType: 'on_start'` (~line 104) — there is no `keywords` ref at all. Round-trip
  the full new trigger model:
  - Add local refs `triggerType` and `keywords: ref<string[]>([])` (alongside `triggerValue`); for
    `EMIT_EVENT` the step's `eventName` already round-trips through `FunnelStepForm`/step persistence, so
    no page-level `eventName` ref is needed here — only the funnel-level trigger fields.
  - **On load** (~line 73): seed `triggerType.value = res.triggerType ?? 'on_start'`,
    `triggerValue.value = res.triggerValue ?? ''`, and `keywords.value = res.keywords ?? []` from the
    `FunnelResponse`.
  - **Bind to `<FunnelTriggerSettings>`** (~line 269): add `v-model:trigger-type="triggerType"` and
    `v-model:keywords="keywords"` next to the existing `v-model:trigger-value`.
  - **In `persist()`** (~line 104): replace the hard-coded `triggerType: 'on_start'` with
    `triggerType: triggerType.value`, and add `keywords: keywords.value` to the PATCH body (send only
    the value the active type owns — see Edge cases). Keep the existing debounced auto-save `watch`
    wiring; ensure switching trigger type also triggers a persist (extend the watched sources or call
    `persist()` on type change).

- **i18n** — add the new keys under `funnels.trigger.*` (type labels for the five types, keyword
  editor strings, per-type value labels/placeholders/hints, event-name strings) and
  `funnels.steps.type.EMIT_EVENT` + `funnels.steps.form.*` event-name strings + any new
  `funnels.steps.validation.*` keys. Add to **both** `uk.json` and `en.json` with identical key sets.

**Files:**
- `frontend/types/funnel.ts` — currently the `StepType` union ends at `'MENU'`; `FunnelStep` has no
  `eventName`; the funnel shapes carry `triggerType: string | null` + `triggerValue: string | null`
  but no `keywords`. Add `EMIT_EVENT`, `eventName`, the `FunnelTriggerType` union, and
  `keywords?: string[] | null` on `UpdateFunnelRequest` / `FunnelResponse` / `FunnelSummaryResponse`.
- `frontend/components/funnels/FunnelTriggerSettings.vue` — today props are `{ botUsername, deepLink }`
  with a single `triggerValue` `defineModel`. The trigger type is hard-coded to `on_start` (a static
  `<span>` rendering `t('funnels.trigger.onStart')`, lines ~57-62). Convert to a `<select>` + per-type
  editor; add a `triggerType` `defineModel` and a `keywords` `defineModel<string[]>`. Keep the
  deep-link `computed`/`copy` logic but gate the deep-link block on `triggerType === 'on_start'`.
- `frontend/components/funnels/FunnelStepForm.vue` — `STEP_TYPES` array (line ~30) lacks `EMIT_EVENT`;
  add it. The per-type templates are a chain of `v-if/v-else-if` on `selectedType`; add an
  `EMIT_EVENT` block. `schemaFor()` (line ~264) and the `onSubmit` switch (line ~414) both branch on
  type; add `eventName` to each, and to `useForm` `initialValues` (line ~314). Note non-matching
  types default fields to `z.any()` — follow that idiom (only validate `eventName` when `EMIT_EVENT`).
- `frontend/i18n/locales/{uk,en}.json` — the `funnels.trigger.*` block is at ~line 797; step strings
  under `funnels.steps.type.*` (~707), `funnels.steps.form.*` (~732), `funnels.steps.validation.*`
  (~777). Add the new keys to BOTH files identically.
- `frontend/pages/projects/[projectId]/funnels/[funnelId].vue` — **required file to modify.** Currently
  `triggerValue` is the only trigger ref (`ref('')`, line ~24), seeded on load (line ~73) and sent in
  `persist()` with `triggerType: 'on_start'` hard-coded (line ~104). There is **no** `keywords` ref. Add
  `triggerType` + `keywords: ref<string[]>([])` local refs; seed all three on load from the
  `FunnelResponse` (`res.triggerType ?? 'on_start'`, `res.triggerValue ?? ''`, `res.keywords ?? []`);
  bind `v-model:trigger-type` + `v-model:keywords` on `<FunnelTriggerSettings>` (line ~269, next to the
  existing `v-model:trigger-value`); and in `persist()` replace the hard-coded `triggerType: 'on_start'`
  with `triggerType: triggerType.value` plus `keywords: keywords.value`. Keep the debounced auto-save
  `watch`; make trigger-type changes also persist.

**Dependencies:**
- Depends on **Task 1** (backend) for the canonical `triggerType` enum values + `StepType.EMIT_EVENT` +
  the `keywords`/`eventName` field names this UI mirrors. Sequenced in **Wave 5** after the backend.
- **Wave 6 / Task 10** (API-key settings card) is intentionally serialized *after* this task because
  both append to the i18n locale files — single-owner-per-file avoids a merge collision. Do not touch
  locale areas reserved for Task 10.

**Edge cases:**
- Switching trigger type must not leak a stale value from the previous type into the PATCH (e.g.
  keyword chips left over when switching back to `on_start`). Mirror the step form's "only the active
  type's fields are submitted" discipline — emit only the value model the selected type owns.
- An `on_start` deep-link must stay suppressed when the value fails the pattern (existing behavior) and
  must be hidden entirely for non-`on_start` types.
- `keyword` does NOT use `triggerValue` — it owns the `keywords` list; don't conflate them.
- The tag/field `SearchableSelect` is a strict pick over existing project entities (lazy-fetched);
  reuse the exact lazy-load + error-swallow idiom from `FunnelStepForm` (network failure → empty list,
  no block).
- Event-name slug client validation is a **UX mirror** of the backend `^[A-Za-z0-9_-]{1,64}$` — a bad
  value still surfaces as a server 422 on save; the client check only guides the author.
- i18n parity: every new key MUST exist in both locales or the `prebuild` gate (and CI) fails.

**Implementation hints:**
- `SearchableSelect.vue` takes `options/modelValue` + i18n strings as props and emits
  `update:modelValue`; the parent owns the fetch. Use `:show-value="true"` (default) for tag/field
  pickers so the slug/key is visible (consistent with the step form).
- Keep the trigger component presentational + self-contained (Decision 11): authored state in via
  `defineModel`, no store coupling beyond the lazy tag/field fetch — so a future canvas can mount it as
  a node form unchanged.
- Follow the existing `data-test="funnel-trigger-*"` naming so specs can target the new controls; add
  `data-test="funnel-trigger-type-select"`, `funnel-trigger-keyword-*`, `funnel-trigger-event-*`, and a
  `data-test` per value editor.
- For `EMIT_EVENT`, mirror the `ADD_TAG`/`SET_CUSTOM_FIELD` field-block markup + `step-*-error`
  convention; add `funnels.steps.type.EMIT_EVENT` (label "Emit event" / "Надіслати подію") and a
  `funnels.steps.form.eventName*` set.
