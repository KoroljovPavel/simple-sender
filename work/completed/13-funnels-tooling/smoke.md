# Smoke / ручна перевірка — 13-funnels-tooling (Фаза 4: інструменти автора)

Гайд для ручної перевірки фічі на локальному середовищі. Чотири інструменти автора:
**Test for me**, **Дублювати**, **Зупинити всі активні запуски**, **Прев'ю повідомлення**.

> Деплою немає (CI/CD не налаштований) — фіча на гілці `main`, перевіряється локально.
> Автотести вже зелені (backend funnel-suite + frontend 440 vitest + i18n parity). Цей документ — про **ручну** перевірку поведінки в реальному UI та через API.

---

## 0. Передумови

1. Підняти локальне середовище:
   - Backend: `cd backend && ./gradlew bootRun` (потрібні Mongo + Redis — напр. `docker compose -f infra/... up`).
   - Frontend: `cd frontend && pnpm dev` (Node 20+; якщо `node` не на PATH — через nvm).
2. Залогінитись у веб-кабінет, мати **проєкт** із **підключеним ботом** (`status=CONNECTED`).
3. Створити воронку з кількома кроками (хоча б один SEND_MESSAGE зі змінною, напр. `Привіт, {user.first_name}!`).
4. Для перевірки «Test for me» з реальною доставкою — **написати `/start` своєму боту в приватному чаті** (це проставляє `Bot.ownerChatId` і створює підписника-власника). Без цього кроку Test for me має показати підказку «напишіть /start» — це теж сценарій для перевірки.

Базовий шлях API: `/api/v1/projects/{projectId}/funnels`.

## A. Перевірка через UI (основний шлях, найпростіше)

### A1. Кнопки в списку воронок (`/projects/{pid}/funnels`)
- [ ] У кожному рядку списку є кнопки **Дублювати** та **Зупинити всі активні запуски**.
- [ ] Кнопки **Test for me** в рядку списку **немає** (вона лише в редакторі — контекст «відкрита воронка»).

### A2. Дублювати (зі списку та з хедера редактора)
- [ ] **З хедера редактора** → після дублювання відбувається **редирект на нову (дубльовану) воронку** (відкривається її редактор).
- [ ] **Зі списку** → нова воронка **одразу з'являється у списку** (список перечитується). Примітка: копія — `draft`, тож якщо активний фільтр статусу ≠ «draft»/«усі», вона буде відфільтрована (це коректно).
- [ ] Назва копії = `"<назва> (копія)"`.
- [ ] Копія має статус **draft** (чернетка).
- [ ] Тригер копії **скинутий** до дефолту (`on_start`, порожнє значення) — навіть якщо оригінал мав keyword/tag-тригер.
- [ ] Кроки скопійовані повністю (той самий граф); оригінал **не змінився**.
- [ ] Показано success-toast.

### A3. Зупинити всі активні запуски
> Підготовка: щоб побачити ненульовий результат, потрібні активні запуски воронки (напр. кілька підписників у середині воронки). Можна спершу зробити кілька Test for me / реальних enroll.
- [ ] Натиснути **Зупинити всі активні запуски** → відкривається **діалог підтвердження** (дія деструктивна).
- [ ] **Скасувати** в діалозі → нічого не відбувається.
- [ ] **Підтвердити** → toast із кількістю зупинених (`Зупинено запусків: N`); активні запуски переходять у `cancelled`.
- [ ] Якщо активних немає → toast із `0` (це не помилка).

### A4. Test for me (в хедері редактора)
- [ ] Кнопка **Test for me** є в хедері редактора (і на **draft**-воронці теж активна).
- [ ] **Бот зв'язаний** (зробив `/start`): натиснути → за кілька секунд повідомлення воронки приходить у твій Telegram. Повторний клік **перезапускає** тест з першого кроку.
- [ ] **Бот не зв'язаний** (ownerChatId порожній): натиснути → **inline-підказка біля кнопки** «напишіть /start вашому боту» (саме inline, **не** toast).
- [ ] Для лінійної воронки тунель не потрібен. Для воронки з MENU-кроком тест дійде до MENU й зупиниться (натискання кнопки приходить вхідним webhook — потрібен тунель).

### A5. Прев'ю повідомлення (перемикач у хедері редактора)
- [ ] У хедері є перемикач **Прев'ю**; увімкнення показує панель праворуч (desktop ≥1024px).
- [ ] Панель має **підпис «Крок N · <тип кроку>»** — видно, який саме крок рендериться.
- [ ] **Клік по рядку кроку** (по назві/опису, не по кнопках ↑↓/Редагувати/Видалити) → прев'ю перемикається на цей крок, рядок підсвічується.
- [ ] **Дефолт**: при увімкненні Прев'ю без вибору — показує **перший message-крок** (кнопки дій кроку при цьому працюють як раніше й не «крадуть» вибір).
- [ ] **Message-крок** (SEND_MESSAGE / SEND_IMAGE / MENU) зі змінною `{user.first_name}` → панель показує рендер, як виглядатиме в Telegram (підставлене ім'я; якщо бот не зв'язаний — семпл-значення `Іван` + індикатор «семпл-дані»).
- [ ] **SEND_IMAGE** → панель показує **саме зображення** (з `imageUrl`) над рендереним підписом; порожній/битий URL → плейсхолдер «Зображення недоступне» (без зламаної іконки). Для SEND_MESSAGE/MENU картинки немає.
- [ ] Прев'ю **реактивне**: міняєш текст кроку → прев'ю оновлюється (не чекає збереження).
- [ ] **Не-message крок** (Delay / Add-Tag / Remove-Tag / Set Custom Field / Emit Event) → підпис кроку + нейтральний плейсхолдер «Цей крок не надсилає повідомлення».
- [ ] Екранування: якщо у тексті є `<` `>` `&` під `parse_mode=HTML` — у прев'ю підставлене значення екранується, а твій авторський `<b>…</b>` лишається.
- [ ] (Безпека) У тексті повідомлення введи `<img src=x onerror=alert(1)>` → у прев'ю це має з'явитися як **звичайний текст**, без спрацювання (жодного `v-html`).
- [ ] Прев'ю **байт-в-байт як рантайм**: булеве кастом-поле (напр. `{custom.for_what}`) показує `true`/`false` — це і є фактичне значення, що пішло б у Telegram (якщо потрібен текст — змінюй тип/значення самого поля).

## B. Перевірка через API (curl, альтернатива/додатково)

Ендпоінти захищені сесією + CSRF. Потрібні: cookie сесії та XSRF-токен. Найпростіше — узяти їх із DevTools браузера після логіну (cookie `SESSION` і `XSRF-TOKEN`), або залогінитись через curl і зберегти cookie jar.

```bash
BASE=http://localhost:8080
PID=<projectId>; FID=<funnelId>; SID=<stepId>
# приклад заголовків: -H "Cookie: SESSION=...; XSRF-TOKEN=..." -H "X-XSRF-TOKEN: ..."
```

### B1. Дублювати
```bash
curl -i -X POST "$BASE/api/v1/projects/$PID/funnels/$FID/duplicate" $AUTH
# очікувано: HTTP 201; тіло FunnelResponse зі status=draft, triggerType=on_start, triggerValue="",
# name="<original> (копія)", той самий граф кроків. Оригінал не змінено.
```
- [ ] 201, копія draft, тригер скинутий, граф ідентичний.

### B2. Зупинити всі активні запуски
```bash
curl -i -X POST "$BASE/api/v1/projects/$PID/funnels/$FID/executions/stop" $AUTH
# очікувано: HTTP 200; тіло {"cancelled": N}; активні execution-и стали cancelled + stepRunStatus=done.
```
- [ ] 200 + лічильник; 0 активних → `{"cancelled":0}` (не помилка).

### B3. Test for me — незв'язаний бот (негативний кейс)
```bash
curl -i -X POST "$BASE/api/v1/projects/$PID/funnels/$FID/test-run" $AUTH
# якщо ownerChatId=null / підписник відсутній / не ACTIVE:
# очікувано: HTTP 422, тіло {"code":"funnel_owner_not_linked", ...}  — НІКОЛИ не 500.
```
- [ ] 422 `funnel_owner_not_linked` (не 500).
- [ ] Зв'язаний бот → 2xx (enroll зареєстровано; доставка асинхронна).

### B4. Прев'ю
```bash
curl -s -X POST "$BASE/api/v1/projects/$PID/funnels/$FID/steps/$SID/preview" \
  -H "Content-Type: application/json" $AUTH \
  -d '{"stepType":"SEND_MESSAGE","text":"Привіт, {user.first_name} <b>!","parseMode":"HTML"}'
# очікувано: 200, {"rendered":"Привіт, Іван <b>!","sampleData":true,"kind":"message"}
# (підставлене значення екрановане під HTML; авторський <b> untouched)
```
- [ ] 200, рендер зі змінними й коректним екрануванням; не-message крок → `kind=non_message`; невідомий stepId → 404.

### B5. Anti-IDOR (негативний кейс)
- [ ] Будь-який із 4 ендпоінтів на чужий/неіснуючий `funnelId` або `projectId` → уніфікований **404** (не 403/500, без витоку існування).
