# Task 1: Duplicate + Stop-all ендпоінти

## Required Skills

Перед виконанням задачі завантаж:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Перша бекенд-задача Фази 4 епіку воронок (інструменти автора). Додаємо два POST-ендпоінти на наявному `FunnelController` під базовим шляхом `/api/v1/projects/{projectId}/funnels`, обидва через `FunnelService.requireFunnel` (anti-IDOR, уніфікований 404):

1. **`POST /{funnelId}/duplicate`** — створює незалежну копію воронки: граф кроків копіюється verbatim через наявний `FunnelStep.copyOf`, статус форсимо `draft`, тригер скидаємо до дефолтів, назва — `"<назва> (копія)"` з обрізанням до 128 символів. Повертає 201 + `FunnelResponse`. Оригінал не змінюється.
2. **`POST /{funnelId}/executions/stop`** — bulk-cancel усіх активних запусків воронки. Виносимо вже наявну логіку bulk-cancel із `FunnelService.delete` в окремий метод `stopAllExecutions(ownerId, projectId, funnelId)`: `mongoTemplate.updateMulti` над `{projectId, funnelId, status IN [running, waiting, waiting_for_reply]}` встановлює `status=cancelled` + `stepRunStatus=done` + `updatedAt`. Повертає 200 + лічильник `modifiedCount`.

Обидва інструменти — переважно extraction + wiring наявних примітивів (`FunnelStep.copyOf`, bulk-cancel із `delete`). Greenfield-частина мінімальна: один DTO-рекорд відповіді у пакеті `funnel.dto` і два хендлери контролера. Це Wave 1 (незалежна бекенд-задача); Task 2 (test-run + preview) секвенована в наступну хвилю, бо ділить ті самі `FunnelController.java` + `FunnelService.java`.

Деталі — Decisions 6 (duplicate), 7 (stop-all через `updateMulti`, `stepRunStatus=done` обов'язковий), 8 (лічильник `modifiedCount` best-effort) у tech-spec.

## What to do

**Duplicate (`POST /{funnelId}/duplicate`):**
- Додати хендлер у `FunnelController` (дзеркало наявного `activate`/`create`: owner із сесії через `currentUserId()`, делегація в сервіс, 201 + `FunnelResponse`).
- Додати метод `FunnelService.duplicate(ownerId, projectId, funnelId)`:
  - `requireFunnel` для anti-IDOR + завантаження оригіналу.
  - Побудувати нову `Funnel`: `steps = original.getSteps().stream().map(FunnelStep::copyOf).toList()` (id та ребра `next`/`timeoutTargetStepId`/`Button.targetStepId` лишаються verbatim); скопіювати `keywords`, `allowReEnter`, `description`.
  - Форсити `status=draft`, `triggerType=on_start` (константа `TRIGGER_ON_START`), `triggerValue=""`.
  - `name = "<назва> (копія)"` з обрізанням до 128 символів (суфікс `" (копія)"` не повинен спричиняти 400 від `@Size(max=128)`).
  - Виставити свіжі `createdAt`/`updatedAt` через `Instant.now(clock)`.
  - Зберегти через `funnelRepository.save(...)` (НЕ `saveHandlingTriggerConflict` — draft не входить у partial-unique індекс, колізії неможливі).
  - Повернути `toResponse(...)`.

**Stop-all (`POST /{funnelId}/executions/stop`):**
- ⚠️ **НЕ копіювати тіло bulk-cancel із `delete()` verbatim.** Наявний `delete()` (FunnelService.java рядки 180-181) скоупить `updateMulti` ЛИШЕ по `funnelId` (`Criteria.where("funnelId").is(funnelId)`) — буквальний міррор створив би tenant-isolation-баг (скасування execution-ів іншого проєкта з тим самим funnelId). Зразок правильного скоупу — `FunnelExecutionFactory.cancelExistingForPair` (рядки 57-65): критерії `projectId` **І** `funnelId` (+ `status.in(...)`), set `status=cancelled` + `stepRunStatus=done`.
- **Рекомендований рефактор:** винести спільне тіло bulk-cancel у приватний хелпер `cancelInFlightExecutions(projectId, funnelId)`, який скоупить `Query` по **обох** `projectId` І `funnelId` і повертає `modifiedCount`. Викликати цей хелпер і з `delete()`, і з нового `stopAllExecutions(...)`. Тобто рефактор `delete()` ОДНОЧАСНО додає `projectId` у критерії (підсилення, не послаблення — `delete()` вже завантажив funnel через `requireFunnel`, проєкт відомий).
- Новий метод `stopAllExecutions(ownerId, projectId, funnelId)`, що повертає лічильник скасованих:
  - `requireFunnel` для anti-IDOR.
  - `mongoTemplate.updateMulti` (через спільний хелпер) над `Query` з критеріями `projectId == projectId AND funnelId == funnelId AND status IN [running, waiting, waiting_for_reply]`, set `status=cancelled` + `stepRunStatus=done` + `updatedAt=now`. **Скоуп по `projectId` обов'язковий** (fail-closed tenant hardening, як `cancelExistingForPair`).
  - Повернути `UpdateResult.getModifiedCount()` (long).
- Поведінка `delete` (потім `funnelRepository.delete`) має лишитися незмінною з точки зору видимого ефекту; наявні тести `delete` (`deleteReturns204AndCancelsActiveExecutions`, `deleteDraftWithoutExecutionsReturns204`) мають лишитися зеленими. НЕ дублювати update двічі — спільний хелпер.
- Додати хендлер у `FunnelController`: `POST /{funnelId}/executions/stop` → 200 + `StopAllResponse{ cancelled }`.

**DTO (новий рекорд у пакеті `com.botfunnel.funnel.dto`, поряд із наявним `FunnelResponse`):**
- `StopAllResponse(long cancelled)` — відповідь stop-all. (Duplicate перевикористовує наявний `FunnelResponse`.)

**Тести (`FunnelControllerIT`):**
- Дописати IT-сценарії для duplicate і stop-all (див. TDD Anchor нижче). Перевикористати наявні хелпери `seedFunnel`, `seedExecution`, `execStatus`, `seedConnectedBot`, `mongoTemplate`, `url()`.

## TDD Anchor

Тести писати ДО реалізації: пишемо → запускаємо → переконуємось що падають → пишемо код → переконуємось що проходять. Розташування — `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java` (IT через MockMvc + `@WithMockAppUser` + `.with(csrf())`); перевірки графа/назви/статусів — через reload `funnelRepository.findById` / `mongoTemplate`.

**Duplicate:**
- `FunnelControllerIT::duplicateReturns201DraftWithResetTrigger` — `POST /{fid}/duplicate` на активній воронці з тригером `(on_start, "promo")` → 201; тіло `status=draft`, `triggerType=on_start`, `triggerValue=""`; назва = `"<original> (копія)"`.
- `FunnelControllerIT::duplicateCopiesGraphVerbatim` — копія має ту саму кількість кроків, ті самі `id`/`next`/`timeoutTargetStepId`/`Button.targetStepId`, скопійовані `keywords`/`allowReEnter`/`description`; оригінал (reload із БД) не змінено.
- `FunnelControllerIT::duplicateNameAt128NotTruncated` — оригінальна назва така, що `"<назва> (копія)"` == рівно 128 символів → копія зберігається з повною назвою (без обрізання), 201.
- `FunnelControllerIT::duplicateNameAt129TruncatedStill201` — `"<назва> (копія)"` == 129 символів → обрізається до 128, 201 (не 400); назва копії має довжину 128.
- `FunnelControllerIT::duplicateOfDraftOrEmptyFunnelResetsTrigger` — дублювання порожньої/draft воронки → копія `draft` із скинутим тригером (тригер скидається незалежно від статусу/наповнення оригіналу).
- `FunnelControllerIT::duplicateForeignFunnelReturns404` — duplicate чужого/неіснуючого funnel під своїм project-шляхом → уніфікований 404 (anti-IDOR через `requireFunnel`).

**Stop-all:**
- `FunnelControllerIT::stopAllCancelsActiveAndSetsStepRunDone` — засіяти running/waiting/waiting_for_reply + completed/failed/cancelled; `POST /{fid}/executions/stop` → 200, тіло `cancelled` == 3; усі три активні стали `status=cancelled` **І** `stepRunStatus=done`; термінальні не зачеплені. **`stepRunStatus=done` асертити ЯВНО** через прямий reload поля з БД — `mongoTemplate.findById(execId, FunnelExecution.class).getStepRunStatus()` має повернути `done` (хелпер `execStatus()` повертає лише `ExecutionStatus`, тож сам по собі НЕ доводить claim-CAS-контракт Decision 7; перевірка `stepRunStatus` обов'язкова окремо).
- `FunnelControllerIT::stopAllWithNoActiveReturnsZero` — 0 активних запусків → 200, `cancelled` == 0 (не помилка).
- `FunnelControllerIT::stopAllScopedByProjectAndFunnel` — засіяти активний execution в ІНШІЙ воронці (інший funnelId) та/або іншому projectId → після stop-all поточної воронки той execution НЕ скасований (доводить скоуп `projectId`+`funnelId`, tenant-isolation).
- `FunnelControllerIT::stopAllForeignFunnelReturns404` — stop-all чужого/неіснуючого funnel → 404 (anti-IDOR).

**Регресія (мають лишитися зеленими після рефактору `delete`):**
- наявні `deleteReturns204AndCancelsActiveExecutions`, `deleteDraftWithoutExecutionsReturns204`.

## Acceptance Criteria

**Duplicate:**
- [ ] `POST /{funnelId}/duplicate` повертає 201 + `FunnelResponse`.
- [ ] Копія народжується `status=draft`, `triggerType=on_start`, `triggerValue=""` (тригер скинутий незалежно від статусу/наповнення оригіналу).
- [ ] Граф кроків копіюється verbatim: `id` та ребра `next`/`timeoutTargetStepId`/`Button.targetStepId` збережені; копіюються `keywords`, `allowReEnter`, `description`.
- [ ] Назва копії = `"<назва> (копія)"`, обрізана до 128 символів; суфікс не спричиняє 400 (boundary 128 — без обрізання, 129 — обрізається, обидва 201).
- [ ] Оригінал не змінюється.

**Stop-all:**
- [ ] `POST /{funnelId}/executions/stop` повертає 200 + `StopAllResponse{ cancelled }` (= `modifiedCount`).
- [ ] Переводить лише `running|waiting|waiting_for_reply` → `cancelled` **і** виставляє `stepRunStatus=done` (Decision 7, claim-CAS); термінальні статуси (`completed`/`failed`/`cancelled`) не чіпає. `stepRunStatus=done` доведено явним reload поля з БД (не лише `ExecutionStatus`).
- [ ] Запит скоупиться по `projectId` **І** `funnelId`; активні запуски інших воронок/проєктів не зачіпаються. (Скоуп — за зразком `cancelExistingForPair`, який вже містить `projectId`; НЕ verbatim-копія `delete()`, що скоупить лише по `funnelId`.)
- [ ] 0 активних → 200 + `cancelled=0` (не помилка).
- [ ] Логіка bulk-cancel винесена у спільний приватний хелпер, що скоупить по `projectId`+`funnelId`, і перевикористовується і `delete`, і `stopAllExecutions` (без дублювання update). Рефактор `delete` додає `projectId` у критерії; видимий ефект `delete` незмінний, наявні тести `delete` зелені.

**Спільне:**
- [ ] Обидва ендпоінти проходять `requireFunnel` → уніфікований 404 для чужого/неіснуючого funnel/project (anti-IDOR), ніколи не 500.
- [ ] Без змін схеми БД / без міграцій.
- [ ] Усі тести (наявні + нові) зелені; немає регресій у funnel/engine-тестах.

Перевикористати наявні `requireFunnel`, `toResponse`, `blankToNull`, `clock`, `TRIGGER_ON_START`, enum `.name()`-літерали (`ExecutionStatus.*`, `StepRunStatus.done`).
- `backend/src/main/java/com/botfunnel/funnel/dto/StopAllResponse.java` — новий рекорд `record StopAllResponse(long cancelled) {}`.
- `backend/src/test/java/com/botfunnel/funnel/FunnelControllerIT.java` — нові @Test-методи (TDD Anchor). Перевикористати `seedFunnel`, `seedExecution`, `execStatus`, `seedConnectedBot`, `mongoTemplate`, `url()`.

**Dependencies:** немає зовнішніх задач (Wave 1, `depends_on: []`). Нових пакетів немає — усе на наявному стеку (Spring MVC + Spring Data Mongo). Task 2 секвенована ПІСЛЯ цієї (ділить контролер/сервіс) — не торкатись test-run/preview тут.

**Edge cases:**
- Назва-boundary: `"<назва> (копія)"` == 128 → без обрізання; == 129 → обрізати до 128. Обережно з підрахунком довжини суфікса `" (копія)"` — це кирилиця; рахуй `String.length()` по UTF-16, як `@Size`.
- Дублювання порожньої воронки (`steps=[]` або null) — `copyOf`-map над порожнім/null списком має дати порожній список кроків, не NPE.
- Дублювання draft/active/paused — статус копії завжди `draft`, тригер завжди скинутий.
- Stop-all із 0 активних → `modifiedCount=0`, 200 (не 404 / не помилка).
- Stop-all не повинен зачіпати термінальні статуси (`completed`/`failed`/`cancelled`) і запуски інших funnel/project.
- `requireFunnel` кидає 404 ДО будь-якої bulk-операції — anti-IDOR має передувати побічним ефектам.

**Implementation hints:**
- **`stepRunStatus=done` обов'язковий** у stop-all разом зі `status=cancelled` (Decision 7 / claim-CAS): cancel, що флипнув лише `status`, програє mid-tick `persistProgress` рушія (CAS на `stepRunStatus=in_progress`). Тест має асертити це поле ЯВНО — `mongoTemplate.findById(id, FunnelExecution.class).getStepRunStatus() == done` (хелпер `execStatus()` повертає лише `ExecutionStatus` і НЕ покриває цей контракт).
- **Скоуп — за зразком `cancelExistingForPair`, НЕ `delete()`.** `FunnelExecutionFactory.cancelExistingForPair` (рядки 57-65) скоупить по `projectId` + `funnelId` + `status.in(...)` і set `status` + `stepRunStatus` + `updatedAt` — це правильний шаблон. Наявний `delete()` (рядок 181) скоупить ЛИШЕ по `funnelId` — буквальне копіювання його тіла дало б tenant-isolation-баг. У спільному хелпері `cancelInFlightExecutions(projectId, funnelId)` критерії мають містити `projectId` І `funnelId`; рефактор `delete()` ОДНОЧАСНО додає `projectId` (підсилення).
- `updateMulti` повертає `com.mongodb.client.result.UpdateResult` — лічильник через `.getModifiedCount()`.
- Draft НЕ входить у partial-unique trigger-індекс (`Funnel.java` partialFilter `{status:'active', triggerType:'on_start'}`), тож для duplicate колізії неможливі — звичайний `funnelRepository.save`, без `saveHandlingTriggerConflict`.
- `FunnelStep.copyOf` зберігає `id` та всі ребра; step-id не мають unique-індексу (можна reuse across funnels) — remint НЕ потрібен (Decision 6 / code-research TOOL 2).
- Не псевдокод: ДЕ і ЯКІ виклики — дивись наявні `create`/`activate`/`delete` як зразок shape.
