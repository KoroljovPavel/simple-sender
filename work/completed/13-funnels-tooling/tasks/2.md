# Task 2: Test-run + Preview endpoints (author-context)

## Description

Друга бекенд-задача фази 4 («інструменти автора»). Додає **два POST-ендпоінти на наявному `FunnelController`**, обидва проходять `FunnelService.requireFunnel` (anti-IDOR, уніфікований 404), обидва резолвлять підписника **власника** через `Bot.ownerChatId` — це спільний архітектурний шов (Decision 11):

1. **`POST /{funnelId}/test-run`** — «Test for me»: enroll-ить підписника-власника напряму в воронку, обходячи матчинг тригерів, через наявний примітив `FunnelExecutionFactory.insertExecution(depth=0)` з рестартом пари. Дозволяє автору швидко прогнати воронку на власному Telegram (для лінійних воронок без локального тунелю).
2. **`POST /{funnelId}/steps/{stepId}/preview`** — рендер повідомлення кроку через `VariableTemplateRenderer.render` з **on-the-fly контентом із тіла запиту** (поточний, можливо незбережений текст + parseMode), щоб панель прев'ю на фронті була реактивною до того, що автор друкує зараз. Екранування рахується на бекенді байт-в-байт як рантайм (захист від markup/XSS-дрейфу, OWASP A03).

Задача секвенована в Wave 2 після Task 1, бо обидві задачі редагують `FunnelController.java` + `FunnelService.java` — секвенування усуває merge-конфлікт паралельних агентів при per-wave-комітах (Decision 11). Реалізація — переважно wiring наявних примітивів (`insertExecution`/`cancelExistingForPair`/`render`/`findByChat`/`getOwnerChatId`); нова поверхня — резолв власника, новий бізнес-код `funnel_owner_not_linked`, нові DTO прев'ю.

Деталі рішень — tech-spec Decisions 2, 3, 4, 5, 9.

## What to do

### `POST /{funnelId}/test-run`

1. Додати контролер-метод (дзеркалить `activate`/`pause`: owner з сесії через `currentUserId()`, делегація в сервіс). Повертає 2xx (200 OK достатньо) при успішному enroll.
2. Сервіс-метод `testRun(ownerId, projectId, funnelId)`:
   - `requireFunnel(ownerId, projectId, funnelId)` (anti-IDOR FIRST).
   - Резолв `Bot` проекту через `botRepository.findByProjectIdAndStatus(projectId, BotStatus.CONNECTED)`. Взяти `bot.getOwnerChatId()`.
   - Якщо бот відсутній / `ownerChatId == null` → **422 `funnel_owner_not_linked`** з ремедіейшеном «напишіть `/start` боту».
   - `subscriberService.findByChat(projectId, bot.getTelegramBotId(), ownerChatId)`. Якщо порожньо АБО підписник не `SubscriberStatus.ACTIVE` → той самий **422 `funnel_owner_not_linked`** (усі три гілки — один клас «акаунт не зв'язаний», одна дія для автора — Decision 5).
   - **Pre-validate воронки** через `validateSteps(funnel.getSteps())`: порожня воронка (`steps == null || empty`) → той самий 422-патерн, що й при `activate` (`funnel_no_steps`); невалідні кроки → ті ж 422-коди валідації (Decision 4). Для цього **підняти видимість `validateSteps` з `private` на package-private** (БЕЗ зміни логіки/кодів — Decision 4, ризик у tech-spec).
   - `funnelExecutionFactory.cancelExistingForPair(projectId, funnelId, subscriberId)` (рестарт пари — Decision 3), ПОТІМ `funnelExecutionFactory.insertExecution(projectId, funnel, subscriberId, bot.getTelegramBotId(), 0)`.
   - 2xx означає лише, що execution створено; реальна відправка йде асинхронно рушієм (збій Telegram-send → execution `failed` згодом, HTTP лишається 2xx).
   - **Draft-воронку (валідну, непорожню) теж можна протестувати** — `insertExecution` не перевіряє `funnel.getStatus()`, status-гейт не блокує тест.
   - Інжектувати `FunnelExecutionFactory` + `SubscriberService` у `FunnelService` (factory package-private, той самий пакет — доступний; SubscriberService — публічний інтерфейс).

### `POST /{funnelId}/steps/{stepId}/preview`

1. Новий DTO `PreviewStepRequest` (record, узгодити пакет із наявними DTO — `funnel.dto`): рівно `{ stepType, text, parseMode }` — поточний (можливо незбережений) контент кроку з тіла запиту (on-the-fly — Decision 9).
2. Новий DTO `PreviewStepResponse` (record): **рівно** `{ rendered: String, sampleData: boolean, kind: String }` де `kind ∈ {"message","non_message"}`. Без ownerChatId/identity-полів.
3. Контролер-метод (owner з сесії, делегація в сервіс), приймає `@PathVariable stepId` + `@RequestBody PreviewStepRequest`. Повертає 200 + `PreviewStepResponse`.
4. Сервіс-метод `previewStep(ownerId, projectId, funnelId, stepId, request)`:
   - `requireFunnel(...)` (anti-IDOR FIRST — Decision 9: `requireFunnel`-404 ПЕРЕВАЖАЄ над stepId-404).
   - Знайти крок за `stepId` у `funnel.getSteps()`. Невідомий `stepId` → **404** (узгоджено з `requireFunnel`-патерном — `AppException.notFound`).
   - Резолв `Subscriber` власника через `ownerChatId` (як у test-run: `Bot` CONNECTED → `findByChat`). Якщо резолвиться ACTIVE-підписник → використати його; інакше **стаб-`Subscriber`** із семпл-значеннями (`first_name=Іван`, `last_name=Петренко`, `username=ivan`, порожні custom) + `sampleData=true`. Стаб обов'язковий, бо `render` вимагає non-null `Subscriber` (`requireNonNull`) → інакше NPE/500.
   - Для message-типів (`SEND_MESSAGE`, `SEND_IMAGE`, `MENU`) рендерити **контент із request** (`request.text()` + `request.parseMode()`, НЕ збережений крок) через `VariableTemplateRenderer.render(text, parseMode, subscriber)` → `rendered`, `kind="message"`.
   - Для не-message кроків (`DELAY`, `ADD_TAG`, `REMOVE_TAG`, `SET_CUSTOM_FIELD`, `EMIT_EVENT`) → плейсхолдер-відповідь: `rendered=""` (нейтрально), `kind="non_message"`.
   - **Ніколи не 500** на передбачуваних станах.

- `FunnelTestRunSendIT::testRunLinkedBotSends` (новий IT, MockWebServer) — зв'язаний ACTIVE-бот → новий execution depth=0; після `engine.sweep()` MockWebServer отримав `sendMessage` (delta `getRequestCount()` як у `FunnelExecutionEngineIT`).

**Preview (service + IT):**
- `FunnelControllerIT::previewParseModeNullNoEscape` — `parseMode=null`, значення зі спецсимволами `& < >` → **точний рядок** без екранування.
- `FunnelControllerIT::previewHtmlEscapes` — `parseMode=HTML`, підставлене значення `& < > "` → точний рядок із `&amp; &lt; &gt; &quot;`.
- `FunnelControllerIT::previewMarkdownV2EscapesFullSet` — `parseMode=MarkdownV2`, значення з повним спецнабором `_*[]()~`>#+-=|{}.!` + backslash → точний екранований рядок (кожен спецсимвол + backslash з префіксним `\`).
- `FunnelControllerIT::previewLiteralBraces` — `{{`/`}}` у тексті → літеральні `{`/`}`; незакритий `{` → verbatim.
- `FunnelControllerIT::previewDoubleDropsTrailingZero` — integral `Double` custom-value `30.0` → `30` (без `.0`).
- `FunnelControllerIT::previewUnlinkedBotUsesStubSubscriber` — незв'язаний бот → рендер на семпл-значеннях (`Іван`/`Петренко`/`ivan`), `sampleData=true`, без NPE.
- `FunnelControllerIT::previewNonMessageStepReturnsPlaceholder` — `DELAY`/`ADD_TAG`/`EMIT_EVENT` крок → `kind=non_message` (плейсхолдер, не 500).
- `FunnelControllerIT::previewUnknownStepIdReturns404` — невідомий `stepId` у валідній воронці → 404.
- `FunnelControllerIT::previewOnTheFlyContentNotSavedStep` — текст із request відрізняється від збереженого кроку → рендериться request-текст (доводить on-the-fly, Decision 9).

**Anti-IDOR + precedence (обидва ендпоінти):**
- `FunnelControllerIT::testRunForeignFunnelReturns404` / `previewForeignFunnelReturns404` — чужий/неіснуючий funnel/project → уніфікований 404 (`requireFunnel`).
- `FunnelControllerIT::previewIdorPrecedenceOver422AndStepId404` — чужий funnel + невалідний stepId → **404 від `requireFunnel` ПЕРЕВАЖАЄ** над 422/stepId-404 (404-vs-422 не стає oracle існування — Decision 9).

**Edge cases:**
- Test-run: бот не CONNECTED / відсутній → той самий 422 `funnel_owner_not_linked` (немає `ownerChatId`).
- Test-run: підписник `BLOCKED`/`DELETED`/`UNSUBSCRIBED` → 422 (рушій усе одно скасував би на `preStepGates`, тож фейлимо рано з зрозумілим кодом).

- Preview: `MENU`-крок НЕ має обов'язкового `text` на бекенді — прев'ю не повинен припускати, що text присутній (рендер порожнього/null → `""`).
- Preview: `parseMode` поза `{null, HTML, MarkdownV2}` → `render` трактує як plain (no escape) — не падати.
- Preview: невідомий `stepId` у ВЛАСНІЙ воронці → 404; але чужий funnel → `requireFunnel`-404 ПЕРЕВАЖАЄ (перевірити порядок: `requireFunnel` FIRST, потім пошук кроку).
- `render` escaping: HTML екранує `& < > "` (включно з `"` — attribute-breakout guard); MarkdownV2 екранує повний набір `_*[]()~`>#+-=|{}.!` + сам backslash; точні рядки — у тестах.
