## Description

Phase-4 author tooling (duplicate, test-for-me, stop-all, message preview) needs UI strings and error
messages. This task adds all new i18n keys to **both** `frontend/i18n/locales/uk.json` and
`frontend/i18n/locales/en.json` so the parity-gate (`frontend/scripts/check-locales.mjs`) stays green.
The project enforces strict key parity between locales: every key must exist in BOTH files with no
orphans. This task is purely the i18n layer — no Vue/TS logic. The store actions (Task 3), list/header
buttons (Task 5) and preview panel (Task 6) consume these keys.

**CANONICAL key structure (authoritative contract — Task 5 consumes the IDENTICAL shape).** The
`funnels.editor.stopAll` keys MUST be a NESTED object (button label at `stopAll.button`, dialog body at
`stopAll.message`), NOT a flat `stopAllConfirm` sibling. Use exactly these key names in both locales:

```
funnels.editor:
  duplicate            (button label, e.g. "Дублювати")
  duplicateResult      (success toast, e.g. "Воронку дубльовано")
  testForMe            (button label, e.g. "Test for me")
  testForMeResult      (success toast, e.g. "Тест надіслано")
  preview              (toggle label, e.g. "Прев'ю")
  previewPlaceholder   (non-message step placeholder, "Цей крок не надсилає повідомлення")
  previewSampleData    (sample-data indicator, e.g. "Семпл-дані — бот не зв'язаний")
  stopAll:
    button             (button label, "Зупинити всі активні запуски")
    title              (confirm dialog title)
    message            (confirm dialog body)
    confirm            (confirm CTA)
    cancel             (cancel CTA)
    result             (success toast with {count}, e.g. "Зупинено запусків: {count}")

errors.funnels:
  funnel_owner_not_linked        (inline hint, "Напишіть /start вашому боту, щоб зв'язати акаунт")
  funnel_invalid_trigger_type
  funnel_invalid_keywords
```

Three groups of keys:
1. **`funnels.editor.*`** — labels + confirm/result strings for the four tools (duplicate, test-for-me,
   stop-all, preview): `duplicate`/`duplicateResult`, `testForMe`/`testForMeResult`, `preview`/
   `previewPlaceholder`/`previewSampleData`, and the nested `stopAll` object
   (`button`/`title`/`message`/`confirm`/`cancel`/`result` with a `{count}` placeholder).
2. **`errors.funnels.funnel_owner_not_linked`** — the new 422 business code introduced by test-run
   (Decision 5). `resolveFunnelError` maps a 422 body `code` → `errors.funnels.${code}` inline.
   Message is the owner-not-linked inline hint ("Напишіть /start вашому боту, щоб зв'язати акаунт").
3. **`errors.funnels.funnel_invalid_trigger_type`** and **`errors.funnels.funnel_invalid_keywords`** —
   codes that already exist on the backend but are missing from the frontend error map. Test-run
   pre-validate (Decision 4) makes them reachable now, so without them `resolveFunnelError` would fall
   back to generic and the parity-gate would have no message. Add per Decision 10.

depends_on Task 2 is for spec/code-context coherence (Task 2 introduces `funnel_owner_not_linked` on the
backend); the actual file edits here do not collide with any other task.
