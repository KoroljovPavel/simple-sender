# Task 5: List + header action buttons (no preview panel)

## Required Skills

## Description

Wave-4 фронтенд-задача: підключити три інструменти автора (Дублювати, Зупинити все, Test for me) до UI воронок, перевикористовуючи store-дії з Task 3 (`duplicate`, `stopAllExecutions`, `testRun`) і i18n-ключі з Task 4. Це чисто UI-wiring — нової бізнес-логіки немає.

Дві точки інтеграції:
1. **Список воронок** (`index.vue`) — у кожен рядок додати кнопки **Дублювати** + **Зупинити все**. Зупинити все деструктивна → confirm-діалог. У проєкті НЕМАЄ `alert-dialog` компонента — перевикористати наявний `Dialog`-патерн (точно як delete-confirm у тому ж файлі: `deleteTarget`/`deleting`/`deleteError` refs + `funnels.deleteConfirm.*`). Test for me в список НЕ додаємо (контекст = відкрита воронка).
2. **Хедер редактора** (`[funnelId].vue`, action-група біля Activate/Pause, рядки ~254-274) — додати **Дублювати**, **Зупинити все** (confirm), **Test for me**. Перемикач **Прев'ю** і панель прев'ю тут НЕ додаємо — це Task 6 (секвенована після цієї задачі на тому самому файлі).

**Мапінг помилок (конвенція проєкту):** 422 з бізнес-кодом → inline через наявний `resolveFunnelError(err, ctx)` (вже є в `[funnelId].vue`, рядки 78-86; для `index.vue` — додати аналогічний хелпер або зчитати код і мапити в `errors.funnels.${code}`). Зокрема `funnel_owner_not_linked` від Test for me показується inline-підказкою біля кнопки Test for me («напишіть /start боту»), НЕ toast. Мережева/непередбачена помилка → toast (`vue-sonner`). Успіх (Дублювати створив копію, Зупинити все вернув лічильник, Test for me зареєстрував enroll) → success-toast.

**Test for me доступний і на draft-воронках** — не гейтити кнопку за статусом (бек дозволяє тест draft-воронки; status-гейт не блокує).

Після Дублювати: список оновлюється (store-дія Task 3 синкає рядок копії); у редакторі мінімально — success-toast.

## What to do

1. **`index.vue` (список):** у рядок `<li>` (зараз: open-button + delete-button, рядки 149-176) додати дві кнопки:
   - **Дублювати** (`data-test="funnel-duplicate-{id}"`): викликає `funnelsStore.duplicate(funnel.id)`; успіх → success-toast + рядок копії зʼявляється в списку (store-дія синкає); помилка → toast.
   - **Зупинити все** (`data-test="funnel-stop-all-{id}"`): лейбл кнопки `funnels.editor.stopAll.button`. Відкриває confirm-діалог (новий `Dialog`, окремий від delete-діалогу, з власними `stopTarget`/`stopping`/`stopError` refs): заголовок `funnels.editor.stopAll.title`, тіло `funnels.editor.stopAll.message`, кнопки `funnels.editor.stopAll.confirm` / `funnels.editor.stopAll.cancel`. Підтвердження → `funnelsStore.stopAllExecutions(funnel.id)` → success-toast із лічильником (`funnels.editor.stopAll.result`, інтерполяція `{count}`); cancel → нічого не робить, діалог закривається.
2. **`[funnelId].vue` (хедер редактора):** у action-групу (`<div class="flex items-center gap-2">`, рядки 254-274, біля Activate/Pause) додати:

   - **Зупинити все** (`data-test="funnel-editor-stop-all"`): confirm-діалог (той самий `Dialog`-патерн) → `stopAllExecutions` → success-toast із лічильником.

Кнопка НЕ дизейблиться за статусом draft.
3. **i18n:** використати ТОЧНО канонічні ключі з Task 4 (Task 4 — authoritative). Жодних flat `stopAllConfirm` — лише вкладений обʼєкт `stopAll`:

   - `funnels.editor.testForMe` — лейбл кнопки Test for me
   - `funnels.editor.testForMeResult` — success-toast після Test for me
   - `funnels.editor.preview`, `funnels.editor.previewPlaceholder`, `funnels.editor.previewSampleData` — НЕ використовуються в цій задачі (це Task 6), лише перелічені тут як частина канонічного простору; НЕ чіпати.
   - `funnels.editor.stopAll.button` — лейбл кнопки Зупинити все
   - `funnels.editor.stopAll.title` — заголовок confirm-діалогу
   - `funnels.editor.stopAll.message` — тіло confirm-діалогу
   - `funnels.editor.stopAll.confirm` — кнопка підтвердження в діалозі
   - `funnels.editor.stopAll.cancel` — кнопка скасування в діалозі
   - `funnels.editor.stopAll.result` — success-toast із лічильником (інтерполяція `{count}`)
   - `errors.funnels.funnel_owner_not_linked` — inline через `resolveFunnelError` (не використовувати напряму `t(...)`, тягнути через хелпер).

   НЕ додавати нові ключі тут і НЕ використовувати flat `funnels.editor.stopAllConfirm` — якщо чогось бракує в Task 4, це сигнал що Task 4 неповний (зафіксувати в decisions, не дублювати).
