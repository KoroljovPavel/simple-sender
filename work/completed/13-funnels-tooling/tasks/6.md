# Task 6: Message preview panel (greenfield)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Єдина greenfield-поверхня всієї фічі: панель прев'ю повідомлення в редакторі воронок. Зараз жодної панелі прев'ю не існує (`components/funnels/*` має лише deep-link-прев'ю в `FunnelTriggerSettings.vue`; ux-guidelines описує панель, але вона не побудована).

Під час редагування message-кроку (SEND_MESSAGE / SEND_IMAGE / MENU) автор має бачити праворуч, **як повідомлення виглядатиме в Telegram** — зі змінними (`{user.first_name}` тощо), підставленими й заекранованими під `parse_mode`. Підстановка та екранування рахуються на бекенді (Task 2 ендпоінт `POST /{funnelId}/steps/{stepId}/preview`, поверх `VariableTemplateRenderer` — байт-в-байт як рантайм); фронт лише викликає його через стор-дію `preview` (Task 3) і **виводить готовий рядок як текст**. Для не-message кроків (Delay, Add/Remove Tag, Set Custom Field, Emit Event) панель показує нейтральний плейсхолдер «Цей крок не надсилає повідомлення». Коли бот не зв'язаний, бекенд повертає семпл-дані з прапорцем `sampleData` — панель показує індикатор «семпл-дані».

**КРИТИЧНО (stored-XSS guard, OWASP A03 — Decision 9, tech-spec Risks):** рендерений рядок несе Telegram-екранування (MarkdownV2/HTML під `parse_mode`), яке **НЕ є browser-safe**. Панель виводить його **виключно як текст — НІКОЛИ через `v-html`/`innerHTML`**. Це збігається з конвенцією проєкту «never v-html» у `FunnelStepForm.vue`. Vitest повинен мати ЯВНИЙ assert, що компонент не використовує v-html.

Перемикач **Прев'ю** монтується в хедер `[funnelId].vue` (поряд з action-групою), і при ввімкненні панель з'являється праворуч (desktop-first ≥1024px за ux-guidelines). Задача секвенована після Task 5, бо обидві редагують спільний `[funnelId].vue` (уникаємо merge-конфлікту паралельних агентів — Decision 11).

**Dependencies:**
- Task 3 (store `preview` action + `PreviewStepRequest`/`PreviewStepResponse` типи в `types/funnel.ts`). Очікуваний shape відповіді (tech-spec Data Models): `{ rendered: string, sampleData: boolean, kind: "message" | "non_message" }`.
- Task 5 (хедер `[funnelId].vue` уже містить action-групу з Дублювати / Зупинити все / Test for me — додаємо перемикач Прев'ю в ту саму групу; секвенування уникає merge-конфлікту).
- Task 4 (i18n-ключі в обох локалях). КАНОНІЧНИЙ КОНТРАКТ Task 4 — усі ПЛАСКІ ключі під `funnels.editor`, без вкладеного `preview.*` об'єкта: `funnels.editor.preview` = текстова мітка перемикача (плаский рядок), `funnels.editor.previewPlaceholder` = плейсхолдер для не-message кроку, `funnels.editor.previewSampleData` = індикатор семпл-даних. НЕ вводити вкладений `funnels.editor.preview.*` (плаский рядок і вкладений об'єкт не можуть співіснувати під одним JSON-ключем). Якщо ключ відсутній на момент роботи — не дублюй, узгодь із Task 4.
- Бекенд ендпоінт `POST /{funnelId}/steps/{stepId}/preview` (Task 2) — стор-дія `preview` ходить саме туди.

**Edge cases:**
- MENU не має обов'язкового `text` на бекенді (`validateMenu` не кличе `requireText`) — панель не повинна падати на порожньому MENU-тілі (рендерить порожньо/нейтрально).
- Невідомий `stepId` → бекенд 404 (узгоджено з `requireFunnel`); панель показує нейтральне повідомлення, не падає.
- Незбережений/неповний крок: прев'ю реактивне до поточного вводу (on-the-fly, Decision 9) — не чекати auto-save.
- `rendered` із symbol-набором MarkdownV2-екранування (`\_`, `\*` тощо) — це нормальний текст, виводимо as-is, без додаткового екранування на фронті (інакше подвійне екранування).
- Немає вибраного message-кроку → нейтральний пустий стан панелі (не помилка).

**Implementation hints:**
- Конвенція стору (`stores/funnels.ts`, коментар lines 14-18): стор НІКОЛИ не кличе `useApiError`; дії catch-flip-RETHROW. Тому компонент ловить помилку `preview` у власному setup і вирішує текст (за потреби через `useApiError`, як `[funnelId].vue` робить через `resolveError`/`resolveFunnelError`).
- Дебаунс реактивного прев'ю — за зразком `scheduleTriggerPersist`/`triggerTimer` у `[funnelId].vue` (setTimeout ~600ms, clear у `onBeforeUnmount`).
- Вивід тексту: `{{ rendered }}` в `<template>` (Vue екранує за замовчуванням) — це і є text-only вивід. НЕ використовувати `v-html`. Зберегти переноси рядків через CSS (`whitespace-pre-wrap`), не через HTML.
- vitest «no v-html» assert: подати payload із розміткою й перевірити `wrapper.text()`/`textContent` містить літерал + `wrapper.find('img').exists() === false` (або `document.querySelector` для teleported DOM, як у `CreateFunnelDialog.spec.ts`).
- Стиль кнопок/`data-test` — дзеркалити наявні в хедері (`data-test="funnel-activate"` тощо); перемикач → `data-test="funnel-preview-toggle"`, панель → стабільний `data-test` для тестів (напр. `funnel-preview-panel`).
- i18n: усі видимі рядки через `t('...')` (ux-guidelines) — без хардкоду.
