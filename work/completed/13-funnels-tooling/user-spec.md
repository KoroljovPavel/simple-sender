# User Spec: Воронки. Фаза 4 — інструменти автора (13-funnels-tooling)

## Что делаем
Четверта вертикальна фаза епіку воронок. Поверх готового рушія (Фази 1-3) додаємо **чотири інструменти автора** в редакторі воронок: «Test for me» (запустити воронку на власному Telegram), «Дублювати воронку», «Зупинити всі активні запуски» та **панель прев'ю повідомлення** (як воно виглядатиме в Telegram). Це завершує MVP-набір інструментів для роботи з воронками.

## Зачем
Воронки вже працюють, але автору **незручно ітеративно їх перевіряти й безпечно ними керувати**:
- щоб протестувати воронку, автор мусить вручну зробити `/start` з потрібним payload / тегом, а при локальній розробці — ще й тримати піднятий публічний тунель, щоб Telegram-апдейти доходили до localhost;
- немає способу **зупинити «поламаний» запуск** одразу на всіх підписниках;
- немає прев'ю — автор не бачить, як повідомлення зі змінними виглядатиме насправді.

Гострого болю немає — це інструментарій швидкості ітерації та безпеки, що добиває MVP воронок. «Test for me» з прямим enroll обходить тригер, тож **для лінійних воронок локальний тунель більше не потрібен** (інтерактивні MENU-кроки з натисканням кнопок усе одно потребують вхідного webhook).

## Как должно работать

**Test for me**
1. Автор відкриває воронку в редакторі й натискає «Test for me» в хедері.
2. Система бере `Bot.ownerChatId` (Telegram власника, проставлений при першому приватному `/start` боту), знаходить відповідного підписника й **напряму enroll-ить** його у цю воронку, обходячи матчинг тригерів.
3. Автор отримує воронку у своєму Telegram. Повторний клік перезапускає тест з першого кроку.
4. Якщо власник жодного разу не писав боту (`ownerChatId` порожній) — система показує підказку «Напишіть `/start` вашому боту, щоб зв'язати акаунт».

> **Доставка асинхронна.** Успішна HTTP-відповідь означає лише, що запуск **зареєстровано** (execution створено), а не що повідомлення дійшло. Реальна відправка йде через рушій; збій Telegram-send проявляється як перехід execution у `failed` згодом (видно в аналітиці/статусах), а не як помилка цього HTTP-виклику.
>
> **Обмеження для змішаних воронок.** Якщо воронка лінійна до першого MENU-кроку, «Test for me» дійде до MENU й **зупиниться там** (`waiting_for_reply`) — натискання кнопки приходить вхідним webhook, тож для проходження далі локально все одно потрібен тунель. Для суто лінійних воронок тунель не потрібен.

**Дублювати воронку**
1. Автор натискає «Дублювати» в рядку списку або в хедері редактора.
2. Система створює **незалежну копію зі статусом `draft`**: граф кроків копіюється as-is, тригер скидається до дефолтів, назва — `"<назва> (копія)"`.
3. Автор редагує копію, не зачіпаючи оригінал.

**Зупинити всі активні запуски**
1. Автор натискає «Зупинити всі активні запуски» (хедер редактора або рядок списку).
2. Система показує **діалог підтвердження** (дія деструктивна).
3. Після підтвердження всі активні запуски воронки (`running|waiting|waiting_for_reply`) переводяться у `cancelled`; автор бачить кількість зупинених.

**Прев'ю повідомлення**
1. Під час редагування message-кроку автор бачить праворуч **панель прев'ю** — як повідомлення виглядатиме в Telegram (зі змінними та форматуванням).
2. Підстановка та екранування рахуються на бекенді (байт-в-байт як рантайм). Дані — реального підписника автора (через `ownerChatId`), а якщо бот не зв'язаний — семпл-дані + підказка.
3. Для не-message кроків (Delay, Add/Remove Tag, Set Custom Field, Emit Event) панель показує нейтральний плейсхолдер «Цей крок не надсилає повідомлення».

**Розміщення кнопок в UI**
- **Дублювати** та **Зупинити всі активні запуски** — і в рядку списку воронок, і в хедері редактора.
- **Test for me** та перемикач **Прев'ю** — лише в хедері редактора (контекст = відкрита воронка).

## Критерии приёмки

**Test for me**
- [ ] Enroll-ить підписника за `Bot.ownerChatId` напряму (`FunnelExecutionFactory.insertExecution`, depth=0), обходячи матчинг тригерів.
- [ ] `ownerChatId=null` / підписник відсутній / не `ACTIVE` → **422 `funnel_owner_not_linked`** з ремедіейшеном «напишіть `/start` боту», ніколи не 500.
- [ ] Повторний клік скасовує попередній активний запуск пари (воронка, підписник) і стартує заново (`cancelExistingForPair` → `insertExecution`).
- [ ] Перед enroll прогоняється валідація; порожня/невалідна воронка → ті ж 422-коди, що й при активації.
- [ ] **Draft-воронку теж можна протестувати.**
- [ ] Успішний виклик повертає 2xx = enroll зареєстровано (не гарантія доставки); подальший збій Telegram-send переводить execution у `failed` асинхронно, HTTP-виклик при цьому лишається 2xx.

**Дублювати**
- [ ] Копія народжується `status=draft`, тригер скинутий до `on_start`/`""`, назва `"<назва> (копія)"` з обрізанням до 128 символів.
- [ ] Граф кроків копіюється verbatim (`id` та ребра `next`/`timeoutTargetStepId`/`Button.targetStepId` збережені); копіюються `keywords`, `allowReEnter`, `description`.
- [ ] Повертає 201 + `FunnelResponse`; оригінал не змінюється.
- [ ] Назва з суфіксом `" (копія)"`, що перевищує 128 символів, **обрізається до 128** (суфікс не спричиняє 400).
- [ ] Дублювання порожньої або draft-воронки працює так само (тригер скидається незалежно від статусу/наповнення оригіналу).

**Зупинити всі активні запуски**
- [ ] Переводить лише `running|waiting|waiting_for_reply` → `cancelled` **і** виставляє `stepRunStatus=done`; термінальні статуси не чіпає.
- [ ] Запит скоупиться по `projectId` + `funnelId`; повертає кількість зупинених (0 при відсутності активних — це не помилка).
- [ ] Лічильник = `modifiedCount` bulk-операції на момент її виконання; запуск, що стартував/завершився одночасно зі сканом рушія, може не потрапити в число — це прийнятна гонка (коректність гарантує claim-CAS, точність лічильника — best-effort).

**Прев'ю**
- [ ] Бекенд-ендпоінт `POST /{funnelId}/steps/{stepId}/preview` рендерить через `VariableTemplateRenderer` (правильне екранування під `parse_mode`) для SEND_MESSAGE (текст), SEND_IMAGE (caption), MENU (тіло).
- [ ] Підстановка з даних підписника автора, якщо зв'язаний; інакше семпл-дані + підказка; для не-message кроків — плейсхолдер; ніколи не 500.
- [ ] `VariableTemplateRenderer.render` вимагає non-null `Subscriber` — коли підписник автора не резолвиться, прев'ю передає **стаб-підписника** з семпл-значеннями (`first_name=Іван`, `last_name=Петренко`, `username=ivan`, порожні custom-поля), щоб уникнути NPE/500.

**Спільне**
- [ ] Усі нові ендпоінти проходять `FunnelService.requireFunnel` (anti-IDOR, уніфікований 404).
- [ ] 422 з бізнес-кодом показується **inline** біля контролу (`resolveFunnelError`), а не toast; мережева/непередбачена помилка → toast (за конвенцією проєкту).
- [ ] Нові i18n-ключі додані в **обидва** `uk.json` і `en.json` (parity-gate); у `errors.funnels` додані `funnel_owner_not_linked`, а також `funnel_invalid_trigger_type` / `funnel_invalid_keywords` (ці коди вже є на бекенді, але відсутні в `errors.funnels` — спливуть при pre-validate під час test-run, тож parity-gate впаде без них).

## Ограничения
- **Test for me**: отримувач = `Bot.ownerChatId`; **без код-лінкінгу в стилі Manychat** — перевикористовуємо вже наявний зв'язок із Epic 04b (перший приватний `/start` виграє).
- **Дублювати**: копія мусить бути `status=draft` — інакше partial-unique індекс `funnels (projectId, on_start, triggerValue)` filtered `status=active` дасть конфлікт.
- **Зупинити все**: обов'язково виставляти `stepRunStatus=done` разом зі `status=cancelled` — інакше bulk-скасування програє гонку mid-tick запису рушія (claim-CAS контракт).
- **Прев'ю**: екранування мусить точно повторювати `VariableTemplateRenderer` — тому рендер на бекенді, не на фронті (захист від markup/XSS-дрейфу, OWASP A03).
- Технічні: `FunnelExecutionFactory` package-private (нова логіка тесту — в пакеті `funnel`); `validateSteps`/`applyTrigger` приватні (винести за потреби); enum-літерали (`name()`) — load-bearing для індексів/CAS, не перейменовувати; bulk-операції через `MongoTemplate` (репозиторій без query-методів навмисно).
- Редактор воронок — desktop-first (≥1024px) за ux-guidelines.
- **Без змін схеми БД, без міграцій.**
- **Деплою немає**: пайплайн CI/CD у проєкті ще не налаштований (TBD на рівні проєкту) — фіча мерджиться в `main` і перевіряється локально.

## Риски
- **Гонка зупинки vs тік рушія.** Bulk-cancel, що виставив лише `status`, програє mid-tick `persistProgress`. **Митигація:** дзеркалити `FunnelService.delete` точно — `status=cancelled` **і** `stepRunStatus=done` (claim-CAS гарантує детермінований виграш скасування).
- **Винесення приватного `validateSteps` змінить поведінку.** **Митигація:** лише підняти видимість (private → package/public), без зміни логіки й кодів помилок; покрити тестом.
- **Дрейф екранування в прев'ю.** Реалізація на фронті розійдеться з рантайм-екрануванням. **Митигація:** рендер прев'ю на бекенді через той самий `VariableTemplateRenderer`.
- **`ownerChatId` міг бути проставлений не-власником** (документована гонка 04b first-`/start`-wins). **Митигація:** не вирішуємо тут — це наявна модель довіри 04b; «Test for me» просто шле на цей chat.

## Технические решения
- Отримувач «Test for me» — `Bot.ownerChatId`; код-лінкінг не робимо, бо зв'язок уже є з 04b.
- Прямий enroll через `FunnelExecutionFactory.insertExecution(depth=0)`, **не** `fire()`/`dispatchForSubscriber` — ті повторно матчать тригери, що тут якраз треба обійти.
- Політика повторного тесту — **рестарт** (`cancelExistingForPair` перед вставкою), щоб кожен клік перевіряв з нуля.
- Дублювання — `FunnelStep.copyOf` для графа verbatim, тригер скидаємо до дефолтів, статус `draft`.
- «Зупинити все» — виносимо bulk-cancel із `FunnelService.delete` у `stopAllExecutions(funnelId)`.
- Прев'ю — окремий бекенд-ендпоінт `POST /{funnelId}/steps/{stepId}/preview` поверх `VariableTemplateRenderer`; семпл-дані як fallback, коли бот не зв'язаний.
- **Валідацію не переписуємо** — вона вже реалізована (бек `validateSteps` + фронт-мирор у `FunnelStepForm.vue`); лише додаємо два відсутні i18n-коди.
- Не робимо: код-лінкінг, нову сутність тригерів, зміни схеми/міграції, новий E2E, пост-деплой live-крок (немає середовища).
- Чотири інструменти незалежні (немає ланцюга залежностей). Тримаємо їх одним інкрементом, але якщо обсяг розтягнеться — природна точка розбиття — **прев'ю** (єдина greenfield-поверхня); решта три — це переважно extraction/wiring наявних примітивів.

## Тестирование

**Unit-тесты:** делаются всегда, не обсуждаются.

**Интеграционные тесты:** **делаем** — фіча L-розміру з бекенд-логікою на кожен інструмент. `@SpringBootTest` + MockMvc + embedded Mongo; `MockWebServer` для Telegram-відправки в «Test for me». Сценарії: direct-enroll + 422 при `ownerChatId=null`; рестарт повторного тесту; duplicate копіює граф але скидає тригер/статус; force-stop переводить лише активні статуси й повертає лічильник; preview рендерить із правильним екрануванням.

**E2E тесты:** **не делаем** — Playwright у проєкті тримається лише на golden-path перемикання локалі (architecture.md). Нові компоненти покриваємо vitest (панель прев'ю, confirm-діалог, нові дії стора).

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|-------------------|
| Дублювати воронку | curl `POST /api/v1/projects/{pid}/funnels/{fid}/duplicate` | 201, нова воронка `status=draft`, тригер скинутий, граф ідентичний, оригінал не змінено |
| Зупинити всі запуски | curl `POST .../funnels/{fid}/executions/stop` | 200 + кількість; усі активні execution-и стали `cancelled`+`stepRunStatus=done` |
| Test for me при `ownerChatId=null` | curl `POST .../funnels/{fid}/test-run` | 422 `funnel_owner_not_linked`, без 500 |
| Test for me (зв'язаний бот) | bash/IT з MockWebServer | новий execution створено (depth=0); MockWebServer отримав `sendMessage` |
| Прев'ю message-кроку | curl `POST .../funnels/{fid}/steps/{sid}/preview` | рендер зі змінними й коректним екрануванням під `parse_mode` |
| i18n parity | bash `node frontend/scripts/check-locales.mjs` | exit 0 — нові ключі є в обох локалях |

### Пользователь проверяет
- «Test for me» на реальному боті: відкрити воронку → натиснути → перевірити, що повідомлення прийшло у власний Telegram (бек не може спостерігати реальну доставку без live-середовища; тунель/локальний бот потрібні для інтерактивних MENU-кроків).
