# Smoke / ручна перевірка — 15-message-composer

Епік замінює три плоскі типи кроків (`SEND_MESSAGE`, `SEND_IMAGE`, `MENU`) одним кроком-композером
`MESSAGE` із впорядкованим списком `ContentBlock`. Один крок шле підписнику N окремих повідомлень
Telegram по черзі; до останнього не-альбомного блоку опційно чіпляються inline-кнопки + таймаут.

Цей файл — чеклист ручної перевірки. Автотести вже зелені (див. розділ 1); решта — те, що автотести
**не** покривають: реальний UI редактора/превʼю та жива доставка в Telegram.

Статус на момент написання: **код готовий і змерджений локально (16 комітів на `main`, не запушені).
Деплою немає** — кроки 5–6 виконуються після того, як зʼявиться середовище.

## 0. Підготовка (локальний запуск)

```bash
# Бекенд (потрібні Mongo + Redis; Docker для slow-lane ITs)
cd backend && ./gradlew bootRun        # http://localhost:8080

# Фронтенд (Node 24; nvm use)
cd frontend && pnpm install && pnpm dev # http://localhost:3000
```

## 1. Автоматичні тести (мають бути зелені)


> ⚠️ Engine-ITs (per-node at-most-once, snapshot-ізоляція, callback-матриця, tolerant-read) живуть під
> `@Tag("slow")` і **не** входять у дефолтну лінію. Перед будь-яким мерджем/деплоєм проганяй

> залізі), `SubscriberExportSignedUrlIT`/`BotConnectRaceIT` (контеншн під паралелізмом — зелені поодинці).

## 2. Редактор воронок — саб-редактор композера (Task 7)

Відкрий редактор воронки (екран ≥1024px) → додай крок типу **MESSAGE**.

- [ ] **Додавання блоків:** через пікер типу додаються блоки TEXT / IMAGE / VIDEO / AUDIO / FILE / ALBUM.
- [ ] **Порядок:** блоки можна рухати вгору/вниз (move up/down) і видаляти (remove); порядок зберігається.
- [ ] **Per-type віджети:**
  - TEXT — поле тексту + вибір `parseMode` (—/HTML/MarkdownV2).
  - IMAGE/VIDEO/AUDIO/FILE — URL **або** file_id + caption + parseMode.
  - ALBUM — 2–10 елементів; **кожен елемент має свій тип медіа** (IMAGE/VIDEO/AUDIO/FILE); caption
    осмислений лише на **першому** елементі.
- [ ] **Кнопки + таймаут** редагуються лише на **останньому не-альбомному** блоці. Якщо останній блок —
      альбом, секція кнопок ховається з підказкою.
- [ ] **Збірка типового кейсу:** `text → image+caption → album×3`, кнопки причеплені до текстового хвоста
      → форма валідна, **Save** проходить.

### Клієнт-валідація (дзеркалить бекенд) — мають блокувати save з інлайн-помилкою:

- [ ] Порожній композер (0 блоків).
- [ ] Більше 10 блоків (кнопка «Додати» вимикається на 10).
- [ ] Альбом <2 або >10 елементів.
- [ ] **Неприпустиме змішування типів в альбомі** (Decision 5): IMAGE+AUDIO, IMAGE+FILE → помилка.
      Дозволено: усі photo / усі video / photo+video; усі audio; усі document.
- [ ] Кнопки на не-останньому або на альбомному блоці.
- [ ] Медіа-URL не `http(s)` (напр. `file://`, `data:`, `javascript:`) → помилка; `file_id` (без схеми) — ок.
- [ ] Over-length: текст >4096 або caption >1024 → **попередження, але save НЕ блокується**.

## 3. Превʼю редактора — мультиблок-рендер (Task 8)

Редагуючи композер, дивись на панель превʼю праворуч.

- [ ] Блоки показані **стосом у тому ж порядку**, що в редакторі.
- [ ] TEXT/caption — як звичайний текст (не «сирий» HTML).
- [ ] IMAGE — інлайн через `:src`; VIDEO/AUDIO — іконка типу; FILE — іконка/клікабельне посилання
      **лише** якщо URL `http(s)` (file_id → іконка без href).
- [ ] ALBUM — сіткою; caption лише на першому елементі.
- [ ] Кнопки — під останнім блоком.
- [ ] **XSS-guard:** встав у текст/caption щось на кшталт `<img src=x onerror=alert(1)><b>x</b>` →
      у превʼю це **літеральний текст**, жодного спрацювання/реального тега. (Превʼю ніколи не використовує
      v-html; бекенд екранує за parseMode.)
- [ ] Реактивність: зміна блоку → превʼю оновлюється (дебаунс ~600 мс).

## 4. Save/activate через API (опційно, замість UI)

```bash
# Порожній композер → 422 з інлайн-кодом
curl -X PUT http://localhost:8080/api/projects/{projectId}/funnels/{funnelId} \
  -H "Content-Type: application/json" -H "Authorization: Bearer {token}" \
  -d '{"steps":[{"stepType":"MESSAGE","blocks":[]}]}'        # очікувано 422

# 11 блоків → 422; альбом 1 елемент → 422; кнопки на альбомі → 422;
# валідний композер → 200, воронка active
```

- [ ] Усі жорсткі помилки → **422** з бізнес-кодом (`funnel_step_invalid`).
- [ ] **DTO round-trip:** save → fetch повертає `blocks` без втрати полів (вкл. `items[].type` для альбому).
- [ ] Валідний композер → **200**, воронка `active`.

## 5. Жива доставка в Telegram — «Test for me» (Task 14, ПІСЛЯ деплою)

> Єдина перевірка реальної доставки поза автотестами. Виконати у власному Telegram після деплою.

- [ ] Побудуй мультиблок-композер: `text → image+caption → album×3` + кнопки на текстовому хвості.
- [ ] Запусти «Test for me».
- [ ] Отримано **N окремих повідомлень у правильному порядку** (текст, далі фото з підписом, далі альбом).
- [ ] Змінні (`{user.*}` / `{custom.*}`) підставлені і в тексті, і в усіх caption.
- [ ] Кнопки зʼявляються **під останнім блоком**.
- [ ] Натискання кнопки → воронка йде **правильною гілкою** (та сама механіка, що була в MENU).
- [ ] Таймаут без відповіді → перехід на `timeoutTargetStep` (паритет MENU).

## 6. Деплой-крок: ручне очищення даних (Decision 4, ПІД ЧАС деплою)

Старі типи кроків видалені; старі документи воронок несумісні зі схемою.

- [ ] На цільовому середовищі вручну дропнути/очистити колекції `funnels` та `funnel_executions`
      (backfill не робимо — продакшну немає).
- [ ] Після старту перевірити логи: engine-sweep піднявся без помилок серіалізації снапшотів.
- [ ] **Fail-safe (tolerant-read):** навіть якщо легасі-документ зі старим `stepType` переживе wipe —
      engine **не падає** (читає його як `StepType.UNKNOWN` і термінально фейлить лише цей ран, не зриваючи
      sweep-тік). Можна перевірити: вставити raw-документ зі `stepType:"MENU"` → sweep не кидає виняток.

## Що покрито автотестами (НЕ треба перевіряти руками)

- Порядок блоків, підстановка змінних у text + усі caption, trim+WARN над лімітами — `FunnelStepExecutorTest`.
- Крах посеред блоків → крок не просувається, надіслані блоки не дослилаються (at-most-once через 2 тіки) —
  `FunnelExecutionEngineIT`.
- Snapshot-ізоляція: зміна воронки після enroll → in-flight ран шле оригінальний снапшот — `FunnelExecutionEngineIT`.
- Нові sender-методи + альбом-масив-маппер + retry/429/scrub — `TelegramSenderTest`.
- Callback-негативи (битий формат, >64 байти, не-hex, out-of-range, url-кнопка, IDOR) + park/resume +
  `lastButtonClicked` + `funnel_button_clicked` рівно раз — `FunnelTriggerServiceIT`.
- Save-валідація (усі 422-кейси), DTO round-trip, мультиблок-превʼю + XSS-негатив — `FunnelControllerIT`.
- Тип елемента альбому (Decision 5) — `FunnelControllerIT` + `FunnelStepExecutorTest`.
