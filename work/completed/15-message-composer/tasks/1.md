# Task 1: ContentBlock модель + StepType + FunnelStep рефактор

## Required Skills

Перед виконанням задачі завантаж:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Foundation-крок фічі 15-message-composer (Wave 1, незалежний). Замінюємо три плоскі типи кроків
(`SEND_MESSAGE`, `SEND_IMAGE`, `MENU`) одним кроком-композером `StepType.MESSAGE`, що тримає
впорядкований `List<ContentBlock>`. Цей таск закладає **модель і snapshot-контракт**, на яких далі
будуються send-гілка (Task 3), валідація/DTO (Task 4) і callback-шлях (Task 5).

Що робимо:
- Net-new immutable `ContentBlock`/`MediaItem` records + `BlockType` enum у пакеті
  `com.botfunnel.funnel` (flat, **без Mongo `_class`** — дзеркалить Decision 12 / Decision 1).
- `FunnelStep`: прибрати плоскі msg-поля (`text`/`parseMode`/`imageUrl`/`caption`), додати
  `List<ContentBlock> blocks`; `buttons` + `timeout*` лишаються (переюзаються композером — Decision 2).
- `FunnelStep.copyOf`: захисна копія `blocks` (`new ArrayList<>(...)`; елементи immutable) — зберігає
  snapshot-ізоляцію (Decision 3).
- `StepType`: видалити `SEND_MESSAGE`/`SEND_IMAGE`/`MENU`, додати `MESSAGE`.
- `FunnelExecutionFactory.deepCopySteps` — переконатися, що deep-copy steps лишається коректним
  (він уже делегує в `FunnelStep.copyOf`, тож зміна тут — переважно перевірка/коментарі).

Результат: модель компілюється, snapshot-копія `blocks` валідна (новий інстанс списку).

**Важливо про blast-radius:** видалення значень `StepType` і плоских полів `FunnelStep` зламає
компіляцію у `StepExecutor`, `FunnelService`, `FunnelTriggerServiceImpl`, DTO-шарі та наявних тестах.
Це **очікувано** — ці місця доводяться до зеленого в Tasks 3/4/5. У межах ЦЬОГО таску слід довести
до компіляції лише три цільові файли + нові records; не треба ремонтувати
`StepExecutor`/`FunnelService` (це окремі таски). Якщо повна збірка модуля не зелена через ці
залежні файли — це нормально; критерій таску — компіляція цільових файлів + зелений unit на `copyOf`.

## What to do

1. Створити enum `BlockType` у `backend/src/main/java/com/botfunnel/funnel/BlockType.java` зі
   значеннями `TEXT, IMAGE, VIDEO, AUDIO, FILE, ALBUM`. UPPERCASE — дискримінатор типу блоку
   (за конвенцією enum-дискримінаторів у проєкті, як `StepType`).

2. Створити immutable record `MediaItem` у
   `backend/src/main/java/com/botfunnel/funnel/MediaItem.java`:
   `record MediaItem(String mediaUrl, String caption)`. `mediaUrl` — URL або file_id; `caption`
   осмислений лише на **першому** елементі альбому (правило enforce-иться валідацією в Task 4 — тут
   лише модель). Record → deeply immutable.

3. Створити immutable record `ContentBlock` у
   `backend/src/main/java/com/botfunnel/funnel/ContentBlock.java` з дискримінатором + nullable
   per-type полями (Data Models):
   ```
   record ContentBlock(
     BlockType type,          // TEXT|IMAGE|VIDEO|AUDIO|FILE|ALBUM
     String text,             // TEXT only
     String parseMode,        // TEXT / media caption: null|HTML|MarkdownV2
     String mediaUrl,         // IMAGE/VIDEO/AUDIO/FILE: URL або file_id
     String caption,          // IMAGE/VIDEO/AUDIO/FILE only
     List<MediaItem> items    // ALBUM only (2–10)
   )
   ```
   Record → deeply immutable (контракт snapshot-ізоляції). Без Mongo `_class` (embedded flat POJO).
   `items` для ALBUM — список immutable `MediaItem`; список як контейнер мутабельний, але це нормально
   для embedded-документа, бо `ContentBlock` сам immutable і `FunnelStep.copyOf` робить захисну
   shallow-копію зовнішнього списку `blocks` (елементи immutable).

4. `FunnelStep.java`:
   - Видалити поля `text`, `parseMode`, `imageUrl`, `caption` (під коментарями `// SEND_MESSAGE`/
     `// SEND_IMAGE`) + їхні getter/setter.
   - Додати поле `private List<ContentBlock> blocks;` + getter/setter (за конвенцією решти полів).
   - Лишити `buttons`, `timeoutValue/Unit/TargetStepId`, `id`, `next`, `order`, `stepType`,
     `delay*`, `tagSlug`, `customField*`, `eventName`, SUBSCRIBE_TO_FUNNEL-поля — без змін.
   - Оновити class-level Javadoc: `buttons`/`timeout*` тепер належать кроку-композеру MESSAGE (а не MENU).
   - У `copyOf`: прибрати рядки копіювання `text`/`parseMode`/`imageUrl`/`caption`; додати захисну
     копію `blocks`: `copy.blocks = source.blocks == null ? null : new ArrayList<>(source.blocks);`
     (shallow-копія достатня — елементи `ContentBlock` immutable records; `null` лишається `null`).
   - Оновити Javadoc `copyOf`: задокументувати `blocks` як мутабельний список immutable records →
     захисна shallow-копія (аналогія до наявного трактування `buttons`).

5. `StepType.java`: видалити `SEND_MESSAGE`, `SEND_IMAGE`, `MENU`; додати `MESSAGE`. Оновити
   коментарі: `MESSAGE` — крок-композер (N окремих повідомлень + опційні inline-кнопки + таймаут
   park-on-reply на останньому не-альбомному блоці).

6. `FunnelExecutionFactory.deepCopySteps`: логіка вже делегує в `FunnelStep.copyOf` — переконатися,
   що deep-copy steps лишається коректним для нового поля `blocks` (структурно міняти нічого не треба,
   бо `copyOf` тепер сам копіює `blocks`). Оновити коментар, що snapshot тепер несе `blocks`.

## TDD Anchor

**Передумова (critical):** `FunnelStepTest.java` і `StepTypeTest.java` уже існують. `FunnelStepTest`
посилається на символи, які цей таск видаляє (`SEND_MESSAGE`/`SEND_IMAGE`/`MENU`, `getText/setText`,
`getParseMode/setParseMode`, `getImageUrl/setImageUrl`, `getCaption/setCaption`). Поки ці посилання
там — тестовий sourceset НЕ компілюється, а отже жоден новий тест навіть не запуститься (червоний
крок неможливий). Тому **спершу** перепиши/прибери ці місця (What to do, крок 7), і лише потім
червоний→зелений-цикл на нових `blocks`-тестах нижче стає валідним. Порядок: (1) переписати наявні
тести на `MESSAGE`/без плоских msg-полів → (2) додати нові `blocks`-тести (червоні, бо моделі ще
немає) → (3) реалізувати модель → (4) зелені.

Нові тести пишемо ДО реалізації моделі (пишемо → запускаємо → переконуємось що падають → пишемо код → зелені).

- `backend/src/test/java/com/botfunnel/funnel/FunnelStepTest.java::copyOf_copiesBlocksToNewListInstance`
  — `copyOf(step)` повертає копію, де `getBlocks()` — **новий інстанс списку** (`assertNotSame` до
  оригінального reference), але з тими самими (immutable) елементами `ContentBlock`
  (поелементна рівність контенту). Доводить захисну копію (Decision 3).
- `…::copyOf_nullBlocksStaysNull` — `blocks == null` у джерелі → `getBlocks()` копії теж `null`
  (не порожній список).
- `…::copyOf_mutatingCopyBlocksDoesNotAffectSource` — додавання/видалення елемента в
  `copy.getBlocks()` НЕ змінює `source.getBlocks()` (snapshot-ізоляція на рівні списку).

- `backend/src/test/java/com/botfunnel/funnel/StepTypeTest.java::messageStep_present` —
  `StepType.valueOf("MESSAGE")` резолвиться у `StepType.MESSAGE`, `name()=="MESSAGE"` (новий гард для
  нового значення enum; видалені значення тут не гардились, тож нічого прибирати не треба).

(Обидва файли `FunnelStepTest.java` і `StepTypeTest.java` уже існують — додати/переписати методи в
них, НЕ створювати наново.)

**Edge cases:**
- `blocks == null` у `copyOf` → копія теж `null` (не порожній список) — паритет із трактуванням

- `ContentBlock.items` для не-ALBUM блоків → `null` (нормально; валідація per-type — Task 4).
- Видалення значень enum зламає exhaustive-switch у `StepExecutor`/`FunnelService` — лишити для

- `MediaItem.caption`/`ContentBlock.caption` на не-першому елементі/не-тому типі — модель не enforce-ить
  (Task 4 валідація); тут лише структура.

**Implementation hints:**
- Дзеркаль immutable-record стиль `Button.java` (record, Javadoc по компонентах, без bean-validation —
  валідація живе у DTO/service шарі).
- `ContentBlock`/`MediaItem` — БЕЗ Mongo `_class`: просто records, Spring Data серіалізує їх як вкладені
  документи в межах `FunnelStep.blocks` без дискримінатора (Decision 1 / Decision 12). Жодних
  `@JsonTypeInfo`/sealed-ієрархій.
- `copyOf`: shallow-копія списку (`new ArrayList<>(source.blocks)`) достатня — елементи immutable. НЕ
  робити глибокого клонування елементів.
- Javadoc-патерн `copyOf` уже пояснює, чому scalar-поля копіюються by-reference, а `buttons` —
  defensively; додати `blocks` у те саме пояснення (мутабельний список immutable records).
- Тест на `copyOf`: будуй `FunnelStep` з `stepType=MESSAGE` і `blocks` зі свіжого
  `new ArrayList<>(List.of(new ContentBlock(...)))`, потім `FunnelStep copy = FunnelStep.copyOf(step)`;
  `assertNotSame(step.getBlocks(), copy.getBlocks())`; поелементна рівність контенту; мутація
  `copy.getBlocks()` не зачіпає джерело.
