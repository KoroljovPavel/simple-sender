# Task 7: FunnelStepForm — саб-редактор композера

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Переписати `FunnelStepForm.vue`: для типу кроку `MESSAGE` (composer) замінити три старі плоскі гілки
(`SEND_MESSAGE`, `SEND_IMAGE`, `MENU`) одним саб-редактором композера — упорядкованим списком
контент-блоків. Це Wave-4 фронтенд-таск (US «Как должно работать» кроки 1–7): автор додає крок
«Повідомлення», всередині будує блоки через picker типу (Text / Image / Video / Audio / File / Album),
редагує per-type поля, переставляє блоки вгору/вниз, видаляє. До **останнього не-альбомного** блоку
причеплює inline-кнопки + опційний таймаут park-on-reply (механіка MENU, що тепер живе на рівні кроку
`MESSAGE` — Decision 2). Решта типів кроків (DELAY/ADD_TAG/REMOVE_TAG/SET_CUSTOM_FIELD/EMIT_EVENT/
SUBSCRIBE_TO_FUNNEL) у формі лишаються без змін.

Клієнт-валідація має **дзеркалити backend `FunnelService.validateSteps` case `MESSAGE`** (Task 4):
1–10 блоків, per-type обовʼязкові поля, медіа-URL `http(s)`-scheme (або непрозорий `file_id`),
альбом 2–10 елементів і type-mixing предикат (всі photo / всі video / суміш photo+video; audio і
document **не змішуються** з іншими — Decision 5), кнопки лише на останньому не-альбомному блоці,
over-length text(>4096)/caption(>1024) як **мʼяке попередження** (не блокує save). Усі рядки —
через `t()` (нові ключі в `uk.json` + `en.json`).

**Залежність:** Task 6 уже оновив `frontend/types/funnel.ts` — `StepType` містить `MESSAGE` (без
`SEND_MESSAGE`/`SEND_IMAGE`/`MENU`), додані інтерфейси `ContentBlock`/`BlockType`/`MediaItem`,
`FunnelStep.blocks`. Будувати форму проти цих типів (читати їх на старті, не вигадувати).

## What to do

1. **Picker типу кроку:** у `STEP_TYPES` замінити `SEND_MESSAGE`/`SEND_IMAGE`/`MENU` на одне
   `MESSAGE`; `selectedType` default → `'MESSAGE'` (а на edit — `props.initial?.stepType`).
2. **Саб-редактор блоків (нова гілка `v-if selectedType === 'MESSAGE'`):**
   - Локальний reactive масив блоків (на кшталт `menuButtons` нині — НЕ vee-validate поля), seed з
     `props.initial?.blocks` на edit, інакше один порожній блок-заготовка.
   - **Picker типу блоку** для додавання: Text / Image / Video / Audio / File / Album (значення з
     `BlockType`). Кнопка «Додати блок».
   - **Per-type віджет** для кожного блоку:
     - `TEXT` — textarea (`text`) + `parseMode` select (None/HTML/MarkdownV2).
     - `IMAGE`/`VIDEO`/`AUDIO`/`FILE` — input `mediaUrl` (URL або `file_id`) + опційний `caption` +
       `parseMode` select.
     - `ALBUM` — список 2–10 медіа-елементів (`MediaItem`: `mediaUrl` + опційний `caption` лише на
       **першому**); add/remove елемента в межах [2..10].
   - **Move up / move down / remove** блоку (як кроки воронки нині; переюз ідіоми reorder).
3. **Кнопки + таймаут на останньому не-альбомному блоці:** переюзати наявний MENU-саб-редактор
   (`menuButtons`, `menuTimeout*`, `menuTargetOptions`, `SearchableSelect`), але рендерити його **не**
   як окрему гілку типу, а як секцію, привʼязану до останнього блоку — і лише коли останній блок
   **не** ALBUM. Кнопки/таймаут лишаються полями рівня кроку (`FunnelStep.buttons`/`timeout*`,
   Decision 2), не блоку.
4. **Клієнт-валідація (дзеркало backend, Task 4):** computed-функції, що повертають локалізований
   error або null — на рівні композера (кількість блоків 1–10, кнопки лише на останньому не-альбомному)
   і на рівні блоку (per-type обовʼязкові поля, медіа-URL scheme, album 2–10 + type-mixing). Over-length
   text/caption — **інлайн-warning** (показати, не блокувати submit). Mark-touched на submit, як `menuTouched`.
5. **`onSubmit` гілка `MESSAGE`:** зібрати `FunnelStep` з `stepType: 'MESSAGE'`, `blocks: ContentBlock[]`
   (тримінг, blank→null для опційних полів), `buttons`/`timeout*` тільки коли останній блок не-альбомний
   і кнопки задані; зберегти server-minted `id`/`next` (як MENU зараз). Заблокувати emit, якщо валідація
   композера/блоків не пройшла.
6. **i18n:** додати всі нові ключі під `funnels.steps` (form/validation/type блоків) у `uk.json` **і**
   `en.json`; прибрати/перепризначити застарілі `SEND_MESSAGE`/`SEND_IMAGE`/`MENU` записи в
   `funnels.steps.type` (додати `MESSAGE`). Жодного хардкоду рядків у шаблоні.
7. **Перевірити споживачів форми:** `pages/projects/[projectId]/funnels/[funnelId].vue` має
   `MESSAGE_STEP_TYPES = ['SEND_MESSAGE','SEND_IMAGE','MENU']` (рядок 60) — оновити на `['MESSAGE']`,
   щоб preview-панель і далі знаходила message-крок. Це in-scope, бо інакше форма не інтегрується.

## TDD Anchor

Тесты (frontend vitest), які пишемо ДО реалізації: запускаємо → бачимо падіння → пишемо код →
бачимо зелене. Новий spec композера кладемо у `frontend/tests/components/funnels/FunnelStepForm.composer.spec.ts`
(дзеркалить розташування наявного `frontend/tests/components/funnels/FunnelMessagePreview.spec.ts`).
Наявні specs форми живуть у `frontend/tests/pages/funnel-editor.spec.ts` — звірити там існуючі
сценарії `FunnelStepForm`, щоб не дублювати й не зламати їх.

**Block editor:**
- `FunnelStepForm.composer.spec.ts::adds a block of the picked type` — picker TEXT → у списку зʼявляється
  text-віджет; picker IMAGE → media-віджет.
- `FunnelStepForm.composer.spec.ts::moves a block up and down` — move-up/down переставляє порядок блоків.
- `FunnelStepForm.composer.spec.ts::removes a block` — remove прибирає блок зі списку.
- `FunnelStepForm.composer.spec.ts::renders the per-type widget for each block type` — TEXT→textarea+parseMode;
  IMAGE/VIDEO/AUDIO/FILE→mediaUrl+caption+parseMode; ALBUM→2–10 items, caption лише на першому.
- `FunnelStepForm.composer.spec.ts::emits a MESSAGE step with ordered blocks on submit` — valid composer →
  emit `{ stepType: 'MESSAGE', blocks: [...] }` у порядку автора.

**Validation mirror (backend `validateSteps` case MESSAGE):**
- `FunnelStepForm.composer.spec.ts::blocks submit on empty composer` — 0 блоків → emit не відбувається, inline-error.
- `FunnelStepForm.composer.spec.ts::blocks submit on more than 10 blocks` — >10 блоків → блокується.
- `FunnelStepForm.composer.spec.ts::blocks album with fewer than 2 or more than 10 items` — album <2 / >10 → error.
- `FunnelStepForm.composer.spec.ts::blocks invalid album type-mixing` — audio/document змішані з photo/video → error
  (всі photo / всі video / суміш photo+video — ОК).
- `FunnelStepForm.composer.spec.ts::blocks buttons on a non-last or album block` — кнопки дозволені лише на
  останньому не-альбомному блоці.
- `FunnelStepForm.composer.spec.ts::warns but does not block on over-length text or caption` — text>4096 / caption>1024
  → inline-warning, submit проходить.
- `FunnelStepForm.composer.spec.ts::rejects non-http(s) media url` — `file://`/`data:`/`javascript:` → error;
  `http(s)` URL і непрозорий `file_id` → ОК.

## Details

**Files:**
- `frontend/components/funnels/FunnelStepForm.vue` — поточний стан: один `<form>` із select типу кроку
  (`STEP_TYPES`, рядки 32–42, містить `SEND_MESSAGE`/`SEND_IMAGE`/`MENU`), per-type гілки в `<template>`
  (SEND_MESSAGE рядки 624–652, SEND_IMAGE 654–680, MENU 733–911). MENU вже має повний саб-редактор
  кнопок: `ButtonRow` type (рядок 73), `blankButtonRow`/`initialButtonRows` (рядки 74–89),
  `menuButtons` ref (рядок 91), `addMenuButton`/`removeMenuButton`, `menuButtonLabelError`/
  `menuButtonUrlError` (рядки 150–172), `menuButtonsValid` (рядок 176) + опційний таймаут
  (`menuTimeout*`, `menuTargetOptions`, рядки 95–147) — **переюзати цю механіку** для кнопок на
  останньому блоці. **Guard для seed:** `initialButtonRows()` (рядок 79) нині читає кнопки лише коли
  `props.initial?.stepType === 'MENU'` (рядок 80) — для композера це має стати `=== 'MESSAGE'`
  (так само `menuTimeout*` seed-гарди на рядках 103/108/111 з `=== 'MENU'` → `=== 'MESSAGE'`).
  `onSubmit` (рядки 528–607)
  має switch по типах — додати гілку `MESSAGE`, видалити `SEND_MESSAGE`/`SEND_IMAGE`/`MENU` гілки.
  vee-validate `schemaFor` (рядки 371–421) і `useForm`/`defineField` (рядки 425–454) тримають плоскі
  поля `text`/`imageUrl`/`caption`/`parseMode` — їх більше не використовувати для composer (блоки —
  локальний reactive масив, валідований вручну, як `menuButtons`); прибрати/перепризначити плоскі
  message-поля зі схеми. Зберегти гілки DELAY/ADD_TAG/REMOVE_TAG/SET_CUSTOM_FIELD/EMIT_EVENT/
  SUBSCRIBE_TO_FUNNEL без змін.
- `frontend/i18n/locales/uk.json` + `en.json` — структура `funnels.steps.{type,form,validation}`.
  `funnels.steps.type` нині має `SEND_MESSAGE`/`SEND_IMAGE`/`MENU` — додати `MESSAGE`, прибрати
  видалені (звірити, чи їх ще читає щось — `funnels.steps.type.${s.stepType}` у формі й на сторінці).
  Додати ключі під `form` (block-type picker labels, mediaUrl, album add/remove item, composer add-block/
  move/remove) і `validation` (composerEmpty, composerTooMany, mediaUrlScheme, albumSize, albumTypeMix,
  buttonsOnNonLast, captionMax/textMax warning). Іменування — у стилі наявних ключів (`menu*`, `subscribe*`).
- `frontend/pages/projects/[projectId]/funnels/[funnelId].vue` — рядок 60
  `MESSAGE_STEP_TYPES: StepType[] = ['SEND_MESSAGE', 'SEND_IMAGE', 'MENU']` → `['MESSAGE']`.

**Dependencies:** Task 6 (`frontend/types/funnel.ts` — оновлені `StepType`/`ContentBlock`/`BlockType`/
`MediaItem`/`FunnelStep.blocks`). Wave 4. Пакетів нових немає (vee-validate+zod, vue i18n, наявний
`SearchableSelect`).

**Edge cases:**
- Останній блок — ALBUM, але автор хоче кнопки → секція кнопок прихована; UX-підказка: додати
  text-блок-хвіст після альбому (US крок 5). Не дозволяти емітити кнопки на альбомному останньому блоці.
- Edit існуючого composer-кроку → seed блоків із `props.initial.blocks`, кнопок із `props.initial.buttons`,
  таймаут із `timeout*`; зберегти server-minted `id`/`next`.
- `mediaUrl` — або `http(s)` URL, або непрозорий `file_id` (НЕ відхиляти все, що не URL): відхиляти лише
  явні небезпечні schemes (`file://`/`data:`/`javascript:`), приймати http(s) і будь-який нерозпізнаний
  токен як file_id — звірити з backend disambiguation (Task 4 decisions.md).
- Album type-mixing: всі photo / всі video / суміш photo+video — ОК; audio або document у суміші з
  іншими типами — error. **Передумова, яку треба зняти проти типів Task 6:** у data model (tech-spec)
  `MediaItem` = `record MediaItem(String mediaUrl, String caption)` — **немає** per-element поля підтипу
  медіа. Type-mixing-валідація вимагає, щоб елемент альбому ніс свій media-subtype (photo/video/audio/
  document). Не припускати — звірити з фінальним дизайном `MediaItem`/`BlockType` із Task 6 (decisions.md):
  якщо підтип не закладено в типі, узгодити з Task 6, як саме фронт визначає тип елемента (явне поле в
  `MediaItem` чи похідне з UI-picker'а item'а), і лише тоді будувати предикат type-mixing.
- Over-length text(>4096)/caption(>1024) — НЕ блокувати save (мʼяке попередження), на відміну від
  hard-помилок.
- Блоки без id (ще не збережені) у picker target кнопок — пропускати (як нині `menuTargetOptions`).

**Implementation hints:**
- Дзеркалити наявний MENU-саб-редактор як зразок: локальний reactive масив + ручна валідація
  (`*Error()` повертає локалізований рядок або null) + `menuTouched`-подібний touched-флаг.
- Точні backend-правила брати з decisions.md Task 4 (validateSteps case MESSAGE) — не вигадувати
  межі; дзеркалити байт-у-байт, як коментарі в нинішній формі підкреслюють для MENU.
- Переюзати `SearchableSelect` для target кнопок/таймауту 1:1 з нинішнім MENU.
- НЕ використовувати v-html ніде (XSS-guard, Decision 8) — лейбли/текст лише через `{{ }}`.
