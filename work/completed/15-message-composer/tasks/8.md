# Task 8: FunnelMessagePreview — мультиблок-рендер + store preview action

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](.claude/skills/code-writing/SKILL.md)

## Description

Переписати панель превʼю редактора воронок (`FunnelMessagePreview.vue`) під нову модель композера:
замість одного рядка (`text`/`caption` плоского кроку) панель тепер рендерить **впорядкований стос
різнотипних блоків** так, як підписник побачить їх у Telegram — N окремих "повідомлень" одне під одним
у тому ж порядку, що й `step.blocks`. Кожен блок рендериться за своїм `BlockType`:

- **TEXT / медіа-caption** — відрендерений бекендом рядок (екранований за `parseMode` на сервері),
  виводиться **виключно як текст через `{{ }}`**, ніколи через `v-html`/`innerHTML`. Це load-bearing
  XSS-guard (Decision 8 / OWASP A03): Telegram-екранування (HTML/MarkdownV2) **не** browser-safe, тож
  виведення його в `v-html` було б stored-XSS-сінком.
- **IMAGE / VIDEO / AUDIO** — медіа через прив'язку `:src` (для зображень) або іконку типу (для
  video/audio, де inline-плеєр недоцільний), плюс caption під медіа. `:src` бінд (не `v-html`):
  `<img src>` не виконує JS, інваріант "no HTML sink" зберігається.
- **FILE / document** — як посилання/іконка; `:href` рендериться **лише** якщо URL має `http(s)`-scheme
  (відхиляти `file://`/`data:`/`javascript:` тощо — Decision 6 anti-SSRF/anti-XSS), `file_id` (непрозорий
  токен без scheme) → іконка без клікабельного href.
- **ALBUM** — сітка з 2–10 елементів; caption осмислений лише на першому.
- **Кнопки** (`step.buttons`) — рендеряться під **останнім** блоком (механіка композера: клавіатура
  чіпляється до останнього не-альбомного send-у).

Паралельно оновити `preview` action у `stores/funnels.ts` під новий request-shape: замість плоских
`{ stepType, text, parseMode }` надсилається масив блоків (`PreviewStepRequest` з `blocks`), а відповідь —
масив відрендерених блоків (`PreviewStepResponse.renderedBlocks[]`). Зберегти контракт стора (catch →
flip error flag → RE-THROW, ніколи не викликати `useApiError` усередині action) і дебаунс-виклик у
компоненті (наявний `schedulePreview`/`previewTimer` ідіом, 600 мс).

Старі типи `SEND_MESSAGE`/`SEND_IMAGE`/`MENU` видалені (Task 1/6); панель будується лише на `MESSAGE`
+ `step.blocks`. Типи `ContentBlock`/`BlockType`/`MediaItem` та оновлені preview DTOs приходять з Task 6
(`types/funnel.ts`) — ця таска їх споживає, не визначає.

## What to do

1. Оновити `preview` action у `frontend/stores/funnels.ts`: прийняти новий `PreviewStepRequest`
   (масив блоків замість плоских полів), повернути новий `PreviewStepResponse` (масив `renderedBlocks`).
   Зберегти контракт стора — catch лише фліпає `error` і RE-THROW; `useApiError` не викликається.
2. Переписати `FunnelMessagePreview.vue` на мультиблок-рендер:
   - `isMessageStep` → `stepType === 'MESSAGE'` (видалити `MESSAGE_TYPES` масив зі старими типами).
   - Зібрати тіло превʼю з масиву `step.blocks`, зіставленого з `rendered.renderedBlocks` (порядок
     блоків = порядок DOM-елементів).
   - Для кожного блоку відрендерити відповідний віджет за `BlockType` (text/image/video/audio/file/album),
     caption/text — лише через `{{ }}`, медіа — через `:src`, file-href — лише за `http(s)`-scheme.
   - Кнопки `step.buttons` — під останнім блоком.
   - Зберегти наявні стани: empty (немає кроку), non-message placeholder, loading, error (404/мережа/5xx
     → нейтральне in-panel повідомлення), sample-data indicator, "Крок N · type" heading.
   - Зберегти дебаунс (`schedulePreview`, 600 мс) + immediate-перший прогон. **Перевести `watch()`
     (наразі ~рядки 108-125, спостерігає `[step.text, step.caption, step.parseMode]` — поля видалені
     Task 1/6) на `step.blocks` (deep watch)**, щоб реактивна зміна блоку тригерила
     `schedulePreview`/дебаунс-виклик preview.
   - **Видалити осиротілий SEND_IMAGE / single-field dead code**, який після мультиблок-переписки
     більше нікуди не звʼязаний: computed/хелпери `imageUrl`, `imageLoadFailed`, `showImage`,
     `showImagePlaceholder`, `previewText()` та масив-константу `MESSAGE_TYPES =
     ['SEND_MESSAGE','SEND_IMAGE','MENU']`. Усі вони побудовані навколо старої плоскої single-field
     моделі кроку. Після переписки в компоненті **не повинно лишитися жодного посилання** на видалені
     плоскі поля (`step.text` / `step.imageUrl` / `step.caption`) чи старі step-type константи —
     ні в `<script>`, ні в `<template>`. (Per-block image-load-fallback узагальнюється на per-block
     стан замість старого глобального `imageLoadFailed`.)
3. Оновити `data-test`-хуки, щоб тести могли перевірити порядок і типи блоків (наприклад
   `funnel-preview-block` з індексом/типом), зберігши наявні хуки де доречно.
4. Усі рядки — через `t()` (i18n-ключі вже наявні в `funnels.editor.*`; нові ключі для типів медіа за
   потреби додати у локалі — узгодити з Task 7, який володіє `i18n/locales/*`).
5. **Ця таска володіє переписуванням ОБОХ тестових файлів** під новий DTO-контракт (TDD: спершу тести,
   потім код):
   - `tests/components/funnels/FunnelMessagePreview.spec.ts` — повна переписка під мультиблок-модель.
   - `tests/stores/funnels.spec.ts` — **preview-related тест (~рядки 235-244)** наразі шле старий
     `PreviewStepRequest{ stepType, text, parseMode }` і чекає `PreviewStepResponse{ rendered }`; обидві
     форми ламаються після DTO-міграції. Переписати на новий request-shape (масив `blocks`) і
     `renderedBlocks[]`-відповідь.

## TDD Anchor

Тести, які треба написати ДО реалізації. Пишемо → запускаємо → переконуємось що падають → пишемо код →
переконуємось що проходять. Файли: `frontend/tests/components/funnels/FunnelMessagePreview.spec.ts`
(переписати під мультиблок-модель) **і** `frontend/tests/stores/funnels.spec.ts` (переписати
preview-related тест під новий DTO-shape).

- `FunnelMessagePreview.spec.ts › renders an ordered stack of mixed block types` — `MESSAGE` крок з
  `blocks` [TEXT, IMAGE, ALBUM] + відповідні `renderedBlocks` → у DOM три блок-елементи в **тому ж
  порядку**, що й `blocks` (перевірка через `indexOf` позицій `data-test` хуків).
- `FunnelMessagePreview.spec.ts › calls store preview with the blocks request shape` — action
  викликається з `(funnelId, stepId, { stepType: 'MESSAGE', blocks: [...] })`, рівно один раз на
  immediate-прогон.
- `FunnelMessagePreview.spec.ts › reactive block change re-triggers debounced preview` — після
  immediate-прогону реактивно мутувати `step.blocks` (напр. змінити текст блоку чи додати блок) →
  після дебаунсу `previewMock` викликається ще раз з оновленим масивом `blocks` (перевіряє, що `watch`
  переведено з плоских `text`/`caption`/`parseMode` на `step.blocks` deep).
- `FunnelMessagePreview.spec.ts › renders text/caption as TEXT, never via v-html` — ворожий payload
  `<img src=x onerror=alert(1)><b>x</b>` у відрендереному блоці → зʼявляється як **літеральний текст**,
  створює 0 реальних `<img>`/`<b>` елементів; статичний guard: source без коментарів не містить
  `v-html=` / `.innerHTML=`.
- `FunnelMessagePreview.spec.ts › binds media via :src for IMAGE block` — IMAGE-блок → `<img>` з
  `src` = mediaUrl блоку (не `v-html`); caption під медіа як текст.
- `FunnelMessagePreview.spec.ts › renders FILE href only for http(s) scheme` — FILE-блок з `https://…`
  → клікабельний `:href`; FILE-блок з `file_id`/не-http scheme → іконка без href (anti-SSRF/XSS).
- `FunnelMessagePreview.spec.ts › renders album as a grid of items` — ALBUM-блок з 3 елементами →
  3 медіа-елементи; caption лише на першому.
- `FunnelMessagePreview.spec.ts › renders buttons under the last block` — `step.buttons` присутні →
  кнопки після останнього блок-елемента в DOM.
- `FunnelMessagePreview.spec.ts › placeholder for non-message step, no backend call` — `DELAY` крок →
  placeholder, `previewMock` не викликано.
- `FunnelMessagePreview.spec.ts › neutral message on preview error` — `previewMock` reject 404 →
  `funnel-preview-error`, без падіння панелі.
- `funnels.spec.ts › preview action sends the blocks request and returns renderedBlocks` —
  preview-related стор-тест (~рядки 235-244) переписаний: `preview` шле новий
  `PreviewStepRequest{ stepType, blocks: [...] }` body і повертає `PreviewStepResponse{ renderedBlocks }`
  (старий `{ stepType, text, parseMode }` / `{ rendered }` видалено); контракт стора (re-throw, без
  `useApiError`) збережено.

- Ворожий markup у відрендереному text/caption → лишається літеральним текстом (XSS-guard).

**Implementation hints:**
