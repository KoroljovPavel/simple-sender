# Task 5: Frontend preview panel

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Extend the funnel editor's preview panel (`FunnelMessagePreview.vue`) to render the two new
keyboard step types. Today the panel renders ONLY `MESSAGE` steps (gate
`isMessageStep = props.step?.stepType === 'MESSAGE'`, line 50) — every other type gets a neutral
placeholder and the backend is never called. After this task, `SET_KEYBOARD` and `CLEAR_KEYBOARD`
steps also call the preview endpoint and render: the backend-rendered text (variables substituted
via `VariableTemplateRenderer`, returned as a single TEXT `RenderedBlock` — tech-spec Decision 7)
plus, for `SET_KEYBOARD`, a bottom-keyboard mock — rows of chips built from the response's clamped
raw label rows. `CLEAR_KEYBOARD` renders text only (its `keyboardRows` is `null`).

This completes the user-spec AC "Прев'ю (бекенд endpoint + фронтова панель) рендерить обидва нові
кроки". The backend side (preview endpoint, `kind="keyboard"`, clamped `keyboardRows`) ships in
Task 4; the editor form, `StepType` union literals, `FunnelStep` keyboard fields, and the
`funnels.steps.type.SET_KEYBOARD/CLEAR_KEYBOARD` labels ship in Task 2 — both are dependencies of
this task. Here we mirror the preview DTO contract in `types/funnel.ts` (`kind` union gains
`'keyboard'`, response gains `keyboardRows`, request gains the keyboard fields) and wire the panel.

The stored-XSS guard is load-bearing: the rendered text carries Telegram escaping
(MarkdownV2/HTML) that is NOT browser-safe — all output stays `{{ }}` interpolation, never
`v-html`. The spec file contains a static source guard that must stay green.

## What to do

1. **`frontend/types/funnel.ts` — mirror the Task-4 preview DTO contract:**
   - `PreviewStepRequest`: add optional keyboard fields — `keyboardText`, `keyboardParseMode`,
     `keyboardRows` (the `KeyboardRow[]` type introduced by Task 2); `blocks` becomes irrelevant
     for keyboard steps (backend tolerates unknown/absent fields).
   - `PreviewStepResponse`: extend the `kind` union to `'message' | 'non_message' | 'keyboard'`
     and add `keyboardRows?: string[][] | null` (raw labels for the mock — `null` unless
     SET_KEYBOARD). Update the doc comments to match the new backend contract.
2. **`FunnelMessagePreview.vue` — renderable gate:** replace the single-type gate with a
   renderable-step check covering `MESSAGE`, `SET_KEYBOARD`, `CLEAR_KEYBOARD` (keep a separate
   computed to distinguish the keyboard branch from the block-stack branch in the template).
   Non-renderable types (DELAY, ADD_TAG, …) must still show the neutral placeholder with no
   backend call.
3. **`FunnelMessagePreview.vue` — request payload:** in `runPreview`, for the keyboard step types
   send `stepType` + `keyboardText` / `keyboardParseMode` / `keyboardRows` from the step prop
   (MESSAGE keeps sending `blocks` as today).
4. **`FunnelMessagePreview.vue` — watch source:** extend the watched tuple (line 116) with the
   keyboard fields (`keyboardText`, `keyboardParseMode`, `keyboardRows`) so edits to them
   re-trigger the debounced preview.
5. **`FunnelMessagePreview.vue` — render branch:** when the response `kind === 'keyboard'`,
   render the rendered text (single TEXT `RenderedBlock` from `renderedBlocks`) as plain
   `{{ }}` text with `whitespace-pre-wrap`, then — only when the response `keyboardRows` is
   non-null/non-empty — a bottom-keyboard mock: one chip per label, grouped in rows, visually
   distinct from the inline-buttons style (it mocks the Telegram bottom reply keyboard). Add
   `data-test` hooks for the text and the mock (e.g. `funnel-preview-keyboard-text`,
   `funnel-preview-keyboard`, per-row hooks) so specs can select them. The existing
   `previewBlocks` pairing (clamps to `step.blocks` length) must NOT be reused for keyboard steps
   — keyboard steps have no `blocks`, so that computed yields `[]`.
6. **i18n (`uk.json` + `en.json`):** add any new panel strings introduced by the render branch
   under `funnels.editor.*` (e.g. a keyboard-mock caption/aria label), in BOTH locales (prebuild
   parity gate). The step-type heading needs nothing new — `funnels.steps.type.SET_KEYBOARD` /
   `.CLEAR_KEYBOARD` ship in Task 2 and the heading already composes them for any focused step.
7. **`FunnelMessagePreview.spec.ts`:** add the keyboard cases (see TDD Anchor) and keep all
   existing tests green — including the no-v-html source guard and the non-message placeholder
   test (DELAY must still show the placeholder after the gate change).

**Edge cases:**
- Unsaved keyboard step (no `step.id`) → backend 404 → neutral in-panel error (existing
  behavior; do not special-case).
- Saved-type gate (backend renders per the SAVED step's type — Decision 7): a step whose type
  was just changed in the dialog but not saved previews per the old type; existing behavior for
  all types, not a regression — don't try to fix it here.
- `kind === 'keyboard'` with empty/null `keyboardRows` (CLEAR_KEYBOARD, or a SET_KEYBOARD draft
  with no rows yet) → text only, no empty mock shell.
- `renderedBlocks` empty in a `keyboard` response (desync) → render nothing rather than crash
  (same defensive spirit as the `previewBlocks` clamp).
- Hostile content in rendered text AND in row labels → literal text via `{{ }}`.

**Implementation hints:**
- Render the mock rows from the RESPONSE `keyboardRows` (backend clamps to ≤10×≤4, label ≤64 —
  Decision 7), not from the local form state — one source of truth, and the clamp is free.
- Keep `runPreview`'s early-return condition aligned with the new gate, or keyboard steps will
  silently keep the placeholder.
- The watch source is an array of getters — append `props.step?.keyboardText`,
  `props.step?.keyboardParseMode`, `props.step?.keyboardRows` (deep watch already on).
- `stores/funnels.ts` `preview` action takes `PreviewStepRequest` — extending the TS interface
  is the only store-level change (no action logic).
- Heading works for free: it renders for ANY focused step from `funnels.steps.type.*`.
