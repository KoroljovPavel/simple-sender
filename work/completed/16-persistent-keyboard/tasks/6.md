## Description

Add the feature's slow-lane integration coverage to `FunnelExecutionEngineIT` (`@Tag("slow")`, Testcontainers Mongo+Redis, static `MockWebServer TELEGRAM`) per tech-spec Decision 9. This is the first time the engine IT asserts actual `/sendMessage` request bodies — until now it asserts only counts and statuses (`sentCount()`, `reload(execId).getStatus()`). Decision 9 explicitly pins where the body-assert idioms come from so this task does NOT invent a new pattern:

- **JsonNode body idiom** — `TelegramSenderIT.sendText_withReplyMarkup_includesInlineKeyboardInBody` (lines 286-314): `JsonNode body = OBJECT_MAPPER.readTree(req.getBody().readUtf8()); body.path("reply_markup").path(...)`.
- **Request drain idiom** — `FunnelTestRunSendIT` (lines 131-136 take, line 174 drain): `RecordedRequest sent = TELEGRAM.takeRequest(); String body = sent.getBody().readUtf8();` — and drain leftover recorded requests because the JVM-singleton MockWebServer's request log is cumulative across tests.

Coverage to add (user-spec ACs 4, 5, 6 / tech-spec AC "Engine slow-lane IT asserts exact wire bodies"):

1. **SET_KEYBOARD full sweep cycle** — seed an execution whose snapshot has a SET_KEYBOARD step, `engine.sweep()`, then assert the exact `/sendMessage` body: `reply_markup.keyboard` (rows of `{"text": ...}` objects), `is_persistent`, `resize_keyboard: true`, `one_time_keyboard`; execution ends `completed` — never `waiting_for_reply` (fire-and-forget, Decision 4).
2. **CLEAR_KEYBOARD full sweep cycle** — same shape, body asserts `reply_markup.remove_keyboard: true`; execution `completed`.
3. **Keyword dispatch from a button label** — a button-label text starts the matching keyword funnel via `FunnelEventService.dispatchForSubscriber(projectId, subscriberId, "keyword", label, 0)`: seed an active `triggerType="keyword"` funnel whose keywords contains-match the label, dispatch, assert a new execution exists for that funnel+subscriber. The webhook leg (`ProcessTelegramUpdateJob` → `dispatchKeyword`) is already covered by `ProcessTelegramUpdateJobTest.plainText_dispatchesKeyword` — cite it in a comment, do not rewrite it.

Depends on Task 3 (StepExecutor cases for both step types) and transitively Task 1 (`FunnelStep` keyboard fields, `KeyboardRow`/`KeyboardButton` records).

## Details

**Files:**
- `backend/src/test/java/com/botfunnel/funnel/FunnelExecutionEngineIT.java` (~1785 lines) — current state: `@Tag("slow")`, extends `AbstractIntegrationTest`, JVM-singleton static `MockWebServer TELEGRAM`, mutable `@Primary` test Clock, per-test `sendBaseline` delta counting. Asserts only counts/statuses today — zero body assertions. Add: 3 test methods + 2 step-builder helpers (`SET_KEYBOARD`, `CLEAR_KEYBOARD`) + `@Autowired FunnelEventService` + an `ObjectMapper` for `readTree` (the class does not have one yet — `TelegramSenderIT` uses a static `OBJECT_MAPPER`; a plain `new ObjectMapper()` constant matches that idiom).

**Dependencies:**
- Task 3 (StepExecutor SET_KEYBOARD/CLEAR_KEYBOARD cases — without it the new tests fail on UNKNOWN-type handling, not on wire shape) and transitively Task 1 (`FunnelStep.keyboardText/keyboardParseMode/keyboardRows/isPersistent/oneTimeKeyboard`, `KeyboardRow`/`KeyboardButton` records).
- No new packages. MockWebServer, Testcontainers, Jackson all already on the test classpath.

**Existing helpers to reuse (do not duplicate):**
- `seedActiveSubscriber()` / `seedExecution(subId, BASE, steps...)` — index/linear-mode seeding (no step ids); `seedConnectedBot()` runs in `@BeforeEach`.
- `enqueueOk(n)` — enqueue n OK sendMessage responses; `json(status, body)` for error responses.
- `reload(execId)`, `sentCount()` (delta from `sendBaseline`).
- For the keyword case: `seedTargetFunnel` hardcodes `TRIGGER_ON_START` — either seed the keyword funnel directly via `funnelRepository.save(...)` with `triggerType="keyword"` + lowercase `keywords` list, or extend the helper. Keywords must be lowercase (FunnelService normalizes on save; the repository bypasses that — seed them lowercase yourself).

**Edge cases:**
- `waiting_for_reply` assertion: asserting `completed` already excludes it, but the user-spec AC names it explicitly — assert `isEqualTo(ExecutionStatus.completed)` and add a comment (or an explicit `isNotEqualTo`) referencing the no-park contract.
- Cumulative request log: `getRequestCount()` is JVM-lifetime; `takeRequest()` consumes from a shared queue. Each new test must `takeRequest()` exactly as many times as it sends, otherwise later tests' `takeRequest()` returns a stale request. Prefer `takeRequest(2, SECONDS)`-style timeouts if the class's drain comment suggests it; `FunnelTestRunSendIT` uses bare `takeRequest()` after asserting `sentCount()`.
- Keyword dispatch is error-isolated (`never throws outward`) — a misconfigured seed shows up as "no execution created", not an exception. Assert the created execution's `funnelId`/`subscriberId`/`enrollDepth==0` so a silent no-op cannot pass.
- `dispatchForSubscriber` lowercases the matchKey internally (`matchingKeywordFunnels`) — pass the raw button label (e.g. with an uppercase letter) to also prove case-insensitivity.
- Buttons in the body are the OBJECT form `{"text": ...}` (Decision 5), not bare strings — assert `keyboard.get(r).get(c).get("text").asText()`, mirroring the inline-keyboard JsonNode walk.

**Implementation hints:**
- SET_KEYBOARD body walk: `body.path("reply_markup")` then `.path("keyboard")` (assert `isArray()`, sizes, labels), `.path("is_persistent").asBoolean()`, `.path("resize_keyboard").asBoolean()` true, `.path("one_time_keyboard").asBoolean()`. CLEAR_KEYBOARD: `.path("remove_keyboard").asBoolean()` true. Also assert the request path ends with `/sendMessage` (idiom from both source tests).
- Use distinct, non-overlapping keyboard fixtures (e.g. 2 rows × 2/1 buttons, `is_persistent=true`, `one_time_keyboard=false`) so a transposed row/column or a swapped boolean fails loudly.
- Seed builders mirror `sendMessage(text)`: `new FunnelStep()`, `setStepType(...)`, set keyboard fields, NO `setId` (id flips the snapshot into graph mode — see the `multiTextMessageIndexed` comment at lines 1433-1442).
- For the keyword test no Telegram send is needed (dispatch only creates the execution); don't enqueue responses and don't sweep — count executions via `mongoTemplate.find` on (funnelId, subscriberId), same query shape as `activeChildren`.
