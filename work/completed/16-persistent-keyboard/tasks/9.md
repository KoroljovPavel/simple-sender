# Task 9: Security Audit

## Required Skills

Before starting, load:
- `/skill:security-auditor` — [SKILL.md](../../../.claude/skills/security-auditor/SKILL.md)

## Description

Full-feature security audit of 16-persistent-keyboard. This is an Audit Wave task: the
`security-auditor` skill IS the review — there are no separate reviewers. The auditor reads **all**
source files created/modified in this feature (backend funnel-package changes: step model + records,
validation, StepExecutor cases, preview DTOs; frontend: types, FunnelStepForm.vue,
FunnelMessagePreview.vue, locale files) and analyzes them holistically against OWASP Top 10, with
five feature-specific focus areas pinned by the tech-spec:

- **Rendered-text XSS surface in preview (Decision 7, OWASP A03):** `previewStep` returns rendered
  text via the same `VariableTemplateRenderer` as the engine; button labels are echoed **verbatim**
  (raw, unrendered — labels are the keyword link) but **clamped** to validation caps (≤10 rows ×
  ≤4 buttons, label ≤64) so preview never reflects an unbounded unvalidated payload. The frontend
  keyboard render branch (`FunnelMessagePreview.vue`) must display text and labels through `{{ }}`
  interpolation only — **never** `v-html`/`innerHTML`; the no-v-html source guard must hold.
- **Input validation completeness (Decision 6, OWASP A03/A04):** `validateSetKeyboard` enforces
  mandatory non-blank text ≤4096, valid parse mode, 1..10 rows × 1..4 buttons, button text non-blank
  ≤64, duplicate trimmed button texts blocked; `validateClearKeyboard` enforces text + parse mode
  AND **strictly rejects** `keyboardRows`/`isPersistent`/`oneTimeKeyboard` being present (no
  silently-ignored fields). All rejections → 422 `funnel_step_invalid`.
- **No PII in logs (OWASP A09):** the two new `StepExecutor` cases log ids/codes only — never
  rendered text, never button labels, never chat content. Error mapping
  (`TelegramSendException`/`BotTokenInvalidException`/`AppException`) must not leak payloads into
  log messages either.
- **Anti-IDOR on the preview path (OWASP A01):** `POST /{funnelId}/steps/{stepId}/preview` for the
  new `kind="keyboard"` branch keeps funnel/step ownership scoping (fail-closed by `projectId` —
  patterns.md Security Gates); the new branch must not introduce a lookup that bypasses
  project/owner checks.
- **No injection via button labels into the wire body (Decision 5, OWASP A03):** the `reply_markup`
  is built as a `LinkedHashMap`/`List` with buttons in object form `{"text": ...}` and serialized
  verbatim by Jackson through the existing 6-arg `sendText` — labels must enter the JSON as data
  (Jackson-escaped), never via string concatenation into the body, and must not be able to inject
  sibling keys (`selective`, `web_app`, etc.).

Beyond the five focus areas, the audit covers the rest of OWASP Top 10 across the changed
components: mass-assignment in the new DTO fields (`FunnelStepDto`/`PreviewStepRequest` must not
accept `ownerId`/`projectId` from the body — patterns.md DTO whitelist), injection through
`{user.*}`/`{custom.*}` variable substitution in `keyboardText`, excessive payload logging on the
send path, and the client-side keyword hint (store data only, no new endpoint — confirm no data
exposure was added).

## Details

**Files:** audit is read-only — modify nothing. The definitive source list comes from
`decisions.md` (tasks 1–7) + tech-spec Implementation Tasks; the Context Files list above is the
expected set from the tech-spec Architecture section. If decisions entries reveal extra touched
files, include them in scope.

**Dependencies:** tasks 1–7 (the whole feature implemented). Runs in the Audit Wave in parallel
with Task 8 (code audit) and Task 10 (test audit); all three gate Task 11 (pre-deploy QA).

**Edge cases / targeted checks:**
- Preview clamping: confirm the echo of `keyboardRows` in `PreviewStepResponse` is actually clamped
  (≤10×≤4, label ≤64) and not just validated-on-save — preview accepts the *live form state*, which
  may be unvalidated; an unclamped echo is a reflected-payload amplifier.
- Preview branch gates on the SAVED step's type (Decision 7) — confirm the new branch did not start
  trusting `request.stepType()` (that would let any saved step type drive the keyboard render path).
- CLEAR_KEYBOARD strict rejection: keyboard-only fields present → 422, not silently dropped —
  check both the validator and the DTO→domain mapping (`toSteps`) so fields cannot sneak past
  validation into storage.
- Duplicate check uses *trimmed* texts in a `HashSet` — confirm trimming is consistent between
  validator and frontend mirror (a mismatch is a validation-bypass vector for the keyword link).
- StepExecutor defensive guard for null/empty `keyboardRows` on a SET_KEYBOARD snapshot
  (terminal-fail) — confirm the failure log carries ids/codes only.
- Wire body: `resize_keyboard:true` hardcoded, only the documented keys present
  (`keyboard`/`is_persistent`/`resize_keyboard`/`one_time_keyboard`; `remove_keyboard`); no path
  where user input becomes a JSON key or a non-`text` button field.
- Frontend: keyword hint computed from `useFunnelsStore` summaries — confirm it renders keyword
  strings via `{{ }}` and introduces no `v-html`; locale files contain no raw HTML in new keys
  that components would need to inject.
- Mass-assignment: new `FunnelStepDto`/`PreviewStepRequest` fields are content-only — no
  `ownerId`/`projectId`/`botId` readable from the request body.

**Implementation hints:**
- OWASP focus: A01 (preview IDOR), A03 (XSS/injection), A04 (validation design), A09
  (logging/PII). SSRF (A10) is largely N/A here — no URLs in reply-keyboard buttons; state that
  explicitly rather than skipping silently.
- Map findings to patterns.md Security Gates lines and tech-spec Decisions 5/6/7 where applicable.
- Report shape precedent: `work/completed/15-message-composer/logs/working/audit/security-auditor.json`
  (verdict, counts, scope_reviewed, findings, positive confirmations).
