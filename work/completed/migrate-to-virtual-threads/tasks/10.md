**Edge cases:**

- `ConcurrencyTestUtils.parallelInvoke` exception propagation: if any task throws, the loop collecting `future.get()` will throw `ExecutionException` wrapping the original. Race-test call-sites (`BotConnectRaceIT`) need to assert on counts of `{200, 409}` responses, so the contract should be: tasks that throw are surfaced through the returned `List<T>` rather than aborting the call. Agent decides — but if exceptions abort the whole call, the existing `BotControllerIT.connect_concurrent_race` (which assumes both responses come back) breaks. Recommended: collect `future.get()` per-future and let the caller assert.
- `ready.countDown()` ordering vs `task.call()` thrown exception: D10 mandates `try { … } finally { ready.countDown(); }` exactly. The natural inversion (countDown FIRST inside the try, then start.await, then call) achieves the same property — `ready` reaches zero even if `task.call()` later throws. Whichever shape the agent picks, the `parallelInvoke_taskThrowingBeforeBarrier_doesNotHang` test is the contract.
- `MockMvc` and `@WithMockUser` interaction: the 6 wiring-only files DO NOT use `@WithMockUser` today; they use either the bare client or the `mockUser()` mutator. Translation: `mockMvc.perform(get("/...").with(user("...")))` from `SecurityMockMvcRequestPostProcessors`. No annotation-level changes.
- `SecurityConfigTest.authEndpoints_permitWithoutAuthentication` calls `/api/auth/me` and expects 401. Under MVC the controller still emits 401 — preserve the assertion verbatim. (The endpoint reaches the controller which checks `HttpSession` and returns 401 if no session.)
- `JobRunrInMemoryConfig` is referenced by 5 of the 6 classes via `@Import(JobRunrInMemoryConfig.class)` — DO NOT touch this config in this task. It's owned by an earlier Epic (JobRunr storage provider configuration) and remains valid under both reactive and servlet stacks.
