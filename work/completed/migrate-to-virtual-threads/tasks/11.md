Перед выполнением задачи загрузи:

## Description

Post-flip observational gate for Wave 3 that turns the abstract VT-pinning risk (R1 / R2 in tech-spec + user-spec) into named, bounded, documented findings. After Wave 2 lands the atomic WebFlux → MVC + virtual-threads flip, this task boots the backend once with `-Djdk.tracePinnedThreads=full`, drives three workload shapes (idle startup, register-storm, webhook-storm), captures every `Thread held by virtual thread...` stack the JVM logs, and writes the resulting catalogue into `.claude/skills/project-knowledge/references/patterns.md` under a brand-new top-level "Virtual Threads" section.

The migration deliberately does NOT chase zero pinning — user-spec AC7 says "Нулевой pinning НЕ требуется", user-spec line 86 forbids preemptive `Semaphore` defenses, and tech-spec R1/R2 accept BCrypt + Lettuce internal locks as known-and-tolerated pinning sites that Spring Boot 4 + JDK 24 will fix automatically once JobRunr 7.3.2 unblocks that upgrade. The deliverable here is therefore a documentation artefact, not a code fix: an honest map of every pinning stack actually observed on this codebase, an explanation of why each is acceptable today, and a forward-pointer to the SB4/JDK24 future-fix.

This task is the **first writer** into `patterns.md` in Wave 3 — it appends a fresh "Virtual Threads" section. Task 13 then runs strictly sequentially after this task to rewrite the remaining (WebFlux → MVC) sections of `patterns.md` and update `architecture.md` + `deployment.md`. The single-file-ownership constraint from tech-spec line 47 forbids parallel edits to `patterns.md`. Result: user-spec AC7 and tech-spec R1/R2 are satisfied — pinning is observed, named, and bounded; the section becomes input to Task 13.
