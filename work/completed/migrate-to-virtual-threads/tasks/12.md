## Description

Phase C verification task: add four MockMvc integration tests with strengthened
assertions per validator feedback so that the previously-manual checks AC11
(R4 CSRF cookie write), AC12 (manual remember-me Max-Age DevTools inspection),
and partially R3/R5 (session continuity) are lifted from manual into the
standard `./gradlew test` run.

The tests live inside the Wave-2-migrated MVC stack — they consume the
post-flip `SecurityConfig` (Task 3), the new `RememberMeCookieSerializer`
(Task 3), the new MVC `GlobalErrorHandler` (Task 3), the synchronous
repositories (Task 4), and the MockMvc-based `AbstractIntegrationTest`
(Task 10). Therefore Task 12 runs in Wave 3 with the entire Wave 2 set
(Tasks 3–10) as `depends_on`.

Four invariants covered by six new test methods:

- **AC16 — session continuity across the flip and across `change-password`.**
  Two assertions: (1) a logged-in user X with two sessions (A, B) calling
  `change-password` causes session B to be terminated (its `principal`-keyed
  `sessions` document is deleted) while session A continues; (2) a
  hand-crafted BSON document representing the **pre-flip
  `ReactiveMongoSessionRepository` byte-shape** is inserted directly into
  `sessions`, and after `MongoIndexedSessionRepository` (post-flip) reads it
  back, the `principal` field is still recognised by the
  terminate-by-`principal` query path. This covers R5
  (in-flight session bytes-shape) end-to-end inside `./gradlew test`.

- **AC17 — validation 400 response shape preserved across
  `WebExchangeBindException → MethodArgumentNotValidException` swap.**
  POST `/api/auth/register` with an empty email. Body MUST be
  `ErrorResponse{message, code}` JSON with `code: null` AND `message`
  matching the existing joined-error format
  `"<field>: <defaultMessage>[, <field>: <defaultMessage>]*"` (the joiner
  shape that the frontend `useApiError` composable may parse).

- **AC18 — remember-me cookie attributes + XSRF-TOKEN co-emission.**
  `MockMvc` POST `/api/auth/login` with `rememberMe=true` MUST produce
  `Set-Cookie: SESSION=...; Max-Age=2592000; Path=/; HttpOnly; Secure;
  SameSite=<configured>` — assert ALL attributes, not just `Max-Age`.
  The `SameSite` value comes from `server.servlet.session.cookie.same-site`
  via `SESSION_COOKIE_SAME_SITE` (default `lax`); test env does not override
  it, so the assertion is `SameSite=Lax`. Hard-coding `Strict` would fail
  against the actual config — read the configured value via
  `@Value("${server.servlet.session.cookie.same-site:Lax}")` and assert
  against it, OR assert the exact literal `Lax` and add a comment that this
  mirrors `application.properties` default. Same login
  with `rememberMe=false` MUST omit `Max-Age` (session cookie). ALSO: the
  same response MUST carry a co-emitted `Set-Cookie: XSRF-TOKEN=...`
  alongside `SESSION` — closes TC11 regression risk (removal of the
  pre-flip `csrfCookieMaterializer` WebFilter must not silently drop the
  XSRF cookie write).

- **TC5 — `CookieSerializer` bean type assertion.** Context-load test
  asserts that the `CookieSerializer` bean in the application context is an
  instance of `com.botfunnel.security.RememberMeCookieSerializer`. Without
  this assertion, a future regression that drops the `@Bean` registration
  would silently fall back to Spring Session's auto-configured
  `DefaultCookieSerializer`, and remember-me Max-Age branching would
  disappear undetected.

Result: AC16 + AC17 + AC18 + TC5 + TC11 covered by automated tests; AC12 +
R3 + R4 + R5 lifted from manual checks into the standard test run.

**Edge cases:**

- `MockMvc` does not propagate cookies between requests by default. AC16 session continuity is asserted at the `sessions` collection (document count) level, not via cookie introspection — mirrors the pattern already used by the existing `changePassword_correctCurrent_...` test (line 225 pre-flip) which seeds sessions directly and asserts document counts.
- AC18 `SameSite` attribute is not always exposed via `MockHttpServletResponse.getCookie(name).getAttribute("SameSite")` on all Tomcat versions. Fallback: parse the raw `Set-Cookie` header via `response.getHeaders("Set-Cookie")` and string-match `;\s*SameSite=Strict;?`. Document the choice in a Javadoc on the test method.
- AC17 message regex MUST tolerate Hibernate Validator's default-message text variation across locales (`"must not be blank"` in en, possibly different in ua locale if the test profile sets one). The regex `^email: .+(, .+: .+)*$` pins the joiner shape but allows any default-message body — this is the right balance per spec ("pin the joiner shape that `useApiError` may parse").
- AC18 `rememberMe=false` test must not accidentally accept the absent `Max-Age` because the cookie itself was not emitted. Assert `response.getCookie("SESSION")` is non-null first, then assert `getMaxAge() == -1`.
- AC16 pre-flip BSON fixture: spring-session-data-mongodb 3.5.x writes the `attributes` field as a `Document` containing `SPRING_SECURITY_CONTEXT` as a BSON `Binary` (Java-serialized `SecurityContext`). Constructing a fully-deserialisable `SecurityContext` blob for the fixture is unnecessary — the terminate-by-`principal` query only reads the top-level `principal` field. Populate `principal` + `_id` + `created` + `expireAt` only; leave `attributes` empty or omit. This keeps the fixture minimal and avoids brittle byte-shape coupling.
- TC5 test: if `RememberMeCookieSerializer` is registered via a `@Bean` method that returns `CookieSerializer` (not `RememberMeCookieSerializer`) AND another `@Bean` for `CookieSerializer` exists somewhere (auto-config conditional), `@Autowired CookieSerializer` may pick the wrong one. If the assertion fails for this reason, surface as a Task 3 fix-up — do NOT weaken the assertion.

**Implementation hints (not pseudocode):**

- For AC18 SESSION cookie attribute assertions, prefer parsing the raw `Set-Cookie` header via `response.getHeaders("Set-Cookie")` over the `cookie()` matchers — the latter only cover `Max-Age` and `Path`. A small helper that splits on `;`, trims, and converts to a `Map<String, String>` keyed by attribute name (case-insensitive) makes the assertion readable.
- For AC17 message regex matching, use `jsonPath("$.message").value(matchesPattern("^email: .+(, .+: .+)*$"))` with `org.hamcrest.Matchers.matchesPattern`.
- For AC16 pre-flip BSON fixture, build the `Document` exactly as `ProfileControllerIT.seedSession(...)` does today (line 57 pre-flip) — same fields, same types. The point of the test is to assert that this shape continues to be read correctly by the post-flip repository, not to fabricate a more exotic shape.
- For TC5, the plain `@Autowired CookieSerializer cookieSerializer` field is enough; use `Optional<CookieSerializer>` only as a local debugging step if the assertion fails on the first run and you need to disambiguate "bean missing" vs "bean is wrong type".
- All six tests are MockMvc-based and live inside classes that already extend `AbstractIntegrationTest` (Mongo / Redis / Mailpit testcontainers wired). No new test infrastructure required.
