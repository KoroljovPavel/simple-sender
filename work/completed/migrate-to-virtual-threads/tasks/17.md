## Required Skills

## Description

Final-wave acceptance testing for the WebFlux → Spring MVC + virtual threads migration. After all functional waves (Phase A pre-flip, Phase B atomic flip, Phase C post-flip + cleanup) and the three audit tasks (Code / Security / Test) have completed, this task runs the full Agent Verification Plan from `tech-spec.md` against the merged codebase and produces a JSON pass/fail report per acceptance criterion.

Scope of this QA:
- Run the entire test suite (default + `-PrunSlow=true` slow-tagged P99 probe).
- Execute the 4 user-spec grep gates (AC3 reactive imports, AC4 Lombok, AC5 VT property, AC6 reactive starters) plus the 1 doc-update grep (AC14 — same grep emitted by Task 13's `Verify-smoke`).
- Verify user-spec AC1-AC6, AC14, AC15, AC16, AC17, AC18 from automated evidence (test runs + greps).
- Verify tech-spec TC1-TC11 (TC12 per-file coverage floor is a coverage check, included).
- Run AC7 (VT pinning probe) once: boot backend with `-Djdk.tracePinnedThreads=full`, capture pinning sites, confirm they are documented in `patterns.md` "Virtual Threads" section (written by Task 11).
- Walk AC11-AC13 manual UI smoke flows on `localhost:3000` (register/verify-email/login/logout; remember-me cookie Max-Age; forgot-password → reset).
- Confirm AC8-AC10 (staging-smoke runbooks 06/07/08 for Telegram) are operator-runnable as-is — do not require automation; documented as deferred to operator post-deploy verification per `deployment.md` (production hosting TBD).

Out of scope: deploy and post-deploy verification — this migration has no production deploy in scope (deployment.md → TBD); value is delivered to local-dev + staging-smoke workflows.

Output: a single JSON pass/fail report at `work/migrate-to-virtual-threads/logs/working/qa-report.json` per the `pre-deploy-qa` skill schema, with one entry per AC (user-spec + tech-spec TCs), plus a concise decisions.md summary.
