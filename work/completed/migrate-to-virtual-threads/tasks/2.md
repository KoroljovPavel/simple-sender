# Task 2: Stub interface flip — subscriber/ + funnel/ Mono<Void> → void

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Phase A pre-flip cleanup task that prepares two no-op stub service contracts (`SubscriberService`, `FunnelTriggerService`) for the upcoming atomic WebFlux → MVC + virtual-threads flip in Wave 2.

Today both interfaces return `reactor.core.publisher.Mono<Void>` and their `NoOp*` implementations return `Mono.empty()`. The four call sites in `ProcessTelegramUpdateJob` invoke them with trailing `.block()`. Because neither file imports WebFlux HTTP types (only `reactor.core.publisher.Mono`), Reactor remains on the classpath via the reactive starter and these symbols are safe to flip while the rest of the codebase is still reactive. Flipping them now reduces the size of the eventual atomic flip commit and lets the change land as an independently-green, isolated PR.

After this task, `ProcessTelegramUpdateJob` calls the two stub services directly (no `.block()` on the four stub-service sites). The 17 `.block()` budget tracked by code-research §5(d) for the atomic flip drops to 13 (4 sites removed here; remaining 13 cover `RawUpdateRepository`, `BotRepository`, `ProjectRepository`, `ReactiveMongoTemplate`, and `EventService` — all of which still depend on the reactive starter and must flip atomically in Wave 2). The two `NoOp*` unit tests stop relying on `reactor.test.StepVerifier` and become direct invocation assertions that document the side-effect-free contract.

End state: project still compiles and tests pass on the reactive stack. The stub-service contracts are pre-aligned with the post-flip synchronous shape.
