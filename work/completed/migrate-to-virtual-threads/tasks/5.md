# Task 5: Services not touching `ServerWebExchange` — `UserService`, `EventService`, `EmailService`, `common/HttpRequestUtils`

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Flip three leaf services (`UserService`, `EventService`, `EmailService`) from reactive (`Mono<T>` / Reactor fire-and-forget) to plain synchronous APIs on the servlet stack, and create the new shared helper `common/HttpRequestUtils` (per D13) consolidating the four duplicate `extractIp(ServerWebExchange)` + cap-user-agent implementations currently scattered across `AuthService`, `ProjectController`, `ProfileController`, `BotController`.

These three services were singled out because they do NOT depend on `ServerWebExchange`/`WebSession` — they only deal with plain domain types and `JavaMailSender` — so they can be flipped in isolation without touching the security/session shell (which is owned by Task 3 / Task 6). `HttpRequestUtils` belongs in this task because once Wave 2 lands every caller is on `HttpServletRequest` and the four duplicated extractors must be rewritten anyway — extracting once is cheaper than rewriting four times (per D13 rationale).

Per-service deltas:
- **UserService:** `Mono<User> findByEmail(...)` → `Optional<User> findByEmail(...)`; `Mono<User> save(...)` → `User save(...)`; `Mono<User> softDelete(...)` → `User softDelete(...)` (throws `AppException` instead of `Mono.error(...)`); `canActivate(User)` stays as-is (already synchronous).
- **EventService:** collapse the current two-method API (`void logEvent(...)` fire-and-forget via `.subscribe(...)` + `Mono<Event> logEventBlocking(...)`) to ONE synchronous method `Event logEvent(String userId, String eventType, String ipAddress, String userAgent, Map<String,Object> metadata)` per D12. The Reactor fire-and-forget pattern (`.subscribe(null, log::error)`) was only needed because the caller's reactive chain wouldn't otherwise execute the save — under VT that escape disappears. Cascade-ordering callers (`ProcessTelegramUpdateJob`) get the synchronous return for free and no longer need `.block()`.
- **EmailService:** `private void sendAsync(...)` rewrites the body — drops `Mono.fromRunnable(...).subscribeOn(boundedElastic()).subscribe(null, log::error)` and replaces it with a direct `try { ... build + send ... } catch (Exception e) { log.error("Email send failed to {}: {}", to, e.toString()); }` per D15. This PRESERVES the silent fire-and-forget semantics: SMTP failures continue to produce a single ERROR log + a successful response to the API caller (no propagation to user-facing 500). Method signature unchanged; remove `reactor.core.publisher.Mono` and `reactor.core.scheduler.Schedulers` imports.
- **HttpRequestUtils (NEW):** public final utility class in `com.botfunnel.common` with two static methods — `public static String extractIp(HttpServletRequest request)` (X-Forwarded-For leftmost entry preserved per current `AuthService.extractIp` security note about reverse-proxy trust; falls back to `request.getRemoteAddr()`; returns `"unknown"` if neither resolves) and `public static String extractUserAgent(HttpServletRequest request)` (reads `User-Agent` header, caps at the same length currently used in `ProjectController.capUserAgent`). Private constructor to prevent instantiation.

Result: three leaf services on the servlet stack, one new shared helper, no behavioural regression (silent-email-failure preserved, fire-and-forget event-logging preserved, X-Forwarded-For trust-boundary preserved).

   - Remove `import reactor.core.publisher.Mono;`.
   - Delete `logEventBlocking(...)` entirely.
   - Rewrite `logEvent(...)` to RETURN `Event`: build the `Event`, call `eventRepository.save(event)` synchronously, return the saved entity. Drop the `.subscribe(null, err -> ...)` swallow.
   - Class-level comment update: drop the obsolete "Fire-and-forget: never throws" promise — under D12 the method now throws on persistence failure; callers that want the previous silent semantic do their own try/catch (none currently do — every caller either ignored the return or `.block()`'d it per D12 rationale). 4. Rewrite `backend/src/main/java/com/botfunnel/email/EmailService.java` per D15:

   - Body of `sendAsync`: wrap the `createMimeMessage` + `MimeMessageHelper` setup + `javaMailSender.send(msg)` in a single `try { ... } catch (Exception e) { log.error("Email send failed to {}: {}", to, e.toString()); }`. The catch swallows `MailException`, `IllegalStateException` (the existing "Failed to build email" wrap), and any other unchecked exception — preserves the silent-failure semantic that the current `.subscribe(null, log::error)` provides.
   - Keep `buildVerificationBody`, `buildPasswordResetBody`, `buildAccountBlockedBody`, `loadTemplate`, `htmlEscape` untouched.

5. Update the three test files (`UserServiceTest`, `EventServiceTest`, `EmailServiceTest`) per Task 10 mock-triple guidance but ALSO covering the new sync semantics — see TDD Anchor section. Drop `reactor.test.StepVerifier` + `reactor.core.publisher.Mono` imports throughout; rewrite assertions on direct return values; drop `Awaitility` polling from `EventServiceTest` / `EmailServiceTest` (sync send → assertion is direct).

6. Sanity-check that no other module breaks compilation due to the `UserService` / `EventService` signature flip. Direct callers identified during code-read: `AuthService` (multiple `eventService.logEvent(...)` sites inside Reactor chains — these will be flipped by Task 6, but their compile-time signature must align with the new `Event` return), `ProjectService.logEvent` sites (Task 7), `ProfileService.logEvent` sites (Task 7), `TelegramSender.logEvent` (Task 8), `BotService.logEvent` (Task 7), `ProcessTelegramUpdateJob.logEventBlocking` sites (Task 9). **Edge cases:**
- X-Forwarded-For with leading/trailing spaces (`"  203.0.113.1  "`) — trim per existing `AuthService.extractIp` `xff.substring(...).trim()` logic.
- X-Forwarded-For with only commas (`",,,"`) — current code returns the substring before the first comma which is empty; replicate exactly to avoid behavioural drift (do NOT silently change to fallback). Tests are not required to cover this exotic case but the implementation must match the current source-of-truth.
- `MailException` subclasses (`MailSendException`, `MailAuthenticationException`, `MailPreparationException`) — all swallowed by the `catch (Exception e)` in D15. Verified by the unit test `sendVerificationEmail_smtpFailureLogsError`.
- `IllegalStateException` from the current `MimeMessageHelper` wrap (`"Failed to build email"`) — must remain swallowed under D15. The test `sendVerificationEmail_buildFailureLogsError` covers this.
- Empty / null `User-Agent` header — return `null` (matches `ProjectController.capUserAgent` returning `null` for `null` input). Do NOT return `""` — would be a behavioural drift visible in event-log fields.
- `EventService` cascade-ordering callers in `ProcessTelegramUpdateJob` — they currently rely on `.block()` for ordering. Once `logEvent` is synchronous, the `.block()` becomes a `;` (direct sync call) and ordering is naturally preserved. Task 9 owns those edits; THIS task only changes the `EventService` API surface.
