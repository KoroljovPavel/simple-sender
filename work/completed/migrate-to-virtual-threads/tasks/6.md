# Task 6: Auth stack — AuthService + AuthController + tests

## Description

Flip the 650-LOC `AuthService` and its `AuthController` (8 endpoints) plus four test files from the WebFlux reactive stack to the synchronous servlet stack. Part of Wave 2 atomic-flip commit per D5/D9 — this task is one logical chunk inside the single physical commit; it does NOT compile in isolation.

Goals:

1. Public API of `AuthService` flips from `Mono<X>` to `X` across all 9 public methods. `ServerWebExchange` and `WebSession` parameters split into `HttpServletRequest` and `HttpServletResponse` per the servlet-stack signature mapping in `code-research.md §2` (Reactive security stack — `WebSession` → `HttpSession`, `WebSessionServerSecurityContextRepository` → `HttpSessionSecurityContextRepository`).
2. `AuthController` returns `ResponseEntity<X>` directly (no `Mono` wrap) and takes `HttpServletRequest request, HttpServletResponse response` where the previous handler took `ServerWebExchange`.
3. Internal `Mono.fromCallable(() -> bcrypt...).subscribeOn(Schedulers.boundedElastic())` ceremonies at the 4 BCrypt sites in `AuthService` (`resetPassword` line 366, `register` line 420, `handleUserNotFound` line 522, `authenticate` line 532) collapse to direct synchronous `passwordEncoder.encode(...)` / `passwordEncoder.matches(...)` calls. Implicit `boundedElastic` back-pressure cap removed per D4 (explicit accept — not a regression).
4. `ReactiveMongoTemplate` field becomes `MongoTemplate`; `ReactiveRedisTemplate<String,String>` becomes `RedisTemplate<String,String>`. `terminateAllSessions(...)` uses sync `mongoTemplate.remove(...).getDeletedCount()`. Brute-force counter ops (`INCR` + `EXPIRE` + `DEL`) use sync Lettuce primitives — atomicity invariant preserved (still no Lua; per-key INCR-then-conditional-EXPIRE shape unchanged).
5. `ReactiveSecurityContextHolder.getContext()` in `me()` becomes `SecurityContextHolder.getContext()`.
6. Session-fixation guard: on successful login, invoke `request.changeSessionId()` BEFORE `securityContextRepository.saveContext(context, request, response)` to mint a fresh `JSESSIONID` (mirrors current WebFlux `WebSession.invalidate() + new session` behaviour and matches `SecurityConfig` rewrite expectations from Task 3). `logout(...)` calls `request.getSession(false).invalidate()` when a session exists.
7. Timing-attack guard preserved: `handleUserNotFound` keeps the BCrypt dummy-hash consume; `forgotPassword` keeps the `FORGOT_DUMMY_DELAY` calibrated baseline path.
8. `REMEMBER_ME_ATTR` write site (`openSession` line ~604) reads constant from `common.SessionAttributes` (post-Task-1) and writes to `request.setAttribute(...)`. The reader is `RememberMeCookieSerializer` (delivered by Task 3) which reads via `CookieValue.getRequest().getAttribute(...)`.
9. IP/UA extraction uses `common.HttpRequestUtils.extractIp(HttpServletRequest)` / `extractUserAgent(HttpServletRequest)` (delivered by Task 5) — drop the private `extractIp(ServerWebExchange)` static helper at the bottom of `AuthService.java`.
10. All four test files rewrite from `StepVerifier` + `MockServerWebExchange` + reactive mocks to direct assertions + `MockHttpServletRequest`/`MockHttpServletResponse` + sync mocks. `AuthControllerSliceTest` switches `@WebFluxTest` → `@WebMvcTest`, `WebTestClient` → `MockMvc`, and uses `org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.csrf()`. `AuthControllerIT` extends the new MockMvc `AbstractIntegrationTest` (delivered by Task 10) and uses `MockMvc` instead of `WebTestClient`.

All security invariants enumerated in the tech-spec must remain intact: BCrypt dummy-hash on user-not-found, brute-force INCR+EXPIRE+conditional reset atomicity, fail-open semantics on Redis errors, audit-event emission order on threshold trips, session-fixation post-login, `forgotPassword` enumeration-oracle suppression. This is part of the Wave 2 atomic commit per D5/D9 — `Mono`/`Flux`/`ServerWebExchange`/`WebSession` symbols leave the classpath the moment `spring-boot-starter-webflux` is removed (Task 3), so all WebFlux-coupled imports in these 7 files must be resolved in the same commit.

## What to do

1. **`AuthService.java`** — rewrite all 9 public method signatures to synchronous return types and servlet-stack parameters:
   - `AuthResponse login(LoginRequest, HttpServletRequest, HttpServletResponse)`
   - `MeResponse me()`
   - `RegisterResponse register(RegisterRequest, HttpServletRequest)` (no response param — register does not open session)
   - `void resendVerification(String)`
   - `void logout(HttpServletRequest, HttpServletResponse)`
   - `void forgotPassword(String, HttpServletRequest)`
   - `void resetPassword(String, String, HttpServletRequest)`
   - `VerifyEmailResponse verifyEmail(String, HttpServletRequest)`
   - `long terminateAllSessions(String)` (private — flipped from `Mono<Long>`)
2. Replace `ReactiveMongoTemplate` field + ctor param with `MongoTemplate`. Replace `ReactiveRedisTemplate<String,String>` with `RedisTemplate<String,String>`. Replace `ServerSecurityContextRepository` with `SecurityContextRepository` (servlet variant).
3. Collapse all 11 Reactor-boundary sites enumerated in `code-research §1.6` to direct synchronous calls. Two distinct shapes: (a) 4 `Mono.fromCallable(() -> bcrypt...).subscribeOn(boundedElastic())` BCrypt sites (lines 366, 420, 522, 532) → direct `passwordEncoder.encode(...)` / `.matches(...)` returning `String` / `boolean`; (b) 7 `Mono.fromRunnable(() -> eventService.logEvent(...))` event-emission sites (lines 470, 506, 525, 537, 571, 577, 585) → direct `eventService.logEvent(...)` statements with no return capture (the `void`/Event return is discarded as it was before). Reactor error/`.then`/`.flatMap` chains around these sites become imperative `if`/`throw` and ordered statements.
4. Rewrite `openSession(...)`: take `HttpServletRequest request, HttpServletResponse response`. Write `request.setAttribute(SessionAttributes.REMEMBER_ME_ATTR, Boolean.valueOf(rememberMe))`. Call `request.changeSessionId()` for session-fixation defense. Set TTL via `request.getSession(true).setMaxInactiveInterval((int) ttl.getSeconds())`. Call `securityContextRepository.saveContext(context, request, response)`.
5. Rewrite `me()`: read principal via `SecurityContextHolder.getContext().getAuthentication()` and map to `MeResponse`.
6. Rewrite `logout(...)`: read `HttpSession session = request.getSession(false)`; if non-null call `session.invalidate()`. Drop the `WebSession.invalidate()` reactive call.
7. Rewrite `terminateAllSessions(userId)`: `mongoTemplate.remove(Query.query(Criteria.where("principal").is(userId)), "sessions").getDeletedCount()`. Same `principal` field path — Spring Session 3.x document shape identical across reactive/servlet variants per `code-research §2`.
8. Rewrite all Redis brute-force ops to sync: `redisTemplate.opsForValue().increment(key)` returns `Long`; `redisTemplate.expire(key, ttl)`; `redisTemplate.delete(key1, key2)` returns `Long`. Same INCR-then-conditional-EXPIRE-on-count==1 invariant. Same fail-open `try/catch` shape (wrap with `try { ... } catch (Exception e) { log.warn(...); }` except `AppException` rethrows).
9. Delete the private `extractIp(ServerWebExchange)` static helper at file end. Call sites use `HttpRequestUtils.extractIp(request)` and `HttpRequestUtils.extractUserAgent(request)` instead.
10. Update import: `com.botfunnel.security.RememberMeWebSessionIdResolver` → `com.botfunnel.common.SessionAttributes` (already done by Task 1 — verify post-merge).
11. **`AuthController.java`** — flip all 8 endpoint signatures:

**Edge cases:**

- Login as user-not-found MUST still consume ~250ms in BCrypt — `passwordEncoder.matches(password, DUMMY_HASH)` runs synchronously on the calling VT (acceptable per D4).
- `forgotPassword` unknown-email / soft-deleted-email branch MUST still incur a `FORGOT_DUMMY_DELAY` (~40ms) — use `Thread.sleep(FORGOT_DUMMY_DELAY.toMillis())` or similar synchronous delay to keep the timing-oracle suppression.
- Brute-force `INCR + EXPIRE` race: same small race window exists in sync Lettuce as in reactive Lettuce (no Lua atomicity). Keep the existing comment explaining the window.
- `register` path: when email already exists (status != deleted), do NOT call BCrypt — fast-path returns 409 to avoid wasting CPU on a known-bad input. Test asserts BCrypt was never invoked.
- `me()` when no session: `SecurityContextHolder.getContext().getAuthentication()` returns an `AnonymousAuthenticationToken` (not null) under default `SecurityContextHolder` strategy — explicitly check `authentication.isAuthenticated() && !(authentication instanceof AnonymousAuthenticationToken)` before reading principal; throw `AppException.unauthorized(...)` otherwise. Mirrors current reactive `ReactiveSecurityContextHolder.getContext()` `.switchIfEmpty(...)` behaviour.
- Session-fixation: `request.changeSessionId()` REQUIRES an existing session — if none exists yet (anonymous login flow), the call throws `IllegalStateException`. Defensive shape: `if (request.getSession(false) == null) { request.getSession(true); } request.changeSessionId();` — or simply `request.getSession(true); request.changeSessionId();`. The current reactive code only invalidated on a present session; mirror that conditional shape.
- `logout` when no active session: `request.getSession(false)` returns null — must skip `invalidate()`. Already covered in current reactive `WebSession` flow (returns Mono.empty when no session); keep the same null-guard in servlet variant.
